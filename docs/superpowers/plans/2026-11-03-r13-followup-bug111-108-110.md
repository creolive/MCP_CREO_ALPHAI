## 驱动报告与判定约定

- 三个 `judge_*` 函数只处理证据字典，不启动进程、调用 MCP 或访问真实模型；单测用合成字典验证判定，不能把它写成实机证据。
- 每例至少保存 `case_id`、`scope`、原始 `request`、`model_id`、`job_id`、终态回执、前后快照、`checks` 和身份。`checks` 每项包含实际值、预期、通过/失败/不可测；缺必要检查为 unverified，实际违反预期为 fail，必要项全部证实才为 pass。
- 报告顶层区分 `verification_level=offline|live` 与目标 `scope`。控制场景 pass 不补齐目标覆盖；BUG-111 的 reproduce pass 不能当作 verify pass；零件 ack pass 不能补齐装配 ack。
- 实机驱动写完报告后：目标 scope 为 pass 才返回 0，fail 返回 1，未触发/条件不足/证据不全返回 2；既有“无确认参数返回 2”保持。复现阶段可在正确记录预期失败后返回 0，但 scope 必须标 reproduce。离线单测自身成功退出不改变任何 live 覆盖状态。
