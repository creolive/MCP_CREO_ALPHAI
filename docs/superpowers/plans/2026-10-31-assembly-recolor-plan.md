## 目标与范围

将建议包中的 Toolkit 上色方法接入 MCP，支持用户已确认的范围：

- 给 MCP 受管的单层装配按零件族上色。
- 默认按来源零件自动分族，也支持显式族表。
- 提供分组预览、颜色读回、保存重载及失败回滚。
- 首版聚焦装配组件外观；独立零件、面级、嵌套及外部装配另行扩展。

建议包作为技术参考及外部测试资料保存；其测试回执不替代本项目验收。

## MCP 接口

新增一个工具：

```python
creo_recolor_assembly(
    model_id,
    expected_revision,
    palette=None,
    families=None,
    dry_run=False,
    limit=50,
    cursor=None,
)
```

- **自动分族**：省略 `families`，按组件绑定中唯一的 `source_model_id` 分组；`palette` 的键为该来源 ID。
- **显式族表**：`families={族名: [组件标签或特征ID]}`，`palette={族名: [r,g,b]}`；族名沿用项目标签规范。族表必须无重复、完整覆盖组件。
- **颜色**：RGB 必须为三个有限数值，范围 `0..1`，拒绝布尔值。写入时色板必须完整匹配所有族。
- **预览**：`dry_run=true` 可省略色板；读取已验证快照，分页返回分组、计数及未匹配项，不连接 Toolkit、不创建作业、不推进 revision。游标绑定 revision 和请求内容。
- **执行**：返回现有 `job_id/model_id`，通过 `creo_get_job` 轮询；始终保存，成功后 revision 增加一次。分页参数只用于预览。
- 同步增加 `recolor_assembly` 计划操作，供 `creo_execute_plan` 使用；仅选择操作前已经存在的组件，计划操作不接受预览参数。

来源缺失或冲突时要求显式族表，不按遍历顺序或随机副本名称猜测分组。

## 实现方式

1. **登记与隔离**
   - 实施前登记 `FEAT-052`，明确范围和验收；若编号已被占用，使用下一未占用编号。
   - 在独立开发分支和隔离工作树开展离线开发，保留当前 DEV-053 的未提交内容。
   - 业务逻辑放入 `src/creo_mechdog/appearance.py`；工具注册、操作校验、装配白名单和能力声明同步接入。

2. **原生批量上色**
   - 在 `native/appearance.h` 实现组件定位、外观设置和读回，接入现有执行器。
   - 使用实际组件模型类型构造 `ProAsmitem`，修正建议包仍传 `PRO_FEATURE` 的问题。
   - 写入前在通道锁内重新核对 revision、组件身份、全部分组及原有外观，再开始设置。
   - 采用建议包的显示参数：ambient `0.4`、diffuse `0.7`、highlite `0.5`、shininess `0.4`、transparency/reflection `0`；高光颜色随 RGB 更新。
   - 颜色写在装配组件层，刷新目标装配窗口；源零件文件保持原字节。

3. **保存、基线与回滚**
   - 组件检查快照增加外观属性及原始查询码，区分“存在”“不存在”和“查询失败”。
   - 设置后逐组件读回，保存并擦除重载后再次读回；RGB 绝对误差须不超过 `1e-6`。
   - 将外观纳入装配入场、保存重载和回滚核验，后续改位置、保存等操作也必须保持颜色。
   - 旧登记缺少外观基线时，提示先通过现有 `creo_save_model` 建立并验证检查点，再执行上色。
   - 任一步失败沿用检查点回滚，并核对恢复后的外观。无法证明恢复成功时保留现有 unknown 保护。

4. **查询与说明**
   - 作业结果提供上色数、未匹配项、各族计数及两次读回结果；compact 仅保留数量和核验状态。
   - 完整逐组件结果通过 full job 查询；当前颜色通过现有组件检查分页读取。
   - 同步能力说明、使用示例、工具描述和测试证据。明确组件外观读回与屏幕实际显示分别验收。

## 验收

新增 `tools/test_assembly_appearance.py`，覆盖：

- **输入与分组**：自动分族、显式合族、多标签同来源、来源冲突、重复或遗漏组件、非法 RGB、过期 revision、非装配及缺件拒绝。
- **预览与协议**：无 Toolkit 调用、无作业及 revision 变化；分页不超过 32 KiB，变更后旧游标失效；busy 沿用立即拒绝契约。
- **实机正例**：新建 80 组件、12 族夹具，采用建议包的颜色和族计数；核对保存擦除重载后的颜色、源零件哈希，以及组件身份、位置、约束和几何不变。
- **持续编辑与失败**：再次换色、后续改位置及保存均保色；原生执行中途失败后恢复原有颜色及“无组件外观”状态。读回错误和失配另用离线受控用例覆盖。

运行专项单测、项目开发检查、匹配 SDK 构建及装配针对性回归。实机成功必须同时具备颜色核验和 `saved_file_reloaded_and_verified=true`，并目视确认显示效果。
