## 方案比较与推荐

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| 一次性大版本 | 稳定性、基准面、钣金四壁、原案复现、全箱一起完成后发版 | 发布依赖缺失附件、外部 SDK 和未定机理，交付时间无法可靠确定 |

| 分阶段独立交付（推荐） | 先消除复现/发布障碍，再修参数契约；四壁按证据推进，缺件和外部环境单列 | 每阶段可独立审查发布，调查结论与能力扩展可分开验收 |

推荐第三种。这是本计划的建议，不表述为用户已经选择的实施方案；本轮不据此运行建模或修改产品代码。

## 契约决策

1. **引用与创建分开。** `{kind:'datum_plane',normal:[...],offset:d}` 是匹配已有面，不能描述成“按法向创建新面”。`datum_axis_feature` 已有解析支持；报告中的 `datum_feature` 轴标签错误先核对类型兼容与诊断。缺 kind、错类型、未知标签必须在适当边界明确拒绝，不能泄露 JSON 缺键异常。
2. **angle 与 offset 不再静默共存。** 第一阶段建议明确拒绝 `angle is not None` 且 `offset != 0`，保留单独旋转、单独偏移以及旋转加 offset=0；推荐两次显式基准特征完成旋转后偏移。若要单次组合，须另定特征数量、编辑、回滚和兼容设计，不在修复中隐式创建两道特征。角度符号由选中轴的实际有向几何核对，不能只凭“Z 轴”名称认定顺逆时针。
3. **草图原点先增强诊断。** 保留现有 `1e-6 mm` 判定阈值，返回原点到支撑面的有符号/绝对距离、归一法向、平面常数及阈值。后续可选投影或容差变化须显式设计，不能默默移动用户坐标，也不能从一份 TXT 推导所有模型通用 `1e-3 mm`。
4. **钣金以帧、几何和壁面共同判定。** depth 沿有符号草图法向，thickness 沿面内垂直直线方向；回显须与实际材料侧一致。标准水平底板采用 YZ/offset=92.5、线 `(-116,0.5)→(116,0.5)`、depth=185、thickness=1、direction=negative，目标 bbox 为 X±92.5/Y±116/Z[0,1]、V=42920、COG=(0,0,0.5)。体积一致不证明壁面可用于折边。
5. **可挂边只承诺已证明的层次。** 如新增检查字段，采用 `eligible/ineligible/unknown` 的壁面轮廓候选状态并保留查询码；候选不等于任意 flange 必定成功，还要通过邻接端与几何检查。不以 `thickness>depth` 或“厚度>5”直接拒绝合法厚壁，也不向未知查询填 false。
6. **种子发布保留显式来源。** 种子先确定性构建，摘要显式回填后再打源码包；新增一致性断言放入现有打包入口，失败必须阻断源码打包。不让打包命令自动改写源码。不为人工逐 ID 状态与 DLL/注册路径核对另造发布工具。
7. **空件预览按可渲染几何判定。** 可显式表达空件跳过，但不能以体积为 0 跳过有草图、曲面等可渲染几何。跳过空件属于状态语义改善，不能声称已经查明 raster=0 却缺图的 I/O 根因。
8. **revision 只在终态后用于写入。** 新建受理阶段 0、成功后 1 可以是合法异步流程。验收同时记录受理返回、终态和 inspect，成功后以最新终态 revision 提交。只有终态或权威 inspection 自相矛盾才登记实现缺陷。

## 架构与并行边界

业务校验和新逻辑放 `src/creo_mechdog/`；`server.py` 只注册/转发和维护工具说明，Toolkit 调度与通道锁仍由 `bridge.py` 持有。新增测试进 `tests/unit/`；原生几何、方向和回读由 Toolkit 执行器验证，Python 不模拟 Creo。

文档、离线单元、夹具设计可并行；同一核心文件的修改需一名集成人收口。构建共享执行器、替换 worker 与所有 Toolkit 操作由一名会话编排人串行安排，不同时构建/连接。busy 立即停止该轮新提交，不自动重试、不排队；已受理任务只查 job_id。
