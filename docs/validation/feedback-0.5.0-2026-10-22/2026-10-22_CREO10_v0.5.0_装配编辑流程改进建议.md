# MCP_CREO_MechDog 装配编辑流程改进建议

> **文档命名**：2026-10-22 / CREO 10 / v0.5.0 / 流程改进建议：**装配编辑"重建管线"的可用性缺口（批量收养、按路径收养、约束回放、矩阵入参、健康诊断、结果比对）**
> **提交日期**：2026-10-22
> **提交对象**：MCP_CREO_MechDog 作者
> **文档性质**：基于一次真实装配编辑实操的改进建议（非缺陷报告；缺陷与观察见同期 `2026-10-22_CREO10_v0.5.0_FEAT045交付与死锁根治但变换单位存疑.md`）
> **实操对象**：`asm_mx.asm.16`（8 组件，Cherry MX 键盘装配）→ 重建为托管装配 `asm_edit_demo` 并完成结构级 + 零件级编辑

---

## 1. 这次实操做到了什么（背景）

FEAT-045 落地后，路线 A（结构级编辑）已验证可行：

```
open_file(asm_mx) → inspect_session_assembly（8 组件 + 4x4 变换）
  → 逐零件 open_file + adopt（MX_UP 成功）
  → new_assembly → assemble_component ×2（位姿放置）
  → component_placement（平移 + 绕 Z 15°，回读矩阵精确）
  → set_dimensions（元件厚度 1.5→2.5mm，体积 611.31→1018.85 mm³）
```

每步均 `saved_file_reloaded_and_verified: true`，产出 `asm_edit_demo.asm.5`，job 自带 preview.jpg。**能力成立，但流程成本与保真度还有明显优化空间**，以下按优先级列出。

---

## 2. 改进建议（按对实用性的影响排序）

### P1-1 缺"按路径收养"，收养被当前窗口串行化 ⭐影响最大

**现状**：`creo_adopt_current_model` 只能收养"当前窗口模型"。收养一个组件必须 `open_file`（使其成为当前窗口）→ adopt inspect → apply → 轮询，四步串行。8 个组件实测耗时：单件 open 7-8s + inspect 10s + apply 21-42s ≈ **约 5.5 分钟纯串行**（单 Toolkit 通道，无法并行）。

**影响**：100 组件的装配 ≈ 1 小时以上，路线 A 在真实装配上基本不可用。

**建议**：
1. 新增 `creo_adopt_file(file_path, mode, model_name?, idempotency_key)`：直接按磁盘路径收养，内部完成 retrieve + 预检 + 复制，**不要求也不改变当前窗口**；
2. 或支持批量：`creo_adopt_current_model(targets=[{file_path}...])` 单 job 多目标（一次通道锁内完成）；
3. 批量时每件返回独立结果，避免一件失败中断全部。

### P1-2 `assemble_component` 只能逐个调用，每件一次 save+reload

**现状**：每次 `assemble_component` 都是一个 job（含 save + reload + verify，实测 12-13s/件）。放 8 个组件要 8 次完整保存重载。

**建议**：支持**批量装配**——`components=[{label, source_model_id, translation, rotation}...]` 在**一个 job** 内完成全部插入，末尾统一 save+reload+verify。预计 8 件可从 ~100s 降到 ~25s。

### P1-3 FEAT-045 的约束快照无法回放到 `assemble_component.constraints`

**现状**：`inspect_session_assembly` 完整返回了约束（`type: align/mate/orient/align_offset`、`type_code`、`item_id`、`item_type`、`occurrence_path`、`offset`），但 `assemble_component` 的 `constraints` 入参是 `additionalProperties: true` 的自由对象，**没有公开的字段映射契约**，无法把快照直接喂回去。本次只能用 `placement: fixed` + 平移兜底——**约束语义（尤其 mate 的几何依附关系）在重建中丢失**，装配改动后不能像原装配那样自动调整。

**建议**：
1. 提供字段映射文档或专用桥接工具，如 `creo_assemble_from_inspection(assembly_name, components?, placement="constraints")`：直接读 FEAT-045 快照 + 已收养组件，一次完成"按约束重建"；
2. 或在 inspect 结果中同时输出 `assemble_component.constraints` 可直接使用的形态（含引用解析后的 item 标识）。

### P1-4 变换入参只有 Euler 角，inspect 只给 4x4 矩阵

**现状**：`inspect_session_assembly` 返回行向量 4x4 矩阵；`assemble_component` / `component_placement` 只接受 `rotation` = XYZ Euler 度。任意矩阵转 Euler 需要 agent 自己做数值换算（本次 15° 旋转验证通过：`[[cos15,sin15,0],[−sin15,cos15,0],…]` 精确回读），但带轴交换的组件（如 MX_PIN 的 `[[0,−1,0],[0,0,−1],[1,0,0]]`）换算是易错点，且存在万向锁退化、矩阵含微小非正交误差时的取舍问题。

**建议**：
1. `assemble_component` / `component_placement` 支持 `rotation_matrix`（4x4 或 3x3）直接入参；
2. 或 inspect 结果每个组件附带 `euler_deg_xyz`（按其自身矩阵精确导出），减少 agent 侧换算；
3. 输出中标注矩阵正交性校验结果（避免把带数值噪声的矩阵当精确刚体）。

### P1-5 收养拒绝"不健康零件"，但无逐特征诊断

**现状**：MX_DOWN（132 特征 / 260 曲面 / 840 边）被拒：
`reason_code: "unhealthy_features"`，`reason: "The model has failed, suppressed or incomplete features"`，且 `health_breakdown: "combined failed/suppressed/incomplete feature check; per-feature reasons are unavailable"`。

**影响**：真实存量装配的组件常带失败特征（转换/历史遗留）。用户拿到"不健康"却不知道是哪个特征，无法修复后再收养——**路线 A 在任何含此类组件的装配上直接断掉**。

**建议**：
1. 拒绝时返回**逐特征明细**（至少失败/抑制特征的 id + 名称 + 状态码；`creo_inspect_model` 的 `features` 节已有数据，可在预检时按需取前 N 条）；
2. 评估提供"结构收养"降级模式：允许把不健康零件作为**只读装配源**（不进入可编辑托管集），或在明确 flag 下收养但标记 `unhealthy`（编辑工具对失败特征操作时再报错）——这样"重建装配"不必先修好每个元件。

### P2-1 无"重建结果 vs 原装配"的比对工具

**现状**：重建后只能人工看图（job 的 preview.jpg）或逐件读 `list_components` 变换。缺少类似 SolidPilot `compare_assemblies` 的自动比对：组件集是否一致、每件 transform 偏差、约束数/类型是否一致。

**建议**：`creo_compare_assembly(inspection_snapshot | assembly_name, managed_assembly_model_id)` 输出：组件集差异、逐件 transform 偏差（位置 mm / 旋转度）、约束清单差异、包围盒/体积差异。FEAT-045 快照可直接作为基准（有 snapshot_id 与 600s 时效，天然支持）。

### P2-2 `inspect_session_assembly` 未输出装配单位

**现状**：`transform_convention` 只写 "units follow the assembly (mm)"；本次源装配的数值呈 `x/25.4` 精确特征（疑英寸建模，详见同期验收报告 §4.1）。没有 `assembly_units` 字段，agent 无法判断是否需要在喂 `assemble_component` 前 ×25.4。

**建议**：结果中显式返回 `assembly_units: "mm" | "inch"`，并在 `transform_convention` 中写明"若为英寸，数值即英寸"或**统一换算 mm 输出**。

### P2-3 批量操作缺少"预览图/差异摘要"

现状每个写操作 job 都带 preview.jpg（很好）。但批量装配/重建完成后，缺少一张整体预览 + 变更摘要（新增/移动/删除的组件清单）。建议批量接口返回时附 `preview.jpg` + `changes: [{op, label, from, to}]`。

### P3 `creo_list_components` 的 `constraints` 只有 `type` 数字

现状：`constraints: [{type: 13}]`——13 是"固定"的枚举值，但没有符号名，也没有原始约束参数。建议附 `type_name: "fixed"` 与（若可）原始约束快照，便于比对原装配。

## 3. 一条建议的"官方管线文档"

FEAT-045 到位后，第三方 agent 需要自己摸索"open → inspect → adopt（逐个）→ new_assembly → assemble → 编辑 → 校验"的顺序、当前窗口依赖、软对齐/约束取舍、单位口径。建议作者在 README/`creo_capabilities` 里给出**标准重建管线**（含每步的失败分支与幂等键约定），可直接减少大量试错。

---

## 4. 优先级汇总

| 优先级 | 事项 | 预期收益 |
|---|---|---|
| **P1-1** | 按路径/批量收养（不依赖当前窗口） | 装配编辑从"不可用"变为"可用"（100 件从 ~1h 降到分钟级） |
| **P1-2** | `assemble_component` 批量 + 单次保存 | 装配耗时降 4 倍 |
| **P1-3** | 约束快照 → `assemble_component.constraints` 的桥接 | 重建保真度从"刚性摆放"提升到"约束驱动" |
| **P1-4** | 矩阵直入参 / Euler 输出 | 消除 25.4× 之外的第二类坐标换算错误源 |
| **P1-5** | 收养拒绝的逐特征诊断 + 只读降级 | 打通含历史失败特征的存量装配 |
| P2-1 | 重建 vs 原装配比对工具 | 验收可自动化 |
| P2-2 | 装配单位显式输出 | 消除单位歧义 |
| P2-3 / P3 | 批量预览与摘要、约束符号名 | 可读性与可审计性 |
