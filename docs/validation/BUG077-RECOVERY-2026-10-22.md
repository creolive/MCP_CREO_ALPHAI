## 6. 场景构造方法（可复用）

- **instant**：提交编辑后 <0.5s 内杀 runner（job.json 出现 runner_identity.pid 即杀）→ 执行器不启动、作业悬挂、现场=基线（restore_baseline 场景）。
- **delayed**：提交后固定 1.5s 杀 runner → 执行器已启动成为孤儿并自然完成（含保存与重载验证）→ 作业悬挂 running、native_result.json 佐证 candidate（accept_saved/accept_live 场景）。执行器写首份 checkpoint 时机接近作业尾声，等 checkpoint 再杀来不及，须用固定延迟。
- 只杀 Python runner 不杀执行器/Creo；执行器作为孤儿自然收尾，Toolkit 侧无中断，不属于故障注入。
