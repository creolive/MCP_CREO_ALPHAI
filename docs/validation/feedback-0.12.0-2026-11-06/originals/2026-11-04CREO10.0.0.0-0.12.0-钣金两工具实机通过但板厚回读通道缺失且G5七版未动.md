## 二、核心问题：FEAT-058 板厚回读通道在本 SDK 代际结构性缺失（守卫静默失效）

### 2.1 根因（已定位到行号）

`native/planar_wall.cpp:145-150`：

```cpp
evidence.thickness_code = ProSmtBodyThicknessValueGet(&bodies[material_index], &value);
evidence.thickness_known = evidence.thickness_code == PRO_TK_NO_ERROR;
...
evidence.thickness_code = -1; // -1: this SDK generation declares no body gauge read
```

本机 Creo 10.0.0.0 的 SDK 头未声明 `ProSmtBodyThicknessValueGet`，编译期守卫落到哨兵分支：**体测量通道按设计跳过**。而"改型前从已保存文件重读板厚"（planar_wall.cpp:439-445 的 `loaded` 通道）内部同样走 `planar_wall_bodies()` → 依赖同一个未声明的调用 → **同样恒为 null**。

### 2.2 后果（按严重性排序）

1. **守卫静默失效**：planar_wall.cpp:444-445 的 `if (loaded.thickness_known && fabs(loaded.thickness - thickness) > 1e-6)` 在本机**永远为 false**——若某条路径真的改了板厚，这个承诺的防线在 Creo 10 上不会报警。回执虽然诚实（`thickness_verified=false`），但"没有报警"和"验证过没问题"对调用方是两种语义，当前回执字段无法区分"SDK 不支持"与"墙体异常"。
2. 文档承诺的"改型带回读自存档厚度"在 Creo 10 上落空（`thickness_source` 恒为 `parameter`）。

### 2.3 建议（含一个已验证可行的兜底）

1. **首选：体积反推兜底**——平面钣金壁的板厚可从已验证量精确反推：`gauge = volume / (length × width)`。本机实测两次分毫不差（19200/(120×80)=2.0；23400/(130×90)=2.0）。在 `thickness_code==-1` 哨兵分支加此兜底，`thickness_source` 记为 `"volume_derived"`，守卫即可在 Creo 10 上恢复火力；
2. 兜底不可用时，回执加显式标记（如 `thickness_readback: "unavailable_on_this_sdk_generation"`），让 `thickness_verified=false` 的原因可机读；
3. Release notes / capabilities 里注明：板厚回读依赖的 SDK 调用在哪些 Creo 代际可用（ Creo 10.0.0.0 = 不可用，实测）。

**严重性：低-中**。体积闸门仍在，当前所有实机数值正确；但这是 FEAT-058 唯一一条在部分 SDK 代际静默降级的防线，值得在下一版补齐。
