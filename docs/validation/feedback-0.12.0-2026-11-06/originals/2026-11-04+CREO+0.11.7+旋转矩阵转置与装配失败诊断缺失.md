## 一、核心问题（按严重度）

### P-1【严重｜静默错误】`assemble_component.rotation_matrix` 实际按“行向量”解释（p′ = Rᵀ·p + t），但接口未声明，按常规列向量写法传入会得到转置结果，全程不报错

**现象**：`assemble_component` 的 `rotation_matrix` 参数没有任何约定说明。按三维软件通用写法（3×3 矩阵的**列**为零件局部 X/Y/Z 轴，`p_asm = R·p + t`）传入后，装配成功、`status=succeeded`、无告警，但整机姿态是转置的。

**实测证据**（同一组 3 个实例：P21、P10、P05）：

| 传入矩阵语义 | 总装质心（Creo 内核回读） | 与正确值的差 |
|---|---|---|
| 列 = 轴（`R·p+t`，通用写法） | (−214.464, 58.923, −206.846) | X 差 **182 mm**、Z 差 **480 mm** |
| 行 = 轴（`Rᵀ·p+t`，实际生效） | (−32.09, 57.44, 271.37) | 0 |

第二次测试把 35 个实例按“列 = 轴”摆好后，整机质心得到 (−411.133, 51.427, 132.126)，而按“行 = 轴”重建后为 (−419.169, 53.168, 286.543)，后者才与源装配内核质心 (−419.224, 41.606, 275.465) 对上。**同一批零件、同一组平移，仅旋转阵转置，整车沿车长整体偏移约 154 mm，且两条履带沿车宽错位 275 mm —— 界面上完全看不出来。**

**为什么难发现**：70 个实例里大部分旋转阵是 ±1 置换阵，22 个还是对角阵（两种读法同解），只有少数非对称阵能暴露；不做到“质心/惯量回代”根本发现不了。

**建议**：
1. 在 `assemble_component` / `AssembleOp` / `ComponentPlacementOp` 的 schema 描述里**显式写出**：`rotation_matrix` 的三**行**是零件局部 X/Y/Z 轴在装配中的指向，换算为 `p_asm = Rᵀ·p + translation`（或反过来，但必须写清并统一）。
2. 增加一个可选的 `rotation_convention: "rows" | "columns"`，默认值保持向后兼容，并在返回值里回显实际使用的约定。
3. 更稳的做法：返回值里回显该组件**读回**的 4×4 变换（`transform`），让人能一眼核对；目前 `creo_get_job` 的 result 里没有这一步的回显。
4. 若传入矩阵非严格正交（|det−1|>1e-9 或行范数偏离 1），建议给出警告而不是静默接受（见 P-2）。

### P-2【严重｜诊断缺失】旋转阵非“±1 置换阵”时 `ProAsmcompAssemble` 返回 −2，计划在第 32 个实例处整批回滚，而失败项里没有任何原因

**现象**：装配计划执行到第 32 个实例（P03 双联轮，绕自转轴转了 17.9°，旋转阵为
`X̂=(0, 0.307383, −0.951586)`、`Ŷ=(0, 0.951586, 0.307383)`、`Ẑ=(1,0,0)`）时失败：

```
stage = execute_assemble_component
result.message = "Toolkit call ProAsmcompAssemble((ProAssembly)board, (ProSolid)child, position, &comp) failed with code -2 during execute_assemble_component"
operations[31].label = "i032"
operations[31].execution_status = "failed"
operations[31].error = {}          ← 空对象
```

- 返回的 `error` 是空对象 `{}`，既没有 `ProError` 文本，也没有回显传入的矩阵；
- 34 个已成功的实例被整批回滚（`components = 0`），我不得不把 35 个实例整段重建一次（约 3 分钟 + 一次完整重传）；
- 后续把这三个实例的自转角归零（改用 ±1 置换阵）后立刻成功，说明**失败点就是“非置换旋转阵”**，但接口没告诉我这一点。

**推测原因**（未证实，供参考）：`(0, 0.307383, −0.951586)` 这类小数位截断的单位向量，行范数 = 0.99999997，Creo 可能在 `ProAsmcompAssemble` 前做严格正交校验（|R·Rᵀ−I| < 1e-9）而拒绝，返回通用 −2。如果是这样，**入参侧做一次正交化/归一化即可自愈**，比让调用方猜要好。

**建议**：
1. `failed` 的 operation 里至少回填 `{tool_call, pro_error_code, matrix_echo, orthonormality_residual, det}`；
2. 提交前对 `rotation_matrix` 做正交性与行列式校验，超差时**在提交阶段**拒绝并给出可读原因（“matrix not orthonormal, residual 3.1e-8”），而不是让 Creo 返回 −2；
3. 失败时不要连坐回滚所有已成功实例——至少提供 `continue_on_error`，或返回“已完成 31 个、失败 1 个”的可续做状态（当前只能整段重来）。

### P-3【中｜诊断缺失】拉伸/切除失败只有一句 `Regeneration produced a failed, suppressed or incomplete feature`，不指出是哪个特征、什么原因

**现象**：P10 中滑板按 IR 的 9 步建成 5 个拉伸，首次提交时：

```
status = failed
stage  = execute_extrude
result.message = "Regeneration produced a failed, suppressed or incomplete feature"
result.failed_operation = null      ← null
job.error = null
```

`operations[]` 里也找不到哪一条 `extrude` 是失败的（该字段只在成功路径填充）。这组特征的几何本身合法（两个矩形**共边相切**叠加），把相邻矩形的边界从“恰好共面 y=105”改成“重叠 0.5 mm（y=104.5）”后一次通过。也就是说，**失败原因是“共面/相切接触导致的零厚度”，但接口一个字都没说**，我靠猜改了两次（第一次改完仍然失败，第二次才发现还要把起点也做 0.5 mm 重叠）。

**建议**：
1. `result` 增加 `failed_operation_index` / `failed_label` / `failed_sketch`；
2. 把 `ProFeatureWithoptionsCreate` 的 `ProError` 码与 native.log 的最后 5 行摘要一起放进 `result`（`native.log` 里其实有信息，但要人去翻文件）；
3. 在错误文本里对高频成因给出提示：相切/共面接触、切除方向未命中材料、草图落点不在实体上。

### P-4【中｜易误用】`through_all` 切除的方向语义不直观，且被“无材料可切”和“深度参数”两处噪音掩盖

**现象 1**：`depth_type="through_all"` 时 `depth` 仍被要求并回显为 `1.0`（例如 `"depth": 1.0, "depth_type": "through_all"`）。IR 里是“自草图面向 +Z 完全贯穿”，我照抄 `direction="negative"`（因为主体在 −Z 侧），结果：

```
status = failed, stage = execute_extrude
（同样只有一句 Regeneration produced a failed...）
```

改为 `direction="positive"` 后立刻成功。错误信息没有指出“草图面在实体外侧、切除方向朝外，未命中任何材料”。

**现象 2**：`through_all` 的“贯穿”范围按**特征方向**而不是按**整个实体**判定。P24 空心梁（本体 Z=0…1080，草图画在 Z=0 平面）用 `negative` 贯穿切不到任何材料而失败，用 `positive` 成功——这和“完全贯穿”的字面直觉相反。

**建议**：
1. `through_all` 时不再要求/回显 `depth`（或标注 `depth_ignored: true`）；
2. 切除方向未命中材料时，报 `cut_removed_no_material` + 建议方向（“material lies at +Z of the sketch plane; try direction=positive”）；
3. schema 描述里补一句“`through_all` 沿 `direction` 指定的半轴贯穿，方向指向实体外侧时必然失败”。

## 三、本轮确认可用的能力（供作者参考，非问题）

- `sketch`（rectangle / circle / polyline(closed) / arc + line 组合）× `extrude`（add / cut / blind / through_all / positive / negative / symmetric / 单次多轮廓）在 Creo 10 上**稳定可用**：28 个零件、约 90 个特征零失败（除 P-3/P-4 两处语义坑）。
- 三个基准面的局部坐标已实测确定为：**XY → (u=+X, v=+Y, n=+Z)**、**YZ → (u=+Y, v=+Z, n=+X)**、**XZ → (u=+X, v=+Z, n=−Y)**（XZ 的法向为 **−Y**，与“右手系直觉”相反，建议写进文档）。
- `assemble_component` + `placement="fixed"` + `rotation_matrix`（按“行=轴”）+ `translation`：70 个实例 69 个一次通过，读回变换与目标 0.000 mm 吻合；**只要 P-1 的约定写清、P-2 的非置换阵能过，这条链路就是可靠的**。
- 每次作业后的 `part_file` + `sha256` + `saved_file_reloaded_and_verified=true` 很重要，本轮 28 个零件的落盘都可追溯。

## 五、给作者的最小改动清单（按性价比排序）

1. **在 schema 里写清 `rotation_matrix` 的行/列约定**（P-1）——一行文档，能省掉一次整车错位返工；
2. **`failed` 的 operation 回填 `ProError` 码 + 失败 label + 入参回显**（P-2/P-3）——目前失败项是 `{}`，只能靠猜；
3. **提交期做旋转阵正交性校验并自动归一化/正交化**（P-2）——非置换阵（真实装配里很常见）现在直接 −2；
4. **`through_all` 去掉 `depth` 并要求方向指向材料**，或给出方向建议（P-4）；
5. **compact 轮询真的 compact**（P-5）——70 个作业的 token 开销能降一个数量级。
