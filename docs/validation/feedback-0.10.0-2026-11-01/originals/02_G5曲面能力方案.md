# G5 能力缺口完善方案：曲面放样 / 投影曲线 / 曲面剪裁（v1.1，2026-10-31）

面向 MCP_CREO_MechDog 的可实现路线。全部 API 已在本机 Creo 10.0.0.0 的 Pro/TOOLKIT 头文件逐条核实，并给出可直接移植的元素树骨架与实现顺序。

## 0. 结论摘要

| 缺口 | 现状 | 建议新增 op | 实现难度 | 备注 |
|---|---|---|---|---|
| 曲面放样 | 无 | `surface_loft`（元素树，支持 surface 模式） | 中 | **不需要回调/UI 宏**，见 §2 |
| 投影曲线 | 无 | `project_curve`（元素树） | 中 | PRO_E_*_COPYTRIM 族已具备（§3） |
| 曲面剪裁 | 无 | `surface_trim`（元素树） | 中 | 同一 COPYTRIM 元素树（§3） |
| 任意平面草图 | 受限（frame 形式要求已有平面支撑） | `datum_plane` 增加 `thru_points`（三点定面） | **小** | ProDtmPln.h 明确支持 THRU-PRO_POINT（§4） |
| 对称加厚 | 已有 `thicken`（surface 加厚） | — | 已具备 | surfaces.cpp:81 `generic_surface_solid` |

关键事实：现有 direct blend 走"常驻回调 + UI 宏（ProMacroLoad `ProCmdFtPBlend`）"是因为**实体混合没有可用的元素树**；而**曲面放样/投影/剪裁都有元素树**（ProSweep.h 的 sweep-with-surface 模式与 COPYTRIM 族），可以像 `extrude/revolve` 一样在 `creo_worker.exe` 内直接 `ProFeatureCreate`，**无需新的 DLL 回调、无需 UI 自动化**。

## 1. 现状核实（本机头文件行号）

- `creo_loft`（blend_create.cpp:73）：`mode != "add"` 即抛错；截面强制 MCP 自有 XY 草图、Z 单调递增（blend_create.cpp:91-96）；底层走 `ProMacroLoad("~ Command ProCmdFtPBlend ...")` + 常驻回调选线（blend_create.cpp:159-177）。
- `generic.cpp` op 分发表：`extrude` 支持 `mode:"surface"`（generic.cpp:2064, `PRO_EXT_FEAT_TYPE_SURFACE`）——**曲面拉伸已存在**，但只能沿草图法向直拉，做不出扭叶片。
- `generic_surface_solid`（surfaces.cpp:81）：`thicken`/`solidify` 已可用（本报告 v1.0 的表里漏列了 thicken 的对称模式，实际 `PRO_THICKEN_BOTH_SIDES` 已实现）。
- 缺失确认：native 全目录 grep 无 `ProSectionProject`/投影元素树/剪裁元素树；op 分发表无 `surface_loft`/`project_curve`/`surface_trim`。

## 2. `surface_loft`（曲面放样）— 元素树路线

放样（Boundary Blend）在 Pro/TOOLKIT 中可以用元素树直接建（与 sweep 同族）。建议 op：

```json
{"op":"surface_loft","label":"blade_surf",
 "sections":["sk_section_40","sk_section_540"],
 "interpolation":"straight",          // straight|smooth（对应 ProBlend Surf straight/smooth）
 "closed":false}
```

元素树骨架（ProElemIds，自 ProSweep.h/ProBlend.h 同族约定）：

```
PRO_E_FEATURE_TREE
 ├─ PRO_E_FEATURE_TYPE        = PRO_FEAT_DATUM_SURF (942)
 ├─ PRO_E_FEATURE_FORM        = PRO_BLEND_SURF / PRO_STD_BLEND（Boundary Blend）
 ├─ PRO_E_STD_FEATURE_NAME    = <label>
 ├─ PRO_E_BLEND_SECTIONS（ARRAY，按序）
 │    └─ 每节：PRO_E_STD_SEC_METHOD = PRO_SEC_SKETCH
 │             PRO_E_STD_SEC_SELECT → ProSectionCopy 自已有草图（同 blend_create.cpp:99 的 ProFeatureSectionCopy 复用）
 └─ PRO_E_BLEND_ATTRIBUTES    = straight / smooth
```

实现要点（全部可在 creo_worker.exe 内同步完成，与 extrude 相同事务语义）：
1. 截面复用 `ProFeatureSectionCopy(&profile, 0, &section)`（blend_create.cpp:101 已验证此路径），把 MCP 自有草图转成 section，不需回调去 UI 里选；
2. 创建后走现有 `remember(op, f)` + `stage_operation_result`，并新增回执字段 `surface_area_mm2`（`ProSurfaceEval` 面积或用 Measurable 对 quilt 的面积）——v1.2 判据 2 需要这个数；
3. 该路线不受"XY 平面 + Z 单调"限制：放样截面可位于任意平面（P12 需要 y=40 / y=540 两个 XZ 平面）。

> 备注：若作者希望与现有 direct-blend 同一套基础设施，也可以复用回调 + 宏把 `ProCmdFtPBlend` 的 dashboard 切到 Surface 模式；但元素树路线更稳定、无 UI 依赖，优先推荐。

## 3. `project_curve` + `surface_trim` — 同一棵 COPYTRIM 元素树

ProElemId.h:1666-1670 已给出**投影剪裁曲线**（Projected Trim Curve）的完整元素族：

```
PRO_E_COPYTRIM_QUILT       1630   被投影的曲面（quilt selection）
PRO_E_COPYTRIM_CURVES      1631   投影方向/来源
PRO_E_COPYTRIM_CURVE_TBL   1632   曲线表（ARRAY）
PRO_E_COPYTRIM_CURVE_DATA  1633   单条曲线数据 compound
PRO_E_COPYTRIM_CURVE       1634   曲线 selection
```

这就是 Creo"投影曲线"（Edit > Project）的元素树。一个 `project_curve` op 足够：

```json
{"op":"project_curve","label":"curve1",
 "quilt":{"kind":"quilt_feature","label":"blade_surf"},
 "curves":[{"kind":"sketch","label":"sk_n01"}],   // 在 x=180 基准面上的 81 点样条
 "direction_ref":{"kind":"datum_plane","label":"right"},  // 沿 -X 方向投影
 "side":"negative"}
```

元素树（按 ProElemId 族装配）：

```
PRO_E_FEATURE_TREE
 ├─ PRO_E_FEATURE_TYPE      = PRO_FEAT_CURVE (949)
 ├─ PRO_E_STD_FEATURE_NAME
 └─ PRO_E_COPYTRIM_CURVE_DATA (1633)
     ├─ PRO_E_COPYTRIM_QUILT   → resolve(quilt)         （ProSelection of quilt）
     ├─ PRO_E_COPYTRIM_CURVE_TBL（ARRAY）
     │    └─ PRO_E_COPYTRIM_CURVE → resolve(curve)       （每条来源曲线）
     └─ （方向/投影类型子元素按 ProStdSection 的 collection 约定）
```

而 `surface_trim`（曲面剪裁）同样有元素树路线：**Copy-Trim 特征本身既是"投影剪裁"**——Creo 的"曲面裁剪（投影曲线）"实现为 `PRO_FEAT_DATUM_SURF` 的 trim 变体，元素 `PRO_E_COPYTRIM_QUILT` + 剪裁侧（`PRO_E_TRIM_QLT_SIDE` 已在 ProSweep.h 元素表出现，通用）。若作者不想引 COPYTRIM，第二选择是布尔 `boolean_bodies(method="intersect")` 已有的 ProBooleanBodies 基础（surfaces.cpp:108）对 quilt 做保留侧，但**投影剪裁是更贴源的语义**。

实现顺序建议：先做 `project_curve`（独立曲线特征，风险低、回执好验：投影后曲线长度/端点可 Get），再做 `surface_trim`（依赖 quilt 选择，与现有 `thicken` 的 quilt resolve 共用 `{"kind":"quilt_feature","label":...}` 管道，generic.cpp:712 已具备）。

## 4. `datum_plane` 三点定面（一行级补丁，解锁扭叶片的逐站路线）

ProDtmPln.h:70 约束表明确列出 `PRO_DTMPLN_THRU` 可接受 **PRO_POINT**。当前 offset_plane（generic.cpp:873）只写了一个 OFFS/ANG 约束。补丁（伪代码，落在 offset_plane 或新 helper）：

```cpp
// datum_plane op 新增： "thru_points": ["pa","pb","pc"]（MCP 已有的 datum_points 标签）
if (op.contains("thru_points")) {
    for (auto &lbl : op["thru_points"]) {
        ProElement c = node(constraints, PRO_E_DTMPLN_CONSTRAINT);
        integer(c, PRO_E_DTMPLN_CONSTR_TYPE, PRO_DTMPLN_THRU);
        ProSelection s = resolve({{"kind","datum_feature"},{"label", lbl}});
        ref(c, PRO_E_DTMPLN_CONSTR_REF, s);
        ProSelectionFree(&s);
    }
}
```

有了三点定面，P12 扭叶片在现有 MCP 里即可走"逐站弦线 + 三角棱柱"路线（本包 `p12_v12_native_tree.json` 已给全 391 项特征配方），**即使暂不做 surface_loft 也能建出合规扭叶片**（偏差按 A01 声明）。这两条路线互为冗余：优先 surface_loft（贴近源特征树），退路逐站三角棱柱（纯元素树、无新能力依赖）。

## 5. 回执与验收钩子（与 v1.2 判据对齐）

新增 op 建议统一带：
- `surface_loft` → `surface_area_mm2`（未剪裁面积，v1.2 判据 2：138,629.77 ±0.2%）
- `project_curve` → `curve_length_mm`、端点坐标
- `surface_trim` → `trimmed_area_mm2`（判据锚 62,231.97）、`kept_side`
- `thicken`（已有）→ 建议补 `volume_delta_mm3`（判据锚 614,234.967，对称加厚语义已在，只差读数）

这些读数让 v1.2 的五条判别性验收可以在 MCP 回执里逐条闭合，不需要调用方再开 CATIA/SM 测量。

## 6. 优先级与工作量

| 步骤 | 内容 | 预估 |
|---|---|---|
| 1 | `datum_plane.thru_points`（三点定面，解 P12 扭叶片 + 任意斜面草图） | 0.5 天，无风险 |
| 2 | `project_curve`（COPYTRIM 元素树） | 1-2 天，需实测 selection 语义 |
| 3 | `surface_loft`（Boundary Blend 元素树 + 面积回执） | 2-3 天，需验证 smooth/straight 与闭合属性 |
| 4 | `surface_trim`（复用 quilt resolve + 侧向元素） | 1-2 天，依赖 2/3 |

四项落地后，v1.2 的"放样→投影→剪裁→加厚"链在 MCP 内完整可表达，P12 可按源特征树 L2 重建并逐条闭环判别判据；同时新增的 `datum_plane.thru_points` 对任意斜面草图（不等距基准面族）也是通用增益。
