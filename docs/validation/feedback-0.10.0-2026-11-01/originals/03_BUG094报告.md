- Creo：Creo Parametric 10.0.0.0（release_numeric = 42）
- 关联：本报告同时含 **已验证可用的补丁**（`datum_plane.thru_points` 三点定面 + `sketch frame` 的 UV 基回退），可直接并入主线。

## 一、摘要

为在 MCP 内表达 v1.2 P12 扭叶片（"放样→投影→剪裁→加厚"链所需的能力集之外的最后一块拼图），我们实现了 `datum_plane` 的 **三点定面**（3×`PRO_DTMPLN_THRU` 引用 `datum_points` 特征）并在 Creo 10 实测：**基准面创建成功且几何精确**。但随后在该斜面上创建草图（`sketch` op 的 `frame` 形式）失败于 `ProFeatureWithoptionsRedefine`（`CompleteFeature = -1`）。

排查定位到 **两层独立缺陷**，第一层已修复并验证，第二层需要上游（作者）修复：

| 层 | 现象 | 状态 |
|---|---|---|
| L1 | `sketch frame` 的 `project()` 用 `ProSectionLocationGet` 的矩阵把世界坐标映射为截面 UV；在斜面支撑上 incomplete 特征阶段该矩阵**恒为单位阵**，导致世界 XY 被当作截面 UV 写入 | **已修复**（检测单位阵时改用 frame.u/v 基直接点积；实测 LINE 坐标从错误值 `(-95.19,40)→(44.84,45.88)` 修正为 `(0,0)→(190.38,22.39)`） |
| L2 | UV 正确后 `redefine → ProFeatureWithoptionsRedefine` 仍返回 -1（斜面草图特征再生失败） | **待上游修**（已定位到调用，见 §4） |

## 三、L1 缺陷细节与已验证修复

`sketch()` 的投影函数：

```cpp
auto project = [&](const J &p, double *out) {
    V w = frame.origin + frame.u*p.u + frame.v*p.v;
    for (int i = 0; i < 2; i++)
        out[i] = (w - loc_origin)·loc_row[i];      // 依赖 ProSectionLocationGet
};
```

对**主平面支撑**（XY/XZ/YZ），incomplete 特征的 `ProSectionLocationGet` 返回真实矩阵，映射正确（例如 P06 在 YZ 面上 `SECTION_MATRIX` 为 YZ 变换，成功）。对**斜面支撑**，同一函数在 incomplete 阶段返回**单位阵**，`out` 退化成世界 XY——截图证据：native.log 中 `LINE_tri_0=-95.191114,40.000000 → 44.838428,45.875213`（这是 3D 点的 x,y 分量，不是截面 UV）。

**修复（已并入源码并重编验证）**：检测 `loc` 为单位阵时，改用 frame 基直接投影：

```cpp
bool loc_is_identity = /* |loc - I| < 1e-12 */;
if (loc_is_identity) { V d = w - frame.origin; out[0]=d·frame.u; out[1]=d·frame.v; return; }
```

修复后同一用例的 `LINE_tri_0 = (0,0) → (190.382228,22.394433)`，与解析 UV 完全一致。

## 四、L2 剩余层（需上游修）

UV 正确写入后，`redefine()` → `ProFeatureWithoptionsRedefine(nullptr, f, root, options, PRO_REGEN_NO_FLAGS, &es)` 仍返回 -1。已排除：
- 截面质量问题：`solve_profile` 成功（`SectionRegenerate=0`），闭合、无自交、无近容差点；
- 坐标锚：`SKETCH_ANCHOR_PLANE=2`（默认面之一被投影为定位参照）；
- 再生时机：datum_plane 后插入 `regenerate` 无效。

推测方向（供作者参考）：斜面支撑上，`PRO_E_STD_SEC_PLANE_ORIENT_REF` 的投影参照与三点定面的父依赖（3 个 datum point）在再生序列里形成内核侧的参照序问题；或 `PRO_SEC_ORIENT_DIR_UP` 的语义在非水平支撑上需要换锚。建议作者在 `ProFeatureWithoptionsRedefine` 失败分支把 `ProErrorlist` 的 `es` 内容带回执（当前 `errors(es)` 只 check 了返回码），一次运行即可拿到内核的准确抱怨。

## 五、对 P12 / 下游的影响与替代路径

- L1 修复对**任意斜面草图的 UV 映射**是普适收益（坐标不再错）；
- L2 修复前，"斜面上直接画截面"仍不可用，P12 扭叶片的**逐站三角棱柱路线**与**正规放样路线**都被卡在同一处；
- 我们已备好两条替代路线的完整配方（`p12_v12_native_tree.json`：48 带 × 4 特征；正规链路需 `surface_loft/project_curve/surface_trim` 三个元素树 op，ProElemId.h:1630-1634 已给出投影剪裁曲线的元素族）。
- **不受影响的现有能力**：主平面（XY/XZ/YZ）上的全部草图工作流完全正常（本轮 12 零件 + 80 组件装配已验证）。

## 六、建议

1. 并入 L1 修复（`project()` 的 identity 回退），这是无副作用的正确性修复；
2. `datum_plane.thru_points` 三点定面（本报告同批实现，已实测）是通用增益，建议并入；
3. L2：在 `errors(es)` 处把 `ProErrorlist` 内容带回执，定位后修复斜面草图的再生语义；
4. 中期补 `surface_loft / project_curve / surface_trim` 三个元素树 op（COPYTRIM 元素族已在 SDK 中），让 v1.2 P12 走正规链路。
