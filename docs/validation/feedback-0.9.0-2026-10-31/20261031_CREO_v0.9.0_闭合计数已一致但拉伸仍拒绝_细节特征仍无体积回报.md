## 头号问题 P1：`native_section` 声称完美闭合，`extrude` 照样 -1，且明说"原因未定"

### 复现（全部可复跑，`scripts/` 下已有素材）

同一零件 `p1_weld_probe`（`3bdc6851a5bb403f8e84ecb0c2094494`）、同一会话、同一平面 XY、同样的 10 环 × 40 弧几何，
唯一差别是端点是否吸附：

| | `scripts/gear10.json`（原始，端点间隙 7.72e-7 mm） | `scripts/gear10_snapped.json`（吸附，7.83e-13 mm） |
|---|---|---|
| `profile.closed_contour_count` | 10 | 10 |
| `profile.categories.near_tolerance` | **40** | **0** |
| `native_section.closed_contours` | **10** | 10 |
| `native_section.open_ends` | **0** | 0 |
| `profile.material_area_mm2` | 184.98029507425974 | 184.98028543645881 |
| extrude add depth 10 | ❌ `ProFeatureWithoptionsCreate=-1` | ✅ `volume_mm3 = 1849.8028532376422` |

吸附版解析值 184.980285×10 = 1849.802854，实测差 8e-7 mm³，**能力本身没问题**。

### 问题在哪

失败信息原文：

> Extrude feature creation failed (ProFeatureWithoptionsCreate=-1). Toolkit rejected the referenced
> sketch section; the return code alone does not identify whether closure, a geometric condition or the
> feature tree caused it. **Detected native section: 10 closed contour(s), 10 contour(s), 40 entity(ies),
> 0 open end(s). These counts do not identify the cause; the cause is not determined.**

也就是说：MCP 自己数出来"10 个闭环、0 个开端点"，然后 Creo 拒绝创建，MCP 说"不知道原因"。
上一轮的失败还能归因于"端点没焊上（2 closed / 24 open ends）"，这一轮**连归因都没了**，
调用方拿到的是一对互相矛盾的事实：完美的计数 + 未定的原因。

`near_tolerance: 40` 是唯一的线索，但它是 `profile` 里的计数，没有告诉调用方
**哪一对端点、间隙多少、超没超容差**。而 `native_section.tolerance_mm = 1e-6` 又暗示"容差内应该没问题"，
实际 0.77×容差就已经不行。

### 建议（按优先级）

1. **把 `native_section` 从"计数"升级为"可判定"**：给出 `max_endpoint_gap_mm`、
   `near_tolerance_pairs: [{a, b, gap_mm}]`（按间隙降序，取前 N 对），以及
   `weldable: true/false`。当前的 `open_ends=0` 会让调用方误判为"可以拉伸"。
2. **在提交草图时就拒绝，而不是把失败推迟到 extrude**：当 `near_tolerance > 0` 且
   `max_endpoint_gap_mm` 超过某个实测可用阈值（本轮证据：7.8e-13 可用、7.7e-7 不可用，
   阈值介于两者之间，建议用 1e-9 这一档）时，直接返回"草图端点未精确重合，请吸附"，
   并附带上面的配对清单。这样错误发生在"造草图"这一步，语义正确。
3. **`open_ends=0` 与 `-1` 不应同时出现而不解释**。若确实存在"计数闭合但 Creo 拒绝"的情形
   （例如焊接后出现零长度边、近切点、自接触），请把探测到的几何异常类别打出来，
   而不是统一写 "the cause is not determined"。

## 问题 P6：round / chamfer / draft 成功但不回报体积增减量（未修）

用一个 40×30×10 的方块（体积 12000 精确）做标定，每个特征的解析值都已知：

| 操作 | 入参 | 操作回报 | 实测 `volume_mm3` | 解析期望 |
|---|---|---|---|---|
| 起点 | — | — | 12000.0 | 12000 |
| `creo_chamfer` | size 2，面 65∩67 | `succeeded:true, size:2.0`，**无体积字段** | **11980.0**（Δ −20.000） | −20.000 = 0.5·d²·h ✅ |
| `creo_round` | radius 3，面 69∩63 | `succeeded:true, size:3.0`，**无体积字段** | **11960.685831397488**（Δ −19.314169） | −19.314168 = (r²−πr²/4)·h ✅ |
| `creo_draft` | 10°，flip=**false**，面 69，中性面 53 | `succeeded:true`，**连 angle 都没回显** | **12224.875235711397**（Δ **+264.19**） | 应为 **−264** 左右 → **方向反了，静默加料** |
| `feature_state delete` | `["t_draft_a"]` | `applied:1, tombstone_count:1` | 回 11960.685831397488 | ✅ |
| `creo_draft` | 10°，flip=**true** | `succeeded:true` | **11695.894293639314**（Δ −264.79） | ✅ |

两个 draft 都报 `succeeded`，只看返回值无法区分"内收 −264"和"外扩 +264"。
draft 的 operation 记录里连 `angle` 都没有（chamfer/round 至少回显了 `size`），
事后无法从 job 记录判断"这一刀用的是几度、往哪边"。

**建议**
1. round / chamfer / draft 的 operation 结果补 `material_delta_mm3`（带符号），与 extrude cut 的
   `material_removed_mm3` 对齐。这是唯一能让调用方自证方向对错的证据。
2. draft 的 operation 记录补 `angle`、`flip`、以及解析出的 `pull_direction` 向量和
   `taper: inward|outward`。
3. 可选但很有用：当 draft 导致体积**增加**时，在 job 的 `warnings` 里提示
   "本次拔模增加了材料，请确认 flip 是否取反"。

## 问题 P3：`creo_new_part` 的 preview 恒失败（未修）

```
"preview_status": "failed",
"failed_step": "output_file",
"failed_code": -4,
"verification_error": "FileNotFoundError"
```
`window_matches_model: true`、`current_window_matches: true`，只有 `view_matrix_matches: false`；
raster 之前的每一步 code 都是 0。同一会话里 sketch / extrude / chamfer / round / draft 的
preview 全部 `written`（包括 17~20 KB 的正常图片）。所以只发生在**空模型**（无实体）的首次 preview。

**建议**：空模型跳过 preview 或返回 `preview_status: "skipped_no_geometry"`，
不要报 `failed`——现在这样会让调用方以为整个建零件流程坏了。

## 已修复 / 值得肯定的部分

1. **P2 已修**：`profile` 与 `native_section` 现在完全一致（都是 10 closed / 10 contours / 40 entities），
   不再出现"调用方以为 10 个闭环、Creo 只认 2 个"的矛盾。
2. **`near_tolerance` 语义改进**：从"隐性失败"变成显式计数（40/40），至少能预警。
3. **报错文案质量大幅提升**：`message` 里直接列出 `Detected native section: ...`，
   并且 `creo_get_job` 新增 `native_log_tail`，能看到 `PHASE=...`、`ProSolidRegenerate(...)=0`
   等原生调用序列。排查效率明显变好。
4. **`creo_draft` 成为独立工具**（本轮新），配合 `creo_round` / `creo_chamfer`，
   细节特征不再必须走 `creo_execute_plan`。
5. **`creo_capabilities` 新增 `arbitrary_planar_support`**：
   `plane = {reference:{kind:'surface', id:N}, origin:[x,y,z], u_axis:[x,y,z]}`。
   这意味着可以直接在"由某个面 + 自定义原点/方向"决定的任意平面上画草图，不必先建基准面。
   对本项目（星形架斜槽需要一张 36° 倾斜面）是**最有价值的新能力**，下一轮会用它重建斜槽。
6. `creo_get_job` 支持 `detail=compact`，长 job 的输出体量小了很多。
