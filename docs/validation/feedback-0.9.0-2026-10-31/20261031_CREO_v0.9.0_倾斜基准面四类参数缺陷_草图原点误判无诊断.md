# 2026-10-31｜CREO｜v0.9.0｜核心问题：倾斜基准面四类参数缺陷 + 草图原点误判无诊断信息 + 枚举文档不一致

- MCP：`MCP_CREO_MechDog` 0.9.0（`up_to_date`）
- Creo：Parametric 10.0.0.0，`release_numeric: 42`，mmns 模板
- 场景：在任意倾斜面上按给定"原点 + u 轴 + 法向"建草图并切槽（TXT 的 P02 斜槽）。
  该链路在本轮**最终跑通了**，但试错成本很高，全部原因都在下面四条。

---

## 背景：目标面

法向 `n = (0.587785, 0.809017, 0)`（水平），过点 `O = (−5.090, −7.006, 0)`，
面内 `u = (0.809017, −0.587785, 0)`、`v = (0,0,−1)`。即一张**竖直面**，不是"从 XY 面倾斜"能得到的。

---

## 问题 1：`creo_datum_plane` 的 `axis` 只认 `{kind:'axis', id:N}`

```json
{ "op":"datum_plane", "reference":{"kind":"datum_plane","id":2},
  "angle":54, "axis":{"kind":"datum_feature","label":"ax_z"} }
```
→ `failed_stage: execute_datum_plane`，`message: "Datum feature label does not identify a datum plane"`

`ax_z` 是**基准轴**，但报错说它"不是基准面"，语义误导。同一份 schema 里
`axis_pattern` 的 `axis` 明确支持 `{kind:'datum_axis_feature', label:...}`，
而 `datum_plane.axis` 不支持——两个字段对同一概念用了不同 kind 命名。

**建议**：`datum_plane.axis` 接受 `{kind:'datum_axis_feature', label:X}` 与 `{kind:'axis', id:N}`；
报错时区分"找不到该 label"与"该 label 不是基准轴"。

---

## 问题 2：`reference` 的 kind 只能是 `datum_plane / surface / datum_feature`

```json
{ "reference": { "normal": [0.587785, 0.809017, 0] }, "offset": -8.65981 }
```
→ `[json.exception.out_of_range.403] key 'kind' not found`（这是原生层异常直接透出）

改成 `{ "kind":"normal", "normal":[...] }`
→ `Unsupported model reference kind: normal`

但 `creo_datum_plane` 的说明写的是"reference accepts ... **or a plane axis/normal filter**"。
说明与实现不一致：文档承诺的"法向过滤器"实际不存在。

**建议**：要么实现 `{kind:'normal', normal:[x,y,z]}`（这是最直接的"过点 + 给法向"定义方式，
本轮如果有它，问题 1/3/4 都不会发生）；要么把这句从说明里删掉，并列出合法 kind 清单。

---

## 问题 3：`angle` 与 `offset` 同时给出时，`offset` 被静默忽略

```json
{ "reference":{"kind":"datum_plane","id":2}, "angle":54, "offset":-8.65981 }
```
结果面：`normal (0.587785, −0.809017, 0)`、`origin (0,0,0)`
→ **offset 完全没生效**（面仍然过 Z 轴），且 `succeeded: true`，无任何警告。

只能拆成两次调用：先 `angle` 定方向（offset 必须给 0），再以新面为 reference 单独 `offset`。
代价是多一次 job + 一次 inspect，而 inspect 是唯一能发现"offset 没生效"的手段。

**建议**：offset 与 angle 同时给出时按"先转后偏移"执行，或在结果里回显
`resolved_offset` 与 `origin`，让调用方能自证。

---

## 问题 4：`angle` 的旋转方向与直觉相反，且无法预知

`reference = RIGHT（法向 +X）`、`axis = Z`：

| angle | 得到法向 | 期望 |
|---|---|---|
| `+54` | `(0.587785, −0.809017, 0)` | ✗ 镜像 |
| `−54` | `(0.587785, +0.809017, 0)` | ✓ |

要拿到 `(0.5878, +0.809, 0)` 必须给 **−54**。这是"绕轴顺时针为正"的约定，
但 schema 与说明里都没有写，只能靠试两次 + inspect 反查。

**建议**：在结果里回显 `normal` 与 `angle_applied`（含符号），并在说明里写明旋转方向约定
（右手定则 / 逆时针为正 是多数 CAD 的习惯）。

## 问题 5：`creo_create_sketch` 的 `plane.origin` 被判"不在支撑面上"，且不告诉差多少

```json
{ "plane": { "reference":{"kind":"datum_plane","id":167},
             "origin": [-5.090, -7.006, 0],          // TXT 原文 3 位小数
             "u_axis": [0.809017, -0.587785, 0] } }
```
→ `failed_stage: execute_sketch`，`message: "Sketch origin is outside support plane"`

实测该点与面的距离只有 **1.07e-4 mm**（面由 offset −8.65981 生成，原点实际在
`(−5.0901086, −7.0059335, 0)`）。1e-4 mm 被拒，说明判定阈值远严于建模精度；
而报错信息既不给偏差值、也不给平面方程，调用方无法知道该往哪边挪。

去掉 `origin` 走面的默认原点后一次通过。

**建议**
1. 报错附带 `distance_to_plane_mm` 与平面方程 `n·p = d`；
2. 阈值放宽到 1e-3 mm（与 TXT 声明的"正文 0.001 mm"精度一致），或允许 `origin` 自动投影到面上；
3. 说明里写清 `origin` 是否允许偏离、容差多少。

---

## 问题 6：`creo_extrude` 的 `depth_type` 枚举与 `creo_capabilities` 不一致

`creo_capabilities` 报：
```json
"extrude_depths": ["blind", "through_all_cut", "symmetric"]
```
实测工具 schema 只接受：
```json
"depth_type": { "enum": ["blind", "through_all"] }
```
传 `"through_all_cut"` 直接被参数校验拒绝。

**建议**：以工具 schema 为准统一两处文案（`symmetric` 实际是 `direction` 的取值，不是 `depth_type`）。
