# 曲面修剪只能靠手写元素树，且 quilt 引用在链路第二环就断

> 反馈对象：MCP_CREO_MechDog **v0.11.5**（stable，tag v0.11.5）
> 对照版本：v0.3.5（上一轮反馈）
> 运行环境：Windows win32 / Creo Parametric 10.0.0.0（release_numeric=42）/ stdio
> 验收场景：用「可乐瓶五爪花瓣瓶底」任务书重跑，并逐项复测上一轮提出 12 个问题

---

## 0. 结论摘要

**进步很大**：上一轮 12 项问题中 **6 项已修复**（含最痛的"含中心线草图不能就地改"、以及"完全没有删除特征"）。诊断信息密度提升了一个量级。

**但纯曲面法仍然跑不通**，原因从"缺工具"变成了"工具在低层、引用链断裂"：

| 级别 | 问题 | 状态 |
|---|---|---|
| **P0** | 高层仍无 `trim` / `merge` / `boundary_blend` / `quilt_offset`（operations 仍 60 项，`surface_solid` scope 未变） | 未修 |
| **P0** | 曲面修剪**只能**用 `creo_create_feature_tree` 手写 10 个元素；少写 `PRO_E_MATERIAL_SIDE` 直接再生失败，无文档无示例 | 新发现 |
| **P0** | **quilt 面 id 不可查询**：`inspect_model(section=surfaces)` 对纯曲面模型返回 `[]`（只遍历 solid body） | 新发现 |
| **P0** | 因此只能靠 `{kind:"quilt_feature",label}`，而它对 **trim 结果特征**解析失败（`ProFeatureGeomitemVisit` code **-4**）→ 缝合无法引用上一步的修剪结果 | 新发现 |
| **P0** | `loft` 仍只支持 solid add / XY 平行截面（`mode:surface`、`new_body` 均无） | 未修 |
| P1 | `feature_state` 依赖缺口**一次只回一个**（本次试错 2 轮才删成功） | 新发现 |
| P2 | `creo_get_job` 仍无 `wait_seconds` | 未修 |
| P2 | 纯曲面模型 `counts.surfaces/edges` 恒为 0，无法验收曲面面积/边界 | 新发现 |

## 2. 仍缺 / 新发现（P0）

### 2.1 曲面修剪：低层能跑通，但不是"可用功能"

**实测成功**（`job 7045d780…`，features 12 → 13，`saved_file_reloaded_and_verified=true`）：把圆柱面 quilt 用球面 quilt 修剪。可用的元素树如下（建议直接收进文档/示例）：

```json
{
  "id": "PRO_E_FEATURE_TREE",
  "children": [
    {"id": "PRO_E_FEATURE_TYPE",   "integer": "PRO_FEAT_CUT"},
    {"id": "PRO_E_FEATURE_FORM",   "integer": "PRO_USE_SURFS"},
    {"id": "PRO_E_SRF_TRIM_TYPE",  "integer": "PRO_SURF_TRIM_USE_QLT"},
    {"id": "PRO_E_SURF_TRIM_TYPE", "integer": "PRO_SURF_TRIM_USE_QLT"},
    {"id": "PRO_E_STD_FEATURE_NAME", "string": "TRIM_PROBE2"},
    {"id": "PRO_E_TRIM_QUILT",     "reference": {"kind": "quilt_feature", "label": "q_cyl"}},
    {"id": "PRO_E_STD_USEQLT_QLT", "reference": {"kind": "quilt_feature", "label": "q_dome"}},
    {"id": "PRO_E_MATERIAL_SIDE",  "integer": "PRO_TRIM_MATL_SIDE_ONE"},
    {"id": "PRO_E_PRIMARY_QLTSIDE","integer": "PRO_TRIM_PRIM_QLT_SIDE_TWO"},
    {"id": "PRO_E_KEEP_TRIM_SURF_OPT", "integer": "PRO_KEEP_TRIM_SURF_OPT_NO"}
  ]
}
```

**踩坑记录（说明为什么这不能算"可用"）**：

1. 第一次我按 `ProTrim.h` 的 (1.1) 树写，**漏了 `PRO_E_MATERIAL_SIDE`** → `execute_feature_tree` 报 "Regeneration produced a failed, suppressed or incomplete feature"，无任何字段提示缺哪个元素。补上该元素立即成功。这个元素只在 (2.1)(2.2) 的 Use-Quilt 分支里出现，(1.1) 与 (2.2) 的表格还不一致。
2. `PRO_FEAT_TRIM` 这个常量在 Creo 10 SDK 里**不存在**，必须是 `PRO_FEAT_CUT` + `PRO_E_SRF_TRIM_TYPE`。上一轮我按这个名字找过，没找到就误判"无法构造"。
3. `PRO_E_SRF_TRIM_TYPE` 与 `PRO_E_SURF_TRIM_TYPE` 两个元素都要写，值相同。

**建议**：把这段树固化成 `creo_surface_trim(target, tool, keep_side, material_side)`，内部按上面 10 个元素生成；失败时把"缺/错元素 id"回传，而不是只说再生失败。

### 2.2 quilt 面 id 不可查询 —— 引用链从第二环就断

- `creo_inspect_model(section="surfaces")` 对纯曲面模型返回 **`{"surfaces": []}`**，`counts.surfaces=0`、`counts.edges=0`。原因是检查走 `ProSolidBodySurfaceVisit`，只枚举**实体**面，quilt 不在其中。
- 于是 `{"kind":"surface","id":N}`（唯一通用的几何引用方式）对曲面**永远拿不到 id**，只能退回 `{"kind":"quilt_feature","label":...}`。
- 而 `quilt_feature` 的解析要求该特征**恰好只有 1 个 PRO_QUILT 几何项**（`resolve()` 里 `ids.size()!=1` 就报错）。实测对**修剪结果特征**直接崩在更早一步：

```
job 97ce4522…  merge(trim_probe2 + q_dome)
→ Toolkit call ProFeatureGeomitemVisit(&f, type, collect_geom_ids, nullptr, &ids)
  failed with code -4
```

也就是说：**"修剪 → 缝合"这条最基本的曲面链，在第二环就没有合法引用可用了**。同理，`trim` 之后想再 trim 一次、想 offset、想 solidify，都卡在同一处。

**建议（任一即可）**：
- 在 `inspect_model` 增加 `section="quilts"`：遍历 `PRO_QUILT` 几何项，返回 `{quilt_id, feature_id, area_mm2, closed, face_count}`。对曲面工作流这是刚需，也是"缝合是否封闭"的唯一判据来源。
- 或放宽 `resolve()`：`quilt_feature` 命中多个项时，返回候选列表而不是直接抛错；并支持 `{kind:"quilt", id:N}`（代码里已有这个分支，但没暴露入口）。

### 2.3 其余三个曲面算子仍未封装

| 任务书步骤 | 需要的命令 | v0.11.5 |
|---|---|---|
| 曲面放样（两个 50° 截面） | `loft{mode:"surface"}` | ❌ limits 未变："solid add into the default body only; no cut/surface/new_body" |
| 爪谷 G1 桥接 | `boundary_blend` | ❌ 无（`surface_fill` 仍只有 planar） |
| 面组向内偏置 0.3 | `quilt_offset` | ❌ 无（`thicken` 语义不同） |
| 缝合封闭组 | `merge` | ❌ 无高层；低层受 §2.2 阻断 |

`surface_solid` 家族的 scope 与 limits 与 0.3.5 **逐字一致**，说明这块本轮没有推进。

## 3. 新发现的易用性问题

### 3.1 `feature_state` 依赖缺口一次只回一个（P1）

删除一个凸台要连带它的草图与自动支撑平面。失败两次，每次只报一个缺失项：

```
第 1 次 → 缺 88
第 2 次 → 缺 81
第 3 次 → 成功
```

两个都是 `label:null / name:"no_name"` 的 datum_plane，只能靠数字 id。建议：一次返回**完整**缺口集合（`missing: [...]`），并把自动生成的支撑平面标成 `auto_support_of: "sk_boss"`，否则调用方只能盲试。

### 3.2 `creo_get_job` 仍无长轮询（P2）

签名仍是 `(job_id, detail, section, limit, cursor)`。本轮 16 个 job 共轮询 ~50 次。建议加 `wait_seconds`（≤30），完成即返回。

### 3.3 曲面上没有面积/封闭性信息（P2）

`inspection_summary` 只有 `volume_mm3`（曲面上为 null），没有 quilt 面积。任务书验收要"缝合公差 0.01 内封闭""斑马纹光顺"，目前没有任何可查询依据。

## 4. 建议的最小可用增强（MVR）

按顺序做，纯曲面法就能真正闭环：

1. **`inspect_model(section="quilts")`** —— 返回 quilt id / 面积 / `closed` / 面数。（不解决这条，后面全卡住）
2. **`creo_surface_trim`** —— 内部用 §2.1 的 10 元素树；`target`/`tool`/`keep_side`/`material_side`；返回修剪前后面积。
3. **`creo_quilt_merge`** —— `{targets, tools, intersect}`，返回 `closed:true/false`。常量 `PRO_FEAT_MERGE`、`PRO_E_SRF_MRG_*`、`PRO_SRF_MRG_JOIN/INTSCT` 均已导出，元素树见 `ProMerge.h` 第 14–30 行。
4. **`creo_quilt_offset`** —— 偏置面组（方案 B 的 0.3 向内偏置）。
5. **`creo_boundary_blend`** —— G1/G2 桥接（`PRO_E_BNDRY*` 已导出 21 条）。
6. **`creo_loft` 支持 `mode:"surface"` 与 `new_body`**。
7. **`feature_state` 一次返回完整依赖缺口**；`get_job` 加 `wait_seconds`。

> 1–3 做完，"曲面放样→修剪→缝合→实体化"这条最小闭环就通了；4–6 补齐过渡与偏置；7 是纯体验。
