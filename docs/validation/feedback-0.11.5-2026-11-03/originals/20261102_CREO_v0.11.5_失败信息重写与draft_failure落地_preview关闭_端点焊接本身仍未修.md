## 二、R1：extrude 失败信息终于"说人话"了（连续四轮之后）

连续四轮（0.9.0 → 0.11.0）一字不变的 *"the cause is not determined"*，0.11.5 变成：

> The section has no open ends, but its endpoint clusters spread up to **8.21534267e-07 mm**
> at the diagnostic clustering tolerance: **endpoints joined only by that tolerance are not
> necessarily welded by the kernel, so a closed-looking count can still be rejected**.
> **Snap the near-tolerance endpoints (see the sketch profile's weldability block) and retry.**

这一段把三件以前没说的事全说了：
1. `0 open ends` 不等于"内核已焊接"；
2. 失败的机理就是**诊断容差内的端点未被焊接**；
3. 修复路径 = 吸附端点，并指向 `profile` 里的 `weldability block`。

这正是 0.10.0 / 0.11.0 两轮反馈的诉求（引用诊断字段、解释 open_ends=0 与 -1 并存）。
`native_log_tail` 里也同步出现了 `cluster_spread_mm=8.21534267e-07 endpoint_gap_mm=0`。

**判定：诊断/文案侧满分落地。** `near_tolerance_pairs`（40 对明细）与吸附对照法
（`gear10_snapped.json` → 1849.8028532376422）继续可用。

**未变的部分**：端点**焊接本身仍未实现**——8.2e-7 mm（0.82×容差）依然不可拉伸，
只有吸附到 ~1e-13 才行。若作者能在 sketch 提交时按 `max_endpoint_gap_mm` 阈值
（建议 1e-9 档）自动吸附或直接拒绝，这条链路才算真正闭环；
当前的"失败但告诉你怎么救"是次优但可用的形态。

## 三、R2：`draft_failure` 诊断块落地，`requested_flip` 回显

`surface 67 + angle=10 + flip=true`（0.11.0 起 `-1` 的那个方向依赖失败）仍失败，但 operation 里新增：

```json
"draft_failure": {
  "angle_deg": 10.0,
  "api": "ProFeatureWithoptionsCreate",
  "classification": "no_element_evidence",
  "element_errors": {"sample": [], "total": 0},
  "requested_flip": true,
  "surface_count": 1,
  "note": "The kernel returned no element diagnostics. On a face bounded by rounds or
           chamfers this usually means the requested angle cannot be built there; try a
           smaller angle, remove the adjacent round/chamfer first, or re-read the surface
           ids with creo_inspect_model before retrying."
}
```

上一轮的三条诉求：✅ 区分几何不可行、✅ 回显 flip、✅ 给修复建议（减小角度/先删圆角倒角/重读面 id）。
`volume_before_mm3` 也照常回报（12134.98065354499），rollback 干净。

**仍待办**：`flip=false` 成功时回显的 `draft_geometry.flip` 仍是 `true`
（入参 `false` → 回显 `true`，签名混用在成功路径上依旧存在）。
建议成功路径同样带 `requested_flip`，或改名 `effective_flip`。
