## 核心问题 1：既然已判定"刚体平移、未重解"，为什么仍判失败？

**0.11.5 的重大改进**：错误消息与回执新增 BUG-108 的刚性诊断。本条实测：

```
Coordinate dimensioning changed the supplied geometry; maximum deviation mm=0.000016
(the whole profile translated by u=0.000016 v=-0.000000 mm; it was not re-solved)
```

回执里同时出现 `geometry_deviation.rigid` 与 `geometry_deviation.translation_mm`，源码注释写明 `residual <= 1e-9` 才判 rigid（即**形状完全未变，只是整体挪了 16 纳米**）。

**问题**：识别出"形状未变、纯平移"之后，仍然按"几何被改变"**拒绝建特征**。

- 默认阈值仍是 `COORDINATES_DEFAULT_TOLERANCE_MM = 1e-5`（`src/creo_mechdog/geometry_deviation.py:29`）；
- 而求解器自身的刚性平移噪声实测在 **1.6×10⁻⁵ ~ 4×10⁻³ mm** 量级（0.11.1 时我在 48 条带构建中遇到 4.0×10⁻³，本次 1.6×10⁻⁵）；
- 也就是说：**闸门阈值低于被测对象自身的噪声**，同一份完全自洽的坐标，能否建成取决于当次求解器挪了多少——这是随机失败，不是用户错误。

**实测对照**：

| 调用 | 结果 |
|---|---|
| `dimensioning=coordinates`（默认） | ❌ 拒绝：dev 1.61×10⁻⁵ > 1e-5 |
| 同一份几何 + `geometry_tolerance_mm: 0.01` | ✅ 成功，volume 19,659.70 = 1991.6 mm² × 9.87 精确 |

**建议**（按收益排序）：

1. **刚体平移不判失败**：`rigid == true` 时形状是精确的，只差一个平移。要么放行并在回执里报 `translation_mm` 供上层补偿，要么把平移量折进草图参考系（`origin` 加 -Δ）后重建，让几何回到请求坐标。当前语义把"形状精确 + 位置差 16 nm"与"形状被改坏"合并处理，代价是用户只能靠放宽容差把闸门关掉；
2. **默认阈值提到 1e-3**（与 `autodim` 的 warning 阈值一致），或对 `coordinates` 单独用"形状偏差"而不是"点位移"作判据；
3. **成功回执也带 rigid/translation**：现在只有失败消息里有，成功的 `geometry_deviation.rigid` 为 `null`，上层无法审计"这次实际挪了多少"。建议无论成败都填。

## 核心问题 2：G5 曲面三 op 四个版本未动，P12 仍只能靠 96 ops 的切片堆

`creo_check_environment` 的 `supported_features` 在 0.11.1 与 0.11.5 上**逐字相同**（95 项），`surface_loft` / `project_curve` / `surface_trim` 仍不存在。

后果（本次 P12 实建的直接代价）：

- 扭叶片只能"逐站平板切片"：48 片 × (草图 + 拉伸) = **96 ops**，紧贴 200 ops 上限，必须分 2 批；
- 加上 union（1 target + 47 tools）、剪裁棱柱、intersect，全链路 **约 105 个特征、40 分钟机器时间**；
- 若 `surface_loft` + `project_curve` + `surface_trim` 到位，同一零件是 **~10 ops**（两截面放样 → N01 投影 → 剪裁 → 对称加厚）。

建议仍按我 `2026-10-31` 那份 G5 方案的四步走（datum_plane.thru_points 已在 0.11.1 落地，剩三步）。

## 核心问题 4：`geometry_transform` 的 `keep_original` 复制在第 5 个副本处必然失败，且 225° 单独也失败

P12 风扇要做 8 叶（1 本体 + 7 个 45° 副本）。`geometry_transform` 有 `keep_original`，理论上正好能做"实体-移动/复制"（源件 P12 的第 ⑧ 步就是它）。实测两次都在**第 5 个 op** 崩：

| 计划 | 结果 |
|---|---|
| 45° / 90° / 135° / 180° / **225°** / 270° / 315°（7 个） | ❌ 前 4 个成功，**225° 处** `ProFeatureWithoptionsCreate = -1`，整批回滚 |
| 45° / 90° / 135° / 180° / **−135°** / −90° / −45°（7 个，改等价负角） | ❌ 前 4 个成功，**第 5 个（−135°）** 同样 -1 |
| **单独** 225°（1 个） | ❌ 同样 -1 |

**两个独立现象**：
1. **副本数上限**：同一计划里第 5 个 `keep_original` 复制必失败（两次不同角度集合同一位置，可复现）；
2. **角度范围**：225° 单独执行也失败，而 45/90/135/180 可过 → 旋转角疑似必须在 ±180° 内，但 schema 没有任何范围约束，也不报参数错，只给裸 Toolkit -1。

**影响**：8 叶阵列无法一次完成；变通是拆成 ≤4 个/批（第二批要重新引用已经变化的 body id），耗时翻倍且易错。源件的"实体-移动/复制 8 等分"在本工具上不可达。

**建议**：
1. 复现并修第 5 个副本的 -1（怀疑与复制出的实例在特征树里的父链/参考失效有关）；
2. 给 `rotation` 加 ±180 的 schema 校验 + 明确文档，超范围时前置拒绝而不是让 Toolkit 兜底；
3. 若短期修不了，暴露一个真正的 `body_pattern`（绕轴 N 等分、单 target、一次成型），语义上比"自己复制 7 次"更稳。

## 附：本次实机建模中撞到的三个"能力边界"（非 bug，但建议写进文档）


1. **`extrude mode=cut` 挖的是轮廓内部**，不是外部。想"只保留轮廓内"必须用 `boolean_bodies(method=intersect)`。我第一次剪裁因此把叶片中间整条挖掉（1,381,331 → 746,178 mm³），只能 `feature_state delete` 回退。建议在 extrude 的 cut 描述里补一句。
2. **`boolean_bodies` 的 union/intersect 只接受单个 target**（`Union/intersection require one target body`），48 个实体要合并必须两段式：先 `targets=[b1], tools=[b2..b48]` 合并，再 intersect。建议在 schema 描述里点明。
3. **`feature_state delete` 必须把自动生成的依赖特征一起列出**，否则拒绝并回列清单（本次回了 2 个 `no_name` 基准面的 feature_id）。行为是对的，但错误信息可以更前置——比如 schema 里写明"删除拉伸会连带其草图与自动基准面"。
