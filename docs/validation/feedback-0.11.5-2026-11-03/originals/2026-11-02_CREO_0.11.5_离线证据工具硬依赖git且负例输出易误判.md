# 2026-11-02_CREO_0.11.5_离线证据工具硬依赖git且负例输出易误判

> 反馈对象：MCP_CREO_MechDog **0.11.5**（commit b3f6d43；含 0.5.2～0.11.4 全部累积变更）
> 环境：Windows 10 x64 19045 / Python 3.13.14 x64 / MSVC 19.44.35229 + Windows SDK 10.0.26100 / Creo Parametric **9.0.0.0** Toolkit SDK
> 结论先行：0.11.5 安装、Creo 9 SDK 原生编译、种子安装与冒烟全部通过（**95 工具**）。**未发现产品功能缺陷**。本次唯一系统性问题在开发/证据工具链：**37 个 tools/ 脚本硬依赖 PATH 中的 `git`（32 处 `check=True`，无任何兜底）**——在未安装 git 或使用源码 ZIP 解压的机器上，全量单元测试出现 **38 项错误**、离线证据报告无法生成；把 git 加入 PATH 后 **2196/2196 全部通过**。文末附一处容易误判的输出建议。

---

## 一、核心问题：离线证据/开发工具硬依赖 `git`，无兜底、无指引

### 1. 现象

未安装 git（或 git 不在 PATH）的机器上运行官方入口 `python tools\test_unit.py`：

```text
Ran 2196 tests ... FAILED (failures=0, errors=38)
```

错误集中在一批「离线证据/验收」脚本测试（`test_arc_direction_live`、`test_dev049_*`、`test_t07_preview`、`test_seed_regression_contract`、`test_t05_geometry`、`test_startup_retry` 等），统一 traceback：

```text
File "tools\test_arc_direction.py", line 474, in local_provenance
    git("ls-files", "--", "*.py", "native/*.h", "native/*.hpp", "native/*.cpp")
File "tools\test_arc_direction.py", line 463, in git
    return subprocess.run(["git", *args], ..., check=True, ...).stdout.strip()
FileNotFoundError: [WinError 2] 系统找不到指定的文件。
```

### 2. 验证（因果已闭环）

| 步骤 | 结果 |
| --- | --- |
| `shutil.which("git")`（venv python） | `None` |
| 单跑 `tests.unit.test_arc_direction_live`（无 git） | FAILED (errors=3) |
| 把 `…\PortableGit\cmd` 加入 PATH 后单跑同模块 | 通过（错误消失） |
| **加 git 后全量 `tools/test_unit.py`** | **2196/2196 通过，`unit_test_report.json` success=true、errors=0** |
| 无 git 全量 | 38 errors（同一批模块 + 上述 traceback） |

### 3. 影响范围

- `grep -rl '\["git"' tools/`：**37 个工具**调用 git；其中 **32 个使用 `check=True`**（失败即抛），其余也无 `which("git")` 或 `FileNotFoundError` 兜底；
- 覆盖 `tools/test_*.py` 系列离线验收脚本与 `tools/dev_check.py`（即作者 CI 入口），产生的"离线报告"依赖 `local_provenance()`（git ls-files + 逐文件 SHA256）作为来源指纹；
- 受影响人群：**用 GitHub Release 的源码 ZIP 安装的用户**（ZIP 无 `.git`，机器上通常也没有 git）、精简环境/离线机器。这些人跑 dev 工具/离线验收会得到原始 `WinError 2`，且离线报告完全无法生成，不知道原因。
- 注意：**MCP 服务本体不依赖 git**（本次 95 工具、编译、冒烟均正常），问题仅限 tools/ 开发与证据链。

### 4. 建议（按代价排序）

1. **兜底降级**：`local_provenance()` 一类函数用 `try/except (FileNotFoundError, subprocess.CalledProcessError)` 包住，返回 `{"git": "unavailable"}`/`source_provenance: null`，报告里显式标注"来源指纹不可用"，让离线报告仍能生成；
2. **明确指引**：捕获后报错文案写明"离线证据工具需要 git（PATH 中可解析）；纯服务运行不需要"；
3. **文档前置条件**：在 README/INSTALL 的开发工具节把 git 列为 tools/ 的前置（当前前置只写了 Python/Creo SDK/MSVC）；
4. （可选）像 `vswhere` 那样在常见安装路径探测 git（`Program Files\Git\cmd` 等），减少对 PATH 的强依赖。

## 二、易误判提示（建议改进输出，非缺陷）

全量测试 stdout 会打印多行醒目的红字，例如：

```text
Seed archive: ...\seed-library.zip; 24 files; 9 seeds; SHA256 0000...0000
ERROR: Seed archive SHA256 6793ea58... differs from docs/seed_package.json seed_archive_sha256 daaa1098...
The archive was kept at ... so the digest can be backfilled into docs/seed_package.json; nothing was published.
```

实测这些是**负例测试的预期输出**（如 `test_tampered_archive_bytes_are_rejected` 故意篡改 `.prt.1` 后断言 `SHA256 differs`；`test_trusted_record_digest_mismatch_is_rejected` 用全零记录），最终结果为 `success=true`。但它们与真实失败在视觉上无法区分，且每次运行的摘要值不同（本次三次全量分别出现 `d2c6b86b…`/`c460d84a…`/`6793ea58…`，均为负例夹具，非产品不稳定）——外部用户很可能误判为"种子包不可复现/校验失败"。

建议：负例测试把这些打印改为 `unittest` 的 capture（`self.assertLogs`/`redirect_stdout`）或降低到 debug 级别；只有真实失败才在 stdout 输出。
