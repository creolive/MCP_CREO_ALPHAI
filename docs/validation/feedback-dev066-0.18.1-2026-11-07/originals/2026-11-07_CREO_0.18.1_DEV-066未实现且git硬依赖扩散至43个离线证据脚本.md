## 三、次要观察（低优先级，不影响建模）

1. **`session_activity.json` 仍被 git 跟踪且服务运行时追加**（DEV-066 卡登记内容第 4 点，0.11.5 起已知）：本次升级必须先备份 → `checkout` → 恢复，否则 `git checkout -B main origin/main` 会直接覆盖用户会话记录；每次升级都要人工兜底，建议移入 `build/` 或加入 `.gitignore`。
2. **源码内工具数文档不一致**：`README.md` 写「102 个公开工具」（与 `creo_capabilities` 实测一致），`AGENTS.md:26` 仍写「本开发分支98个」。0.18.1 的 DEV-073「文档精简」未同步该数字。
3. **`tools/test_unit.py` 机器可读报告字段偏少**：仅 `version/timestamp/tests_run/success/failures/errors`，不记录 `skipped` 与耗时；发布记录写「2830 项、2 跳过」，外部复验无法从 `build/unit_test_report.json` 核对跳过项，只能翻日志。
4. 发布记录未注明验收所用工作区形态（干净短路径 vs 真实升级工作区）与单测耗时，建议补一句，便于外部复验者预估超时。

## 四、建议（直接沿用 DEV-066 拟议范围，便于一次闭环）

1. 抽出统一 helper（例如 `creo_mechdog.git_provenance`）：先 `shutil.which("git")`，不可用时把 provenance 降级为 `{"git": "unavailable", "source_provenance": null}`，报告显式标注「来源指纹不可用」，**不抛异常、不中断报告**；43 个脚本统一改走该 helper，不再各自 `subprocess.run(["git", ...], check=True)`。
2. 报错文案写明「离线证据工具需要 git（PATH 中可解析）；**纯 MCP 服务运行不需要**」；`README.md` / `docs/INSTALL.md` 的开发工具节把 git 列为前置，并给出全量单测约 17 分钟的预期耗时。
3. `creo_check_environment` 增加 `git_available` 检查项（标注仅开发工具用途），让受限环境在跑到一半崩溃前就能看到原因。
4. 负例夹具的 `ERROR: … differs` 改 `assertLogs` / `redirect_stdout`，或统一加 `[expected-negative]` 前缀，避免与真实失败同形。
5. 顺手项：`session_activity.json` 移出版本控制；`AGENTS.md` 工具数与 capabilities 对齐；`test_unit.py` 报告补 `skipped` / `duration_seconds`。
6. 验收（对齐 DEV-066 验收表）：无 git PATH 下 `python tools\test_unit.py` 应 **0 errors** 且报告标注来源指纹不可用；有 git 时 2830/2830 无回归；全量日志不再出现裸 `ERROR:` 负例红字。
