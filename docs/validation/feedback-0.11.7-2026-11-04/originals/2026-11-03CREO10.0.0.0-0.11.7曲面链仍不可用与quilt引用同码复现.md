# 诊断能力在 Creo 10 上验收通过，但曲面链仍未实现、quilt 引用断链同码复现

> 反馈对象：MCP_CREO_MechDog **v0.11.7**（stable）
> 对照：v0.11.5（上一轮反馈）→ 0.11.6 → 0.11.7
> 环境：Windows win32 / **Creo Parametric 10.0.0.0**（release_numeric=42）/ stdio
> 说明：作者 0.11.6/0.11.7 的实机证据全部来自 **Creo 12.4**，本报告是这两个 PATCH 在 **Creo 10** 上的独立复验。

---

## 0. 结论

**0.11.6 的四项修复在 Creo 10 上全部生效**（阶段归因、坐标求解判据、旋转前置校验都实测通过），诊断可读性比 0.11.5 又上了一个台阶。

**但曲面链一行没动**——作者在 0.11.6 说明里已明确写出：「曲面链、…`get_job` 长轮询均只登记待规划，**未实现**」。上一轮报告的两条 P0 因此原样保留，且我用同一段元素树在 0.11.7 上**复现出与 0.11.5 完全相同的失败码**（见 §3）。

| 上一轮 P0 | 0.11.7 状态 |
|---|---|
| 无高层 `trim` / `merge` / `boundary_blend` / `quilt_offset` | 未修（operations 仍 60 项，`surface_solid` scope 未变） |
| 曲面修剪只能手写元素树 | 未修，但可用（本轮再次验证成功） |
| **quilt 面 id 不可查询**（`inspect_model` 无 quilts 分区） | 未修（`sections_available` 20 项与 0.11.5 **逐项相同**） |
| quilt 引用在 trim 结果上解析失败 → 无法缝合 | 未修，**同码复现**（`ProFeatureGeomitemVisit` −4） |

## 2. 仍未覆盖（4 项）

1. **曲面链**：`trim` / `merge` / `boundary_blend` / `quilt_offset` 均无高层工具（作者 0.11.6 自述"未实现"）。
2. **`inspect_model` 没有 quilts 分区**：`sections_available` 仍为 features / dimensions / surfaces / edges / bodies / datum_planes / datum_axes / parameters / aliases / components / feature_geometry / sketch_dimensions / sheets / views / notes / tables / models / shown_dimensions / metadata，与 0.11.5 **逐项相同**。纯曲面模型 `counts.surfaces=0`、`edges=0`。
3. **`get_job` 仍无 `wait_seconds`**：签名仍为 `(job_id, detail, section, limit, cursor)`。本轮 8 个作业轮询 ~25 次。
4. **`loft` 仍无 `mode:"surface"` / `new_body`**：limits 与 0.11.5 一致。

## 3. 核心问题：quilt 引用断链，跨两个版本同码复现

| | 0.11.5 | 0.11.7 |
|---|---|---|
| job | `97ce4522…` | `1ec07e69…` |
| 操作 | merge(trim 结果 + 球面 quilt) | 完全相同的树与标签 |
| 失败阶段 | `execute_feature_tree` | `execute_feature_tree` |
| 失败调用 | `ProFeatureGeomitemVisit(&f, type, collect_geom_ids, nullptr, &ids)` | **同一行** |
| 码 | **−4** | **−4** |

也就是说：**"修剪 → 缝合"这条链，两版都断在同一处**。`{kind:"quilt_feature", label}` 只能解析"恰好含 1 个 PRO_QUILT 几何项"的特征，而修剪结果特征不是这种形态；`{kind:"surface", id:N}` 又拿不到 id（§2.2）。两个版本的行为没有任何差别。

**建议的最小修复（二选一即可解链）**：

**A. 给 `inspect_model` 加 `section="quilts"`** —— 这是最省事、收益最大的一条：

```json
{"quilts": [
  {"quilt_id": 12, "feature_id": 1501, "feature_label": "trim_probe2",
   "face_count": 3, "area_mm2": 1256.6, "closed": false,
   "bbox": [[...],[...]]}
]}
```
有了 `quilt_id`，`PRO_E_TRIM_QUILT` / `PRO_E_SRF_MRG_QUILT_REF` / `PRO_E_STD_USEQLT_QLT` 都能直接填 `{kind:"surface", id}`；`closed` 顺便解决"缝合是否封闭"的验收判据（任务书要求"缝合公差 0.01 内封闭"）。

**B. 放宽 `resolve()` 的 `quilt_feature` 分支** —— 现在是"必须恰好 1 个几何项，否则抛错"。改为：命中多个时返回候选（feature_id + 每个 quilt 的 id/面积），只在调用方显式 `require_single` 时才报错。这样至少不会在 −4 上黑屏。

无论走哪条，都建议把 `ProFeatureGeomitemVisit` 的 −4 翻译成可读原因（例如"该特征不含可直接用作 quilt 引用的几何项"），现在这个 -4 只有查 Toolkit 头文件才知道含义。

## 4. 本版新增的小问题（都不影响建模）

### 4.1 `verify_model_start` 吃掉了整个作业的 60%，却没有子阶段

三个作业的这一段分别是 **5088 / 7236 / 8297 ms**，而其余 12 段加起来只有 200–700 ms。也就是说 0.11.6 把"验证阶段"切成了 13 段，但最大的一块仍然是个黑盒——它包含了 connect、再生、初次巡检等动作。

建议：把 `verify_model_start` 再拆成 `connect` / `open` / `pre_regenerate` / `initial_inspect` 四段，否则"作业慢"这件事仍然只能归因到"启动慢"。

### 4.2 `native_progress` 在 connect 期间 `idle_seconds=null`

```json
{"stage":"connect","log_bytes":15,"stages_seen":0,"reason":"no_stage_timing","idle_seconds":null}
```
如果作业卡在 connect（例如 Creo 未响应），调用方拿不到任何"停滞了多久"的信号，只能自己数轮询次数。建议 connect 阶段也填 `idle_seconds`（用作业 `started_at` 与当前时间差即可）。

### 4.3 终态与运行态的字段名不统一

- 运行中：`native_progress.stages_seen`（数字）
- 终态：`verify_stages`（数组）

同一个"阶段进度"概念有两个名字、两种形态。建议终态也保留 `native_progress`（作者在 0.11.6 说明里写"终态不带 native_progress"，这是刻意设计，但对调用方不友好）。
