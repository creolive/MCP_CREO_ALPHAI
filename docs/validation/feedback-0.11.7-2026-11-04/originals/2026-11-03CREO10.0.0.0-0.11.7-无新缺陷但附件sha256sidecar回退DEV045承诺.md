## 1. 唯一问题：0.11.7 附件缺 `.sha256` sidecar —— 固化过的约定回退了

**现象**：`v0.11.7` 的 Release assets 只有 2 个文件：

```
MCP_CREO_MechDog-0.11.7-source.zip        7,468,537 B
MCP_CREO_MechDog-0.11.7-seed-library.zip    493,442 B
```

对照历史：

| 版本 | `.sha256` sidecar | 依据 |
| --- | --- | --- |
| 0.3.2 – 0.3.5 | 有 | 早期惯例 |
| 0.4.0 – 0.4.3 | **无**（只发布后回填 RELEASE 文档） | 我 10-18/10-20 报告指出"无法即时核对" |
| 0.4.4 起 | 有（且 Release body 直给哈希） | **DEV-045 定名落地**（附件命名与校验固化） |
| 0.4.4 – 0.11.5 | 有（连续多版） | 稳定执行 |
| **0.11.7** | **无** | **本版回退** |

**影响很小**（Release body 给了完整 SHA256，0.11.6 也给了一份对照），但这是 `docs/development/RELEASING.md` 检查单里已经固化的条目（DEV-045：`附件 SHA256 直接写在 Release body + .sha256 sidecar`）——昨天到今天的三个版本里 0.11.6 有、0.11.7 没有，说明这一项**没进脚本化检查**（`package.py --seed-archive` 闸门管的是种子摘要一致性，不管 sidecar 附件本身）。

**建议**：把 `.sha256` sidecar 的生成与上传并进 `tools/package.py` 的既有流程（它已经在算这两个哈希了，输出 sidecar 文件是一行事），或在 `RELEASING.md` 第 6 步的核对清单里加一条"四附件数量 = 4"。这条已经第二次出问题（0.4.0–0.4.3 第一次），机制化最省心。

另：本报告归档核对时确认 **`feedback-0.11.5-2026-11-03/` 已收 5 份他人反馈原件**（含逐章 MAPPING），我的 0.11.5 报告写于昨晚 23:07、晚于 0.11.6/0.11.7 发布时点，下批归档时应能赶上。

## 2. 好消息（据实，本轮全是别人的反馈被高质量消化）

### 2.1 BUG-111 定因过程是教科书级的（0.11.7 主体）

`keep_original` 第 5 副本失败这条（另一位用户 0.11.5 报告 + 作者两轮实机）：

- **0.11.6 先给出变通**（"单批 ≤4 个副本、下一批重新引用当前 body"）；
- **0.11.7 用 C0—C6 七个独立底板对照实验推翻了自己的变通**（拆 4+3 两批仍在批 B 首个 op 失败）并**真正定因**：失败不跟随位置或角度，而跟随"体已含多副本 + 该角度"的组合——`keep_original` 复制的是**整个当前体**，追加副本与既有凸块重合/交叠时再生失败；
- **失败回执直接给出证据**：`failed_transform.selection.selected_surface_count=26`（整个累积体）vs 新建底板 6 面，"复制的是整个当前体"从回执一眼可见；
- 顺带修了一个**行为不一致**：0.11.6 发现两条原生后端把负角 `+360` 导致 −135 与 225 走不同路径，统一归一为 `(-180, 180]`，并把 `rotation` 范围收紧为提交前拒绝（此前提交后吃内核裸 -1，现在给出等价值如 225→-135）。

这套"先变通→对照实验→推翻变通→真定因→回执可见→撤销变通"的链条，比直接塞一个修复更可信。且 0.11.7 明确**不做行为修复**，只交付诊断与能力边界——把"不能修"和"没发现"分得很清楚。

### 2.2 BUG-109/108/110（0.11.6，A 组四项"失败后无定位无出路"）

- **`verify_model` 拆 13 个子阶段**（`verify_stages` ≤32 条 + `creo_get_job` 只读 `native_progress` 只 seek 日志末尾 8 KiB + 超时文案点名最后子阶段）——"卡在哪一步"从猜变成读数。静态核对：`verify_stages` 在 native+Python 落码、`native_progress` 在 bridge.py 三处；
- **坐标求解改按"形状"判定**（BUG-108 续）：去共模平移后的逐点残差，刚体平移 ≤1e-2 mm 放行并标 `accepted_rigid=true`，形状闸门 1e-5 mm 未放宽——阈值没动，只是把"位置偏差"和"形状偏差"分开判，语义更准；
- **`ack_failure`（BUG-110）**：终态失败装配可用纯注册表事务退回 `ready`，审计块如实记 `disk_state_verified=false`——本机作者无法安全造出 failed 装配验证成功路径，如实标注"仅单测覆盖"。

### 2.3 发布说明的"调用方语义变化"段稳定存在

0.11.6/0.11.7 都明确列出"调用方需要复核的语义变化"（rotation ±180° 拒绝、新字段只增不改、ack_failure 需显式 confirm）——这类段落是自动化升级最需要的信息，连续保持是好事。
