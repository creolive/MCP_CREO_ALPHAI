## 一、已修好：刚性平移不再被当成"几何被改变"（0.11.5 核心问题 1 闭环）

**0.11.5 的问题**：能识别出"整体平移、未重解"（`rigid`，残余 ≤1e-9），却仍按"几何变了"拒绝；默认阈值 1e-5 低于求解器自身噪声。

**0.11.7 的实现**（`native/sketch_coordinates.cpp`）：

```cpp
static constexpr double RIGID_TRANSLATION_LIMIT_MM = 0.01;   // 新增
const bool rigid = shifted && residual <= 1e-9;
const double translation = rigid ? hypot(mean_u, mean_v) : 0.0;
const bool rigid_accepted = rigid && translation <= RIGID_TRANSLATION_LIMIT_MM;
...
if (deviation > tolerance_mm && !rigid_accepted)   // 拒绝条件加了 !rigid_accepted
```

这正是我建议的第 1 条（"刚体平移不判失败"）与第 2 条（"给一个可用的量级阈值"）的组合，0.01 mm 的量级也选得合理——比求解器噪声高两个数量级，又远小于任何工程公差。

**实机验证**（同一份坐标，0.11.5 会拒绝、0.11.7 直接通过）：

| 版本 | 默认容差下的结果 |
|---|---|
| 0.11.5 | ❌ `maximum deviation mm=0.000016 ... it was not re-solved` |
| **0.11.7** | ✅ **通过**，volume 19,659.700 = 1991.6 mm² × 9.87 mm 精确（job `856a5d4cb06c415db346d52ca9439418`）|

**我建议的第 3 条也做了**：成功回执新增 `sketch_shifted` 块，实测内容：

```json
{"detected": true, "rigid": true,
 "translation_mm": {"u": 1.61e-05, "v": -9.5e-15},
 "shape_deviation_mm": 1.89e-14, "residual_mm": 1.89e-14,
 "point_count": 6, "sample": [...]}
```

`shape_deviation_mm` 与 `max_point_mm` 分列是关键设计——一眼能区分"形状变了"与"只是挪了"。这条以后可以直接做上层验收判据。

## 二、已修好：rotation 越界前置拒绝并给出等价角（0.11.5 核心问题 4 的一半）

0.11.5 时 225° 单独执行会得到裸 `ProFeatureWithoptionsCreate = -1`。0.11.7 在 schema 层前置拒绝：

```
rotation components are limited to -180..180 deg; use the equivalent -135 deg
```

`capabilities.py` 的 limits 里也写明了"两个后端都归一化到同一区间，−135 与 225 指同一旋转"。这正是我建议的第 2 条，且比我提的"只报错"更好——它直接告诉你该填什么。

---

## 三、未修但已被文档吸收：第 5 个 `keep_original` 副本必失败

我 0.11.5 报的"同计划第 5 个副本必失败"，0.11.7 没有修，但 `capabilities.py:406` 把它写成了正式口径：

> the fifth keep_original copy in one batch fails after regeneration (reproduced on **Creo 12.4** at operation index 4 regardless of angle or batch length, also reported on Creo 10; **cause not identified**) so copy at most four times per batch and re-reference the current body ID in the next batch

我认为这个处理是**可接受的工程决定**：作者在 Creo 12.4 上独立复现、标明"原因未查明"、给出可执行变通（≤4/批 + 重新引用 body id），并且没有假装修好了。我按这个口径实测有效（8 叶风扇分两批）。

**唯一建议**：既然"≤4/批"是硬约束，考虑在 `geometry_transform` 的 schema 层直接前置拒绝"单计划 >4 个 keep_original"，而不是让用户在第 5 个 op 上撞 `-1` 再整批回滚（回滚代价 = 前 4 个副本的建模时间，实测每次约 3 分钟/副本）。

## 四、仍未实现：G5 曲面三 op（0.11.1 → 0.11.7，六个版本）

`creo_check_environment` 的 `supported_features` 与 `surface_loft` / `project_curve` / `surface_trim` 在六个版本里一字未变、三者仍不存在。

**P12 的代价是可量化的**：
- 扭叶片只能"48 片平板切片 + 布尔求交"，全链路约 **105 个特征**、单批 48 ops 时机器时间 13–17 分钟；
- 有了这三个 op 是 **~10 ops**（两截面放样 → N01 投影 → 剪裁 → 对称加厚），且不会有下面第五节的剪裁口径问题。

我 2026-10-31 那份 G5 方案的第一步（`datum_plane.thru_points`）已在 0.11.1 落地并一直可用，剩三步未动。如果作者担心 Boundary Blend 的复杂度，我建议先做 `project_curve`（COPYTRIM 元素族，ProElemId.h:1630-1634）——它不依赖放样，还能配合现有 `extrude` 曲面 + `thicken` 拼出"平板 + 投影剪裁"的半条链。

## 六、P12 结果：整台风扇已建成（1 实体，rev9）

**这次真的做出来了**：48 片平板切片 → 投影剪裁 → 4 次旋转复制（`keep_original`，按 ≤4/批口径）→ 意外得到 8 片 45° 均布 → 轮毂 Ø100×150 → 合并 → 镗 Ø50×130 盲孔。最终 1 个实体、2167 面。

| 指标 | 实测 | TXT v1.2 | 判定 |
|---|---|---|---|
| 体积 | **5,963,344.0 mm³** | 5,743,190.969 | +3.83% |
| 包络 | 150.00 × 1064.85 × 1064.85 | 175.00 × 1065.32 × 1065.32 | Y/Z ✅；X 少 25（缺 R20 圆角与轮毂端面） |
| 质心 | (1.753, 0, 0) | (−0.464, 0, 0) ±0.3 | ❌ 符号相反 |
| 八重对称 | Y/Z 均 ±532.4 | ±532.66 | ✅ |
| 单片叶片体积 | 635,151.5 | 614,234.967 | +3.41% |

**两处偏差的原因（均在我配方侧，不是 MCP 缺陷）**：

1. **剪裁口径**：N01 的 `u` 是弦向坐标，投到 Z 要乘 `cosα`。我按 `Z ≤ u_max` 建棱柱，等价于允许 `u ≤ u_max/cosα`（根部 1.47 倍），所以多留 3.4% 材料、单片 X 跨度 117 而不是 98。修法：棱柱轮廓按 `Z = u·cosα(v)` 变宽。
2. **Z 极性**：源件右视基准面局部 X 与全局 Z 反号，我正放草图 → 质心 x 符号翻转（幅值量级与 TXT 的"可达区间 [−1.8,−0.4]"一致，说明只差一个镜像）。

**尚未做的源件特征**：R4.5（2 处边）、R2.0（6 条边）两处叶片圆角，以及轮毂 R20 端棱圆角。加上它们体积会略降（源件 614,234.967 → 605,703.65，−1.4%），正好能把 +3.83% 压到 +2.2% 左右——但仍过不了 ±0.05%，所以真正要修的还是上面第 1 条。

**一个意外收获**：`geometry_transform` 的 `keep_original` 在第 2–4 次复制时是**累积复制**（对当前 body 整体复制），4 次调用在 8 片位置上收敛（体积恰为 8×单片），所以"4 副本/批"的限制对 8 叶风扇刚好够用——不需要第二批。
