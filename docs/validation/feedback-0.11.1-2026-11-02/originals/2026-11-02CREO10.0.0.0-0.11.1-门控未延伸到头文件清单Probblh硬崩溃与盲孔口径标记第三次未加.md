## 1. 核心问题 A（P1）：`generate_constants.py` 新增 `HEADERS` 条目在 Creo 10 上**硬崩溃** —— 门控思想没有延伸到头文件清单

### 现象

0.11.1 首次 `bridge.py build` 失败：

```
FileNotFoundError: 'D:\...\protoolkit\includes\Probbl.h'
→ RuntimeError: SDK constant generation failed
```

（顺带说明：报错链路本身是好的——失败信息明确指向 `build/generate_constants.log`，日志含完整 traceback，10 秒定位。）

### 根因

Q07（G5 边界混合探测）给 `generate_constants.py` 的 `HEADERS` 清单新增了 5 个头，注释写明"boundary blend form, trim sides/types and section selection enums are declared outside the original feature-header list"。本机 Creo 10 SDK 实测存在性：

| 头文件 | Creo 10 SDK |
| --- | --- |
| `Probbl.h` | **缺失**（崩溃源） |
| `ProTrim.h` / `ProStdSection.h` / `ProMerge.h` / `ProAsmcomp.h` | 存在 |

`read_text()` 对缺失文件直接抛 `FileNotFoundError` → 整个常量生成失败 → 构建中止。

### 为什么这值得优先处理：它和 BUG-090 是同一族，而且恰恰绕过了 BUG-090 的成果

BUG-090 的教训是"**SDK 各代能力不同，探测不到的东西不能进编译单元**"——0.10.0 为此建了 `FUNCTION_PROBES`、`MECHDOG_HAS_*` 门控和 `GATED_SDK_CALLS` 契约测试，做得很好。但 0.11.1 为 Q07 新增探测**头**时，走了老路：把只在 Creo 12 存在的文件名写进了无条件清单。函数有门控、头文件没有——同一个问题换了个入口又回来一次。

### 有利条件：影响面其实很小

我核对了 native 全部源码：**当前没有任何代码引用 `Probbl.h` 独有的符号**（P08 用的是 `ProSmtedgeContourGet`，在既有头里；generic.cpp 的 788 行新增不含 bbl 类枚举）。也就是说这个头目前只为"将来 Q07 G5 落地时能抓到枚举"做准备——为准备性探测把 Creo 10 构建搞崩，成本收益完全倒挂。

### 建议（一行哲学延伸：探测不到就跳过，与既有 PROBES 行为一致）

`generate()` 里对 `HEADERS` 做存在性过滤，缺失头**跳过读取、且不生成 `#include` 行**（否则 constants.inc 里会留下编译不过的 include）：

```python
    names = set()
    missing_headers: list[str] = []
    for header in HEADERS:
        header_path = inc_dir / header
        if not header_path.exists():
            missing_headers.append(header)   # 缺失头贡献零枚举、零 include
            continue
        source = header_path.read_text(...)
    ...
    lines = [
        "// Enum names generated from the locally installed Creo Toolkit SDK.",
        *["#include <" + h + ">" for h in HEADERS if h not in missing],
        ...
    ]
```

这与现有 `PROBES`（交集为空就不产生宏）的"宁缺毋假"语义完全一致。再配一条契约测试：**`HEADERS` 清单里的每个文件，要么存在于参考 SDK，要么有跳过测试**——可以复用 `GATED_SDK_CALLS` 的思路做一个 `GATED_HEADERS`。

另一个可选方案：把 `native/constants.inc` 的 `#include` 段改为由 CMake/编译期判断（`__has_include`），那样连清单都不用区分 SDK——C++17 支持 `#if __has_include(<Probbl.h>)`。
