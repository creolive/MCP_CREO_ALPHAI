## 核心问题 1：坐标尺寸求解微移仍在，且直接阻断多条带批量构建

**现象**：24 条带扭叶片（194 ops）在第 26 个 op（`s01x` 草图）失败：

```
Coordinate dimensioning changed the supplied geometry; maximum deviation mm=0.004004
COORDINATE_ORIGIN=-0.004003728342,0.000000000000
COORDINATE_DEVIATION entity=tri_0 point=start axis=0 moved=0.004003728342   （3 个图元全部同量平移）
SKETCH_SOLVE_WITHOUT_INFERENCE=-1
AutodimensionSketch=0
```

**特征**：草图坐标我给的完全自洽（三点坐标精确、闭合、零 gap、非自交），求解器却把**整个截面沿 u 轴平移 0.004 mm**（不是变形，是刚体平移），然后被 1e-5 mm 的闸门拒绝。

**为什么必须修**：这不是边角场景。P12 只能走"逐站三角棱柱"替代路线（因 G5 未实现），一条带 = 2 个细长三角形草图（260×20.9 的钝角细条），共 48 个。第 2 个就中招，说明**≥2 个同类草图就必然复发**。用户唯一出路是给每个草图加 `geometry_tolerance_mm: 0.01` 把闸门放宽 1000 倍——等于把作者精心设置的几何保真闸门关掉了。

**同类历史**：`2026-10-31_CREO_0.10.0_坐标尺寸求解微移拒绝仍未修复且autodim静默失真无告警.md` 报的就是这个家族。0.11.1 加了 `geometry_tolerance_mm` 作为**逃生口**，但没有修求解器本身，也没有解决"为什么自洽坐标会被平移"。

**建议**：
1. 定位 0.004 mm 平移的来源：怀疑是 `AutodimensionSketch` 在重算时把原点约束当弱约束重新安置（日志里 `COORDINATE_ORIGIN` 从 0 变成 -0.004，而所有图元跟着走 = 原点被移动）。建议对"原点 + 首点重合"的常见形态跳过原点的重求解；
2. 即使保留闸门，也应把"发生位移"提升为回执顶层字段，例如 `sketch_shifted: [{label, max_mm}]`——现在只有翻 `geometry_deviation.sample[].deviation_mm` 才能发现，而 `tolerance_source: "request"` 时 `exceeds_warning: false`，看起来像"完全精确"；
3. `geometry_tolerance_mm` 建议支持按 op 覆盖默认值（现在可以），但在文档里明确它是"验收放行阈值"，不等于"求解精度"。

## 核心问题 2：装配的失败恢复死路仍未修（0.11.0 反馈第 3 条）

**现象**：`src/creo_mechdog/reconciliation.py:520` 仍为

```python
supported = model.get("model_type", "part") in ("part", "sheetmetal")
```

装配命中任何作业失败（包括 connect 阶段零变更的预检拒绝）后，`status=failed`，四个恢复动作用 `"Assembly/drawing reconciliation is not supported"` 全部拒绝，唯一出路仍是**手工编辑 `models/<id>/model.json` 的 status 字段**。

**影响**：装配是上色（FEAT-052）的唯一载体，也是装配重建（FEAT-049）的对象。这条死路把"上色失败一次"变成"必须手改注册表"，与 0.11.0 报告一致，本次复查未变。

**建议**（与 0.11.0 报告同）：区分"零变更失败"（connect/预检阶段）不要置 failed；或给装配提供最小 `ack_failure` 动作。

## 核心问题 3：save 的 origin 不匹配仍不引导 erase（0.11.0 反馈第 2 条）

`native/generic.cpp:6130` 仍是裸错误：

```
Loaded model origin does not match this MCP model's output directory
```

会话里有同名非受管副本时（外部程序保存、GUI 打开、上次会话残留），用户必须自行推断"先擦除会话副本再保存"。建议在错误信息里直接附上 `creo_erase_session_models` 的调用形态。

---

## 核心问题 4：G5 曲面三 op 仍未实现，P12 只能靠 194 ops 的替代路线

Q07 的新增只是 `tools/generate_constants.py` 的 `HEADERS` 里多了 `Probbl.h` 等 5 个头（读常量做探测），`surface_loft` / `project_curve` / `surface_trim` 在 op 分发表里**依然不存在**（`creo_check_environment` 的 `supported_features` 也没有）。

后果：
- P12 的正规链路（放样 → 投影 → 剪裁 → 加厚）仍不可表达；
- 替代路线（逐站三角棱柱）需要 **50 个单点 + 48 平面 + 48 草图 + 48 拉伸 = 194 ops**，紧贴 200 ops 上限，必须在**一个**计划里完成（跨计划会中断条带连续性），任何一次 0.004 mm 拒绝就整批回滚；
- 这意味着 P12 的可行性完全依赖核心问题 1 被修（或全程放宽容差）。

**建议**：优先把 `datum_plane` + `sketch` 之外的最小组合 `surface_loft`（Boundary Blend 元素树）+ `project_curve`（COPYTRIM 元素族，ProElemId.h:1630-1634）落地——两者到位即可把 P12 从 194 ops 降到 ~10 ops，并摆脱 0.004 mm 窄条草图的暴露面。

## 正向确认（本轮真正修好的）

1. **BUG-094 闭环**：斜面草图 + 三点定面。实测：三点定面 `normal=(-0.6775,-0.0932,0.7296)` 与解析一致；斜面草图 `geometry_deviation.max = 8×10⁻³⁸ mm`；拉伸后 `volume = 9,866.313 mm³ = 999.626 mm² × 9.87 mm` 精确闭合；保存重载校验通过。
2. **失败模型清理**（0.10.0 的 E 项）：失败作业回执新增 `failed_model_cleanup: {status: "erased", absence_verified: true}`，本次 194 ops 失败后会话未残留同名模型——不用再靠改名绕开。
3. **`geometry_tolerance_mm` 机制本身**：`tolerance_source: "request"`、`warning_threshold_mm` 如实回显，边界校验（布尔/NaN/负值拒绝）清晰。
4. **recolor 回归正常**：`appearance_baseline.present=true, missing_count=0`（0.11.1 未破坏 0.11.0 的基线迁移），80 组件 / 12 族分组与真值逐件一致。
5. **两点成面后的真实建模能力**：本轮已实建 2 条带扭叶片（bbox X = [-99.87, 98.88]，理论 ±98.55），证明"逐站弦线 + 三角棱柱"这条路在几何上成立。
