## 2. 核心问题

### P-A（本轮新发现，优先级高）多轮廓含圆弧切除：`material_removed_mm3` 系统性少于 `material_area_mm2`

同一 Creo 10、同一 1 mm 钣金侧壁、同一 `depth=2.0` 的 `extrude(mode="cut")`：

| 作业 | 轮廓数 | `material_area_mm2` | `material_removed_mm3` | 差 / 相对偏差 |
|---|---|---|---|---|
| `9267c5…` +X 格栅首扇区 4 孔 | 4 | 109.346743 | 109.346743 | ≈0 |
| `20f32075…` +X 格栅其余 28 孔 | 28 | 765.427200 | 749.425416 | **16.001784 / 2.09 %** |
| `e57bbd4b…` −X 格栅全部 32 孔 | 32 | 874.773942 | 858.771608 | **16.002334 / 1.83 %** |
| `45f2a692…` +X 百叶开口 6 | 6 | 1084.0293 | 1062.660171 | **21.369129 / 1.97 %** |
| `45f2a692…` −X 百叶开口 6 | 6 | 1084.0293 | 1062.658949 | **21.370351 / 1.97 %** |
| 对照 `c8af555a…` 4×Ø30 整圆孔 | 4 | 2827.433 | 2827.432745 | ≈0 |

补充证据：
- 数值栅格法（0.05 mm）对 32 个格栅轮廓做了并集分析：各轮廓面积之和 874.75 mm²、并集面积 874.75 mm²、`double-covered=0`、`max coverage=1` —— **无重叠、无嵌套、无自交**；`profile.categories` 全部为 0，`native_section.closed_contours` 与轮廓数一致、`max_endpoint_gap_mm=0.0`。
- 拓扑计数逐孔吻合：28 孔作业新增 105 个面（=7×3 中心扇孔 + 21×4 环扇孔）；12 个百叶开口新增 48 个面（=12×4）。`healthy=true`、保存重载通过。
- 因此孔确实切穿，差异在**面积/体积回执口径**，不是几何缺陷；根因未定因。整圆轮廓完全一致、含部分圆弧的轮廓才有偏差，强烈指向 `material_area_mm2` 的部分圆弧面积计算与 Creo native section 的实际截面不一致。

**建议**：回执中同时给出 native section 实测截面面积（`section_area_mm2`）与二者差值/告警；或明确文档化 `material_area_mm2` 是「草图解析面积」而非「实际去除面积」，避免下游把它当作体积校核依据。

### P-B `creo_measure_surface_curvature` 默认输出超 MCP 响应预算
单面、只读、`samples_per_direction=12` 的测量返回 99,512 字符（144 个逐采样点），触发
`Error: result (99,512 characters) exceeds maximum allowed tokens`，结果只能落盘到 tool-results 后再用脚本提取摘要（`sample_count=144 / failure_count=0 / max_abs_curvature_per_mm=0.0`）。
另：merged planar quilt 被 retrim 成 1 个成员面后，传 `faces:[0,1]` 会报 `member index 1 is outside the quilt's 1 member faces`，需先查成员数。
**建议**：默认只返回 `summary` + `g1_status`，用 `include_samples=true` 显式开启逐点数据；或在描述中给出 `face_count` 前置提示。

### P-C 大草图作业无法用默认 `creo_get_job` 轮询
含 105~120 个草图实体的作业（如 `20f32075…`），默认 `detail=full` 轮询报
`Single operations_input record exceeds the response budget; request a narrower section`。
必须用 `detail="compact", sections=[]` 才能拿到状态；作业本身其实是 `succeeded`（从 `jobs/<id>/job.json` 读到）。
0.19.1 把 `wait_seconds` 上限从 30 放宽到 300，但**没有解决响应预算问题**；0.19.0 上 `wait_seconds=40` 仍被 schema 拒绝。
**建议**：终端作业默认返回 compact 摘要；`operations_input` 分页或提供 `omit_operations_input`。

### P-D 钣金成形能力 0.19.1 仍全数缺位
0.19.0 release notes 明示「不可用（门禁保持）：钣金成形类（corner relief、百叶/成形、hem/jog、格栅孔、凸台/铰链/门板耳）、独立 quilt 偏置、任意非平面闭合边界 surface_fill」；0.19.1 为 PATCH，不新增公开工具（仍 107），「不可用结论与门禁保持不变」。
因此配电箱 TXT 的 §5 百叶、§6 格栅、§7 凸台、§8 铰链、§11 门板耳**依然没有原生钣金特征可用**，只能靠 `cut` + `new_body=true` / `thin` 做多实体近似。

### P-E（本轮新证据）四壁盒的 ±X 顶边被碎片化，第三/四道折边无法挂
TXT §4.3/§4.4 要求四边均有 20 mm 向内框边 + 8 mm 向上止口。当前 `out4` 建法只做出 ±Y 两侧。读取 rev14 检查快照（`inspection-verified-d644f8…`，1732 条边）中 Z=80 平面的长边：

```
id 776  L=70.586  [ 92.5, 35.293, 80] -> [ 92.5,-35.293, 80]
id 777  L=70.586  [ 91.5, 35.293, 80] -> [ 91.5,-35.293, 80]
id1275  L=70.586  [-92.5,-35.293, 80] -> [-92.5, 35.293, 80]
id1276  L=70.586  [-91.5,-35.293, 80] -> [-91.5, 35.293, 80]
```

±X 壁顶边最长连续段只有 70.586 mm，远小于所需的 232 mm；其余段被 ±Y 折边与角部 miter 切成 X=±88.96 / ±72.5 的短边。`sheetmetal_flange` 依赖 `edge_geometry` 精确选边，无法挂出完整折边。
**建议**：提供 corner relief / 多段连续共线边合并选边 / 「按整条 wall 顶边生成折边」的高层操作，而不是要求调用方逐段猜端点。

### P-F（延续，未修）钣金体无法与实体合并
- `SHEETMETAL_SOLID_ADD_UNSUPPORTED` 仍只放行 `new_body=true` / `thin` / `cut` / `surface`。
- `schema.py::BooleanOp.valid_bodies` 仍拒绝负 body id：`r["id"] < 0 → "Explicit body IDs are required"`（`native_planar` 钣金主体 id 为负）。
- Creo 10 实测：换 `conversion` 模板得到正 id 后，`union` 正反两方向均 `ProFeatureWithoptionsCreate failed with code -1` 并 `rollback_succeeded=true`；`thin` 增料会静默并入辅助实体 body 而非钣金主体。
- 结果：`out6` 箱体 11 bodies、门板 3 bodies，达不到 TXT 的「各 1 个实体」。补充了作者在 `sheetmetal.py` H05 注释中「Creo 10 has never been tried / untested」的空白。
**建议**：回执显式给出 `merged_into_body_id`；放开负 id 或提供 body id 别名解析；提供钣金专用 merge。

### P-G 草图缺少参数化 / 文件入口，64 孔只能内联硬堆
`creo_run_plan` 在本版不可用；`creo_execute_plan` 只能内联 `entities`。单侧 32 个环扇孔 = 120 实体 / 13,135 字符，两侧需重复提交；`axis_pattern` 需要 datum axis 且 4 组 `r1/r2` 不同，无法一轮阵列。
**建议**：支持 `entities_file`（工作区内 JSON 路径）、`polar_pattern` 草图实体，或环扇/辐条格栅模板。

### P-H（P11 延续）装配交付仍需手工复制组件快照
`out6_asm.asm.4` 内部引用 `C_4C01FD431CAE492C_0.PRT` / `_1.PRT`，必须人工从 `models/<id>/output/` 复制 `c_*.prt.N` 到交付目录，否则 `.asm` 打开为空白。0.19.0 已有 `creo_export_model(format="native_bundle")`，本轮未验证其是否能自动打包，暂不判定为已修复。

### P-I（延续多版）`origin≠[0,0]` 的大跨度 `resize_sheetmetal_planar_wall` 体积错误
0.17.4 / 0.18.0 / 0.18.1 连续反馈未修；0.19.0 / 0.19.1 release notes 未提及。本轮未复测。

### P-J 建议把 Creo 10 纳入发布前回归
0.19.0 与 0.19.1 release notes 均写明「Creo 9/10 实机未执行」。本轮在 Creo 10 上 4 个曲面链能力全部通过、同时也复现了 P-A / P-C / P-F，说明 Creo 10 与作者 Creo 12.4 的行为并不完全一致，建议在 CI 中至少覆盖 Creo 10 的曲面链、钣金增料与多轮廓 cut 三条路径。

## 3. 对「配电箱任务能否进一步推进」的结论

**能推进，但不是靠 0.19.0 / 0.19.1 的更新。** 0.19.0 新增的是曲面链能力（`surface_round` / `measure_surface_curvature` / `quilt_merge`），0.19.1 是回执与长轮询的 PATCH，都与钣金成形无关。

本轮实际进展来自两条既有路径，已落到 `out6/`：

1. `extrude(mode="cut")` 不受 `SHEETMETAL_SOLID_ADD_UNSUPPORTED` 影响 → 用解析级内联草图补齐 §6 两侧共 **64 个环扇/扇状格栅孔**（此前 0 个）。
2. `extrude(add, new_body=true)` → 补齐 §5 两侧共 **12 个百叶弧形薄壳 + 12 个侧壁开口**（此前 0 个），并沿用 TXT §5.6 明确许可的近似。

箱体 rev8 → rev14 的实测体积链、罩壳增料与解析值吻合、拓扑面数逐孔核对、双侧对称性、装配变换与 STEP（24 个 `MANIFOLD_SOLID_BREP`）均已落盘在 `out6/交付说明.md`。**仍未完成**：±X 两条 20 mm 框边 / 两条 8 mm 止口（P-E）、角部 0.2 mm 接缝、R2.54 / R3 圆头、单实体拓扑（P-F）、百叶圆滑端部（TXT §5.6 允许的简化已披露）。
