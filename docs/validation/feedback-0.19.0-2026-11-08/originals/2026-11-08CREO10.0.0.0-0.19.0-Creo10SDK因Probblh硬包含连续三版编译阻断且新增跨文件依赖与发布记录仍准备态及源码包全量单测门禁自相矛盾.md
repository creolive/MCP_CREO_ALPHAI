## 2. 问题明细

### P1-1｜Creo 10 SDK 连续第三版整包编译阻断，且 0.19.0 引入跨文件符号依赖

**证据**

1. 官方 0.19.0 包内 `native/surface_loft.cpp` 与 0.18.4 **逐字节相同**（15 936 B，`af856a58ebf2…`），第 15 行仍是无条件 `#include <Probbl.h>`，全文件无 `__has_include` / 任何头门控。
2. `native/generic.cpp:3887` 无条件 `#include "surface_loft.cpp"`，所以 Creo 10 SDK 上**一个目标文件都编不出**：
   ```
   native\surface_loft.cpp(15): fatal error C1083: 无法打开包括文件: "Probbl.h"
   BUILD_UNPATCHED_EXIT=1
   ```
3. `tools/generate_constants.py` 仍**没有** `MECHDOG_HAS_HEADER` 宏、也没有 `__has_include` 支持；它只把缺失头从生成的 `native/constants.inc` 中剔除并打印 `MISSING_SDK_HEADER=Probbl.h`。`tests/unit/test_gated_headers` 4/4 通过，但它断言的对象只是生成的 `constants.inc`，**覆盖面不含手写 TU**。这正是「测试全绿 + 整包编不出」能同时成立的原因。
4. **0.19.0 新增难点**：`native/surface_boundary_fill.cpp` 复用了 `surface_loft.cpp` 内部的
   - `SURFACE_LOFT_TREE_SAMPLE_LIMIT`（第 175/176/179 行）
   - `loft_element_json()`（第 178 行）
   - `PRO_E_DTM_SRF_TYPE_BND_BLEND`（第 223 行，另 225–227 行用 `PRO_E_BNBLN_*`、236 行用 `PRO_E_BBL_ADD_CLOSED`）

   直接套用 0.18.4 那版「把 `surface_loft.cpp` 整个主体用 `__has_include` 包起来」的补丁，会把上述 helper 一起隐藏，产生 5 个新错误：
   ```
   BUILD_PATCHED_EXIT=1
   surface_boundary_fill.cpp(175)(176)(179): error C2065: SURFACE_LOFT_TREE_SAMPLE_LIMIT 未声明
   surface_boundary_fill.cpp(178): error C3861: loft_element_json 找不到标识符
   surface_boundary_fill.cpp(223): error C2065: PRO_E_DTM_SRF_TYPE_BND_BLEND 未声明
   ```

**影响**：所有使用 Creo 10（及任何不提供 `Probbl.h` 的 Toolkit SDK）的用户，**从 0.18.3 到 0.19.0 连续三版无法完成 `bridge.py build`**，除非自行打补丁；而 0.19.0 起补丁复杂度上升。Release body 明确写「Creo 9/10 未复测」「本机无 Creo 9 SDK，Creo 10 未复测」，所以这是**已声明的未测范围**，本报告按「已声明范围外的实际阻断」记录，不指责隐瞒。

**本机处置（仅本机，不改语义、不伪造几何）**

把「与 SDK 头无关」的元素树读取 helper（`SURFACE_LOFT_TREE_SAMPLE_LIMIT` / `loft_element_json` / `loft_tree_json`）留在 guard 之外，只对两个真正依赖 `Probbl.h` 的操作体做 `__has_include` 门控；缺头时两个入口都抛明确的 unavailable 运行时错误（`surface_boundary_fill` 上游本就是 `UNAVAILABLE_OPERATIONS` GATED 项）。两处 diff 分别为 44 行与 27 行，见归档 `surface_loft.cpp.local.patch.diff` / `surface_boundary_fill.cpp.local.patch.diff`。结果 `BUILD_EXIT=0`，0 error。

**建议（给作者）**

1. 把 `loft_element_json` / `loft_tree_json` / `*_TREE_SAMPLE_LIMIT` 抽到独立 `native/element_tree_json.h`（不依赖 `Probbl.h`），让 `surface_loft.cpp` 与 `surface_boundary_fill.cpp` 都从该头取符号，消除「一个 cpp 内部符号被另一个 cpp 隐式复用」的耦合。
2. 由 `tools/generate_constants.py` 的 `available_headers()` 生成一个 `#define MECHDOG_HAS_PROBBL 0/1` 写进 `constants.inc`，手写 TU 统一用它做 `#if`，而不是各写一份 `__has_include`；这样「生成的头清单」与「手写 TU」共用同一个真值源。
3. **扩展 `tests/unit/test_gated_headers` 的覆盖面**：新增一条契约，扫描 `native/*.cpp` 中出现的 `#include <...>`，凡命中 `available_headers()` 的 `missing` 列表而未加门控即失败。目前的 4 项测试只守生成层，守不住手写层。
4. 在 `docs/COMPATIBILITY.md` 与版本说明里明确写清：`creo_surface_loft` / `surface_boundary_fill` 在不含 `Probbl.h` 的 SDK 上不可用，并给出降级回执文案，避免用户把「编译失败」误判为安装问题。
