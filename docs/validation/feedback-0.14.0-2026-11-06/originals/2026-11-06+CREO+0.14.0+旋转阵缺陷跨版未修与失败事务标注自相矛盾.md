## 4. 核心问题

### 4.1【严重｜跨三版未修】`rotation_matrix` 的 `1e-6` 正交容差与 Creo 内核要求不匹配

**源码证据**：0.14.0 的 `src/creo_mechdog/schema.py:41-62` 与 0.13.0 **逐字节相同**：

```python
if abs(dot - (i == j)) > 1e-6:   raise ValueError("... orthogonal within 1e-6")   # line 52-53
if abs(determinant - 1) > 1e-6:  raise ValueError("... determinant must be +1 within 1e-6")  # line 60-61
```

`AssemblyPose.rotation_matrix`（:73）与 `AssembleOp`（:1058，继承 `AssemblyPose`）**仍无 `Field(description=...)`**；全仓仍无 `rotation_convention`、`matrix_echo`、`orthonormality`、`continue_on_error`。

**实机 A/B**（同一零件 `b8734faf…`）：

| 输入 | 残差 | 校验器 | Creo 10 结果 |
| --- | --- | --- | --- |
| A4：30° 严格正交 `[[0.8660254037844387,0.5,0],[-0.5,0.8660254037844387,0],[0,0,1]]` | ~1e-16 | 放行 | ✅ 2 实例全部 committed（`bfc3551e`） |
| A3：I032 截断阵 `[[0,0.307383,-0.951586],[0,0.951586,0.307383],[1,0,0]]` | 行范数 `1.000000112042`；`R·Rᵀ−I` 与 `det−1` = **`2.24085e-7`** | **放行**（< 1e-6） | ⛔ `ProAsmcompAssemble -2`（`017c62e4`） |

这一条从 0.11.7（35 实例整批回滚）→ 0.13.0（加校验器但阈值过松）→ 0.14.0（源码未动、复现依旧）**跨三版未闭环**。0.14.0 的 Release Notes 自称「PATCH 性质的回执与预览补证批」，28 个真实改动文件里没有 `schema.py` 的这段，说明该缺陷不在本版范围——但既然 0.13.0 已经收到带精确残差与 A/B 样本的反馈，建议下一版务必排入。

**建议**（与 0.13.0 报告相同，未重复实现）：
1. 提交前对矩阵做 Gram-Schmidt / 行归一化，把**修正后的矩阵**传给内核，并回显 `matrix_echo` + 归一化前后残差；
2. 或把阈值收紧到 `1e-9`（与 `weldability` 的 `1e-9` 同量级），在提交期给出可读拒绝原因，而不是让 Creo 返回通用 −2；
3. 把 A3/A4 两个样本固化为回归用例。

### 4.2【严重｜0.14.0 新增矛盾】同一份失败结果里五处事务标注互相打架

作业 `017c62e4` 的返回同时包含：

| 位置 | 值 | 含义 |
| --- | --- | --- |
| `component_changes.status` | `"unknown_outcome"` | 新增保守提示：「**rollback is unconfirmed**; do not treat any requested change as effective. Protection is retained」 |
| `result.failed_model_cleanup` | `status="erased"`, `absence_verified=true`, `erase_code=0`, `reason="cleaned"` | 新建模型**已被擦除且验证不存在** |
| `result.rollback_status` | `"not_attempted"` | 根本没有执行回滚 |
| `result.rollback_succeeded` | `false` | 回滚「未成功」 |
| `result.operations[].effect_status` | 两个 op 都是 `"unknown"` | 无法判断已执行实例是否生效 |

再加上 `creo_inspect_model(c1b59e36…)` 会给出 `status=failed / revision=0 / part_file=null`（模型确实不存在），事实是**干净的**：新建失败模型已被删除，不存在"残留变更"风险。但新增的 `unknown_outcome` 提示却声明「rollback 未确认、保护保留、不要当任何变更生效」，与 `absence_verified=true` 直接冲突。

这不是纯措辞问题：`unknown_outcome` 会触发调用方的恢复流程（保留 reservation、不许重放、转人工核对），而实际上这里只是一次普通的「新建件失败已擦除」，重试同名即可。0.13.0 的 `fe27b48a…` 同类失败给的是 `effect_status="rolled_back" / rollback_succeeded=true`，0.14.0 反而更含糊。

**建议**：
1. 以 `failed_model_cleanup.absence_verified` 为判据：新建模型失败且已验证擦除 → 事务状态应为 `no_effect`/`cleaned`，**不要**打 `unknown_outcome`，也不要保留未知保护；
2. `unknown_outcome` 只保留给真正的「IPC 断连/作业结果未取回」场景；
3. `effect_status` 收敛到 `committed / rolled_back / no_effect`；`rollback_succeeded` 与 `rollback_status` 二选一，避免 `false` 与 `not_attempted` 并存；
4. `component_changes.note` 应当与 `failed_model_cleanup` 由同一段事务判定逻辑生成，而不是两条独立路径各写各的。

### 4.3【中｜跨版未修】失败 op 仍无任何可定位原因

`017c62e4` 的 `operations[1]` 只有 6 个键：`{op, index, label, succeeded, execution_status, effect_status}`，**没有** `error`、ProError 文本、`matrix_echo`、`orthonormality_residual`、`det`。`failed_toolkit_call` 只是一句函数签名。原生日志尾里明明有：

```
ProAsmcompAssemble((ProAssembly)board, (ProSolid)child, position, &comp)=-2
BUILD_FAILED=-2
```

建议把 `pro_error_code=-2`、传入矩阵、残差 `2.24e-7`、`det−1` 一起回填到失败 op；这些信息对定位 §4.1 是决定性的。

### 4.4【中｜未修】`creo_list_jobs(detail="compact")` 仍不投影

`creo_list_jobs(limit=1, detail="compact")` 对失败作业仍内联完整 `result.operations[]`、`inspection`、`runner_identity`，以及 **8 KiB `native_log_tail`**（`native_progress.tail_bytes=8192`、`log_bytes=9560`）。0.14.0 改了 `operation_results.py`，但 compact 投影未变。建议 compact 只留状态/时间/截断 message/`result.success`/失败原因/operation_count。

### 4.5【中｜部分改善但仍有噪音】`through_all` 的 `depth` 在两处口径不一致

`creo_extrude` 的 docstring 已明确写「`through_all`（cut mode only; **depth is ignored**）」，这是改善。但 A1 的**提交响应**把省略的 depth 补全并回显成 `"depth": 1`（同时 `defaulted_fields:["depth"]`），而**作业回执**里 `extrude_depth.requested_depth_mm = null`。同一作业两处对「有没有传 depth」给出相反答案。建议提交响应的 `operations[]` 只回显原始入参（或明确标注 `defaulted_values`），别把补全值伪装成请求值。

### 4.6【低｜未修】其余接口层遗留

- **P-1**：`execute_plan` 依赖的 `AssemblyPose` / `AssembleOp` schema 仍无旋转约定说明，job result 不回显 `rotation_convention` 或读回 transform；只能靠额外调用 `creo_inspect_model(detail=full, section=components)` 核对。
- **P-6**：装配 `inspection` 仍只有 volume / cog / counts，无 bbox；`asm_v2` 与新装配都一样。
- **P-8**：`connected=true / toolkit_code=0 / startup=ready` 时，`session_health` 仍是 `unknown / session_identity_stale`（04:11:27Z 实测）。
- **P-9**：本轮 `channel.busy=false`，未复现。
- **P-10**：仍无 managed 模型 delete/rename；本轮又新增了 `acc140_*` 一批避重名模型。
- **P-11**：提交响应仍把每个 op 展开回显（含 `endpoint_policy`/`weld_pairs`/`dimensions`/`constraints`/`new_body`/`defaulted_fields`）。
