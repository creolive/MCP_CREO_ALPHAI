## 3. 问题清单

### P0-1 `creo_get_mass_properties(density_g_cm3=...)` 在「有材料但质量查询失败」的模型上必然报错，且是 0.18.1 引入的回归

**现象**：公开工具直接抛错，调用方拿不到任何回执文本：

```text
Error executing tool creo_get_mass_properties:
A mass reading with a density source cannot carry an unavailable reason
```

**关键反差**：报错的同时，底层只读作业其实 **succeeded**，且原生回执自相矛盾 —— 既给出质量，又说质量不可用。

`jobs/f690d600655e401fb430014e129a1517/native_result.json`（`density_g_cm3=2.7`）：

```json
{
  "op": "mass_properties", "succeeded": true,
  "volume_mm3": 83508.0,
  "mass_g": 225.4716,                       // = 83508 * 2.7 / 1000，数值正确
  "density_g_cm3": 2.7,
  "density_source": "request",
  "mass_unavailable_reason": "material_query_failed",   // 残留，与 mass_g 冲突
  "hint": "The model material could not be measured; mass is unavailable",  // 残留
  "mass_unit": "tonne", "material_assigned": true, "mass_query_code": -1
}
```

`get_job(job_id, detail="full", section="operations_result")` 也能读到这份矛盾回执；`get_job(detail="compact")` 则显示 `status=succeeded`。也就是说：**作业成功、数据落盘、公开工具失败**，三者同时成立。

**根因（两处配合出错）**：

- `native/generic.cpp::mass_properties_json()`（约 L711–L816）在模型有材料但 `ProSolidMassPropertyWithDensityGet(..., PRO_MP_DENS_DEFAULT, ...)` 返回 `-1` 时，先写入
  `out["mass_unavailable_reason"]="material_query_failed"` 与 `hint`；
- 随后 caller-supplied density 成功分支只写 `mass_g` / `density_g_cm3` / `density_source="request"` 就 `return out`，**没有清空前一段的 reason / hint**；
- `src/creo_mechdog/mass_properties.py::normalize_mass_properties()` 有硬守卫
  `if source != "none" and reason is not None: raise ValueError(...)`，于是拒绝整份回执。

**这是回归，不是新环境差异**。同机同条件的历史作业 `jobs/4601bb03...`（2026-11-07 08:32 UTC，`material_assigned=true`、`mass_query_code=-1`、`density_g_cm3=7.85`）回执中 `hint=null`、无 `mass_unavailable_reason`，显式密度路径当时可用。0.18.1 为 `FEAT-057` 补齐「缺失原因」契约后引入残留字段，0.18.2 未修。

**触发条件（已用正/反样本界定）**：

| 模型 | `material_assigned` | `mass_query_code` | 显式密度结果 |
| --- | --- | --- | --- |
| `b53fb69a...`（part） | `true` | `-1` | ❌ 公开工具报错（作业 `f690d600...`、`72df4d48...`） |
| `4c38b0f2...`（sheetmetal，0.18.0 时段） | `true` | `-1` | ✅ 当时可用（回归前样本） |
| `2deff06f...`（assembly） | `false` | `null` | ✅ `d58a2beafb674ceba6fcca0299542c41`，`mass_g=402.9259798803698`，`density_source="request"` |

即：**只要模型有当前材料且材料质量查询失败，`density_g_cm3` 这条 what-if 路径 100% 不可用**。Creo 10 上 `ProMaterialCurrentGet` 常返回默认材料，因此影响面不是个例。

**建议修复**：在 caller-supplied density 成功分支返回前显式清空两个字段，或把失败原因的赋值整体延后到最终 `no_density` 分支：

```cpp
out["density_source"] = "request";
out["mass_unavailable_reason"] = nullptr;   // 新增
out["hint"] = nullptr;                      // 新增
return out;
```

并补一条单元测试：`material_query_failed` + 显式密度 → `density_source=request` 且 `mass_unavailable_reason=null`；同时建议 `normalize_mass_properties()` 在拒绝时把原始回执片段带进错误信息，避免今后再出现「作业成功但工具无诊断」的黑洞。

### P1-1 失败作业 `connect` 阶段计时仍被 8192 字节 tail 窗口截断（0.17.4 反馈跨版未修）

### P1-3 `creo_get_mass_properties` 的「Parts only / 装配体拒绝」契约与实测不符

公开工具 docstring 写：`Parts only: assemblies are refused until their own query path is verified`；`capabilities.families.mass_properties.parts_only=true`。但本机实测装配体可读：

| 作业 | 模型 | 结果 |
| --- | --- | --- |
| `a5e358c3c20e42f99f99eea05f4ab6a7` | `2deff06f...`（`model_type=assembly`） | 成功，`volume_mm3=149231.8444`，`density_source=none`，`no_density` |

## 6. 建议的修复优先级

1. **P0-1 先修**：两行 `nullptr` 清空 + 回归单测。这是当前唯一让一个已发布公开工具在具体模型上完全不可用的缺陷，且是从 0.18.0 → 0.18.1 的功能回退。
