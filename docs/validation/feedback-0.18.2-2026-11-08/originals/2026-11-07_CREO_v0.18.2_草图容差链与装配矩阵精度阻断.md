## 0. 一句话结论

**按"文档级精度"的几何数据（3 位小数轮廓、4 位小数方向向量）无法通过 MCP 的原生校验，调用方被迫在"硬失败 / 静默几何失真 / 自行改写输入数据"三者之间选择，且能力文档中给出的任意平面草图写法不可用。** 任务最终完成，但依赖了多处非显然的绕行。

## 1. 任务背景与约束（说明问题的真实性）

本次任务是**从空白模型**完整重建「简易机械爪夹具结构」：

- **唯一几何数据源**：工作区内的 `简易机械爪夹具结构_跨软件三维建模自然语言说明v1.2.txt`（11 种唯一零件、25 个装配实例、全部轮廓点/拉伸深度/孔位/4×4 装配变换）。
- **硬约束**：不导入任何实体，不使用 CREO/SolidWorks/NX 原文件、STEP、Parasolid、STL、源 JSON 或工作空间以外的任何"模型输入"；建模动作**只调用 MCP_CREO_MechDog**。
- 因此所有坐标只能按 TXT 原样输入（3 位小数轮廓点、4 位小数单位方向向量），这恰好把 MCP 的精度门槛暴露出来。
- 期间用 Bash/Python 做的仅是**纯数值推导**（把 TXT 的圆心+半径+端点反解为圆弧角度、把三轴单位向量 Gram-Schmidt 正交化），未引入任何外部几何数据。

**最终结果（全部成功）**：11/11 零件 + 25/25 装配实例，`mechclaw_asm25.asm`，`inspection.counts.components = 25`，总装体积 `1 744 115.09 mm³`，质心 `(-7.676, 182.806, 65.132)`（Y 与 TXT 对称中面 182.806 精确吻合）。

## 2. 核心问题 A：草图容差链（三个同源现象，构成"硬失败 / 静默变形"两难）

### A-1　轮廓闭合容差 1e-4 mm 与 3 位小数工程数据不兼容，且不做端点吸附　【P0】

**现象**：直接按 TXT 原坐标（圆心 + 名义半径 + 原端点）建 P03 端盖的 6 段圆弧轮廓，被判定为开放轮廓，整个 `solid extrude` 在提交前即拒绝。

**原始报错**（`creo_execute_plan` 提交时的即时参数校验错误，**未创建作业**）：

```
operations[1]: Solid extrude profile rejected: detected 2 closed contour(s), 3 open contour(s)
and 11 curve entities; [open] an open contour (endpoints are not closed within 0.0001 mm)
(l0/a_r200/a_r15) near (150.669881, 36.8421662) mm.
```

**根因**：TXT 的 3 位小数端点与名义圆心/半径之间天然存在约 `2e-4 ~ 1e-3 mm` 的舍入不一致（例如 R200 弧终点到圆心实距 200.000205，R10 弧起点实距 10.000381）。`closure_tolerance_mm = 0.0001` 严格小于这个量级。

**加重因素**：
- `endpoint_policy` 默认 `"report"`，`weld_pairs` 默认 `[]` —— 不执行吸附；
- `weldability.weld_tolerance_mm = 1e-9` 只作为**风险标志**上报（`weldable: false`），并不修复；报告自己也写明 "exceeding pairs are joined only by the closure tolerance"；
- 报错没有给出"哪些端点、差多少、建议如何修正"的清单，只给了一个近似坐标。

**绕行成本**：调用方必须先对每条圆弧做"由两端点 + 名义半径精确反解圆心"的数值处理（本次圆心最大微调 0.00097 mm），才能把 gap 压到 1e-4 以内。这对任何从图纸/文档重建模型的场景都是额外负担。

**建议**：
1. 提供可选 `snap_endpoints: true`（在给定容差内把相邻端点吸附到同一坐标），并在 receipt 中回报每个被吸附的点及位移；
2. 或把 `closure_tolerance_mm` 暴露为可配置参数（例如允许 0.01 mm），由调用方按数据精度声明；
3. 拒绝信息里列出 `entity A / entity B / gap_mm` 完整表，便于定位。

---

### A-2　复杂草图自动切到 `coordinates` 求解器后，1.36e-4 mm 偏差即整体失败　【P0】

**现象**：A-1 的轮廓经精确反解圆心后已**完全闭合**（`closed_contour_count = 3`、`max_endpoint_gap_mm = 1.78e-6`、轮廓净面积 `6224.5958 mm²` 与 TXT 理论值 `6224.6` 一致），但作业仍失败，且新建模型被整体清理。

**原始报错**（job **`fb0e9ef22c0c4fdd84b389a8ac64762b`**，`created_at = 11:14:48 UTC`，`stage = execute_sketch`，`failed_operation_index = 0`）：

```
status = failed, stage = execute_sketch
"Coordinate dimensioning changed the supplied geometry; maximum deviation mm=0.000136"
solver: { requested: "auto", used: "coordinates", selection_reason: "entity_count",
          completed: true, recovered: false }
```

该作业是 A-1 轮廓被拒之后、改用"精确反解圆心"数据重新提交的版本：轮廓此时已完全闭合，但 `coordinates` 求解仍使整个作业失败，新建模型按 `new_model_cleanup_confirmed` 清理。随后改显式 `autodim` 的提交 `b759a97510d54d38a70849b11d85c7b0` 才成功（见 A-3）。

> P03 三步时间线（无歧义）：
> 1. `11:14` 前后，TXT 原坐标提交 → **即时校验错误、无 job_id**（A-1）；
> 2. `11:14:48` 反解圆心后提交 → job `fb0e9ef22c0c4fdd84b389a8ac64762b` → **failed**（A-2）；
> 3. `11:15:14` 显式 `autodim` 提交 → job `b759a97510d54d38a70849b11d85c7b0` → **succeeded**，但几何被改动（A-3）。

**关键点**：`dimensioning` 默认是 `auto`，MCP 因 `entity_count = 11` **自动**选择 `coordinates` 模式（"auto uses complete coordinate dimensions for large/complex supported profiles"）。也就是说调用方并未要求严格模式，却因为实体数被切到一个会以 `1e-5 mm` 为上限拒绝几何的模式；`recovered: false`，**没有自动回退到 `autodim`**。对照：6 实体的 P10 连杆、10 实体的 P02 耳座用显式 `coordinates` 都能成功（坐标本身为精确设计值），说明失败阈值对"来自文档的非精确数据"过于苛刻。

**建议**：
1. `coordinates` 求解偏差超限时自动回退 `autodim`，并在 receipt 中标注 `solver.fallback_reason`；
2. 或把 `1e-5` 阈值暴露为参数（`geometry_tolerance_mm` 已存在，但 `coordinates` 模式默认 1e-5 且失败时没有提示"可显式放宽"）；
3. `auto` 的切换阈值与选择理由建议写进 compact capabilities，方便调用方预判。

---

### A-3　`autodim` 会静默改动草图几何，仅 warning 不阻断　【P1，静默失真】

**现象**：显式指定 `dimensioning: "autodim"` 后 P03 成功（job `b759a97510d54d38a70849b11d85c7b0`），但：

```
geometry_deviation.max_deviation_mm = 0.0082825
exceeds_warning = true, enforced = false, accepted_by_request = null
被改动的实体：a_r130 0.00828 / a_r10b、a_r10c、h2、l1 各 0.005 / l2 0.00507 ...
```

即直线端点、圆弧参数、Ø10 孔都被原生自动标注求解器移动了最多 **0.0083 mm**。P05 推杆的锥台草图同样被改动 `0.0045 mm`（job `74ca1161bfd54e1c817ce87d62e2b1cd`）。

**影响**：对"按文档坐标精确复现 / 跨软件比对"的场景，这是**静默几何失真**——作业 `succeeded`，`effect_status: committed`，只有深入读 `geometry_deviation` 才能发现。与 A-2 结合，调用方陷入"要么整个作业失败、要么拿到一个被悄悄改过的模型"的两难。

**建议**：
1. 在 `assertions` 中增加 `max_geometry_deviation_mm`（或 `require_exact_solve`），让调用方能主动拒绝被改动的草图；
2. `exceeds_warning = true` 时在 job 顶层 `message` / compact 摘要中显式提示，而非只埋在 operations 里；
3. 提供 `preserve_input_geometry` 严格模式：求解后若几何不一致就失败并回报差异表。

## 3. 核心问题 B：装配旋转矩阵 1e-6 正交门槛与 4 位小数方向向量不兼容　【P0】

**现象**：TXT 第八章给出的 25 个实例三轴方向为 4 位小数单位向量。直接按原值提交 `assemble_component` 的 `rotation_matrix`，在**参数校验阶段**即被拒绝（作业根本不会创建）。

**原始报错**：

```
1 validation error for creo_execute_planArguments
operations.1.assemble_component.rotation_matrix
  Value error, rotation_matrix must be orthogonal within 1e-6
  (max |R*R^T-I| = 3.252e-05); the input is echoed and never repaired,
  so supply exact orthonormal values
```

**量化**：25 个实例中 **14 个**的 `max|R·Rᵀ−I|` 超出 1e-6，范围 `3.252e-5 ~ 9.810e-5`：

| 实例 | 正交残差 | det−1 |
|---|---:|---:|
| I002 推杆 | 3.252e-5 | +3.252e-5 |
| I004 / I005 手指 | 6.380e-5 | −6.380e-5 |
| I006 / I007 端盖 | 3.490e-5 | +3.490e-5 |
| I008 / I009 连杆1 | 8.473e-5 | +8.473e-5 |
| I010~I013 连杆2 | 3.902e-5 | −3.902e-5 |
| I015 短销 | 3.980e-5 | −3.980e-5 |
| I016 销轴18 | 9.810e-5 | +9.810e-5 |

**影响**：任何"按文档数据装配"的调用方都必须自行实现 Gram-Schmidt / 归一化，否则一个实例都装不进去。而文档明确声明 "The values are applied exactly as given: never transposed, orthonormalized or repaired"，属于有意为之的设计取舍——这个取舍本身合理，但**没有给调用方任何可配置的缓冲**。

**绕行与代价**：本次对 X 归一化、对 Y 做 Gram-Schmidt、Z 取 X×Y，得到严格正交矩阵；与 TXT 的 Z 轴最大偏差仅 `3.17e-5`，装配后 25/25 组件的 4×4 变换与 TXT 的原点+三轴逐条吻合（见 `creo_inspect_model(section=components)`）。也就是说这 `1e-5` 量级的差异在工程上完全无害，却构成硬阻断。

**建议**（任选其一即可显著改善）：
1. 增加可配置 `orthogonality_tolerance`（默认仍 1e-6），允许调用方按输入数据精度声明 1e-4；
2. 或增加 `orthonormalize: true` 选项，由 MCP 做归一化并**在 receipt 中回报修正前后的矩阵与最大修正量**（既保持可复现，又不阻断）；
3. 报错信息里给出"最接近的合法矩阵"建议值，降低排查成本。

## 4. 能力文档中给出的任意平面草图写法实际不可用　【P0，文档/实现不一致】

`creo_capabilities(detail="full", section="references")` 中 `creo_create_sketch.plane` 给出：

```json
{ "reference": {"kind":"datum_plane","axis":"z","offset":0},
  "origin": [0,0,0], "u_axis": [1,0,0] }
```

照此格式提交一个偏移 + 自定义 u 轴的平面（job `c7d65904e42b41a3acac002bb8d88777`）：

```json
{ "reference": {"kind":"datum_plane","axis":"x","offset":-2},
  "origin": [-2,0,0], "u_axis": [0,0,-1] }
```

**结果**：`status = failed, stage = execute_sketch`，`failed_operation_index = 2`

```
"Plane reference must identify exactly one surface; inspect the model and use a surface ID"
```

同一作业里另两个**字符串主平面**都成功并回报了清晰的坐标系：
- `plane: "YZ", offset: 15.5` → `origin=(15.5,0,0), normal=+X, u=+Y, v=+Z`
- `plane: "XZ", offset: 4` → `origin=(0,4,0), normal=−Y, u=+X, v=+Z`

**影响**：P04 手指的 OP34 末端耳板需要画在 `(d,n)` 倾斜平面（法线 ±Y、H 沿 d=(−0.342,0,−0.9397)、V 沿 n），P01 凸台、P02 耳座也都需要自定义草图坐标系。由于字典式平面不可用，只能把轮廓点全部做坐标变换，改用 `XZ`/`YZ` 主平面 + `offset` 重建（本次即如此完成，P04 体积与 CATIA 口径吻合到 0.018 %，但实现路径与 TXT 的操作序列已不相同）。

**建议**：
1. 明确文档与实现的边界：`origin` / `u_axis` 究竟是否支持"凭空指定任意平面"，还是只能覆盖已解析到唯一 surface 的平面坐标系；
2. 若支持，请修复 `datum_plane + axis + offset` 的解析；若不支持，请在 references 示例中改用可用的 `{kind:"plane", id:N}` / `{kind:"surface", id:N}` 形式，并说明自定义 u_axis 的前置条件；
3. 提供"由 `origin + normal + u_axis` 直接创建基准平面/草图平面"的一等公民工具，这对斜面特征（耳板、斜孔、扫掠截面）很关键。

## 6. 本次采用的绕行方案汇总（供作者评估调用方负担）

| 障碍 | 绕行做法 | 引入的偏差 |
|---|---|---|
| A-1 轮廓闭合 | 由 TXT 两端点 + 名义半径精确反解圆弧圆心，端点严格落在 TXT 坐标 | 圆心微调 ≤ 0.00097 mm |
| A-2 coordinates 失败 | 对含圆弧的复杂草图显式 `dimensioning: "autodim"`；对精确设计值草图用 `coordinates` | 见 A-3 |
| A-3 autodim 静默变形 | 接受（体积校核显示影响 < 0.09 %），并在交付说明中标注 | ≤ 0.0083 mm |

## 7. 值得肯定的部分

- `execute_plan` 的"一次提交有序计划 + 回滚 + 逐操作 `execution_status`/`effect_status`"非常好用：P04 的 20 个操作、总装的 25 个实例都能一次完成，失败时 `terminal_effect` 明确给出 `no_effect` 与清理结论。
- `geometry_deviation` / `weldability` / `arc_geometry` / `material_removed_mm3` 等**可观测证据**字段很扎实，本次所有问题都能靠这些字段定位（尤其 A-3 的静默变形能被发现，全靠它）。
- `creo_get_job(detail="compact", sections=[...])` 的分块读取设计合理。
- 装配后 `inspect_model(section="components")` 能逐组件回报 4×4 变换与 `source_revision`，使 25/25 定位校核成为可能。
- `capabilities.unavailable_operations` 主动公开 `quilt_merge` 不可用，是很值得推广的诚实设计。
