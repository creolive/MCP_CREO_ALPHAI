# MCP_CREO_MechDog v0.13.0 验收报告（第十二轮回归）

- **日期**：2026-11-06
- **被测版本**：**v0.13.0**（`current_version = latest_version = 0.13.0`，release 2026-11-05）
- **一句话结论**：作者响应了上一轮报告——**闭合矩形首壁已通过 `native_planar` + `sheetmetal_planar_wall` 实现**，四条底边全部 `eligible`，连续五轮建议的 `flange_available` 也以 `wall_contour_check` 落地；**但四壁开口箱仍然建不出来**：第 3 道折边被新增的 `adjacent_bend_ends` 预检查无条件拒绝，本版刚加的 `relief` 参数既不能解除该预检查，也未在几何上产生可测差异。另外新平面壁算子的"实测校验"承诺未兑现（`verified:false`、板厚回读为 null）。

## 二、核心问题：`adjacent_bend_ends` 仍锁死四壁盒，`relief` 帮不上忙

### 2.1 正确配方下的完整复现（模型 `acc130_box`）

| 步 | job_id | 操作 | 体积 mm³ | 质心 |
|---|---|---|---|---|
| 建模板 | `9ce3548e32364d0fae8d62329c7256b8` | `native_planar` | — | — |
| 首壁 180×230×1 | `064878e13b8c432ca5a6accbe37b3133` | `planar_wall` | 41 400 | `[90,115,0.5]` |
| 改尺寸 185×232 | `e1a783da2cab48d783b72b58fd31ea59` | `resize` | 42 920 | `[92.5,116,0.5]` |
| 第 1 道围壁 | `7dd07d6656114de0be9c9881335d4ed1` | flange edge 84 (Z=1) h=80 R2.54 Y0.5 | 57 293.61585482141 | z=+10.7058 |
| 第 2 道围壁 | `14c001c91a294042b53a61efcca5fb27` | flange edge 88 (Z=1) | 71 667.23170964286 | `[92.5,116,16.8179]` |
| **第 3 道** | `4e205e1e4f0d4039bf2318692009556e` | flange edge 266 (Z=1, `contour_code=0`) | ❌ 失败 | 回滚干净 |
| **第 3 道 + relief** | `27c0020ffcfd420aba05f18dfc876a57` | 同上 + `relief={rectangular,both,1.0,1.0}` | ❌ **同样失败** | 回滚干净 |

两壁之后剩余 ±X 边 `266 / 268` 的 `wall_contour_query_code` 都是 **0（eligible）**，但两端都紧邻已有折弯，于是被预检查拦下：

> `sheetmetal_flange rejected before create (failure_reason=adjacent_bend_ends): attachment edge 266 has end(s) adjacent to existing bends: end0: neighbour arc edge 174 radius 2.540000 mm within the bend-setback bound 7.081000 mm, bend faces [168]; end1: neighbour arc edge 272 ... bend faces [264]. ... this build implements no corner relief or miter, so the wall is refused before submission. Attach the flange to an edge whose ends are clear of existing bends; four-wall boxes are not supported yet (FEAT-014 stays open).`

### 2.2 新增 `relief` 无法解除预检查

加 `relief={"type":"rectangular","ends":"both","width":1.0,"depth":1.0}` 后，报错**与不带 relief 时逐字相同**（连 bend faces `[168] / [264]` 都不变），说明预检查在建特征之前无条件执行，完全不看 `relief`。而报错自己又说 "this build implements no corner relief or miter" —— **与本版已经提供 `relief` 参数的事实自相矛盾**，容易让使用者以为参数没传对。

### 2.3 `relief` 在干净边上确实被接受，但几何效果存疑

在两端干净的 `edge 60` 上挂带 `relief={rectangular,both,0.5,0.5}` 的折边（`7d70dc1b2fa040afa70b09a84e38f463`）成功，`aliases` 完整回显：

```json
"relief": {
  "type": "rectangular", "ends": "both", "part_thickness_mm": 1.0,
  "corner_overlap_run_mm": 77.46, "depth_covers_corner_run": false,
  "width_at_least_thickness": false,
  "sides": [
    {"side":"side1","relief_type":"rectangular","depth_mm":0.5,"width_mm":0.5,"depth_type":"blind"},
    {"side":"side2","relief_type":"rectangular","depth_mm":0.5,"width_mm":0.5,"depth_type":"blind"}
  ]
},
"relief_element_echo": {"side1": {"type":3,"depth_type":-4,"length_type":-31,"length_mm":0.0,"width_mm":0.5,"depth_mm":0.5}, "side2": {...}}
```

但该模型两壁后的体积是 **71 667.23170964286 mm³**，与**不带 relief** 的同构两壁模型（`14c001c9...`）**逐位完全相同**，即 0.5×0.5 的释放槽没有产生可测的体积变化。作者自己的诊断也给出 `depth_covers_corner_run=false`、`width_at_least_thickness=false`。建议回显"实际切除体积 / 缺口是否生成 / notch 的 bbox"，否则使用者无法判断 relief 到底有没有作用。

> 说明：`relief` 文档已写明"Relief geometry is not verified against the corner overlap"，因此这里不是指控功能造假，而是**缺少可验证的几何证据**，且它对本轮目标（四壁盒）没有帮助。

## 三、次要问题（按影响排序）

### 3.1 🔴 新平面壁算子的"实测校验"恒为 false

`sheetmetal_planar_wall`（2 次）与 `resize_sheetmetal_planar_wall`（1 次）**每次**都返回：

```json
"verified": false,
"thickness_source": "parameter",
"thickness_measured_mm": null,
"thickness_verified": false,
"thickness_body_code": -1,
"body_linked": null,
"problems": ["the sheetmetal gauge was not read back from the wall body (thickness_body_code=-1)"]
```

`resize` 还多一条：`"the resize result reports no gauge read back from the saved wall (thickness_loaded_mm is missing or not finite)"`，且 `thickness_loaded_mm: null`。

工具文档明确写着 "Verification is measured, not echoed ... `thickness_measured_mm`/`thickness_verified` (read back from the wall body)"，并要求使用者以 "`thickness_loaded_mm` and `thickness_measured_mm` must both equal the recorded gauge" 作为验收判据。**实测这两个值恒为 null，作者自己写的判据永远无法满足，而 job 仍报 `status=succeeded`、`saved_file_reloaded_and_verified=true`。** 体积 42 920 与几何 envelope 是对的，但"实测校验"这一层等于失效。建议修好 gauge 回读，或把 `verified` 降级为明确的 `gauge_unverified` 原因码，不要一边 `false` 一边 `succeeded`。

### 3.2 🟠 闭合矩形首壁无法居中，与 TXT §4.1 的坐标不吻合

`sheetmetal_planar_wall` 的矩形固定为 `0..length` × `0..width`，`frame.origin` 恒为 `[0,0,0]`，没有 `origin` / `center` / plane-offset 参数。实测质心 `[92.5, 116, 0.5]`，而 TXT §4.1 明确要求：

> 四角坐标为 (-92.5,-116,0)、(+92.5,-116,0)、(+92.5,+116,0)、(-92.5,+116,0)，实体占 Z=0～1，即质心 `[0,0,0.5]`。

形状/体积/板厚都对，位置整体平移了 `(92.5, 116, 0)`。建议增加 `origin=[u0,v0]` 或 `center=true`，或让 `plane` 接受带 offset 的 dict（顺带修历史项 P3）。

### 3.3 🟠 报错文案把 `native_planar` 用户导向 `conversion` 路径

在 `edge 59` 失败（`656f608d50374d8b975c5e68e2ee2b13`）时，报错整段是：

> ... Frame contract: depth grows one-sided along the signed sketch normal ... (see `wall_contract.wall_face_ids`). To build a horizontal base plate ... sketch on the YZ plane ... call `sheetmetal_wall` ... `examples/sheetmetal_base_yz.json`.

但本模型是 `native_planar` + `sheetmetal_planar_wall` 建的，`aliases` 里**根本没有 `wall_contract`**（只有 `base_planar` / `base_planar_sk` / flange），提示指向不存在的字段，并把人带回上一代单线首壁配方。建议按 `model_type/template` 分派报错。

### 3.4 🟠 一次计划内多个折边的固定 edge id 必然失效

`656f608d...` 一次提交 4 道折边（id 58/59/60/61）：第 1 道成功，第 2 道立刻报 `ProSmtedgeContourGet -8`，因为第 1 道折边后边集从 12 条重排为 28 条，原 id 59 已不存在。文档虽已提示"按当前几何选边，不要用历史 edge id"，但 `execute_plan` 并不提供几何选择器，使用者只能退回"一次一提交 + 每次 inspect"。建议让 plan 内的 `edge` 支持按端点坐标 / 邻接面描述，或在每个操作后自动重解析。

### 3.5 🟡 参数契约与发布说明不一致

- `edge={"id":58}` 被拒：`Reference requires a {kind:...} selection object`；必须写 `{"kind":"edge","id":58}`。报错未说明是哪个参数、需要哪种 `kind`。0.13.0 release notes 写的是"无参数迁移"，建议补记。
- v0.13.0 release notes 通篇是 FEAT-039 曲面链（`surface_trim` / `project_curve` / `surface_offset`，工具 97→100），**完全没有提到**本轮实测到的钣金侧新增算子与 `wall_contour_check` / `adjacent_bend_ends` / `relief`。用户无法从发布说明得知这些能力或边界，建议补一节 changelog。

## 四、建议（按收益排序）

1. 🔴 **让 `adjacent_bend_ends` 与 `relief` 打通，或实现 corner relief / miter / 斜接缝，关闭 FEAT-014**。TXT §4.5 允许"四角可做斜接缝或小开口"作为近似方案，不必追求完美钣金角。只要第 3/4 道能挂上，四壁箱及后续二、三段折边才有继续做的可能。
2. 🔴 **修好 `planar_wall` / `resize` 的板厚回读**，让 `verified`、`thickness_measured_mm`、`thickness_loaded_mm` 名副其实；若短期做不到，请把 `succeeded` 与 `verified:false` 的矛盾显式化为可识别的 warning 码。
3. 🟠 `planar_wall` 增加 `origin` / `center`，支持 TXT §4.1 的中心矩形。
4. 🟠 按模板类型分派 flange 报错，不要在 `native_planar` 模型上引用 `wall_contract.wall_face_ids` 与 YZ 冻结配方。
5. 🟠 `execute_plan` 内支持按几何选择边，避免多折边计划因 ID 重排中途失败。
6. 🟡 `relief` 回显实际切除体积 / notch bbox / 是否覆盖 corner run，让参数效果可验证。
7. 🟡 release notes 补记钣金侧变更与 `{kind:'edge'}` 契约变化。
