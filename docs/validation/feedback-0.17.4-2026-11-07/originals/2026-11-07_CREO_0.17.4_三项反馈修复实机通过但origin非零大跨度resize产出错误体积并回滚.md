## 2. 🔴 本轮核心问题：`origin≠[0,0]` 时大跨度 `resize_sheetmetal_planar_wall` 解出错误体积

### 2.1 复现（最小步骤，Creo 10 / 0.17.4）

```
1) creo_new_sheetmetal(template="native_planar")                 → rev1
2) sheetmetal_planar_wall(185, 232, t=1, plane="XY",
                          direction="positive",
                          origin=[-92.5, -116.0])               → rev2, V=42 920 ✓
3) creo_resize_sheetmetal_planar_wall(feature="base",
                                     length=100.0, width=60.0)  → ✗ 失败并回滚
```

报错：

```text
The resized wall volume 17200.000000 mm3 does not match
length*width*thickness = 6000.000000 mm3
```

原生日志 `jobs/bf2c1b2c4011421495b9d8ca04c49e5d/native.log`：

```text
OPERATION_INDEX=0 INPUT={"feature":"base","length":100.0,"op":"resize_sheetmetal_planar_wall","width":60.0}
PLANAR_WALL_RESIZE feature_id=49 children=0
PLANAR_WALL_GEOMETRY_GAUGE span_mm=1.000000000 requested_mm=1.000000000
PLANAR_WALL_RESIZE axes u=1,v=0 slope=1,-1 offset=0,0 origin=-92.500000000,-116.000000000
ProSecdimValueGet  ×5  /  ProSecdimValueSet ×5
PLANAR_WALL_VOLUME phase=resized measured_mm3=17200.000000000 expected_mm3=6000.000000000 tolerance=0.010000000
BUILD_FAILED=...
PHASE=rollback_to_saved_checkpoint
```

### 2.2 对照矩阵（全部实机，同一 Creo 10 会话）

| # | `origin` | 起始 L×W | 目标 L×W | 实测体积 | 结果 |
| --- | --- | --- | --- | --- | --- |
| 1 | `[-92.5,-116]` | 185×232 | **100×60** | **17 200**（期望 6 000） | ❌ 失败 + 回滚 |
| 2 | `[-92.5,-116]` | 185×232 | 185×232（恒等） | 42 920 | ✅ |
| 3 | `[-92.5,-116]` | 185×232 | 180×230（小改） | 41 400，bbox u `-92.5..87.5` / v `-116..114` | ✅ |
| 4 | `[-92.5,-116]` | 180×230 | **100×60** | **17 200**（与 #1 逐字相同） | ❌ 失败 + 回滚 |
| 5 | `[-92.5,-116]` | 180×230 | **100×200** | 20 000，bbox u `-92.5..7.5` / v `-116..84` | ✅ |
| 6 | **`[0,0]`** | 185×232 | **100×60** | **6 000**，bbox `0..100 / 0..60` | ✅ |

job id 依次为 `bf2c1b2c…` / `899bca67…` / `8563632a…` / `fff144ca…` / `23612452…` / `4a0fbe6d…`。
模型：`b57f7064f33c4af9854fabddb7a048a1`（`origin≠0`）、`4c38b0f2cfbf42aaacdfdf761ba49297`（`origin=0`）。

### 2.3 规律与机制推断（**推断，非已证实**）

- 失败只在 **`origin≠[0,0]` 且目标尺寸明显小于原点偏移量**时出现（#1/#4 `width=60 < |origin_v|=116`；#5 `width=200 > 116` 成功；#3 小改成功）。
- 实测体积 `17 200 = 100 × 172`，而 `172 = 232 − 60`（232 为初始宽度，60 为目标宽度）；从 180×230 起也仍是 17 200，说明结果与**当前**尺寸无关，只由目标尺寸与 origin 决定。这与"某个草图尺寸被当成从上边缘出发的位移、解算后矩形跨距变成 `2×|origin_v| − width`"一致，但本报告不将其作为结论。
- 原生日志显示 `dimension_count=5`，且 `ProSecdimValueGet/Set` 各 **5 次**——即驱动把该截面的 5 个尺寸**全部重写**，而不是只改两个长度尺寸。0.17.0 引入 `origin=[u0,v0]` 后，居中壁的截面多了与原点位置相关的尺寸；合理怀疑是尺寸 ID 映射没有区分"长度尺寸"与"定位尺寸"，当新长度使另一条边越过草图原点时求解器翻转到另一组解。**建议作者优先核查 `native_planar_wall.cpp` 的 5 个 secdim 目标值计算。**
- 正面评价：体积守卫确实拦住了错误几何（没有把 17 200 mm³ 的错壁提交），`rollback_succeeded=true`、`inspection_source=rollback_verified`，之后 #3/#5 仍能在同一模型上继续成功建模。**是"功能不可用"，不是"静默产出错误模型"。**

### 2.4 影响

- 直接冲突 0.17.2 的 FEAT-058 台账「100×60×1、185×232×1 与保存重载 77 项检查 0 失败」——该矩阵大概率只在 `origin=[0,0]` 下跑；而 TXT 任务与 `out4` **必须**用 `origin=[-92.5,-116]` 居中。
- 任何"先建标准壁再改成目标尺寸"的自动化流程，在居中壁上会随机失败且报错只给体积数字，不提示与 `origin` 相关。

### 2.5 建议

1. 在 `origin≠[0,0]` 下补齐 resize 矩阵，特别是目标尺寸跨过 `|origin|` 的用例；把 5 个 secdim 的目标值写入失败诊断（当前日志只有 `ProSecdimValueSet(...)=0`，看不到设成了什么值）。
2. 体积不符时，在报错中附带**解析出的实际 envelope**（u/v/n min-max），便于一眼看出是哪一轴解错；或提供 `strict_origin=true` 在尺寸会跨过草图原点时提前拒绝。
3. 若短期无法修，至少在 `creo_resize_sheetmetal_planar_wall` 文档中明示"`origin≠[0,0]` 时大跨度缩小不受支持"。

## 3. 次要问题（按优先级）

### 3.1 🟠 板厚"字段矛盾"仍字面存在，只是被解释清楚了

0.17.4 的处理是"保留原生 API 原始字段 + 新增 3 个来源说明字段 + 权威判据为 `thickness_validation`"，路线合理、实测有效。但同一 `planar_wall` 块里仍然是：

```json
"verified": true,
"thickness_verified": false,
"thickness_measured_mm": null,
"thickness_body_code": -1
```

旧客户端 / 下游自动化如果按名字读 `thickness_verified`，仍会误判"板厚未验证"。建议补一个单一权威布尔（如 `thickness_verified_effective`），或把旧字段改名为 `thickness_api_verified` 并标注 deprecated；否则请在 `creo_capabilities` 的 references 段用醒目方式写明优先级。

### 3.2 🟠 失败回执里 `feature_id_unchanged=true` 与两个 `null` 并存

`bf2c1b2c…` 失败的 `planar_wall` 块：

```json
"feature": null, "feature_id": null, "feature_id_before": null,
"feature_id_unchanged": true,
"problems": ["the native result carries no feature id", ...]
```

无任何证据却声称"未改变"，容易让调用方误认为 resize 保住了特征身份。建议失败时置 `null` 或 `false`。同一块里 `thickness_loaded_validation` / `thickness_loaded_api_scope` 等新字段也完全缺失（成功时都有），建议显式置 `null` 以保证回执 schema 稳定。

### 3.3 🟡 最近候选边只在报错字符串里，未结构化

1.3 的 5 条候选全部嵌在 `message` / `result.message` 的文本中，客户端只能正则解析；而 `failed_operation.message` 已 `message_truncated=true`（截在 `id=92` 处），精简视图看不到完整列表。建议同时给结构化字段，如 `nearest_edges:[{id,endpoints_mm,endpoint_errors_mm}]`、`tolerance_mm`、`candidate_limit`，并保证 compact 视图不截断关键信息。

### 3.4 🟡 空预览的判定证据没有投影到回执

三例 `skipped_no_geometry` 的 `preview.datum_display` 均为 `model_type="unknown"` / `applicable=false` / `attempted=false` / `hide_status="not_attempted"`。原生日志确有 `ProSolidFeatVisit(...)=0`，但回执看不出"特征查询成功且确认无非基准特征"这一守卫真的跑过。建议加 `preview.empty_geometry_basis`（`feature_visit_code` / `non_datum_feature_count`），与 0.17.4 的判定条件对齐。

### 3.5 🟡 陈旧 startup 快照仍会声称 `ready / connected=true`

本轮开局：`creo_startup_status` 返回 `state=ready, connected=true, verified_at=07:18:57, stale=true`，但同一时刻 `creo_session_status` 为 `connected=false, toolkit_code=-4, worker_exit_code=20, creo_process_snapshot.processes=[]`（Creo 已退出）。`retry=true` 首次 `probe_timeout`，待新 Creo 进程 07:25:08 启动后才 `connected`。建议在 `stale=true` 时把顶层 `state/connected` 标为 `unknown` 或直接展示"快照过期、未验证"，避免只读快照被误当成实时连接状态。

### 3.6 🟡 钣金增料封堵缺 Creo 10 原生证据

```text
SHEETMETAL_SOLID_ADD_UNSUPPORTED: Creo rejects an extrude add that merges solid
material into a sheetmetal body (ProFeatureWithoptionsCreate returns -1,
measured on Creo 12.4.0.0 with and without overlap). ... Blocked operations: boss_add
```

该拒绝发生在**提交前**（直接返回工具错误，无 job_id），因此本机 Creo 10 从未真正尝试过 `add`，无法判断 10 上是否也失败；文案只引用 Creo 12.4.0.0。建议提供显式 opt-in（如 `allow_sheetmetal_solid_add=true`）用于跨版本实测，或在 Creo 10 上补一次真原生尝试并回读 `toolkit_code`。这是 `out4` 报告第 1 条建议至今未闭环的关键。
