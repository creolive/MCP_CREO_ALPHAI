## 三、残留问题

### 3.1 🔴 同一回执块内 `verified` 与 `thickness_verified` 语义冲突

居中首壁的 `planar_wall` 块：

```json
"thickness": 1.0,
"thickness_measured_mm": null,
"thickness_verified": false,
"thickness_body_code": -1,
"thickness_geometry_span_mm": 1.0,
"thickness_validation": {
  "status": "verified",
  "source": "geometry_normal_span",
  "value_mm": 1.0,
  "reason": null,
  "context": "current_plan"
},
"problems": [],
"verified": true
```

0.17 用"几何法向跨距"兜底，把 `thickness_validation.status` 推到 `verified`、`verified` 推到 `true`、`problems` 清空——方向是对的，也如实标注了 `source`。**但工具文档仍写着** "read … `thickness_measured_mm`/`thickness_verified` (read back from the wall body)"，而这两个字段现在**仍然是 `null` / `false`**：

- 严格按文档读 `thickness_verified` 的使用者会认为"板厚未验证"，而 `verified:true` 又表示整体通过；
- 两个结论同时出现在一个块里，谁优先没有说明。

建议二选一：① 把几何兜底结果也写入 `thickness_measured_mm=1.0`（保留 `source=geometry_normal_span` 区分来源），让旧判据继续有效；② 明确文档："`thickness_verified` 仅表示原生 API 读回；几何兜底请看 `thickness_validation`"，并在 `thickness_verified:false` 旁加一句 `reason: thickness_api_unavailable, fallback: geometry_normal_span`。

另外 `thickness_body_code=-1` 说明原生板厚读取仍不可用，`missing_api` 的根因没有变化，只是有了几何兜底。

### 3.2 🟠 `edge_geometry` 端点会随前序折边漂移，四壁坐标无法一次写死

实测：首壁时 X 侧顶边端点是 `[92.5,-116,1]..[92.5,116,1]`；做完 Y=±116 两道壁后，同一位置的边变成 `[92.5,-112.46,1]..[92.5,112.46,1]`（`116-3.54`，折弯让位）。用首壁原始端点提交（`d2ce72a8…`）被拒绝：

> `edge_geometry endpoints [92.500000,-116.000000,1.000000] and [92.500000,116.000000,1.000000] matched none of the 248 straight model edges (tolerance_mm=0.000001); edge ids and geometry change when the model rebuilds, so re-read creo_inspect_model edges[].start/end and pass current coordinates`

诊断本身很好（给出匹配数、容差、并明确要求重读）。但使用后果是：**仍然不能把"185×232 底板四角"这类设计坐标一次写进一条 4 道折边的计划**，必须按"折边→重读边→再折边"分段。这也意味着 `out3` 这类按 TXT 坐标驱动的任务，无法把 §4.2 四壁写成单个原子计划。

建议：① 支持 `expected_endpoints` + 方向/中点 ± 容差吸附（允许端点沿边滑动匹配同一条直线）；② 或允许 `edge_geometry` 用"所在的壁面 + 边序号/相对位置"表达；③ 至少在工作流文档里写明"多道相邻折边必须分段提交，每次重读端点"。

### 3.3 🟠 `miter_cuts` 的 width/offset 与实际切除量仍未量化

0.17.0 / 0.17.1 未涉及此项。本轮沿用 `width=1.0`（offset 默认 1.0），四壁+框边均成功，但**仍未做不同 width/offset 的对照实验**，不声称已验证切除量。建议回显：每道壁实际 span、miter 缺口 bbox、角部间隙、以及 width/offset 变化时的体积差。

### 3.4 🟡 未覆盖项

- TXT §4.4 第三段止口（内缘向上 8 mm）本轮未做；§4.5 角部 0.2 mm 接缝未处理。
- `end_trim_mm` 本轮未复测（0.15.0 记录为"仍被忽略"）。

## 四、正面确认（值得写进 release notes 的部分）

1. **`origin` 语义正确、可 resize 保持**：`origin` 回显、`envelope.u/v` 与 body bbox 三处一致，直接对上 TXT §4.1。
2. **`edge_geometry` 无向端点匹配可用**：同一计划内第 2 道跨 ID 重排成功，容差 1e-6 未误配。
3. **板厚几何兜底**：`thickness_geometry_span_mm=1.0` + `source=geometry_normal_span`，至少让 `verified` 能取到 true，且来源可追溯。
4. **诊断质量继续提升**：`failed_operation` 带 index/op/label/stage；`edge_geometry` 失配给出匹配数与重读建议；四壁遇 `adjacent_bend_ends` 时明确指向 `miter_cuts`。
5. **新增 `terminal_effect` 逐域回滚确认**（managed_model / component_bindings / external_outputs 三域均为 `rolled_back/confirmed` 或 `no_effect/confirmed`），比单一 `rollback_succeeded` 更可信。
6. `get_job(wait_seconds)` 长轮询（本轮 3~23 s 返回终态）与 `sections` 精简回执继续好用；`preview` 全绿。

2. 🟠 让 `edge_geometry` 支持端点吸附/相对定位，使四壁能在一次计划内提交（§3.2）；否则请在文档中固化"分段提交"工作流。
3. 🟠 量化 `miter_cuts`（§3.3）。
4. 🟡 继续推进 TXT §4.4 第三段止口与 §4.5 角部接缝，形成完整三段折边闭环。
5. 🟡 `end_trim_mm` 若确实未实现，建议在 schema 上直接拒绝并说明，而不是接受后忽略。
