## 根因与修复

外部现象（Creo 9 / 服务 0.5.1）：`revolve.axis` 传 `{"entity":"ax"}` 时作业 message 为 `[json.exception.out_of_range.403] key 'kind' not found`。链路：`RevolveOp.axis` 此前为 `dict[str,Any]|None`，无 `kind` 键的字典不触发通用引用校验（该遍历只检查含 `kind` 的字典），原样序列化进入原生执行器；`extrude_or_revolve` 以 `contains("axis")` 选用外部轴分支后 `resolve()` 用 `at("kind")` 取键，nlohmann 抛出异常，被顶层 `catch(const std::exception&)` 直接以 `what()` 作为作业 message 透出（generic.cpp:3917 一带）。

修复（两层）：

1. Python 入口预检：`src/creo_mechdog/references.py` 新增 `RevolveAxis`（`normalize_revolve_axis` + `WithJsonSchema`），`RevolveOp.axis` 与 `creo_revolve.axis` 参数改用该类型。合法形式只有裸引用 `{"kind":"datum_axis_feature","label":...}`（标签需先于回转创建）与 `{"kind":"axis","id":N}`（非负整数）；axis_pattern 专用的 `datum_feature` 兼容别名不适用于回转。拒绝时错误含可操作示例（含"省略 axis 用截面构造中心线"），pydantic 错误位置给出字段路径（execute_plan 为 `operations[N].axis`，独立工具为 `axis`）；校验在 `validate_operations` 内完成，先于 `bridge.toolkit_lock` 与作业创建，故不派发原生作业。`server.py` 仅改参数注解与描述。
2. 原生边界防御：`native/generic.cpp` 新增 `validate_revolve_axis()`，在 `extrude_or_revolve` 起始、任何取键访问之前拒绝非法结构（非对象/空对象、缺 kind 或 kind 非字符串、axis 缺/非法 id、datum_axis_feature 缺/空 label、其他 kind），抛出带可操作示例的 `std::runtime_error`，经既有失败路径形成结构化作业错误（message、failed_stage、failed_operation_index），不再透出裸 nlohmann 文本。

三态语义统一（核对结论与决定）：工具 schema 接受 None（null）与省略，二者经 `exclude_none` 序列化后原生请求不含 `axis` 键，`contains("axis")` 为假，走草图中心线分支——两入口行为本已一致，予以保留并在文档言明；空对象 `{}` 此前会进入外部轴分支并抛裸异常，按验收表归入非法输入（缺 kind），入口直接拒绝、原生侧同样拒绝。`{"entity":"ax"}` 不做任何静默猜测。
