## 1. 好消息（本轮最重要）：种子闸门完整落地，且我做了双向实测

我 10-31 报告 §2 指出"`package_seeds.py` 只打印提示、RELEASING.md 无检查项、archive 路径零测试 → 必然再犯"。0.10.1（DEV-053 P04）把三条建议**全部实现**，且实现方式比建议更完整：

| 我上轮的建议 | 0.10.1/0.11.0 的实现 |
| --- | --- |
| ① `package_seeds.py` 自动回写或断言 exit 1 | **`tools/package.py` 必填 `--seed-archive`**（`required=True`），缺参/失配 exit 非零且**不产生源码 ZIP** —— 比回写更强：源码包根本无法脱离配套种子包生成 |
| —（未提但需要）单一可信来源 | 新增受信记录文件 **`docs/seed_package.json`**（`compatible_server_version` + `seed_archive_name` + `seed_archive_sha256`），`seeds.py` 里手抄的 `expected_digest` 字符串**已删除**，改为 `validate_seed_archive()` 比对受信记录 |
| ③ 补一条走 `archive_file=` 的测试 | `tests/unit/test_seed_distribution.py`、`tests/unit/test_release_integrity.py` 落地 |

**本机双向实测**（用 0.11.0 官方种子包 + 篡改副本，只调 `validate_seed_archive()`，不执行安装写入）：

顺带确认安装路径的纵深防御也已到位：临时目录安装、ZIP CRC 全检、成员路径安全检查（拒绝绝对路径/`..`/反斜杠）、`_validate_library()` 逐种子哈希核验后才 rename 落位、**已存在的 `seed_library/` 会被拒绝覆盖**而不是静默替换。0.8.1→0.9.0 那类"清单/摘要与发布物脱节"的事故，从机制上没有复发通道了。

## 3. 上轮建议②仍未实现：盲孔 `depth` 口径仍无机器可读标记

0.10.0 把 custom 盲孔 `depth` 从"到肩/座面"改为"到钻尖"（`PRO_HLE_DEP_SHOULDER_DIM_SCHEME` → `PRO_HLE_DEP_TIP_DIM_SCHEME`），我在 10-31 报告 §3 建议在响应中加 `depth_basis`/`depth_scheme_query` 字段让重放工具自证口径。本轮复查 0.11.0 源码：`src/`、`server.py`、`native/*.cpp` 中 `depth_basis` / `depth_scheme` 仍**零命中**。

风险不变：按存储 JSON 计划重放的客户端，在 0.10.0 前后提交同一份 hole 请求会得到**深度不同**的孔（差约 0.3×基本径），响应中无字段可察觉。这是 BUG-080 的同构问题，而 BUG-080 的修复范式（`length_unit` + `*_raw` 原始读数）已经存在于装配检查里——照搬到 hole 结果即可，成本一条字段。
