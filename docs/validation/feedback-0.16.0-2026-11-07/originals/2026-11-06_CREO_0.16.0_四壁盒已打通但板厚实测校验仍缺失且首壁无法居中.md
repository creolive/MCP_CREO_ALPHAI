## 三、残留问题（按优先级）

### 3.1 🔴 板厚"实测校验"仍缺 API，`verified` 恒 false 但 job 报成功

`sheetmetal_planar_wall` 本轮仍返回：

```json
"verified": false,
"thickness_measured_mm": null,
"thickness_verified": false,
"thickness_body_code": -1,
"thickness_validation": {
  "status": "unverified", "source": "missing_api", "value_mm": null,
  "reason": "thickness_api_unavailable", "context": "current_plan"
},
"problems": [
  "the sheetmetal gauge was not read back from the wall body (thickness_body_code=-1)",
  "the current plan gauge validation is 'unverified' (thickness_api_unavailable)"
]
```

0.15.0 FEAT-058 把"读不回"从裸 `null` 改成了**可解释的 `unverified/missing_api` 双上下文回执**，这是明确的进步，值得肯定；但工具文档仍写着 "Verification is measured, not echoed … `thickness_measured_mm`/`thickness_verified` (read back from the wall body)"，且 `resize` 的验收判据要求 `thickness_loaded_mm`/`thickness_measured_mm` 等于板厚——**这些判据在当前实现下永远无法满足，而 `status=succeeded`、`saved_file_reloaded_and_verified=true` 照常给出**。

建议二选一：① 补齐原生板厚读取 API（或已核对的几何兜底，0.15.0 已为纯矩形留了口子）；② 若确实无 API，请把文档里的"实测校验"措辞改为"参数申报 + 体积/包络实测"，并让 `verified` 只在真正回读成功时为 true，避免 `false` 与 `succeeded` 长期并存。

### 3.2 🟠 首壁仍无法居中，与 TXT §4.1 坐标不吻合

`creo_sheetmetal_planar_wall` 的 schema 本版仍只有 `length/width/thickness/plane/direction`，矩形固定 `0..length` × `0..width`，`frame.origin` 恒 `[0,0,0]`。实测 `center_of_gravity=[92.5,116,0.5]`、包络 `X 0..185 / Y 0..232 / Z 0..1`，而 TXT §4.1 要求 `X=-92.5..+92.5`、`Y=-116..+116`、质心 `[0,0,0.5]`。形状与体积正确，整体平移了 `(92.5,116,0)`。

0.15.0 把 "R10 首壁 origin 与计划内几何选边" 列在"仍未验证/开放"，本轮实测确认 origin 仍未实现。建议加 `origin=[u0,v0]` 或 `center=true`。这是 `out3`（按 TXT 完整重建）继续推进的前置条件之一。

### 3.3 🟠 `miter_cuts` 的 width/offset 与实际切除量未量化

作者在 release notes 里已诚实标注"未量化"。本轮实测：`width=1.0` 时壁长由 185 → 181.46、232 → 224.92（角部让位），四壁终态 V=106 499.1571758941。**本轮未做不同 width/offset 的对照实验，因此不声称已验证切除量**。建议回显：每道壁的实际 span、miter 缺口 bbox、角部间隙尺寸，以及 `width/offset` 变化时的体积差；否则使用者只能盲选参数。

### 3.4 🟡 计划内多道折边仍需外部逐次重查边

本轮 4 道折边 + 1 道框边共 5 次独立提交，每次都要重新解析 inspection 的端点坐标选边（第 1 道后边集 12→28 条，第 3 道后又重排）。0.15.0 的 R10 仍开放，本轮**没有**专门复测"一次 plan 提交 4 个固定 id"，因此不断言该能力已坏；但当前可依赖的工作流仍是逐次提交。建议 plan 内 `edge` 支持按端点坐标/邻接面描述并逐 op 重解析（与 0.15.0 曲面引用契约一致）。

### 3.5 🟡 其他

- `end_trim_mm` 在 0.15.0 官方实机记录中"仍被忽略"，本轮未复测，按作者结论保持关注。
- 四壁 body bbox 上界 `Z=80.1`（edge bbox 为 80.0），0.1 来自折弯外扩；TXT §4.2 要求总高 80，属可接受近似，但建议在交付说明里显式标注。
- 0.16.0 release notes 说"自由端带/不带 `miter_cuts` 体积差为 0"，本轮前两道未带 `miter_cuts`、后两道带，与之一致；未单独做自由端对照。

## 四、建议（按收益排序）

1. 🔴 补齐或正式降级板厚实测校验，让 `verified` 与 `succeeded` 语义一致（§3.1）。
2. 🟠 `planar_wall` 增加 `origin` / `center`，支持 TXT §4.1 中心矩形（§3.2）。
3. 🟠 量化 `miter_cuts`：回显 span / 缺口 bbox / 角部间隙 / 体积差，并补不同板厚、半径、width/offset 的实机矩阵（§3.3）。
4. 🟠 plan 内支持按几何选边、逐 op 重解析（§3.4），让四壁盒能一次提交。
5. 🟡 继续把四壁链路推到 TXT §4.4 第三组止口、百叶、格栅、门板与装配；本轮只验证到第二组框边中的一条，完整三段折边闭环未做。
6. 🟡 在 release notes / 工具文档中明确 `miter_cuts` 与 `relief` 的分工（本轮报错已讲清，建议同步写进工具说明的显眼位置）。
