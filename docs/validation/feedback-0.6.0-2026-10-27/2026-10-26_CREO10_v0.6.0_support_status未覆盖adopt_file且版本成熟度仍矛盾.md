## 4. 发现的问题

### 4.1 【P2，连续第三轮】`release_status` 与 `is_prerelease` 自相矛盾

同一份 `creo_capabilities`：

- `update.is_prerelease: false`（0.5.2 起即正式版）
- 底部 `release_status: "pre-release candidate; requested complete coverage has not been achieved"`

0.5.2、0.6.0 两轮验收均提出，仍未统一。建议：正式线改为如 `"stable patch/minor line; coverage still expanding"`，或让 `is_prerelease` 反映真实状态。**该类字段是外部判读成熟度的第一入口，两值相反会直接影响取舍**。

### 4.2 【P2，与上轮同类】`support_status` 未覆盖 `creo_adopt_file`

- `families.file_adoption` 已列出 `creo_adopt_file`；
- 但顶层 `support_status` 只有 `adoption`（tool: `creo_adopt_current_model`），**没有 file_adoption 条目**，且 `adoption.summary` 未提及"按路径/批量"能力。

上轮验收曾指出 `support_status` 未随工具更新（当时是 assembly_checks 陈旧），本版修好了 assembly_checks 却又漏了 `creo_adopt_file`——说明**该表缺少发布检查项**。建议把"support_status 覆盖所有 delivered families"列为发版前 checklist 项（可用脚本比对 families 与 support_status 的差集）。

### 4.3 【P2，上轮 P1-3 残余】约束快照仍无回放契约

- FEAT-008 补充了"约束数字码及符号名"（`type_name`），但 `assemble_component.constraints` 仍是 `additionalProperties: true` 的自由对象；
- `creo_inspect_session_assembly` 返回的 `asm_reference/comp_reference(item_id/item_type/occurrence_path)` 仍无公开映射到 `constraints` 入参的字段定义。

**影响**：重建装配仍只能 `placement: fixed`，约束语义（mate/align 的几何依附）丢失。建议下一步给出 `constraints` 的 schema（或提供 `assemble_from_inspection` 桥接）。

### 4.4 【观察】内部 sidecar 写失败未在结果中体现

`mx_down` 探针作业的 `native_log_tail` 末尾出现：

```
INSPECTION_SPLIT_FAILED=Cannot write the inspection sidecar file
```

但该作业的 API 结果仍返回了 `inspection_ref`（708,437 B）。两种可能：内容寻址下文件已存在（复用了先前同名 sidecar），或写入失败被吞。**对拒绝项无害**；但若发生在**成功收养**项上，可能导致快照缺失而结果无感。建议：sidecar 写失败时在结果中显式标注（如 `inspection_ref: null, inspection_note: "sidecar write failed"`），或确认失败原因（本轮路径含中文与长目录，建议排查路径编码/长度）。
