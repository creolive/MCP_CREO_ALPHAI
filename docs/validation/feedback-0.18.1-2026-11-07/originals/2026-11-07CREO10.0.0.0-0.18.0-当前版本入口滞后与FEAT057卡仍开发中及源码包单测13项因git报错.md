## 四、本轮问题明细

### P1-1｜发布规范的「当前版本」入口滞后整整一版

`docs/DEVELOPMENT.md:3`、`README.md:5`、`version.py`、`docs/RELEASE_NOTES_0.18.0.md`、`docs/validation/RELEASE-0.18.0.md`、Release body 全部已同步到 **0.18.0**。唯独：

```text
docs/development/RELEASING.md:18
当前版本为 0.17.4（2026-11-07 [DEV-072] … 离线门禁 2744 项、原生组合编译通过 …）
```

全文 `grep -c "0.18.0" = 0`。`RELEASING.md` 是发布规则的权威入口，且第 8 步要求「当前版本说明的标题与正文、开发入口、主台账、工作卡首页及远端 Release 必须一致」「不允许旧版本遗留的『未发布』描述继续出现在当前入口」。这里不是措辞问题，而是**规则文档自身声明的当前版本是错的**；2744 还与 0.17.4 的 2762、0.18.0 的 2826 形成三个不同数字。

建议：把 0.18.0 沿革段加入第 18 行（门禁 2826、工具 100→102），并让第 8 步的清单显式包含 `RELEASING.md` 的「当前版本为 X」行，避免下次再次漏改。

### P1-2｜`FEAT-057` 卡触发第 8 步明文「视为未通过」

`RELEASING.md:39`（第 8 步）原文：

> 「本版交付 ID」同时包含功能/接口卡（FEAT）：本版新增或扩展的能力，其 FEAT 卡首页状态与目标版本必须与 `capabilities.py`、README 和版本说明一致；**能力已发布而卡仍写"开发中/未排期"视为本项未通过**（DEV-062，对应 0.11.0 反馈 F02 §4）。

0.18.0 已发布 `creo_get_mass_properties`（README、版本说明、Release body、`capabilities.py` 的 `mass_properties` 能力族均确认），但：

```text

docs/work-items/FEAT-057.md 卡首页
状态：开发中（工具已随 0.18.0 集成；离线数值守卫子项完成；材料重心及契约待收口）。目标版本：未排期。
```

同一批的 `FEAT-063`（L305「已交付 0.18.0」/ 目标 0.18.0）与 `FEAT-035`（L335「标准孔定义随 0.18.0 集成」）都已正确回填，说明是**逐 ID 执行漏项**，不是规则缺失。`FEAT-059` 亦为「部分交付…目标版本 未排期」，按 0.17.4 新增的 DEV-072 写法应写成「已交付 0.18.0 子项；<具体余项> 未排期」。

建议：FEAT-057 状态改为「已交付 0.18.0（只读工具）；密度/单位/装配汇总契约待收口」，目标版本 0.18.0；FEAT-059 同步具体交付版本。并把这一步纳入发布前置的机械核对（按 ID 抓第 3、4 列与卡首页）。

### P1-3｜官方源码包解压后单测 13 ERROR（连续第二版复现）


调用链与 0.17.4 完全相同：`tests/unit/test_t07_preview.py:27` → `tools/test_t07_preview.py:340` `Acceptance.__init__` → `local_provenance()` → `git ls-files(check=True)` → `CalledProcessError 128 / not a git repository`。官方 `source.zip` 只有 `.gitattributes`/`.gitignore`/`.github/`，不含 `.git/` 元数据。

`tools/dev_check.py:254` 会调 `tools/test_unit.py` 做全量门禁，而 Release body 宣称「全量单测 2826 项 0 失败 0 错误」——该结论只在开发者 git 工作树成立，与 `RELEASING.md` 第 5 步「从新目录解压并运行适用检查」的意图存在覆盖缺口。`DEV-066` 已登记同类根因（「tools/ 离线证据工具硬依赖 PATH 中的 git」）却仍是「待规划（仅登记，未实现）」。

建议：让 `local_provenance()` 在非 git 环境下降级为目录遍历 + `git_unavailable` 标记，或让单元测试注入 provenance；把「分发包解压后跑全量」作为独立门禁项，并在 Release 说明中区分「git 工作树全量」与「source.zip 解压全量」。

> 本机 `tools/test_unit.py` 全量历史上会因宿主删除守卫干扰挂起，本轮**未复现 2826 项全量**，只跑了 196 项子集 + 59 项 t07 专项；不宣称全量通过，也不据此断言作者门禁结论有误。
