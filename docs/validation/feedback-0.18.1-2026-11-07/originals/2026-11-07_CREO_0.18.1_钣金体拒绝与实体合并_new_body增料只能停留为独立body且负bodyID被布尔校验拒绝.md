# MCP_CREO_MechDog 0.18.1 反馈：钣金体拒绝与实体合并，new_body 增料只能停留为独立 body

- 日期：2026-11-07
- 目标版本：**0.18.1**（上游最新，GitHub tag v0.18.1）
- 本机实机版本：**0.18.0**（`creo_capabilities.version=0.18.0`，`update.latest_version=0.18.1`，未装机）
- Creo：Parametric 10（`creo_release_numeric=42`），单位 mm
- 证据边界：所有**实机**结论均在 0.18.0 / Creo 10 上取得；对 0.18.1 的结论来自 **v0.18.1 tag 源码逐字核对**与 release notes，未装机实跑，已明确标注。

---

## 1. 结论先行

> **0.18.1 没有带来任何钣金能力。** release notes 只修 `FEAT-057` 质量属性回执契约与 `DEV-073` 台账，工具数仍 102。配电箱任务因此**不能靠升级版本一体成形**。
>
> 但我实机验证了一条 TXT §393 明确允许的近似路径（`拉伸/切除/布尔形成近似`），把此前被 `SHEETMETAL_SOLID_ADD_UNSUPPORTED` 完全挡住的 §7 凸台、§8 铰链座/销、§11 门板耳/短孔**真正补进了模型**，并落地为 `out5/`。代价是：新增特征只能作为**独立 body**存在，无法与钣金主体融合。

## 3. 根因（含 0.18.1 源码核对）

### 3.1 Python 层：负 body id 被一律判为非法

`src/creo_mechdog/schema.py` `BooleanOp.valid_bodies`：

```python
refs = [*self.targets, *self.tools]
if any(
    r.get("kind") != "body" or type(r.get("id")) is not int or r["id"] < 0 for r in refs
):
    raise ValueError("Explicit body IDs are required")
```

`creo_inspect_model(section="bodies")` 却如实回显 `native_planar` 钣金主体为 **负 id**（实测 `-5778`）。于是「工具告诉你选哪个 body」和「工具允许你选哪个 body」自相矛盾。

**v0.18.1 tag 源码核对**：上述 `r["id"] < 0` 条件与错误信息**逐字未变**，因此 #4 在 0.18.1 上必然同样发生（此项为源码推断，非实跑）。

### 3.2 Creo Toolkit 层：钣金体不能吸收实体材料

改用 `conversion` 模板后拿到正 id=51，两个方向的 `union` 都返回 `-1` 并回滚。这与 `src/creo_mechdog/sheetmetal.py` 里 `BUG-046 / DEV-051 T04` 的注释一致：

> "the same add with `new_body=true` succeeds as a separate solid body (+500 mm3, **no merge**). Adding material to the sheet therefore has to go through the wall or flange operations."

**v0.18.1 tag 源码核对**：`SOLID_ADD_UNSUPPORTED` 与 `solid_add_on_sheetmetal_problem` 逐字未变，`new_body=true` 仍只被描述为「create a separate solid body」。即作者**已知**这条路只到"独立体"为止，但没有提供任何把它接回钣金体的算子。

### 3.3 附带发现：`thin` 增料的归属是隐式且易误解

`sheetmetal.py` 的封堵只拦截 `extrude` 且要求 `thin is None`；带 `thin` 的 add 被放行。实测它**静默并入"最近一次创建的辅助实体"**（body 142），而不是钣金主体，回执里也没有 `merged_into_body_id`。若模型里没有辅助实体，行为未测。这对"百叶薄壳/冲压凸台"这类最需要它的场景是很大的歧义。

用上述路径在**真实 out4 模型**上继续编辑，全部 26 个操作提交成功、全部 `saved_file_reloaded_and_verified=true`：

## 5. 建议作者修复（按优先级）

1. **A1（核心）** 提供钣金体附着增料算子：`sheetmetal_solid_add` / `sheetmetal_emboss`，或让 `boolean_bodies` 能合法引用钣金体（接受负 id、原生层用 `ProSolidBody` 选择而非 `ProFeatureWithoptionsCreate` 的 merge 路径）。这是百叶罩壳、冲压凸台、铰链座一体成形的唯一缺环。
2. **A2** 至少放宽 `r["id"] < 0` 的判定：把「负 id 是合法 body 但当前布尔不支持」与「引用格式错误」分成两条错误信息，并在 `bodies` inspection 里给出 `boolean_referenceable` 标记。
3. **A3** 参数校验失败时不要倾倒整个 `list[tagged-union[...]]`（0.18.0 已反馈，0.18.1 未修，本次 #4 再次复现，输出 60+ 操作类型名）。
4. **A4** `thin` / `new_body=false` 的 add 在钣金件上的归属 body 必须在回执中显式给出 `merged_into_body_id`；若未合并则明确 `bodies_before/after`。
5. **A5** `solid_add_on_sheetmetal_problem` 只检查 `op=="extrude"`，`revolve(add)` 不受约束但原生行为未定义；建议统一契约并补实机证据。
6. **A6** 延续项：钣金同段多边连续折边 / 共享角部 / corner relief；参数化百叶与环扇格栅算子；`origin≠[0,0]` 大跨度 `resize_sheetmetal_planar_wall` 产出错误体积（0.17.4、0.18.0、0.18.1 连续三版未修）。
