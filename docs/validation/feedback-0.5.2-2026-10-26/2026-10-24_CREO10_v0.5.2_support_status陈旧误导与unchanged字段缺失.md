## 4. 发现的问题

### 4.1 【P1】`support_status` 陈旧：FEAT-045 已交付却仍标 "planned"

`creo_capabilities` 顶层 `support_status` 当前内容：

```json
"assembly_checks": {
  "status": "planned",
  "tracking": "FEAT-045",
  "summary": "read-only external assembly inspection (component tree, transforms) is not available yet; assemblies open for display only"
}
```

**但** `creo_inspect_session_assembly` 自 **0.5.0** 已交付并在本轮可用（families.session_assembly.enabled = true，实测返回 8 组件 + 4x4 变换 + 约束快照）。

**影响**：`support_status` 是 agent 规划能力时的第一手依据（我在 2026-10-22 的装配编辑建议中正是建议"直接依据该表规划，不必试错"）。陈旧条目会让 agent **跳过实际可用的装配检查能力**，甚至重复向作者提"请实现 FEAT-045"。

**建议**：
1. 将 `assembly_checks.status` 改为 `supported`（工具 `creo_inspect_session_assembly`），summary 改为"只读外部/托管装配检查：组件树、约束快照、4x4 变换；不加载、不收养、不编辑"；
2. 把 `support_status` 纳入发布检查清单（每条新工具交付时同步更新）；
3. 顺带核对其他条目：`adoption` 的 summary 未提及 0.5.x 新增的 `prepare` 模式与"文件源 inspect→apply"；`support_status` 也缺 `session_erase` / `registry_maintenance` 两项已交付能力。

### 4.2 【P3】版本成熟度自相矛盾

同一份 `creo_capabilities` 返回中：

- `update.is_prerelease: false`（0.5.2 为首个正式版）
- 底部 `release_status: "pre-release candidate; requested complete coverage has not been achieved"`

两者对"是否 pre-release"给出相反答案。建议统一：若 0.5.2 定位为正式版，将 `release_status` 改为如 "stable patch line; coverage still expanding"；若仍属预发布，`is_prerelease` 应保持 true。

### 4.3 【P2】BUG-030 的 `unchanged` 字段未落地到结果

见 §3.3。若该标记仅适用于几何重提，请在 release notes/接口文档中限定适用操作；若应适用于 `set_dimensions`，则 job result 需补该字段（当前 agent 只能靠"体积未变"间接推断）。

### 4.4 【P3】`update_sketch_geometry` 结果 operations 数组出现重复条目

实测结果：

```json
"operations": [
  { "op": "update_sketch_geometry" },
  { "op": "update_sketch_geometry", "label": "", "succeeded": true }
]
```

一条无 label/succeeded（疑似请求回显），一条为执行结果，未加区分字段。建议合并为一条，或给回显条目标注 `phase: "request"`，避免调用方误计数。
