## 三、P1 新发现：剖面贴在回转轴上时，就地编辑再生失败（BUG-079 修复未覆盖）

**动机**：作者的球体夹具（端点落在轴上）"从未触发此失败"，而修复后的夹具又刻意离开轴线——**"剖面顶点在回转轴上"这一常见构型（例如四分之一圆扇形绕其直边回转造球）是否也被覆盖，没有任何用例回答。**

**实测**（干净模型 `wb_acc051_axis`，XZ 面，中心线为轴，剖面 = 扇形：l1 (0,0)→(10,0) + arc center (0,0) R10 0°→90° + l2 回到轴线）：

| 步骤 | 结果 |
|---|---|
| 初始创建（execute_plan sketch+revolve） | ✅ succeeded，体积 2094.3951 = 2/3π·10³（上半球）✓ |
| **就地编辑：弧 90°→80°**（同步更新 l2 端点，剖面有效闭合） | ❌ `Regeneration produced a failed, suppressed or incomplete feature`；回滚干净（rev 不变、体积不变、part 未变） |
| **就地编辑：弧半径 10→12** | ❌ 同样失败并干净回滚 |
| 显式 `dimensioning="coordinates"` | ❌ 同样失败并干净回滚 |

**证据**：失败作业的 native.log 显示再生后 **REV1（回转特征）status=6（失败）**，而草图 REV_SK 自身 status=0——即草图编辑成功、回转特征再生失败。在另一个模型上重复得到同样结果（排除状态污染）。

**判定**：BUG-079 的坐标/autodim 修复路径对"几何离开轴线"的剖面有效，但对**剖面与回转轴相接（顶点在轴上 / 弧心在轴上）**的构型无效。这类构型是回转建模的常见模式（扇形造球、D 形造半球等），且失败信息没有任何线索指向"在轴"这一原因。

**建议**：
1. 把"在轴剖面"纳入 BUG-079 的回归矩阵（四分之一扇形绕直边、半圆贴轴各一例）；
2. 失败信息中补充可定位的线索（如"再生失败特征 REV1（protrusion）；其截面与回转轴相接，就地编辑暂不支持"），而非笼统的 "failed, suppressed or incomplete"；
3. 若短期难修，在 `creo_update_sketch_geometry` 描述中注明该限制。

## 四、P2 新发现：revolve 显式 axis 引用抛裸 C++ JSON 异常

首次构建回转时我传了 `"axis": {"entity": "ax"}`，作业失败于：

```
[json.exception.out_of_range.403] key 'kind' not found
```

**问题**：
1. 这是 nlohmann::json 的**原始异常文本**直接透出为作业 message，不含任何可操作信息（用户无法得知"axis 引用需要 kind 字段"或"省略 axis 即用截面中心线"）；
2. 正确用法（`docs` 与官方用例一致）是**不传 axis**，让 Creo 使用草图里的构造中心线作回转轴——这一点在 `revolve` 的 schema/工具描述里没有说明，REFERENCE_SYNTAX.md 的轴阵列节也未覆盖 `revolve.axis`；
3. 回滚本身是干净的（rev/体积未变）。

**建议**：native 侧对 `op["axis"]` 做存在性/结构预检并给出规范示例（如 `{"kind":"datum_axis_feature","label":"..."}`），或在 schema 层拒绝缺 `kind` 的 axis 并提示"省略 axis 可使用截面构造中心线"。
