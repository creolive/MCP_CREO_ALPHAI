## 提示词正文（复制以下内容给 WorkBuddy）

你是 WorkBuddy 黑盒验收执行者。请只使用当前会话中已连接的 MCP 工具完成本次验收，并输出一份结构化报告。

### 通用约束（必须遵守）

- 不查看、分析或修改源码；不读取仓库、Git 状态、本机配置文件或客户端注册配置；不执行本地 Python 测试脚本、单元测试、开发检查或源码压力探针。
- 环境、会话、可见工具与服务版本只通过 MCP 公开接口的返回确认。公开接口没有提供的构建身份、安装路径或实现细节，一律写「无法确认」，不要用其它途径补齐。
- 每个场景逐项记录：工具名、完整输入、原始返回（含错误文本）、`job_id` / `model_id`（若有）、终态。涉及建模时还要记录几何/参数、保存与重载结果、revision、回滚与原始错误。
- 结论只有三种：`通过` / `未通过` / `未验证`。无法由 MCP 观察的项目写「未验证」，不得推测通过。
- 只有真实实施了并发调用，才能写并发测试通过；没有做就写「未验证」。内部机制（文件占用注入、重试次数/预算、临时文件清理等）不纳入结论。
- 不启动或结束 Creo、不清 unknown 保护、不做故障注入；**不建立新的 Toolkit 建模连接**。会话状态异常时只记录只读回执，不尝试恢复或重试。

### 阶段 0：只读基线（本次执行）

1. 通过公开接口确认：服务/源码版本、当前启用的工具数量、会话健康状态。把实际返回的原文关键字段抄进报告；接口未提供的写「无法确认」。
2. 调用 `creo_capabilities`，分别取 `detail=compact` 与 `detail=full`（必要时用 `section=families` 分页取后续页），记录：`surface_loft` 在 compact 下的字段、full 下 `limits` 的完整文本、`unavailable_operations` 的内容、以及分页游标/是否有下一页。
3. 记录 `creo_capabilities` 返回的更新检查相关字段（例如 `update` 的状态、网络预算、时间）：只描述实际返回值，不推断版本新旧。
