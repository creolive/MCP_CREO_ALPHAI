# 2026-11-08 CREO 0.19.0 原生放样不可用与草图圆弧预检误拒

> 反馈对象：MCP_CREO_MechDog 作者
> 实测环境：Windows / Creo Parametric 10.0.0.0（release_numeric=42）/ MCP_CREO_MechDog **0.19.0**（107 个已启用工具）
> 测试任务：仅依据工作区内一份自然语言 TXT（1571 行，米单位）重建「简易护卫舰」，全程只用 MCP_CREO_MechDog 建模，不打开/导入任何外部模型文件。
> 版本说明：`creo_capabilities` 的 `update.status = failed`（"GitHub 更新检查超过 5 秒网络预算"），因此 **0.19.0 是本机实际运行版本，无法确认是否为发布最新版本**，请作者核对。

## 二、逐项复现与证据

### P1 原生放样依赖手工注册 DLL，且 seed 路径不稳定

- `creo_callback_status` 返回 `readiness = "not_loaded"`，`registration_status = "unknown"`，
  `next_action = "start_or_register_application_manually"`，`reason = "no_runtime_identity_record"`。
  提示需在 Creo「辅助应用程序」里手工注册 `build/blend_callback_protk.dat` 并启动一次，还要人工确认 DLL 提示。
- `creo_loft` 文档明确：缺少/未验证 callback 会在改动模型前直接拒绝 `BLEND_CALLBACK_SETUP_REQUIRED`。
- 无人值守的 MCP 客户端无法完成 GUI 注册 → **"从两个闭合截面放样成船体"这一核心能力在默认安装下不可用**。
- 退而使用 `creo_new_loft_part`（seed rebinding，文档称 "need no callback"）：
  - 提交两个 XY 截面（Z=-660、Z=0，各 7 个实体，其中含 R=10500 mm 的浅弧），
  - 任务在 `connect` 阶段失败：
    `Toolkit call connect_creo(&process) failed with code -4 during connect`，
    `failed_stage=connect`，`model_unchanged=true`，两个 sketch 均 `not_executed`。
  - 紧接着 `creo_session_status` 显示 `connected=false`、`toolkit_code=-4`、`worker_exit_code=20`、
    `creo_process_snapshot.processes = []`（此前有 `parametric.exe` PID 15896 与 `xtop.exe` PID 28660）。
  - 经 `creo_startup_status(retry=true)` 后自动重启（launch_attempt 由 31 → 32）才恢复。
  - **因果声明**：失败发生在 connect 阶段、几何尚未创建，不能证明是 seed loft 导致 Creo 退出；但结果是该路径在本次会话不可用。

**建议**
1. 提供无 callback 的原生 Blend 创建路径（或将 callback 注册做成 MCP 可触发的一次性命令，并给出明确的可查询状态机）。
2. `creo_new_loft_part` 明确 seed 形状/截面数约束，并在提交前预检 seed 与截面几何是否兼容，而不是到 connect 阶段才失败。
3. 对 `connect -4` 给出可执行的自动恢复（或至少在错误信息里直接指明下一步工具），避免调用方猜测。

### P2 精确圆弧闭合轮廓被 near_tolerance 误拒（最影响几何保真度）

**输入**（TXT 附录 A01 Sketch1 的主甲板艏弧，按 1 m → 100 mm 换算）：
- 弧 d4：`center=[6830, 917.6086957], radius=1607.6086957, start_angle=270, end_angle=325.194591737`
- 弧 d5：`center=[6830,-917.6086957], radius=1607.6086957, start_angle=34.805408263, end_angle=90`

两弧理论上都终止于艏尖 (8150, 0)。工具解算得到
`d4.end = (8150.000000034666, +1.39050371e-08)`，
`d5.start = (8150.000000034666, -1.39052645e-08)`，
间隙 `2.78103e-08 mm`。

**报错**（`creo_execute_plan` 提交阶段，尚未创建 job）：
```
operations[1]: Solid extrude profile rejected: detected 1 closed contour(s),
0 open contour(s) and 7 curve entities; [near_tolerance] endpoints joined only
by the closure tolerance (d4/d5) near (8150, 1.39050371e-08) mm.
```
同一个 profile 分析里 `closed_contour_count=1`、`open=0`、`self_intersecting=0`、`tangent=0`，
即**轮廓本身是闭合且合法的**，仅因浮点残差被判 `near_tolerance`。

**尝试无效**：给 sketch op 加 `"endpoint_policy":"weld"` 后重新提交，报错一字不变，说明该预检发生在焊接之前（或完全不考虑 endpoint_policy）。

**绕行代价**：只能把两条精确圆弧按 TXT 的圆心/半径/角度采样成 25 点 polyline（端点写死 8150.0, 0.0），
`max_endpoint_gap_mm` 才降到 1.78e-15，草图得以通过。**结果是原生圆弧特征被折线替代，几何保真度与可编辑性都下降**。

**建议**
1. 预检对 `near_tolerance` 的阈值不应基于 `1e-9 mm` 的"实测安全界"，而应与 `closure_tolerance_mm`（默认 1e-4 mm）协调；对已判为 `closed_contour_count=1` 的轮廓应放行，或降级为 warning。
2. `endpoint_policy=weld` 应在预检前生效，或提供 `weld_pairs` 显式指定要焊接的实体对（当前仅报"weldable=false"而不给出可用的补救参数示例）。
3. 错误信息里给出可复制的修复建议（例如"把两弧合并为一条 polyline"或"设置 geometry_tolerance_mm"）。

### P3 `arc.radius` 上限 100000 mm

- TXT 第 4.2 节 / 附录 A02 Sketch2 要求下部轮廓艏弧 **R = 105 m**、圆心 (51.2, ±102.9) m。
- 按 TXT 第 26 行的标准毫米换算（×1000）提交 `radius=105000`：
```
operations.1.sketch.entities.3.arc.radius
  Input should be less than or equal to 100000
```
- `Circle.radius`、`Arc.radius`、`Ellipse.x_radius/y_radius`、`SketchDimension.value` 均带 `maximum=100000`。
- 该限制使得"按 TXT 原尺寸毫米建模"直接不可行。本次只能改用 **1 m → 100 mm 的统一缩比**（TXT 允许统一缩放，但只推荐了 1:100；1:10 会让 0.005 m 的护板半厚变成 0.5 mm，接近薄壁极限）。

**建议**：把半径/尺寸上限提高到与 `supported_features` 的实际能力一致，或允许显式 `"allow_large_radius": true` 并记录风险；至少应在错误信息中说明这是 API 硬上限而非 Creo 内核限制。

### P5 曲面替代链未打通（**含未实测项，证据边界见下**）

- `creo_surface_loft` 的 schema 明确："exactly two sketch sections；each sketch must own exactly one
  non-composite curve"，`interpolation` 只能是 `straight`，产出 open quilt 且不生成实体材料，
  "Multi-section, smooth, closed and continuity requests are refused before a job is queued"。
  船体轮廓由 3 直线 + 4 圆弧（后改 25 点折线）组成；`polyline` 会展开成命名 line 实体，仍不满足 "one curve"。
- `creo_capabilities(detail="compact")` 的 `unavailable_operations` / `unavailable_tools` 明确列出
  `creo_surface_boundary_fill`：闭合非平面边界填充在本机 regeneration 失败
  （`feature_status=6 / PRO_FEAT_INCOMPLETE`、`quilt_count=0`）。
- 因此 "两截面放样 → 缝合 → 实体化" 这条**特定替代链**不成立。

**证据边界（重要，避免误导作者）**：本次**没有提交过任何曲面类工具调用**。
全程 122 次 deferred MCP 调用中，曲面 / 扫掠 / 加厚类工具为 **0 次**；
`creo_loft`、`creo_surface_loft`、`creo_solidify` 只在 ToolSearch 里加载过 schema，
`creo_surface_boundary_fill` 连 schema 都未查（仅来自 capabilities 自报）。
而 capabilities 的 `operations` 把
`sweep / loft / draft / surface_fill / thicken / surface_offset / solidify / surface_trim /
surface_loft / surface_round / quilt_merge / project_curve`
都登记为可用，**唯一自报不可用的是 `surface_boundary_fill`**。逐项区分：

| 工具 | 结论 | 依据强度 |
|------|------|---------|
| `creo_loft` | 本次不可用 | **实测**：`creo_callback_status = not_loaded`，schema 声明会预检拒绝 `BLEND_CALLBACK_SETUP_REQUIRED` |
| `creo_surface_loft` | 不适用于本模型 | **静态 schema**，未实际提交验证 |
| `creo_surface_boundary_fill` | 自报不可用 | **工具自报**，未实际提交验证 |
| `creo_sweep` / `thicken` / `solidify` / `quilt_merge` / `project_curve` / `draft` | **完全未尝试** | 无，不能断言不可用 |

所以"曲面路径不可用"只能理解为**"本次会话未打通"**，不是"MCP 曲面能力整体不可用"。
这部分属于**调用方验证不充分，不应作为 MCP 缺陷结论**；作者不必据此改曲面实现。

**建议**：提供接受**闭合复合轮廓**的 surface_loft / boundary blend（这是船体、球鼻艏类模型最常见的需求），
并修复 `surface_boundary_fill` 或给出可用的等价工具；
另建议在 capabilities 里直接标注 `surface_loft` 的 "two sections / one non-composite curve / straight only" 限制，
便于调用方在建模前判断是否需要改走 quilt + solidify 链。

### P6 性能与可观测性

实测（同一会话、同一模型，每个 plan 都做 save + reload + verify）：

| 批次 | 操作数 | 耗时 | 备注 |
|------|-------|------|------|
| 船体 8 op | 8 | ~40 s | |
| 开口 8 op | 8 | ~68 s | |
| 甲板/围板 18 op | 18 | **5 min 18 s** | 24 个栏杆立柱圆 |
| 上层建筑 20 op | 20 | ~8 min | 原生日志 >3.9 MB |
| 塔桅+横翼 14 op | 14 | 7 min 15 s | 日志 3.8 MB |
| 顶部圆台+三角框 12 op | 12 | 7 min 01 s | 日志 3.8 MB |
| 水下附件+球鼻艏 22 op | 22 | >10 min | 日志 **>7.7 MB**（含 6 个 12 点闭合 polyline + 2 个 16 点椭圆） |

- `native_progress.log_bytes` 从 0 增长到约 4 MB，`truncated=true`，`stages_seen=0`、`reason="no_phase_lines"`：
  长任务里几乎没有可读的阶段进度，调用方只能盲等 `get_job`。
- `stage` 字段时有时无（有时是 `extrude:xxx`，有时是 `executing_feature_plan`，有时 null），不利于定位卡在哪个特征。

**建议**：批量 plan 合并原生事务/减少每个特征的往返；输出紧凑的阶段进度（index/total、当前 label）；限制原生日志体积或提供按特征的日志摘要。

### P8 切除没有"作用对象"作用域，无法照搬源特征顺序

TXT 附录 B 中几乎每个 `Cut-Extrude` 都带有明确的「作用对象名称」（例如 `Cut-Extrude9` 只作用于 `Shell1`，`Cut-Extrude13` 只作用于另一个特征），
这是 SolidWorks 类内核的**选择性布尔**。MCP 的 `extrude(mode="cut")` 没有 `targets` / `scope` 参数，只能对整个 part 做全局切除。

实测后果：TXT 14.2 要求"只从艉底厚块上切掉 X≈7.5269～8.0100、Z≈-8.8388～-7.5385 的一小块以露出短轴"。
若按 `through_all` 全局提交，同区间内的短轴、圆头、舵片会被一起切掉，与源记录相反。
本次只能把"厚块 + 局部切除"合并为"厚块艉端直接起于 X=8.0100"，用**改变构造顺序**来等价表达，而不是复刻特征树。

**建议**：给 `boolean_bodies` 之外的 `extrude(mode="cut")` 增加可选的 `target_labels` / `scope_body_ids`，或提供"按特征标签限定切除范围"的等价 op。

### P9 预览图被草图/基准线覆盖

`creo_execute_plan` 成功后 `preview_file` 确实写出（`preview_status="written"`, `preview_code=0`），
但图像是线框模式且叠加了所有 sketch/基准面：
job `fa5eaaaa…`（revision 6）的预览中，整艘船被几十条红色水平基准线覆盖，
只能勉强分辨细长船体、中央台阶建筑、塔桅与横翼轮廓，无法判断表面是否完好、有无破面或悬空块。

补充证据（共三次，表现稳定，非偶发）：
- job `0a66d113…`（revision 8）：船底/艉底新增延伸轮廓可辨，仍被基准线覆盖。
- 最终 job `4ac85ab133a342a992b02859640b04d6`（revision 9）：灰色实体可辨细长船体、
  中央台阶上层建筑、塔桅横翼与船底延伸，但整图被密集暗红色线框/基准线覆盖，
  画面还叠加 `PRT_CSYS_DEF` 文字标签。
最终交付的外观结论因此只能写到"轮廓可辨"，**无法自动判读表面完整性**。

**建议**：提供 `preview_mode`（`shaded` / `shaded_with_edges` / `wireframe`）并默认隐藏 sketch、datum plane、datum axis、csys；
另提供 `view`（iso/front/top/right）与 `fit_all` 开关。这是"文本→三维"自动化里唯一能自动获得的外观证据。

### P10 缺少参数化的锥台/拔模拉伸

TXT 10.1 要求 3×3 m 底、1.6×1.2 m 顶的收窄四棱台；10.4 要求底 R=0.75 m、顶 R=0.5525 m、拔模 7.5° 的圆台。
由于 P1（无放样）且 `creo_execute_plan` 的 `extrude` 无 `draft_angle` 参数，
本次只能用 **5 段矩形台阶**近似塔桅、**3 段圆柱台阶**近似圆台。

**证据边界**：`creo_capabilities` 的 `operations` 中登记了独立的 `draft`，
但本次**没有提交过 `creo_draft`**，也没有查它的 schema。
因此"`draft` 需要逐面引用、无法直接用"只是未验证的推断，**不应作为 MCP 能力缺失的结论**。

实测提交：
```jsonc
{"op":"sketch","label":"mast_s1_sk","plane":"XY","offset":980, ...}   // 3×3 m 底
{"op":"extrude","label":"mast_s1","sketch":"mast_s1_sk","depth":146,"mode":"add","direction":"positive"}
// ... 共 5 段，截面按线性收窄取各段中点值，顶 1.6×1.2 m
```
14 个操作的 plan 全部成功（revision 6，`saved_file_reloaded_and_verified=true`），但外观是台阶而非斜壁。

**建议**：支持 `extrude` 的 `draft_angle` / `top_scale`，或提供一个接受两个闭合截面的轻量 `tapered_extrude`，
不必依赖 Blend callback。

### P11 草图平面 `offset` 与 `direction` 语义不一致，失败信息缺少实际坐标

实测（job `bbb0f653…` 的 `operations_result`）：

| 平面 | 草图坐标 | `origin` | `normal` | `direction:"positive"` |
|------|---------|----------|----------|------------------------|
| XY | (X, Y) | `[0,0,offset]` | `[0,0,1]` | +Z |
| YZ | (Y, Z) | `[offset,0,0]` | `[1,0,0]` | +X |
| **XZ** | **(X, Z)** | **`[0,offset,0]`** | **`[0,-1,0]`** | **−Y（与 offset 符号相反）** |

即 `offset` 是**全局坐标值**，而 `direction` 是**相对法向**的。
对 XZ 平面，`offset=+500` 落在 `Y=+500`，但 `positive` 却让 Y 减小；
调用方按"offset 沿法向位移"的直觉写，就会把切除方向弄反。

**实际故障**：在 `Y=-500` 主舱侧壁开直径 0.8 m 圆窗，提交
```jsonc
{"op":"sketch","label":"mainwin_neg_sk","plane":"XZ","offset":500, ... 4 circles ...}
{"op":"extrude","label":"mainwin_neg","sketch":"mainwin_neg_sk",
 "mode":"cut","direction":"negative","depth":20}
```
Creo 返回
```
Extrude cut removes no material; check the sketch position, direction and depth against existing geometry
```
plan 在 `failed_operation_index=11` 终止，前 11 个已执行操作全部
`effect_status="rolled_back"`，`rollback_succeeded=true`，整批 14 op 白跑约 10 分钟。
正确写法应为 `offset:-500, direction:"negative"`（负侧壁向内）与
`offset:500, direction:"positive"`（正侧壁向内）。

失败信息只提示"检查位置/方向/深度"，**没有给出草图平面的实际 `origin`/`normal`，
也没有给出被切除体在该处的实体范围**，定位成本很高。

**建议**
1. 统一 `offset` 与 `direction` 的参照系（例如 `offset` 明确标注为 `plane_coordinate`，或增加 `world_offset`）。
2. 在 `creo_execute_plan` 的返回值里为每个 sketch 直接给出 `origin`/`normal`/`u_axis`/`v_axis`
   （目前要事后读 `get_job` 的 `operations_result` 才能拿到）。
3. `Extrude cut removes no material` 的错误里附带：草图平面原点、法向、有效深度区间、
   以及该区间内是否检测到实体，让调用方能一次性判断是"方向反了"还是"位置错了"。

## 三、对建模结果的实际影响（诚实声明）

由于 P1/P2/P3 与 P5（曲面链未打通，含未实测项），本次**没有使用 TXT 第 4 节要求的"上下两封闭轮廓平滑放样"**，而是改用等价性较低的构造：
1. 主甲板轮廓沿 -Z 拉伸成直壁船体；
2. 在 YZ 面用两处梯形轮廓沿 X 贯穿切除，形成两舷由 ±2.1 m 线性外张到 ±6.9 m 的斜面（直舷边放样本来就是直纹面，此步为等价构造）；

## 五、建议的优先级

1. **P2**（一行阈值/顺序修复即可让大量合法轮廓通过，收益最大）
2. **P1 / P5**（放开多段闭合轮廓的原生放样，是"文本→三维"类任务的关键能力）
3. **P3**（去掉或放宽 100 m 半径硬上限）
4. **P11**（明确 offset/direction 参照系 + 在失败信息里给出实际平面坐标，可避免整批回滚）
5. **P8 / P10**（选择性布尔作用域、锥台/拔模拉伸，直接决定能否照着其它 CAD 的特征记录重建）
6. **P4 / P6**（稳定性与批量性能）
7. **P9**（预览默认着色并隐藏基准，让自动验证闭环可用）
8. **P7**（版本探测可采用更长超时或本地缓存兜底）
