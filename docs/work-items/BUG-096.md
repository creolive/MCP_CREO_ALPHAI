## 现象与待验证根因

新建模型 `v10_a_profile` 因草图失败后，同一计划仅改 `dimensioning` 为 autodim 用**同名**重交，失败点提前到 connect：

```
message: "New model name already exists in the Creo session"
failed_stage: connect
```

与 0.9.0 行为一致：失败作业没有 prt 落盘，但**会话对象已存在**。现有 `creo_erase_session_models` 的资格条件（已保存、未被引用等）不覆盖这种"由失败作业产生、未保存、无窗口"的孤儿。验收时只能改名绕过（本次改为 `v10_b_autodim`）。

外部报告建议二选一：失败回滚时同事务擦除本次新建的会话对象；或对 `execute_plan(model_name=…)` 提供 `on_conflict: "adopt_unsaved"`，仅接管"无窗口、未保存、有本 job 记录"的对象。**本卡只定行为目标，不预设实现路径**——第二条属接口契约变更，须在实现前单独冻结。

根因未在本仓库复现。待验证：失败收尾时新建对象是否确实残留、对象身份与 job 记录如何关联、哪些字段可证明"由本 job 新建"。

## 范围

- 目标行为：失败作业不得让调用方**必须改名**才能继续。只清理能证明由本次失败新建、未被用户使用、无引用的对象；**名称冲突对象、既有对象、保存检查点与结果未知对象一律不自动擦除**。
- 保留现有 rollback 字段语义；清理不是恢复保存检查点。
- 不借助 `erase_all`、不清 unknown 保护、不接管任意未保存对象、不无条件重试。
- 覆盖"新建→草图失败→无保存→同名再次新建冲突"主路径，并与"预存同名对象"分列，后者不得被通用清理误删。
- 不含：用户已修改或已打开窗口的对象、装配引用对象、擦除失败与 absence 查询失败路径的具体策略（实现时逐项定义 `erased`/`skipped`/`failed`/`unknown` 报告）。

### 后续实验（2026-11-01 深夜）

- **origin 判定修正**：`ProMdlnameCopy` 创建的新模型继承模板的 origin 路径，`ProMdlOriginGet` 非空并不等于本模型已保存。已改为“origin 文件名 stem 必须等于本模型名”才视为 `saved_since_creation`。重跑后 S1 的 reason 从 `saved_since_creation` 变为 `window_open`。

| S3 已保存模型失败回滚 | **通过** | 作业 `13898ed49c8b4924b3c1257dbe7e55f8`：`rollback_succeeded=true`、`rollback_status=succeeded`、revision 1→1、cleanup=`not_new_model_job` |

要点：

- **擦除能确认**：当前代码对失败的新建作业走完整擦除路径，`ProMdlErase=0` 后两条 absence 查询都返回“不存在”。因此**不需要接管（adopt）路线**，也不需要为本卡冻结接管契约或改公开 API；卡内提出的第二条路线保持未实施。
- **轮1 `window_open` 的来源**：r5 报告 `q03_cleanup_r5.json` 的回执是 `{status:unknown, reason:erase_unconfirmed, erase_code:0}`，而本树提交的 `window_open` 分支只会返回 `{status:skipped, erase_code:null}`；`erase_unconfirmed` 只能由已回退的“清理内关窗再擦除”实验产生。也就是说产生 `window_open/erase_unconfirmed` 的那几次运行用的是含未提交实验代码的 worker，与本树源码不一致（与 [BUG-099](BUG-099.md) 同窗口、同结论）。
- **驱动可重跑**：会话保留每次运行创建的模型，固定 `q03s1/q03s2` 会让第二次 S1 变成“同名冲突”（那是 S2 的语义）。驱动改为每次运行用 `q03s1_<run 后缀>`，同一次运行内的重试仍用**完全相同**的名字；断言未放宽。
- **S3 显式终态字段**（本卡尾注）：新增 `rollback_status`（`not_attempted|succeeded|failed|unconfirmed`），由 `src/creo_mechdog/rollback_status.py` 在 `creo_get_job` 终态组装处派生，`rollback_succeeded` 语义不变（BUG-012 不重开）。S1 失败作业如实报 `not_attempted`（新件无检查点），S3 报 `succeeded`。单测 `tests/unit/test_rollback_status.py`（15 项）。

证据 `build/live-0.11.1/q03_cleanup_r7.json`（SHA256 `CA7F26FA2E890EDF2A044F5562A79E488481910D96DBDDFC9196CC99524250E4`）。
