# BUG-096：失败作业遗留未保存会话对象占用模型名

日期：2026-11-01。类型：缺陷。优先级：P1。状态：待复现（外部反馈）。目标版本：未排期。

来源：[0.10.0 晚间包 01 验收报告](../validation/feedback-0.10.0-2026-11-01/originals/01_验收报告_0.10.0.md) §E 与 §复现索引（job `27008cce…`）；[00_README §一页速览 2](../validation/feedback-0.10.0-2026-11-01/originals/00_README_反馈包.md)；[逐章映射](../validation/feedback-0.10.0-2026-11-01/MAPPING.md)。交叉关联 [FEAT-018](FEAT-018.md)（恢复动作）与台账 BUG-012 行（`rollback_succeeded=false` 误读，**只关联，不重开旧档**）。

## 现象与待验证根因

新建模型 `v10_a_profile` 因草图失败后，同一计划仅改 `dimensioning` 为 autodim 用**同名**重交，失败点提前到 connect：

```
message: "New model name already exists in the Creo session"
failed_stage: connect
```

与 0.9.0 行为一致：失败作业没有 prt 落盘，但**会话对象已存在**。现有 `creo_erase_session_models` 的资格条件（已保存、未被引用等）不覆盖这种"由失败作业产生、未保存、无窗口"的孤儿。验收时只能改名绕过（本次改为 `v10_b_autodim`）。

外部报告建议二选一：失败回滚时同事务擦除本次新建的会话对象；或对 `execute_plan(model_name=…)` 提供 `on_conflict: "adopt_unsaved"`，仅接管"无窗口、未保存、有本 job 记录"的对象。**本卡只定行为目标，不预设实现路径**——第二条属接口契约变更，须在实现前单独冻结。

根因未在本仓库复现。待验证：失败收尾时新建对象是否确实残留、对象身份与 job 记录如何关联、哪些字段可证明"由本 job 新建"。

## 范围

- 目标行为：失败作业不得让调用方**必须改名**才能继续。只清理能证明由本次失败新建、未被用户使用、无引用的对象；**名称冲突对象、既有对象、保存检查点与结果未知对象一律不自动擦除**。
- 保留现有 rollback 字段语义；清理不是恢复保存检查点。
- 不借助 `erase_all`、不清 unknown 保护、不接管任意未保存对象、不无条件重试。
- 覆盖"新建→草图失败→无保存→同名再次新建冲突"主路径，并与"预存同名对象"分列，后者不得被通用清理误删。
- 不含：用户已修改或已打开窗口的对象、装配引用对象、擦除失败与 absence 查询失败路径的具体策略（实现时逐项定义 `erased`/`skipped`/`failed`/`unknown` 报告）。

## 验收标准

| 环境 / 用例 | 命令或操作 | 可判断的预期结果 |
| --- | --- | --- |
| Windows / Python | `python -m unittest tests.unit.test_failed_model_cleanup -v`（隔离桩） | 预存同名、用户修改/打开窗口、装配引用、擦除失败、absence 查询失败、`unknown_outcome` 各路径均**不误删**；报告状态可判读 |
| 本机 Creo 12.4 / 匹配 SDK | 隔离夹具：新建→sketch 失败→同名再次新建 | 失败对象确认消失；同名可再次新建；原模型与已有文件不受影响 |
| 本机 Creo 12.4 / 匹配 SDK | 已保存模型失败 | 仍正常回滚，revision 不变；保存重载 `saved_file_reloaded_and_verified == true` |
| 本机 Creo 12.4 / 匹配 SDK | 预存同名对象的失败作业 | 预存对象**仍在**，报告明确未清理及原因 |

单测用隔离桩；实机不对用户对象注入故障。真实 busy/并发交错由统一实机负责人安排，不能靠串行调用宣称并发通过。WorkBuddy 只从公开 MCP 接口验收用户可见行为；文件占用注入、重试次数/预算等内部机制不纳入 WorkBuddy 结论。
