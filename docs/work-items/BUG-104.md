# BUG-104：旧检查点无组件 `appearance` 基线时，上色没有迁移路径

日期：2026-11-02。类型：缺陷。优先级：P1。状态：已修复（随 0.11.3 发布，实机待验）。目标版本：0.11.3（已发布）。关联 [FEAT-052](FEAT-052.md)（受管装配上色）、[BUG-105](BUG-105.md)（同批装配恢复）、[DEV-062](DEV-062.md)。

## 来源

- 原件：[0.11.0 反馈 F01 核心问题 1](../validation/feedback-0.11.0-2026-11-01/originals/2026-11-01_CREO_0.11.0_受管装配上色解锁链路三处断裂与装配失败恢复死路.md)；映射见 [MAPPING](../validation/feedback-0.11.0-2026-11-01/MAPPING.md)。
- 环境：外部 Creo Parametric 10.0.0.0、MCP 0.11.0、80 组件受管装配（12 零件族）。

## 现象

0.10.0 时代保存的受管装配检查点，其组件快照没有 FEAT-052 新增的 `appearance` 字段。升级到 0.11.x 后：

- `creo_recolor_assembly` 的 dry-run 如实报 `present:false, missing_count:80`（`appearance_baseline_report`）；
- 执行被拒，提示 “run creo_save_model on the assembly to establish and verify a new checkpoint”；
- 升级后每个 0.10.x 之前的受管装配都要人工补一次 save 才能上色。

## 当前实现（0.11.2 只读核对）

- 准入：`src/creo_mechdog/appearance.py:99-165` `checkpoint_records(model, require_baseline=True)`，缺 `appearance` 时直接 `ValueError`（`:154-164`），无参数可放宽。
- 预览：`appearance_baseline_report()`（`:168-178`）只回 `present`/`missing_count`/`missing_labels`/`note`，没有可执行下一步。
- `refresh_baseline` 全库 0 命中。

## 范围

包含：

1. 公开工具 `creo_recolor_assembly` 与计划操作 `recolor_assembly` 新增显式 `refresh_baseline`（默认 `false`，保持既有拒绝语义）：
   - 仅放宽“检查点组件缺 `appearance`”这一项；缺 `feature_id`、绑定或源 ID 等其它身份缺口仍拒绝，不扩大放行面。
   - 原生在装配加载准入阶段发现缺基线时，以**当次加载后的实读外观**填充回滚基线（作业前真实状态），随后沿用“上色 → 保存 → 双次读回”路径；回执新增 `baseline_source: "checkpoint" | "adopted_live"`。
   - 一个作业、一次 revision 递增，不拆分补基线作业。
2. dry-run 回执新增 `next_action`：直接给出可复制的调用参数（含 `refresh_baseline=true` 与 `expected_revision`），不建作业、不推 revision、不锁通道。
3. 工具描述、README、`capabilities.py` 的上色范围说明同步。

不包含：

- 不实现“先 save 再 recolor”的隐式自动降级（隐式推进 revision 与既有“执行恰好一次保存”契约冲突）。
- 不实现 `adopt_session_copy`（见 [BUG-106](BUG-106.md)）。
- 不放宽组件身份缺口，不在缺基线时猜测颜色。
