### 根因（本批确认）

**不是**截面放置变换算错，而是**第二参照选到了与 orient 参照同一几何的重复基准面**，使截面只剩一条可用参考线。

1. `native/generic.cpp:1200` 建立草图特征时写入 `PRO_E_STD_SEC_PLANE`（支撑面）与 `PRO_E_STD_SEC_PLANE_ORIENT_REF`（orient 参照）。orient 参照取"与支撑面法向最接近正交"的基准面：本案基准面组为 2/4/6/42/49/74，最小 |dot| 命中的是 **id=6（Z=0）**。
2. `ProSectionEntityFromProjection(section, orient, ...)` 已把该 orient 面的投影线放进截面。随后为补第二条定位参照，代码遍历其余基准面（`native/generic.cpp:1242` 起）。修正前只按 `p.id != frame.orientation` 排除，**不判几何**；本案 2、4 的投影返回 `PRO_TK_BAD_INPUTS(-2)`（与 T05 Live03 记录的非正交情形一致），紧接着 **id=42（同为 Z=0 的重复基准面）投影成功**（`PROJECT_REFERENCE=42 code=0 entity=1`），循环 break。
3. 42 与 6 法向相同、原点相同，投影到截面是同一条线——截面因此只有**一条**可用参考线，正是 [BUG-064](BUG-064.md) T05 Live03 已证明不可求解的状态：`ProSectionSolve` 对任何实体、任何标注模式都返回 -1 且无 section error。
4. 交叉证据：`jobs/*/native.log` 中 61 个同一 `SECTION_MATRIX`（`-0.809,0.588`／`0,0,1`）作业里，只有 6 个第二参照成功落在"与 orient 面同法向"的基准面（id 42）——正是本六例，全部 `SKETCH_SOLVE=-1`；其余 1000+ 个成功作业的第二参照（平面 4/6 或基准轴）都与 orient 面法向不平行，投影线互不相同。

### 关于 trace 中 u∈[0,4]（不是缺陷本体）

失败日志 `LINE_slot_0=4.000,3.000 -> ...` 是**截面局部坐标**，不是放置错误：

- 该截面 `SECTION_MATRIX_0=(-0.809,0.588,0)`、`_1=(0,0,1)`、`_2=(0.588,0.809,0)`，即 Creo 的截面 X = −u、Y = −v、Z = n（绕 n 旋转 180°）。来源是 orient 参照给的是 **UP = +Z**，Creo 由 Y=+Z 与 Z=n 反解 X=Y×Z=−u，而不是按调用方传入的 u_axis 定 X。
- `native/generic.cpp:1264` 起的 `project()` 用 `ProSectionLocationGet` 的矩阵把世界点投影回截面坐标；请求的 (u,v)=(−4,−3) 落到世界 `(-3.236,2.351,3)`，再投影为 (4,3)——**世界位置与请求矩形完全一致**，因此翻转的是"表达坐标"，不是去料位置。
- 结论：翻转本身不需要修；它与求解失败无因果关系（`0020b28e` 等成功作业有同一矩阵）。真正缺陷是重复参照使截面不可解。

### 最小修复范围

只改"补第二条截面定位参照"的取舍：候选基准面除需与支撑面非平行（既有 `<0.95`）外，还必须与 orient 参照面法向不平行（否则投影线与 orient 线重合，无法构成二维定位）。不满足的候选记 `SKETCH_ANCHOR_SKIPPED`，继续后续候选，最终回落到既有基准轴回退路径（T05 Live03 已实机验证 18/18 通过）。
