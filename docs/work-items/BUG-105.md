# BUG-105：零变更失败把装配置 `failed`，官方工具没有任何恢复动作

日期：2026-11-02。类型：缺陷。优先级：P1。状态：已修复（随 0.11.3 发布，实机待验）。目标版本：0.11.3（已发布）。关联 [BUG-104](BUG-104.md)（同批装配准入）、[FEAT-052](FEAT-052.md)、[BUG-096](BUG-096.md)（失败清理与 `rollback_status`）、[DEV-062](DEV-062.md)。

## 来源

- 原件：[0.11.0 反馈 F01 核心问题 3](../validation/feedback-0.11.0-2026-11-01/originals/2026-11-01_CREO_0.11.0_受管装配上色解锁链路三处断裂与装配失败恢复死路.md)。
- 现场 job：失败的 save `43ea652235b34a9e96b81cd211e6fd00`（connect 阶段、零变更），随后 recolor 被拒。

## 现象

- connect 阶段的一次失败 save（未启动原生建模、未改动任何模型）把受管装配 `status` 置为 `failed`。
- 此后 `creo_save_model` / `creo_recolor_assembly` 一律拒绝：`Model is not ready; inspect its last job before recovery`。
- `creo_reconcile_model(mode=inspect)` 返回四个动作 `restore_baseline / accept_saved / accept_live / abandon_new` 全部不可用，理由均为 `Assembly/drawing reconciliation is not supported; preserve component ownership`。
- 唯一出路是手工编辑 `models/<id>/model.json` 把 `status` 改回 `ready`——该路径无官方支持、无审计、也无完整性校验。

## 当前实现（0.11.2 只读核对）

- 终态判定：`generic_bridge.py:641-654`，失败时只有 `readonly`、`rollback_succeeded` 或（`model_unchanged is True` 且 `failed_stage == "callback_preflight"`）且已有 `part_file` 才保持 `ready`，否则 `failed`。
- 恢复动作：`src/creo_mechdog/reconciliation.py:514-555`，`supported = model_type in ("part","sheetmetal")`，装配四动作全不可用（`:541-546`）。
- `failed_no_mutation` / `ack_no_mutation` 全库 0 命中。

## 范围

包含：

1. **收紧失败归因（原生 + 准入）**
   - 原生失败路径在 `mutated` 为假时统一发布 `model_unchanged=true`，不再局限 `callback_preflight`。
   - Python 终态：`model_unchanged=true`、worker 未启动或连接未建立时保持 `ready`（已有检查点）或维持既有新模型语义；仅有变更证据时置 `failed`。
2. **显式恢复动作** `creo_reconcile_model(mode="apply", action="ack_no_mutation")`
   - 必填 `confirm_zero_mutation=true`、`evidence_token`、`expected_revision`、`idempotency_key`。
   - 仅当 `status="failed"`、`pending_job=null`、owner 已停止、且无相反证据（`rollback_status=failed`、`unknown_outcome`、基线哈希变化）时可用。
   - 纯注册表事务：不启动 worker、不连 Toolkit、不触碰组件归属，因此 part / sheetmetal / assembly / drawing 一致可用。
   - 写入 `reconciliation` 审计块（`prior_status`、`prior_job_id`、`evidence`、`acknowledged_at`），清 `recovery_pending`，revision 不变。
   - 幂等：同一 `idempotency_key` 重放返回同一结果。
3. 文档：reconcile 工具描述、`README.md`、`capabilities.py` 写明“零变更失败用 `ack_no_mutation`，不要手改 `model.json`”。

不包含：

- 不支持任意失败（有变更证据、`unknown_outcome`、回滚失败）的强制复位。
- 不放宽装配的 `restore_baseline/accept_saved/accept_live/abandon_new` 语义。
- 不新增公开工具（仍是 `creo_reconcile_model` 的动作扩展）。
