# BUG-009：Toolkit 忙碌拒绝缺少占用诊断与作业收尾竞态

日期：2026-10-14。类型：缺陷。优先级：P0。状态：已完成（2026-10-15，本机 Creo 12.4 约定范围验收）。目标版本：未排期；当前源码 0.3.1，未另行发布。

来源：WorkBuddy 0.3.0 全量原始报告 P0-2（历史复现）及其 `WORKBUDDY-0.3.0.md` 证据边界。历史全量报告由独立文档批次归档，本条独立提交保留本次复现、开发与黑盒验收证据。

## 现象与待验证根因

报告记录作业running期间creo_refresh_model等返回busy，无blocking_job_id/retry_after；上一作业已succeeded后立即提交仍偶发busy。单Toolkit通道不能同时执行原生操作本身不等于缺陷；本条核实拒绝策略、可行动诊断与终态/锁释放顺序。报告“任何调用均被拒”不能外推到get_job、缓存/注册表查询，需逐工具区分。

提交锁等待0秒、作业等待120秒及竞态原因来自源码分析，尚未独立复现。报告未交付真实并行调用时间线，不登记并发通过。

## 范围与验收

Windows x64 / Creo12.4.0.0。先记录实际并行客户端/调用、起止时间与job/model ID；明确排队或拒绝策略，排队能力须有容量/等待预算/顺序契约，不承诺原生并行执行。修改调度/保护时运行对应单元、语言检查及实机会话回归。

| 场景 | 完成条件 |
| --- | --- |
| 作业运行中提交另一Toolkit操作 | 按已定义策略接受有界排队或返回结构化busy，包含可确定的占用job及重试说明；无法确认占用者时如实说明 |
| 运行中查询job/注册表/缓存 | 不依赖Toolkit的公开查询可及时返回；需要Toolkit的只读操作遵守单通道规则 |
| succeeded之后立即提交 | 多轮真实调用验证终态与资源释放契约一致，不发生不可解释busy；保存重载完成再认定建模终态 |
| 相同模型并行写与失败/超时收尾 | revision冲突保护仍有效，无丢失更新或重复提交；核对锁、pending_job与真实模型，未知结果不被盲清 |

最终WorkBuddy须实际并行调用才可给并发结论；无法并行时记录未验证。内部锁/收尾注入另列开发者证据。本次仅登记，未复现或修改策略。

## 2026-10-15 开发完成

受控开发者复现记录了 A 成功后 C 仍 busy 的完整事件链：A 释放通道后仍在登记收尾，B 已取得通道；A 的终态查询返回 succeeded，C 只有笼统拒绝。使用真实 Windows 进程锁和合成原生结果，不计为 Creo 建模复现，也不证明外部报告全部属于同一根因。原实现的持久化终态本就在释放锁之后；本次没有将历史现象误写为“succeeded 时原作业仍持锁”。

现将通用任务的模型登记收尾移入 Toolkit 锁内，释放后再发布任务终态；busy 保持 MCP 错误标志，文本 JSON 与结构化数据同时说明 accepted=false、占用者及重试指引。占用快照无法读取或占用者没有 job 时明确返回 null；已排入同模型的 pending_job 也以结构化 busy 返回。快捷 plate 提交遵守相同的即时拒绝策略。已接受 runner 等锁超时不在锁外覆盖模型，保留 reservation 与恢复说明；native timeout 仍为 unknown_outcome，不允许盲重试。

完整开发检查 210 项单元通过，无新增语言问题。本机 Windows / Creo 12.4 经 Explorer 桌面路径启动两个真实 stdio MCP 客户端：8 轮终态后立即提交、三项同时导出（1 接受 / 2 busy）、运行中查询、占用 job/model 核对、同模型并行写（1 接受）、stale revision 拒绝、原生失败回滚与后续刷新均通过。该路径沿用 BUG-005 的开发者诊断方式，普通 Codex 宿主连接失败未修复；实际 native 超时/挂死恢复未验证。

本次版本保持 0.3.1，未发布或覆盖正式安装；开发源码位于 E 盘当前分支。完整时序、源码指纹、实机与受控证据、一次测试脚本过严断言导致的中断及其未确认作业均见[开发记录](../validation/BUG-009.md)和[结构化证据](../validation/BUG-009.json)。最终由用户按[WorkBuddy 场景](../validation/BUG-009-WorkBuddy-test.md)黑盒验收，尚未登记 WorkBuddy 通过。

## 2026-10-15 验收完成

用户交付 [WorkBuddy 黑盒报告](../validation/BUG-009-WorkBuddy-acceptance-20261015.md)并要求完成验收。E 盘 0.3.1 / Creo 12.4 的 20 轮串行写、同批真实并行导出及被拒请求重试、占用 job/model 核对、运行中四类缓存查询、同 revision 并行写、旧 revision 拒绝、失败回滚与后续编辑通过。开发者只读核对报告引用的 33 个任务：32 succeeded、1 预期 failed；28 个成功写任务均保存重载 true，4 个只读任务不以该标志判断失败。两个测试模型最终 ready、pending_job=null，revision 分别 24 和 4。

报告疑点已分别核对：界面未呈现工具错误不能判定 isError=false；同源码真实 stdio 的 4 个 busy 均 isError=true、文本与结构化结果一致，本次又通过协议回归。并发拒绝时占用快照为空符合已声明契约，不能从另一项稍后被接受反推拒绝瞬间的 holder；正常运行中已由 WorkBuddy 核对占用 job/model。WorkBuddy 的 20 轮存在客户端节拍，不登记为近零间隔；同源码开发者 8 轮真实调用的间隔为 5.321–24.577 ms，证据分开保留，不冒充 WorkBuddy 结论。

按本条约定范围关闭并可推送。真实挂死/超时及失联恢复、WorkBuddy 双独立客户端、其近零间隔调用和占用期 session_status/refresh 分支仍未验证；已有开发者双客户端及 refresh 证据保持各自来源。BUG-008/001 的恢复范围不随本条关闭，BUG-005 宿主差异未修复。报告的“bug009_rect 终态 rev23”是并行写前检查点，实际并行写后为 rev24；原报告保持原样，详见[验收复核](../validation/BUG-009.md#2026-10-15-验收复核与关闭)。
