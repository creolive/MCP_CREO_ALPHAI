# BUG-092：live 驱动结束后 `server.py` 子进程残留占用 stdout 管道

日期：2026-10-31（Asia/Shanghai）。类型：缺陷。优先级：P2。状态：离线修复已交付（P02），实机核对待排期。目标版本：未排期。

来源与关联：[Post-0.9.0 七段实机复测](../development/POST090-LIVE-SEVEN-SEGMENTS-2026-10-31.md)「第二轮遗留项登记」第 1 项（本轮由编排方核号为 BUG-092）。关联 [DEV-052](DEV-052.md) N13 批次；不影响生产建模语义，属实机驱动/服务进程生命周期问题。

## 现象

实机 live 驱动（`tools/test_*.py --live`）结束后，其派生的 MCP stdio `server.py` 子进程不退出，继续占用 stdout 管道，导致外层执行器挂起。2026-10-31 两次实机观察到（见七段实机总报告遗留项登记；具体轮次的驱动 console 与进程观察留在 `build/` 未入库现场）。

## 推测根因（未验证）

stdio MCP 服务在客户端断开后未收到 EOF/退出信号，或驱动侧未关闭管道、无线程负责收尾；需要 daemon 线程 / EOF 退出路径，使驱动结束即触发 server 进程退出。此为处置方向，**不是已定根因**。

## 范围与验收

| 环境 / 用例 | 命令或操作 | 可判断的预期结果 |
| --- | --- | --- |
| Windows / 离线复现 | 以最小 MCP 客户端启动 `server.py` 子进程后关闭 stdin/结束驱动 | 复现子进程残留（进程仍在、stdout 管道被占） |
| Windows / 修复后 | 同上 | 驱动结束（stdin EOF）后 server 进程在有界时间内自行退出，外层执行器不挂起 |
| 既有实机驱动 | 任一 `--live` 驱动完整跑一轮 | 驱动退出后无残留 `server.py`/Python 子进程，后续驱动可立即启动 |

不改生产建模行为、不改 MCP 协议输出；只处理进程生命周期与退出路径。不把杀进程当作修复。

## 实现与证据

2026-10-31 仅登记（POST090 遗留项核号开卡）：未实现、未复现实验、未改代码；现象来自当日实机观察记录。下一步：按最小复现先确认退出路径缺失点，再实现有界退出并补离线回归。

### 2026-10-31 P02 离线修复（分支 `codex/dev053-post0100`）

- **根因定位（离线复现 + 线程现场）**：最小 stdio 客户端 initialize/tools/list 后关闭输入、且不消费 stdout/stderr 时，tools/list 大响应填满 stdout 管道，wire 写侧阻塞在 `WriteFile`。线程现场（py-spy）：MainThread 停在事件循环 select（idle），单个非 daemon 的 AnyIO 工作线程阻塞在同步写；`stdio_server` 任务组 join 不返回，`mcp.run()` 永不退出，进程持续占用管道——与实机"server 子进程不退出占用 stdout 管道、外层执行器挂起"同症状。持有管道的是传输写侧的 `stdout_writer` async 任务及其 AnyIO 工作线程；daemon 的 creo-startup 线程不是根因。正常 EOF（消费输出）路径本身可自然退出，不复现残留。
- **修复**：新增 `src/creo_mechdog/stdio_lifecycle.py` 的 `StdioExitGuard`，由 `server.py` `__main__` 在 `mcp.run(transport="stdio")` 前安装（生命周期边界收敛在 server.py）。复制 wire stdin 句柄后以 `PeekNamedPipe` 只窥测不消费地监测客户端消失（stdin 关闭/客户端被杀/驱动异常退出）；EOF 后宽限 1.5 s（在途受理登记与自然收尾），随后仅对 AnyIO 传输工作线程 `CancelSynchronousIo` 解除卡死写，仍存活则 2.0 s 内 `os._exit(0)` 有界自退。不终止任何子进程、不杀 Python 进程树：已受理建模任务跑在独立的 `bridge.py run-job` runner 进程，server 退出后仍自行登记终态。
- **实测退出耗时**（本机 Windows x64 / Python 3.12.14）：正常 stdin EOF 0.20 s（自然路径先于守卫动作）；stdout/stderr 未消费 2.20 s（守卫解除卡死后自然收尾，`os._exit` 为兜底）。均在空闲服务退出预算 10 s 内。
- **离线回归**：`.\.venv\Scripts\python.exe -m unittest tests.unit.test_stdio_lifecycle -v`，5/5 通过——正常 stdin EOF、客户端异常退出（驱动被硬杀且不关 stdin）、stdout/stderr 未消费、子进程启动失败（有界失败不挂起）、已受理后台任务在 server 退出后仍存活并登记终态。修复前"输出未消费"用例按预期失败并保留现场（即本卡复现的残留路径）；测试规格中的空闲退出预算为 10 s，超时判失败并保留进程/线程现场。
- **范围说明**：已受理后台任务场景使用按 `bridge.py run-job` 分离启动方式生成的离线替身 runner（真实受理需 Toolkit 通道，不在离线范围）；未改 MCP 协议输出与生产建模行为。统一 `tools/dev_check.py` 留待 P14 批末集成，本轮未跑。
- **未测范围**：实机 `--live` 驱动退出后无本次 server 残留的核对——**实机核对待排期**（P01 会话准入结论后由编排人统一串行安排）。
