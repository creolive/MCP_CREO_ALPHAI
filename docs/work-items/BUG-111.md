## 现象（报告方实测）

P12 风扇需要 8 叶（1 本体 + 7 个 45° 副本），用 `geometry_transform` 的 `keep_original` 做"实体-移动/复制"：

| 计划 | 结果 |
| --- | --- |
| 45/90/135/180/**225**/270/315°（7 个） | ❌ 前 4 个成功，**225° 处** `ProFeatureWithoptionsCreate = -1`，整批回滚 |
| 45/90/135/180/**−135**/−90/−45°（7 个，等价负角） | ❌ 前 4 个成功，**第 5 个（−135）** 同样 -1 |
| **单独** 225°（1 个） | ❌ 同样 -1 |

两个独立现象：

1. **副本数上限**：同一计划里第 5 个 `keep_original` 复制必失败（两次不同角度集合同一位置，可复现）；报告的变通是拆成 ≤4 个/批，第二批要重新引用已变化的 body id。
2. **角度范围**：225° 单独也失败，45/90/135/180 可过 → 旋转角疑似必须在 ±180° 内。

## 当前实现（本批只读核对，基线 `main@b3f6d43`）

- `native/placement.cpp:211-225` `flex_transform_values()`：
  ```cpp
  for (int i = 0; i < 6; i++) {
      ...
      double value = i < 3 ? rotation[axis].get<double>() : translation[axis].get<double>();
      if (i < 3 && value < 0)
          value += 360;
      real(move, PRO_E_D3ELEM_MOVE_VALUE, value);
  }
  ```
  **负角统一 `+=360` 归一**，所以 −135° 被写成 225°，与单独 225° 命中同一内核失败路径；这与报告方"改等价负角仍在第 5 个失败"的现象一致。
- `native/placement.cpp:227-282` `generic_transform()`：body 走 `PRO_FEAT_FLEXMOVE` + `PRO_FLEXMOVE_DEF_METHOD_3D_DRAG`，`keep_original` 映射到 `PRO_E_FLEX_KEEP_ORIG_GEOM`（`:278-279`）；surface 收集来自 `inspection()["surfaces"]` 的实体面（`:253-262`）。失败时只回裸 Toolkit 码与 `last_toolkit_error`，**不带操作序号/标签/角度/引用数**。
- `src/creo_mechdog/schema.py:446-482` `GeometryTransformOp.valid_transform()`：`translation` 限 ±100000、`rotation` 限 **±360**；225° 能通过校验，再由内核拒绝。
- `src/creo_mechdog/schema.py:485-497` `TransformUpdateOp.bounded_values()`：同样 ±360。

## 范围

包含：

1. **角度归一改为 (−180, 180]**：−135° 保持 −135°，225° 归一为 −135°，使 batch 内角度集合语义唯一；日志回显原始值与归一值。
2. **前置校验（行为收紧）**：`GeometryTransformOp` 与 `TransformUpdateOp` 的 `rotation` 分量改为 ±180 前置拒绝，报错给出等价值（如 `225 -> -135`）；不静默改写请求。
3. **逐操作诊断**：transform 失败回执补操作序号、标签、backend（`flex_move`/`geometry_move`）、原始与归一后的旋转、引用数、活动 body 数、`keep_original`，仍保持有界（≤20 条 element_errors）。
4. **实机复现第 5 副本**：5 个与 7 个两批对照，捕获 `feature_errors`/`element_errors`，判断是否与复制后 body id/父链失效有关；能定因就修，不能就如实记"未定因 + 分批上限建议"。
5. **文档**：`server.py` transform 工具描述、`docs/REFERENCE_SYNTAX.md`、`docs/COMPATIBILITY.md` 写明 ±180 与等效写法、`keep_original` 分批现状。

不包含：

- **不新增 `body_pattern` 工具**（属新工具，版本未定）；只登记为后续候选。
- 不承诺本轮修好第 5 副本；未定因时不写"已修复"。
- 不改 flex/geometry_move 两种 backend 的选择规则。
- 不改 `mirror`/`pattern` 的既有语义。

## 定因轮实机结果（2026-11-03，T1/T2；用户授权会话）

原始报告 `build/r13_followup_20261103T161114/t1_reproduce.json`（C0—C6 全量，执行器 `0f556504…`）与 `t2_rerun.json`（C2/C4，诊断增强后执行器 `7071b947…`）；假设记录同目录 `hypotheses.md`。

**事实（七个独立底板）**：

- C0：225° 仍在校验层拒绝（报错含 `-135`，不建作业）；单个 -135° 副本成功（体积精确 2×，features 8→9）。
- C1（45/90/135/180）4 op 成功；**C4（-135 在首位，同样 5 角）5 op 全部成功**——"第 5 个副本必失败"不成立；C6 拆 4+3 后批 B 首个 op（累计第 5 个副本，-135）失败——**拆批对该角度集不是变通**。
- C2/C3/C5（-135 在第 5 位，显式 body id 与否）4 个独立模型同型失败于 index 4；失败批整批回滚（after==before、revision 不变），后续合法编辑正常。

- T2 诊断（行为零改动）：`failed_transform.selection` 显示失败 op `selected_surface_count=26`（整个累积体；新底板仅 6 面）、`requested_body_ids=[52]`；C4 重跑行为不变。

**结论（定因）**：现象已复现且可稳定触发；根因归为**"`keep_original` 复制整个当前体"的选集语义 + 追加副本与既有凸块重合/交叠时的再生失败**，不是副本数量上限、不是 -135 角度缺陷、也不是引用解析问题（三者均有反证）。按计划走"完善诊断和边界"分支：`native/placement.cpp` 记录有界选集证据、`native/generic.cpp` 失败回执并入 `selection`；**未做行为修复**。

**口径修正**：本卡与文档中"单批 ≤4 个副本、下一批重新引用当前 body"的建议**作废**（C6 证明无效）；改为"副本累积在同一 body 内，能否追加取决于既有副本集合与角度组合；需要固定原件副本时应另建模型或等待独立的 body 语义"。

**仍未验证**：Creo 10/9 行为；"恰好重合 vs 部分交叠"的内核判据；`body_pattern`（仍未实现）。第 5 副本问题从"未定因"更新为"已定因（选集语义 + 几何重合），实现无缺陷证据，不做行为修复"。
