## 依赖与缺件

- 22 项错误的原始报告：登记行没有留下路径或原件，当时的 `build/development_check.json` 是否还在本机未确认（本次未查运行目录）。若已不存在，只能以"单树复跑 0 错误"作为关闭依据，并明确记录原始 22 条不可逐条回溯。

- 台账当前版本号与分类统计的维护责任需在批次收尾流程中固化，否则每版都会重现。

## 执行步骤

1. 先确认历史报告是否留档；无则直接以单树复跑为准（需要用户同意占用一次全量运行）。
2. 跑 `tools/dev_check.py`，按结果决定"关闭"或"逐类登记"。
3. 若采纳校验脚本：先定规则 → 实现 → 回归（含 ID 重复、合计不符两个负例）。
4. 回填本卡与台账；把"每版收尾同步版本号、统计与计划状态"写进发布检查清单。
