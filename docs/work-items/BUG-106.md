## 现象

会话内存在同名装配 `STRANDBEEST_ASM`，其 origin 是外部目录（`...\CREO_build\asm_components\strandbeest_asm.asm.8`）：

- `creo_save_model` 失败：`Loaded model origin does not match this MCP model's output directory`，不提示“应先擦除会话副本”；
- `creo_erase_session_models` 被 `modified` 挡住：`The model has unsaved changes; save or discard them in Creo first`，不说明保存后还要回到 erase；
- 用户需自行拼出“GUI 保存 → erase → save”三步。

## 当前实现（0.11.2 只读核对）

- `native/generic.cpp:6182-6183` origin 不匹配原文；`:5008-5011` erase `modified` 提示。
- `adopt_session_copy` 全库 0 命中。

## 候选范围（待规划，不在本批实现）

1. `save` 的 origin 不匹配错误：当会话存在同名非受管模型时，附加“session has a same-name model from <origin>; erase it via creo_erase_session_models(targets=[{name, model_type}]) then retry”。
2. `erase` 的 `modified` 拒绝：附加完整链路“先在 Creo GUI 保存清脏位，再重新 inspect 后 apply”。
3. 可选 `adopt_session_copy`：仅当会话副本与受管检查点组件结构一致时允许“以会话副本为准”走一次受管保存；需先定义一致性判定、受管身份改写与审计，边界不清前不实现。

## 不包含

- 不自动擦除、不自动保存、不跨边界接管外部来源模型。
- 不改变 `managed` 与 `modified` 的拒绝条件。

## 实现与证据

本批（R12，0.11.4）只实现候选范围第 1、2 条文案，第 3 条 `adopt_session_copy` 仍不实现：

- `save` 的 origin 不匹配：保留原句，追加"会话内存在同名模型"的成因、`creo_erase_session_models(action='inspect')` 读取目标、`creo_erase_session_models(targets=[{name: 'MODEL_NAME', model_type: 'part'}])` 的调用形态与 `retry creo_save_model`，并声明"is never erased automatically"。
- `erase` 的 `modified` 拒绝：追加"在 Creo 用 File > Save 保存或丢弃修改 → 重新 `creo_erase_session_models(action='inspect')` → apply 同一批目标"，并声明"Erasing does not save or discard for you"。
- 拒绝条件、回执结构与 `adopt_session_copy` 均未改动；`tests/unit/test_session_origin_guidance.py` 3 项通过（含 `adopt_session_copy` 全库 0 命中的反向断言）。
- 未执行：真实同名外部模型的 save/erase 两步链路（需要构造会话副本，本批按用户范围只做文案）。
