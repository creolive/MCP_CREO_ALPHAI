# BUG-073：creo_extrude 草图引用三种写法均失败，仅小写别名可用

类型：缺陷

优先级：P2

状态：已完成（开发者实机与WorkBuddy公开复验均通过；实机loft对照未测，沿用单测覆盖）

目标版本：0.4.1

来源与关联：2026-10-19 WorkBuddy 公开 MCP 黑盒复验（场景：特征引用字段规范化）；关联 BUG-069（命名放宽与小写规范化）、FEAT-043（会话枚举）、FEAT-042（接管快照）；与 `creo_loft` 的公开引用规则对照。

登记时分类依据（2026-10-19，历史）：本机已取得失败复现，但导致解析失败的层（参数序列化、别名查找、原生名称来源）尚未定位，按“待复现”登记，下一步补定位而非直接改实现。定位、修复及公开复验随后完成，当前结论见文末“完成结论”。

## 问题或目标

### 已证实现象（本机 Creo 12.4.0.0，服务 0.4.0）

受测对象为受管接管模型 `wb_fields_managed`（`model_id=d5075d8736a03d6579104530ec6c89ee`，`revision=2`，20×15×20 基准体，体积 24000 mm³，`features=10`）。该模型的草图在 `inspect_model(section=features)` 中记为 `id=48`、`name="RECT_40X30"`、`type_name=sketch_or_curve`；在 `inspect_model(section=aliases)` 中注册名为 **`rect_40x30`**（小写，`op=sketch`、`feature_id=48`）。

同一模型上连续四次 `creo_extrude`，仅改 `sketch` 写法，`depth=5`、`mode=add`、其余参数相同：

| 序号 | `sketch` 输入 | job_id | 终态 | 原始错误 | 回滚 |
| --- | --- | --- | --- | --- | --- |
| 1 | `40`（integer） | `248a41b033a343969e25cbf754e77466` | `failed` / `execute_extrude` | `Unknown feature label: 40` | `rollback_succeeded=true` |
| 2 | `"48"`（纯数字字符串） | `b09bfc1523ab4363b770e596f647d4d9` | `failed` / `execute_extrude` | `Unknown feature label: 48` | `rollback_succeeded=true` |
| 3 | `"RECT_40X30"`（features 段返回的 name） | `381990e14dfc4f4eb94e747601a104f5` | `failed` / `execute_extrude` | `Unknown feature label: RECT_40X30` | `rollback_succeeded=true` |
| 4 | `"rect_40x30"`（aliases 段返回的 name） | `c8fe5ad76c844c59949669689b54d3b0` | `succeeded` / `verified` | — | 不适用 |

关键观察：

1. 序号 1 在提交回执中已被改写：`operations[0].sketch` 从 `40` 变为字符串 `"40"`，随后按标签查找。即整数特征 ID 未被当作 ID 使用。
2. 序号 2 说明“数字串”在 `creo_extrude` 不做 ID 规范化。
3. 序号 3 说明按 `inspect_model(features)` 返回的 `name` 直接引用同样失败——这是最影响使用的一条：客户端唯一能发现特征名的入口给出的名字不可用。
4. 序号 4 成功：`revision` 由 2 变 3，`saved_file_reloaded_and_verified=true`，`part_sha256=69b3adb6…`，体积仍 24000 mm³（40×30 同截面挤出 5 mm 完全落在既有实体内，`features` 10→12，符合几何预期）。
5. 三条失败路径的模型状态均未受损：`inspection_source=rollback_verified`、`volume_mm3=24000`、`features=10`、`surfaces=6`、`edges=12` 前后一致，失败后再用序号 4 正常继续，说明回滚语义正确。

### 与 creo_loft 的规则不一致

`creo_loft` 的公开工具说明写明：`sections accepts sketch labels or integer feature IDs; digit-only strings are normalized to feature IDs for public-client compatibility`。同一服务内，`creo_extrude` 既不接受整数 ID，也不对纯数字串做 ID 规范化，两套引用规则并存。

### 预期行为

1. `creo_extrude.sketch` 传入整数时按特征 ID 解析；传入纯数字串时与 `creo_loft` 一致，规范化为特征 ID。
2. 标签查找与 `inspect` 返回值自洽：`features.name`（当前大写 `RECT_40X30`）与 `aliases.name`（当前小写 `rect_40x30`）至少有一个可直接用于引用；若只接受小写，则 `features` 段应同步返回小写名或显式给出 `alias_name` 字段。
3. 查找失败时错误信息应给出可用候选（例如近似标签或“请使用 aliases 段名称”），而不是仅回显输入串。

### 待验证根因（未确认）

本次为公开接口黑盒复现，未读取源码，以下均为待核对方向，不作为结论：

- 通用参数层是否把所有标量统一序列化为字符串，导致类型信息在进入原生执行器前丢失；
- 标签查找是否大小写敏感，以及 `features.name` 是否来自原生特征名（Creo 侧自动大写）而 `aliases.name` 来自 MCP 登记名；
- 接管快照（`source_kind=session_snapshot`）模型的别名表与 MCP 自建模型的别名表是否走同一注册路径。

## 范围

包含：`creo_extrude.sketch` 的取值分支（整数、数字串、大写标签、小写别名）、`creo_loft.sections` 的同类分支对照、`inspect_model` 的 `features`/`aliases` 段落一致性、失败回滚与 revision 行为。

不包含：本项不改变特征命名规范（仍为小写、≤28 字符）；不借此放宽 `update_sketch_geometry` 的命名实体保护（BUG-030/BUG-062）；不涉及 `creo_execute_plan` 的判别联合数组参数（该差异属调用方客户端校验，见“实现与证据”第 3 条，不登记为服务缺陷）。

## 定位结论与实现（2026-10-19晚，开发者）

三个待验证方向全部核对闭环，登记时标注“待核对方向、不作为结论”的推测修正如下：

1. **参数序列化层——服务端无缺陷。** stdio 直连 `server.py` 以 JSON number 提交 `creo_extrude`（探针 job `4634395592e544c7b4d0aa313ff4d9d0`），服务端函数入参与提交回执均为 int，且整数分支在原生按特征 ID 解析（该 job 引用特征 41 为基准面，失败于 `ProFeatureWithoptionsCreate=-1` 非闭合截面并回滚完好）。五个落盘失败 job（ZCode 与 WorkBuddy 两客户端）的 `sketch` 均为字符串：整数改写发生在**调用方**——LLM 客户端倾向把 `str|int` anyOf 的整数分支写成带引号形式，服务端 schema 的 string 分支使其合法通过。`LoftOp.normalize_section_ids` 的既有注释（“Some public clients stringify integer branches of anyOf”）早已记载同一现象；`extrude` 系缺的是同款数字串规范化，而非序列化缺陷。
2. **标签查找大小写敏感、名称来源两套。** `native/generic.cpp` `feature_id()` 原实现字符串仅精确匹配 `aliases`；`remember()` 以计划里的小写 label 登记 aliases，而特征创建时 `PRO_E_STD_FEATURE_NAME` 被设为同一 label 且 **Creo 将特征名统一大写**（`ProModelitemNameGet` 读回 `RECT_40X30`），故 `inspect_model(features).name` 与 `aliases.name` 大小写必然不一致、前者不可直接引用。
3. **接管快照与自建模型别名表同一注册路径。** aliases 均由原生 `remember()` 在每次操作执行时登记；接管快照初始 aliases 为空是“受管副本从冻结快照重新登记”的设计语义，两类模型解析规则一致。

### 实现（分支 codex/feat-042-adoption-completion）

- `src/creo_mechdog/schema.py`：新增 `SketchRef`（BeforeValidator 数字串→特征 ID、int 范围 0..2^31-1，与 `LoftOp` 契约一致），应用于 `ExtrudeOp`/`RevolveOp`/`SketchDimensionsOp`/`SheetmetalWallOp`/`FillOp`/`RibOp` 六处 `sketch: str | int` 字段；独立工具与 execute_plan 两路径都经 `validate_operations` 覆盖。
- `native/generic.cpp`：`feature_id()` 增加 digit-only 串规范化（strtoll 范围防御）、经新增 `alias_entry()` 做**大小写不敏感回退**（原始串→tolower 回退）、失败错误信息列可用候选（至多 10 个 + 省略号；无别名时提示用数字 ID）；`extrude_or_revolve` 的 `section_normal_sign` 与 `set_sketch_dimensions` 的 `section_path`/`dimension_ids` 元数据读取改走 `alias_entry()`——修复过程中新发现的同链缺陷：大写引用经回退找到特征后，旧代码用原始大写串直接索引 `aliases` 得 null，`.value()` 抛 `type_error.306`（首轮实机 A4/B2 崩溃，修复后通过）。

### 验证（本机 Creo 12.4.0.0，stdio 直连新 server 实例）

- 单元：`tests/unit/test_sketch_references.py` 新增 5 例（规范化/范围/六字段/公开工具与 plan 写入一致），全量 411 项 0 失败 0 错误；`tools/dev_check.py --work-item BUG-073` 通过（含格式检查）。
- 实机（对自建模型 `d9e69db5…` 与接管模型 `wb_fields_managed`）：四种写法全部成功——整数 ID（A2）、数字串（A3、B1 `"48"`→特征48）、`features` 段大写名（A4 `RECT_20X10`、B2 `RECT_40X30`，经大小写回退）、`aliases` 小写名（A5、B3）；接管模型体积恒 24000 mm³、每次成功 revision+1、特征数仅递增（同截面挤出落于既有实体内）。未知标签失败且错误信息含 `available labels: …`、`rollback_succeeded=true`、模型不变。重复标签保护在脚本重跑时正确拒绝（B1/B3 首轮残留标签，换标签后通过）。
- `creo_loft` 无代码改动，其数字串规范化单测保持；实机 loft 对照未测（回调注册需人工前置，沿用登记时未测范围）。
