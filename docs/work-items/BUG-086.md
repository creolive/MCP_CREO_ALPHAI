# BUG-086：Windows PowerShell 5.1 下 pip stderr 通知导致 setup 误报安装失败

日期：2026-10-27（Asia/Shanghai）。类型：缺陷。优先级：P1。状态：**已修复（随 0.7.2 交付）**（T03：夹具复现 + 修复 + 回归通过；T08：批内补充修复 + 回归通过 + 真实新目录安装验证通过）。目标版本：0.7.2。

来源与关联：0.7.1 发布验收记录 [RELEASE-0.7.1](../validation/RELEASE-0.7.1.md)「解包安装」节的安装期发现（不属 0.6.1 报告原有诉求，为 0.7.1 发布中新暴露）；执行归 [派发表 T03](../development/0.6.1-FEEDBACK-TASKS-2026-10-27.md)。关联 [DEV-030](DEV-030.md)（安装/构建工程范围）。

## 问题或目标

已证实现象（0.7.1 解包安装实录，Windows PowerShell 5.1）：`setup.ps1:8` 设 `$ErrorActionPreference='Stop'`，PowerShell 5.1 在重定向 stderr 时会把 pip 的 `[notice]` 输出转成终止错误，导致「依赖已装好但脚本报 `INSTALL_INCOMPLETE: failed at Python dependencies`」。pip 实际 **exit 0**；仅重定向 stdout 后同一命令 exit 0。

待验证根因：依赖步骤对 stderr ErrorRecord 的处理与真实退出码判定耦合（在 Stop 偏好与重定向组合下把通知性 stderr 当失败）。需用最小夹具复现确认触发条件，并区分三种情形：exit 0 且 stderr 含 notice（应继续）、非零退出（应失败并保留原始错误）、可执行文件无法启动/无退出码（应失败）。

T03 复现结论（Windows PowerShell 5.1.26100.9711）：触发条件是**原生命令的 stderr 被重定向**（`2> file`，即上述 0.7.1 实录写法）；直接执行与调用方 `2>&1` 不会走同一条终止路径。见 [T03 验收记录](../development/DEV049-T03-ACCEPTANCE.md)。

## 范围

- 复现（T03）：Windows PowerShell 5.1 隔离夹具，不访问 PyPI、不使用真实 Creo 连接；复现「stderr 输出 notice、退出码 0，却被 Stop/重定向当失败」，并对照退出码非零与启动失败两例。
- 修复（T03）：在 setup 内集中封装两个 pip 步骤的外部 Python 调用——只在外部进程调用的函数局部容忍 stderr ErrorRecord，立即保存真实退出码；执行前清除该次退出码旧值；无法启动/无退出码或非零一律失败；函数退出恢复原错误偏好，**不全局降低 `$ErrorActionPreference`**。stdout/stderr 保留可见或可取证；禁止吞 stderr、仅匹配 `[notice]` 文本、只关 pip 版本提示或把所有异常改成成功。其他配置/校验异常仍按原语义失败。
- 保留：`INSTALL_INCOMPLETE` 阶段语义、completed 列表、配置/模型/jobs 保留与重跑提示；`-CheckOnly` 不产生安装写入；不改服务注册标识（`MCP_CREO_MechDog`）或系统策略。
- 不包含：不连接 Toolkit/Creo；真实新目录 setup 安装由 T08 执行；不改 MCP 工具面。
