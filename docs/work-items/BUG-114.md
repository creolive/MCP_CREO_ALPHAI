# BUG-114：失败新模型已验证清理，但事务效果仍标为未知

类型：缺陷。优先级：P1。状态：已实现（离线；实机未验证）。目标版本：下一修复批，按兼容性核定未发布版本。

来源：DEV-069新增[0.14.0反馈A §4.2](../validation/feedback-0.14.0-2026-11-06/MAPPING.md)，作业前缀017c62e4。报告同时给出failed_model_cleanup={status:erased,reason:cleaned,erase_code:0,absence_verified:true}、component_changes.status=unknown_outcome、op.effect_status=unknown；新模型无检查点，因此rollback_status=not_attempted/rollback_succeeded=false本身不是错误。

## 目标与范围

统一新模型清理证据与受管模型事务效果：已确认为本job新建且未保存的自有对象、擦除及不存在证据均成立时，模型/组件效果应为no_effect，保留各op原有execution_status；不能伪造rolled_back或把实际执行过的操作标not_executed。整体job仍failed，模型登记/历史证据保留。

当前代码：`native/generic.cpp::finalize_operation_results`只接受rollback布尔；`component_changes._status_for`仅看rollback_succeeded/model_unchanged；`operation_results._effect_status`保留已给unknown且缺cleanup上下文。三处需要共享同一有作用域的判定。复用BUG-096清理实现、BUG-113保存检查点差异；本项不修改擦除所有权或恢复权限，不重开BUG-012。

判定接口必须显式传入完整受信operations与effect_scope（managed_model/component_bindings/external_outputs），不能只有新件/回滚布尔。已成功导出后再失败清理，模型净效果可no_effect，外部输出仍按其实际回执/未知状态判定，不能批量覆盖所有op；未知操作/缺请求或副作用证据默认unknown。

## 禁止的推断

- 仅ProMdlErase=0、仅absence_verified单键、旧/不可信/非终态回执，都不足以清未知保护。
- preexisting_same_name/saved_since_creation/not_new_model_job/erase_unconfirmed及真正丢失结果不升级为no_effect。
- 模型已不存在不等于撤销外部导出文件/所有计划副作用；作用域必须明确。job unknown_outcome/registry保护不由一个读取侧摘要擅自重写。
- 保留unknown词汇与rollback两字段兼容，不按报告建议全局删unknown或合并成破坏性新接口。

## 实现（2026-11-06，离线）

新增包内 `src/creo_mechdog/terminal_effect.py`，唯一决策表 `classify_terminal_effect(result, *, job_status, is_new_model, checkpoint_present, operations, effect_scope)`：

- 失败终态按顺序判定：`model_unchanged`→`no_effect`；已验证检查点恢复→`rolled_back`；可信新件清理→`no_effect`；其余保持`unknown`/`unconfirmed`并带原因。
- 可信清理要求同时满足：本job新建、回执为`attempted=true/status=erased/reason=cleaned/erase_code=0/absence_verified=true`、`operations`为完整受信请求且与终态逐op同名同序对应并带合法`execution_status`。仅`ProMdlErase=0`或`absence_verified`单键不足。
- 作用域：`managed_model`/`component_bindings`可由可信清理判`no_effect`；`external_outputs`仅在未请求或对应op为`not_executed`时`no_effect`，已执行的`export`/`dump_tree`保持`unknown`。未知作用域默认`unknown`。
- 真正`unknown_outcome`无论证据多完整都保持`unknown`，读取侧不改写。

接入点：`native/generic.cpp::{finalize_operation_results,cleanup_clears_managed_effect}`与`native/drawing.cpp`调用方（只释放非外部输出op的模型效果）；`operation_results.normalize_operations`/`annotate_native_result`；`component_changes._status_for`；`generic_bridge`在失败/未知终态写入`terminal_effect={managed_model,component_bindings,external_outputs}`；`compact_sections`将`terminal_effect`列入结果白名单与保护字段。旧`rollback_succeeded`/`rollback_status`语义未改。
