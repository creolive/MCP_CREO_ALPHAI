## 目标、范围与假设

分别调查①保存失败②加载检查点后比对失败。增加 `save_failure` 与 `rollback_difference` 有界原生证据、可用 recovery 指引、基线 SHA256/revision 不变性回归。对照一次建成/已有模型追加、独立平面工具/投影依赖工具、纯曲面/转实体；保存目标与文件候选、会话身份、特征/body 差异分别记录。

BUG-078 会话损坏、BUG-099 实验 worker 身份、FEAT-039 自依赖投影链仅作不同假设参考，不能由相同 -1 直接套根因。不能取消 count/身份/几何比较、默认重试 Backup、自动 accept_live/ack_failure 或清保护。

## 验收与环境

失败也能由 compact/full 得到原始调用/码、阶段、目标来源与实际差异；真实不变性才可 ready，无法证明则保留 failed/unknown 与恢复要求。成功需几何、保存重载 true、revision 一次；失败需基线哈希/revision、恢复可用动作及后续编辑。开发者离线替身、健康会话实机、外部 Creo 10 三类分开；Creo 12.4 未复现时记录未复现，不能关闭外部缺陷。详见 R02。

## 2026-11-06 离线诊断实现

只增加诊断，不改保护语义：不因差异存在改变 `rollback_succeeded`/allowed 模型状态，不关闭 count/身份/几何比较，不自动重试 Backup，也不新增 recovery 指引。

改动文件：

- `native/generic.cpp:6291-6456`：新增有界诊断 helper（目录取样、受管相对名、特征/body 差异、体积比较）。
- `native/generic.cpp:6837-6845`：`ProMdlnameBackup` 改为先取 `ProError`，非 0 时写入 `report["save_failure"]` 再按原 CK 文本抛出。
- `native/generic.cpp:6998-7060`：`J restored = inspection()` 提前到 `verify_saved` 之前并保存到 try 外变量；两个 catch 与 load 失败分支写入 `report["rollback_difference"]`。
- `src/creo_mechdog/operation_results.py:149-315`、`556-558`：纯投影 `normalize_save_failure` / `normalize_rollback_difference`，在 `annotate_native_result` 中接入；无该块时不生成。
- `src/creo_mechdog/compact_sections.py:56,110`：两个块加入 `RESULT_KEYS` 与 `PROTECTED_RESULT_KEYS`，空 `sections` 选择也不裁剪。
- `tests/unit/test_surface_save_recovery.py`：四类离线回归。

`save_failure` 键表（仅 Backup 返回非 0 时出现）：`call`="ProMdlnameBackup"、`code`=原始 ProError 整数、`stage`="verify_model_save"、`destination`=受管目录内相对文件名（不含绝对路径/许可信息）、`source_checkpoint`=当前检查点相对名或 null、`candidate_files`={available,total,truncated,sample≤20}。

`rollback_difference` 键表（回滚校验失败时出现）：`available`、`status`（mismatch/unavailable/matched）、`reason`（原校验文本或 null）、`features`/`bodies`={available,before,after,missing_ids,added_ids,reason}，id 列表为 {total,truncated,sample≤20}，不可读时为 null + reason、`volume_mm3`={available,before,after,reason}，测不到时值 null 并说明原因。`status` 仅描述诊断证据；`rollback_succeeded` 仍只由既有 `verify_saved` 成功决定。

测试：四类均离线通过——Backup 失败保留原始 code/call/stage 且不覆盖 `message`；load 失败 `status="unavailable"`+reason；计数不同而体积相同 `status="mismatch"` 并列出 added id，模型仍非 ready、效果仍 unknown；成功回滚时 `rollback_succeeded`、`rolled_back`、ready 与旧结果一致。命令：`.\.venv\Scripts\python.exe -m unittest tests.unit.test_surface_save_recovery tests.unit.test_assembly_recovery_ack tests.unit.test_compact_sections -v`，另跑 6 个既有 operation_results 相关模块共 157 项，均 OK。

未验证：外部 Creo 10.0.0.0 未复现；本机未实机运行，未编译原生（按编排约定未执行 `bridge.py build`），新增 C++ 仅经 clang-format 与源码标记测试，编译期风险未排除；无外部 job/native/检查点附件，差异样本来自离线替身。

## 2026-11-06 R02 定向复现驱动（离线部分）

`tools/test_surface_save_recovery.py` 默认离线，只有同时给 `--live --confirm-session-usable` 才连接 Creo；不注入挂死、不重启/清 IPC、不重试 Backup、不自动 ack，失败只记录并转向下一个独立模型。

- 冻结矩阵：2 路线（`single_plan`/`incremental`）× 2 工具（`independent_plane`/`projected_dependency`）× 3 个独立模型 = 12 例；每题只允许 1 次尝试、`resubmit_on_failure=false`。提交预算按运行期曲线 id 分组：single_plan 独立平面 1、投影依赖 3；incremental 独立平面 3、投影依赖 4。
- 离线复用四类错误回归（Backup 失败、检查点重载失败、计数不同而体积相同、成功回滚），并新增 R02 判定：`unknown_outcome` 永不清保护；matched 计数/体积只作诊断；`part_file`/`part_sha256`/`revision` 全部不变且既有原生规则 ready 才 ready；新模型失败保留 failed 且不伪造基线。
- 报告写入 `build/surface_save_recovery/<run_id>/report.json`，离线显式标注 `native_save_recovery="not_verified"`。

测试：`tests/unit/test_surface_save_recovery.py::DirectedReproVerdictTests` 8 项通过；该模块 26 项全通过。命令：`.\.venv\Scripts\python.exe tools\test_surface_save_recovery.py`、`.\.venv\Scripts\python.exe -m unittest tests.unit.test_surface_save_recovery -v`。
