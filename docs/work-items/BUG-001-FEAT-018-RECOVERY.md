## G1：设计核对与拟定接口

以下是实施契约草案，不是当前已存在的 MCP 工具；接口名称、字段、状态枚举与预算在 G1 根据现有提交/登记路径核对后写入本卡冻结，再开始编码，不要求用户重复审批普通实现选择。

建议复用 `creo_get_job` 的 recovery 证据，并新增单一 `creo_reconcile_model` 入口，区分预检与应用；不能把恢复语义散写进 server.py 或 generic_bridge.py。

| 模式 | 最小输入/输出契约 |
| --- | --- |
| inspect（默认） | model_id；返回原作业/模型状态、revision、pending_job、基线/候选文件身份、已确认阶段、可用动作、不可用原因、证据时间和令牌。持久化证据查询不修改模型，也不因 Toolkit 繁忙就丢失查询入口 |
| 显式实时预检 | 若需连接 Creo，占用现有单通道并遵守 busy 和有界预算；返回真实会话身份、模型归属和偏离/健康情况。失联或权限不足只能标无法确认，不能当未加载、已停止或可恢复 |
| apply | 明确 action、model_id、expected_revision、expected_pending_job_id（允许明确为 null）、证据令牌及幂等键；接收后返回独立恢复 job_id/recovery_id，由 `creo_get_job` 轮询，不能重交原未知作业 |

预检只读不要求业务确认；会丢弃或接纳几何的 apply 必须由调用方显式选择动作，不用预选项或超时替代选择。令牌绑定模型/作业、revision、待处理 reservation、检查点/候选摘要、部署/执行器和可取得的会话身份；执行时重新核验，不能凭旧预检结果直接清保护。

拟定动作及语义：

| 动作（名称在 G1 冻结） | 适用与完成条件 |
| --- | --- |
| restore_baseline | 存在归属明确、摘要与登记一致的完整检查点。授权丢弃该受管模型的会话偏离后重载并核验；已登记 revision=r 保持 r，后续正常编辑为 r+1；恢复作为独立审计事件，不伪造建模修改 |
| accept_saved | 从绑定该作业的证据选择保存候选，禁止传入任意外部路径、猜最新 prt 或接受模板拷贝。原生健康、单位、特征/参数/几何与保存重载核验后，作为明确选择的可用基线提交一次，revision=r+1 |
| accept_live | 只接纳身份/归属可证明、当前健康且经显式选择的会话模型；必须先保存到受管产物、擦除重载核验后提交，revision=r+1。不能证明安全、存在外部引用缺失或模型不健康时准确拒绝 |
| abandon_new | 无可用基线的新模型可显式放弃：审计/归档状态和文件证据保留，停止将其当可继续编辑的 ready 模型；只在证明本项目归属且无活动执行器后处置其会话副本。不能删除用户模型或原始证据，也不能静默复用原身份创建另一个模型 |

接纳保存/live 只证明“调用方选择的模型已核验并成为新基线”，不自动证明原计划剩余操作执行完成；原始 unknown_outcome 作业及输入/日志保留，附可追溯处置记录。公开查询要区分原始不确定结果、已协调处置和当前可用性，不能因旧状态重复封锁已完成协调的模型。

## G2：状态、事务与保护

### G1 冻结（2026-10-17）

接口冻结为 `creo_reconcile_model(model_id, mode="inspect", live=false, action=null, expected_revision=null, expected_pending_job_id=null, evidence_token=null, idempotency_key=null)`。apply 要求明确 action、revision、pending（null 表示明确无 pending）、令牌和幂等键；四个动作沿用上表名称。accept_live 必须使用 live=true 预检取得的令牌，并在执行时重新比较会话几何。inspect 返回候选是否可用及拒绝原因；持久化查询不要求 Creo 就绪。

包内 `reconciliation.py` 统一协调业务。令牌绑定完整登记、原任务/恢复任务证据、输入文件流式 SHA256、部署源码和执行器身份，10 分钟失效。单次文件核验上限 1 GiB/8 秒；整个持久化快照 12 秒，到期拒绝，不接受空摘要。实时预检和恢复原生阶段预算 90 秒（只终止该新建 worker），断开另有既有 20 秒看门狗；Python 外层 115 秒，大于两段预算之和。构建沿用已有有界构建流程；恢复 runner 不等待通道，不增加排队。进程身份使用 Windows 创建时间；缺失或权限不足只允许诊断。

恢复登记采用 durable intent → verified evidence → committed decision → model materialization → 通道释放 → job 终态发布。committed 之前中断保留保护；committed 之后只允许同一幂等键补全元数据，不再次执行原生动作。原始 unknown 作业保持原状，通过模型 resolution 和恢复审计关联，不能冒称原计划完成。已有基线必须与原成功作业记录的 SHA256 一致；没有可追溯摘要时拒绝 restore。候选必须来自绑定作业的原生核验检查点，不按目录后缀推断。

1. **先核实活动所有者。** 核对 runner 的 PID 与创建时间、已有 Toolkit 所有者和恢复任务身份。进程权限不足或存活性无法确认时拒绝写恢复；PID 被复用不能误判旧执行器仍在或已结束。沿用 bridge.py 唯一持锁路径与现有锁顺序，不建立第二套 Toolkit 锁。
2. **受控穿过模型保护。** 正常写工具继续拒绝 pending/unknown；只有正式恢复请求按绑定的 expected_pending_job_id 进入专用路径，且全程持有所需模型/通道保护。不能在执行前清 pending_job，也不能全局跳过 verify_saved 或简单移除 mutated 条件。
3. **有界执行。** 在 G1 冻结元数据查询、实时探测、原生恢复、保存重载与断开的预算、来源和到期动作，验证外层看门狗不提前杀合法阶段。超过现有只读诊断摘要预算的文件，须受控流式核验或准确拒绝，不能把 hash_not_computed 当摘要通过。
4. **成功最后发布。** 先持久化恢复意图/身份与可恢复证据，完成原生处置、保存重载和必要登记，最后发布恢复终态及解除该模型保护。跨 job/model/审计文件不得依赖一次普通 JSON 替换假设多文件原子；选择可重入的 intent/commit 或等价方案。
5. **再次中断保持可判断。** 覆盖保存前、保存后核验中、核验后登记前、登记中和释放锁前的中断。缺少一致提交证据时继续保留保护；证据足够时可以幂等补全登记，不能自动重跑原生几何操作。
6. **明确普通写行为。** 有基线偏离时在变更前返回结构化不一致和恢复指引；无检查点但同名会话残留时拒绝隐式采纳。仅有状态 failed、没有活动 pending_job 也不能绕过这两个检查。
7. **旧能力不回归。** 正常新建、编辑、失败回滚、只读查询、busy、过期 revision 和后续模型操作不退化；unknown 原任务不自动重交，通道复核不等于模型协调成功。
