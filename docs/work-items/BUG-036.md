# BUG-036：应用装配约束后元件位姿与约束不一致

日期：2026-10-16。类型：缺陷。优先级：P1。状态：验收中（位姿查询修复，实机几何待验证）。目标版本：未排期。

## 现象与待验证原因

2026-10-20 按 0.3.7 剩余计划核对本机 12.4 SDK：现有 inspect_components 用 ProAsmcompPositionGet 读取的是约束/运动前的初始位置，并非求解后真实位姿；ProAsmcompConstraintsSet 本身已有组件再生语义，不能仅凭旧矩阵认定未求解。实施最小修复：transform 改取当前组件路径到装配的变换（ProAsmcomppathTrfGet bottom_up=true）。先独立提交 advanced.cpp 格式整理，再改查询行为；不盲目增加再生、不改约束求解及 side 语义。原外部失败和真实几何结论继续等待实机对照。

元件 af_inst2 原固定放置于 (-30,20,0)+Z30°，再提交 mate TOP↔TOP、align FRONT↔FRONT、align RIGHT↔RIGHT，工具成功、revision 增加且 underconstrained=false，但 transform 仍为旧值，报告称面法向不满足新约束。

需补完整装配、面引用、约束 side 与调用输入；核对 TOP 等标签解析、坐标变换约定和查询快照。`ProAsmcompConstraintsSet` 后缺少重求解只是建议性原因，尚未确认。

本批查询修复及新旧检查点兼容已实现；匹配 SDK 构建、7 项无 Creo 的 SDK 契约检查、全量 455 项单元和增量风格检查通过。真实约束/面法向/保存重载因会话门槛失败未执行，不据 SDK 替身结果宣布求解通过，见[本轮验证记录](../validation/FEEDBACK-0.3.7-IMPLEMENTATION-2026-10-20.md)。

## 范围与验收

覆盖固定放置→约束放置、已约束件更新、独立工具/计划入口；将约束存储、求解状态和实际位姿分开检查。对于可解约束，返回的矩阵及实际面位置/法向满足明确残差公差，underconstrained/冲突标志与求解结果一致，保存重载后仍满足，revision 正确。

相冲突/无效约束保留具体失败原因，原元件位姿、约束与检查点可恢复；不以手动 Creo 再生作为默认完成条件。偏移丢参与矩阵手性分别由 BUG-041/045 验收，不因本项通过一并关闭。

后续使用 Windows x64 / 本机 Creo 12.4 / 匹配 SDK、适用开发检查及装配实机回归，记录输入、job/model、矩阵/残差和重载。源 Creo 9 未独立复测，本次仅登记。

## 2026-10-23 外部 Creo 9 证据补录（第八轮，2026-10-25 归档登记）

- 环境：外部 Windows 10 / Creo 9.0.0.0（release 41）/ 服务 0.5.0；模型 wb_acc_asm，元件 c1 原放置 (-30,20,0)+绕 Z 30°，施加 mate+align+align 于三正交基准面、零偏移。
- **本轮实测**：施加约束后 `transform_to_parent` 仍为旧放置（平移 (-30,20,0)、旋转 cos30°/sin30°）；`creo_regenerate` 成功后**位姿仍为原放置**。约束几何要求三基准面重合（零偏移），期望变换应为单位矩阵，实际 30° 旋转法向不可能满足——装配留在违反新约束的状态，而 `component_constraints` 返回 succeeded、`underconstrained=false`，无不一致提示。
- 读侧改善确认：0.4.3 位姿查询修复后 `creo_inspect_session_assembly` 报告与真实位姿一致，调用方能发现不一致。**读侧改善与写侧失败分别记录**，不承诺通用期望矩阵求解器。
- 写侧重解（一致性自检 `placement_matches_constraints`、重解调用序列排查）为后续保留范围，收到排期再实施。归档见 [feedback-0.5.0-0.5.1-2026-10-23](../validation/feedback-0.5.0-0.5.1-2026-10-23/manifest.json)。
