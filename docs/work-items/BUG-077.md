# BUG-077：注册表条目膨胀阻断收养与 reconcile 恢复通道（死锁）

类型：缺陷

优先级：P0

状态：开发中（2026-10-21 随 [0.4.4 反馈计划](../development/0.4.4-FEEDBACK-PLAN-2026-10-21.md) 第一阶段登记）

目标版本：待定（按阶段独立交付；兼容修复使用下一未发布 PATCH，新增公开工具按项目规则使用 MINOR——本条含新增工具，版本归属由交付时确定）

来源与关联：[0.4.5/Creo 10 反馈](../validation/feedback-0.4.4-2026-10-21/report-registry-bloat.md) §4.1（P0 死锁）与 §5（P0 膨胀治理）；BUG-076 的根因后续条目（076 的定位诊断与资料分离不覆盖注册表条目本身）。

## 问题或目标

已证实现象（外部 Creo 10 / 0.4.5，2026-10-21）：

1. **收养阻断（BUG-076 已定位根因）**：单个历史模型注册表条目 `models\c437cace0625425496fec62d8c14743a\model.json`（`track_p01b`，21,472,751 字节 > 16 MiB 预算）在 `origin_conflict_scan` 阶段阻断**所有零件**的收养——冲突扫描需全量读取每个 `model.json`，与被收养零件无关。
2. **reconcile 死锁（本条核心）**：同一文件也阻断 `creo_reconcile_model`（`Recovery metadata exceeds the 16 MiB read budget`，裸 `isError` 无结构化字段）。adopt 诊断的 recovery 指引要求"保留文件、走诊断流程"，而唯一官方治理通道 reconcile 自身全量读取同一文件——两条路都走不通，用户只剩手工改删注册表（恰是 recovery 指引禁止的动作）。
3. **膨胀机制**：`generic_bridge.py` 每次成功编辑把完整 `aliases`（含逐实体 geometry/entity_ids 映射）与 `inspection` 内联写入 `model.json`；多次 axis_pattern/geometry_transform 追加后无界增长（同模型 8.4MB 备份 → 21.4MB 数小时）。线索：第二名 `hull` 目录 39MB、model.json 3.4MB，接近预算。

预期行为：

- reconcile 的预算错误升级为结构化诊断（稳定原因码 `RECOVERY_METADATA_BUDGET_EXCEEDED` + metadata_kind/相对路径/实际字节数/预算/失败阶段/job/model 标识/恢复指引），同步错误与后台任务返回一致。
- 注册表条目拆分为小型控制记录（所有权、状态、revision、作业关联）+ 内容寻址详情 sidecar（aliases/inspection 完整资料分块、按需读取）；统一预算不提高。
- 显式迁移流程兼容历史（含超限）条目：原始字节备份、摘要、迁移日志，详情先持久化、控制记录原子发布，中断可识别并续作，不改变模型身份和历史结论。
- 收养冲突扫描改用完整性核验的控制记录；登记存在但无法核验（超限/损坏）时明确拒绝并给迁移指引，不静默跳过。
- revision ≥ 1 的已保存超限模型保留可编辑性，不套用仅适用于无保存文件 revision 0 的 `abandon_new`。

## 范围

本次包含：

- `src/creo_mechdog/reconciliation.py` `_read` 预算错误结构化；恢复指引指向注册表健康检查与迁移工具。
- 新增统一持久化模块（包内）：model.json 控制记录读取（预算+损坏检查、结构化拒绝）、内联详情拆分（内容寻址 sidecar）、原子写、按需加载；所有 model.json 登记写入点（generic_bridge 提交/收尾、adoption、reconciliation）经过该模块。
- 请求侧详情引用化：发给原生执行器的 `model.aliases`/`model.inspection` 以受控引用传递（native 兼容旧内联），超限模型的编辑/回滚/恢复请求不再受读取预算约束。
- 收养冲突扫描（`_origin_conflict`）与会话关联（`session_models._associations`）读取控制记录；登记损坏时冲突扫描拒绝、会话关联维持尽力而为。
- 显式迁移工具（inspect/apply 双模式 + 幂等键）：逐条目备份→详情 sidecar→原子发布控制记录→追加迁移日志；重复执行幂等。
- 单元测试：16 MiB 边界、各类恢复文件超限、缺失/篡改详情、迁移中断续作、重复执行、旧内联格式兼容、超限模型迁移后别名解析/编辑/revision 推进语义。

不包含：统一提高预算；跳过历史登记；删减几何核验；revision 16 已保存模型的 `abandon_new` 化处理；FEAT-047 健康检查工具本体（另卡，共享本条的迁移状态口径）。
