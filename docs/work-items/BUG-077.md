# BUG-077：注册表条目膨胀阻断收养与 reconcile 恢复通道（死锁）

类型：缺陷

优先级：P0

状态：验收中（2026-10-21 第一阶段实现完成：单元 515 项、dev_check、SDK 构建通过；实机 >16 MiB 夹具与原环境复测开放）

目标版本：待定（按阶段独立交付；兼容修复使用下一未发布 PATCH，新增公开工具按项目规则使用 MINOR——本条含新增工具，版本归属由交付时确定）

来源与关联：[0.4.5/Creo 10 反馈](../validation/feedback-0.4.4-2026-10-21/report-registry-bloat.md) §4.1（P0 死锁）与 §5（P0 膨胀治理）；BUG-076 的根因后续条目（076 的定位诊断与资料分离不覆盖注册表条目本身）。

## 问题或目标

已证实现象（外部 Creo 10 / 0.4.5，2026-10-21）：

1. **收养阻断（BUG-076 已定位根因）**：单个历史模型注册表条目 `models\c437cace0625425496fec62d8c14743a\model.json`（`track_p01b`，21,472,751 字节 > 16 MiB 预算）在 `origin_conflict_scan` 阶段阻断**所有零件**的收养——冲突扫描需全量读取每个 `model.json`，与被收养零件无关。
2. **reconcile 死锁（本条核心）**：同一文件也阻断 `creo_reconcile_model`（`Recovery metadata exceeds the 16 MiB read budget`，裸 `isError` 无结构化字段）。adopt 诊断的 recovery 指引要求"保留文件、走诊断流程"，而唯一官方治理通道 reconcile 自身全量读取同一文件——两条路都走不通，用户只剩手工改删注册表（恰是 recovery 指引禁止的动作）。
3. **膨胀机制**：`generic_bridge.py` 每次成功编辑把完整 `aliases`（含逐实体 geometry/entity_ids 映射）与 `inspection` 内联写入 `model.json`；多次 axis_pattern/geometry_transform 追加后无界增长（同模型 8.4MB 备份 → 21.4MB 数小时）。线索：第二名 `hull` 目录 39MB、model.json 3.4MB，接近预算。

预期行为：

- reconcile 的预算错误升级为结构化诊断（稳定原因码 `RECOVERY_METADATA_BUDGET_EXCEEDED` + metadata_kind/相对路径/实际字节数/预算/失败阶段/job/model 标识/恢复指引），同步错误与后台任务返回一致。
- 注册表条目拆分为小型控制记录（所有权、状态、revision、作业关联）+ 内容寻址详情 sidecar（aliases/inspection 完整资料分块、按需读取）；统一预算不提高。
- 显式迁移流程兼容历史（含超限）条目：原始字节备份、摘要、迁移日志，详情先持久化、控制记录原子发布，中断可识别并续作，不改变模型身份和历史结论。
- 收养冲突扫描改用完整性核验的控制记录；登记存在但无法核验（超限/损坏）时明确拒绝并给迁移指引，不静默跳过。
- revision ≥ 1 的已保存超限模型保留可编辑性，不套用仅适用于无保存文件 revision 0 的 `abandon_new`。

## 范围

本次包含：

- `src/creo_mechdog/reconciliation.py` `_read` 预算错误结构化；恢复指引指向注册表健康检查与迁移工具。
- 新增统一持久化模块（包内）：model.json 控制记录读取（预算+损坏检查、结构化拒绝）、内联详情拆分（内容寻址 sidecar）、原子写、按需加载；所有 model.json 登记写入点（generic_bridge 提交/收尾、adoption、reconciliation）经过该模块。
- 请求侧详情引用化：发给原生执行器的 `model.aliases`/`model.inspection` 以受控引用传递（native 兼容旧内联），超限模型的编辑/回滚/恢复请求不再受读取预算约束。
- 收养冲突扫描（`_origin_conflict`）与会话关联（`session_models._associations`）读取控制记录；登记损坏时冲突扫描拒绝、会话关联维持尽力而为。
- 显式迁移工具（inspect/apply 双模式 + 幂等键）：逐条目备份→详情 sidecar→原子发布控制记录→追加迁移日志；重复执行幂等。
- 单元测试：16 MiB 边界、各类恢复文件超限、缺失/篡改详情、迁移中断续作、重复执行、旧内联格式兼容、超限模型迁移后别名解析/编辑/revision 推进语义。

不包含：统一提高预算；跳过历史登记；删减几何核验；revision 16 已保存模型的 `abandon_new` 化处理；FEAT-047 健康检查工具本体（另卡，共享本条的迁移状态口径）。

## 实现与证据

2026-10-21 实施于分支 `codex/bug077-registry-split`（自 main `e3a7480`）。

### 膨胀来源核对（本机实证）

本机 526 条登记分布（迁移前）：最大条目 329,383 B，其 `inspection` 128,704 B + `aliases` 34,754 B（单别名 `sk_big` 34,742 B，含数千 `entity_ids` 映射）+ 其余；第二/三名（197KB/172KB）为 `inspection` 与 `last_live_inspection` 各占约 37KB。**确认报告推断成立**：`generic_bridge.py` 每次成功编辑把完整 aliases/inspection 内联写入 model.json，`write_model` 前的 `aliases=result["aliases"]`（原 447 行）形成无界累积；检查全库无消费者依赖 `aliases` 键在 model.json 内联存在（native 3 处、Python 6 处已逐一核对）。

### 变更

- 新增 `src/creo_mechdog/model_registry.py`：统一注册表持久化。`write_model` 先把 aliases/inspection/last_live_inspection 写入 `models/<id>/details/` 内容寻址 sidecar（路径/SHA256/字节数绑定）再原子发布控制记录；`read_control` 按预算+链接+类型检查读取，超限抛结构化 `RegistryBudgetExceeded`；`aliases_of`/`inspection_of` 按需解析并兼容旧内联；`detail_digests`/`semantic_view` 提供与存储形态无关的语义比较。
- 新增 `src/creo_mechdog/registry_ops.py`：`creo_migrate_registry`（inspect/apply + 幂等键 + 目标集指纹）；逐条目先备份原始字节为 `model.json.pre-split-bak`（job 文件为 `*.pre-split-bak`），详情先持久化、控制记录后发布，动作追加到 `models/registry-migration.jsonl`，apply 结果按键持久化可重放；同键换目标集拒绝。
- `reconciliation.py`：`_read` 升级为 `RecoveryMetadataBudgetExceeded`（RECOVERY_METADATA_BUDGET_EXCEEDED + 六要素 + 指向健康检查/迁移的 recovery）；`_snapshot` 的 native 原文件超限时不再致命，改用拆分后的 job result 供给 candidate（evidence 标注来源文件）；candidate 携带 `aliases_ref`；`_check_execution` 改用 `semantic_view` 比较（拆分不构成"模型变更"）；`_native_request` 与 accept_saved 路径改引用优先。
- `adoption.py`：`_origin_conflict` 改为控制记录读取（大小+完整性预检）；超限抛既有 `AdoptionMetadataBudgetExceeded`，损坏条目抛 `AdoptionRefused(registry_entry_unreadable)` 并给迁移指引——不再静默跳过历史登记；六个登记写入点全部经 `write_model`。
- `generic_bridge.py`：`model_info` 经 `read_control`；`list_models` 单条损坏/超限以占位条目继续；组件图与重复标签检查用 `aliases_of`；submit 请求视图引用优先（legacy 内联保留，`aliases` 始终以对象到达 native）；成功收尾以结果中的引用替换模型详情键并清除陈旧内联；`split_job_result` 防 job.json 反复内联膨胀。
- `model_queries.py`/`server.py`：aliases 章节与组件列表按需解析引用；`bridge.py` compact 透传 `aliases_ref`/`alias_count`。
- native `generic.cpp`：`aliases_ref` 与 `inspection_ref` 解析（含 component_sources 内联化、回滚路径、主模型 verify_saved），旧内联请求保持兼容。

验证（515 项单测全过，含新增 `tests/unit/test_model_registry.py` 13 项：控制记录 <64 KiB、语义视图形态无关、篡改引用拒绝、超限条目结构化六要素、冲突扫描损坏拒绝与拆分后仍检出冲突、inspect 无副作用、apply 拆分+备份+日志、幂等与键冲突、损坏条目拒绝、健康报告五态分类与单条异常不中断）；`tools/dev_check.py` success=true 无新增语言问题；`bridge.py build` SDK 编译通过；本机 526 条登记未改动。
