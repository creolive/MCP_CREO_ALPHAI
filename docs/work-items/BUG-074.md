# BUG-074：无进程身份的历史作业永久阻断模型恢复

日期：2026-10-20。类型：缺陷。优先级：P1。状态：验收中。目标版本：未排期。

来源：0.3.7 剩余反馈处理计划及 2026-10-18 Creo 9 第七轮报告；关联 FEAT-018、BUG-059。

## 现象与范围

旧作业缺少 runner/native owner PID 和创建时间，inspect 将身份缺失等同无法证明停止，四动作均永久不可用。新增可核验的跨 Windows 启动停止证据，仍保留每种动作原有条件、所有权、令牌、revision、幂等和锁内终态保护。不清理用户文件、不结束进程、不自动重交原作业。

复用 windows_boot.boot_info 的 WMI 与内核时钟交叉核验；只接受绑定本模型、控制记录及记录时间均在已核实启动前的历史作业。身份完整但活动或查询不确定的所有者不走历史兜底。同次启动、证据缺失、时间异常、文件变更及启动时间不可核验均拒绝，并给操作指引。证据进入 token 绑定，准入和执行前重新校验。

## 验收标准

- Windows/Python：先用隔离旧作业复现四动作禁用，再验证跨启动证据只解除 owner 门槛，各动作仍有自身条件。
- 覆盖同次启动、时钟不一致/查询失败、记录缺失、文件触碰/替换、活动 owner、证据过期、幂等和准入后变化；全量单元及 dev_check 通过。
- 原生与 WorkBuddy 分层记录；隔离夹具不作为真实恢复通过，现有 Toolkit 连接/注入限制继续适用。

## 实现与证据

2026-10-20 续做范围：复核发现首批兜底只处理整个 identity 缺失，未覆盖“只有 PID、没有创建时间”的旧 runner/native_owner，以及仅有 native_pid 的检查点。先增加隔离复现，再让这类不完整身份使用相同的跨启动证据；完整活动/权限未知身份、无可靠启动时间及同次启动的拒绝继续保持。不得仅因当前 PID 不可区分就解除保护。

续做结果：两项新增用例修复前实际失败，修复后通过；新增格式错误保护后共13项历史恢复测试、相关恢复53项及全量458项单元通过，dev_check通过。字符串创建时间不得被当作PID复用；不完整身份仍需全部跨启动证据。尚无真实系统重启后的原生恢复或WorkBuddy验收，状态保持验收中。

实施基线 main cfcea22（0.4.2），分支 codex/bug-057-feedback-037。10 项新增隔离回归及全量 455 项单元、dev_check 通过。真实跨启动作业的原生恢复、续作及 WorkBuddy 未验证，不能以夹具代替。会话就绪探测失败前未提交任何建模或恢复作业，现有保护保持。详见[本轮验证记录](../validation/FEEDBACK-0.3.7-IMPLEMENTATION-2026-10-20.md)。

## 2026-10-23 外部 Creo 9 证据补录（第八轮，2026-10-25 归档登记）

- 环境：外部 Windows 10 / Creo 9.0.0.0（release 41）/ 服务 0.5.0；对象为报告者 0.3.7 报告的死路模型 `wb_fulltest_blade`（0.3.0 时代作业，无进程身份，此前四种恢复动作永久不可用）。
- inspect：`runner/worker.stopped=true`、`reason="Historical owner predates verified OS boot"`；`stop_evidence` 含启动时间 2026-10-22T10:07:30Z、双源核验（Win32_OperatingSystem.LastBootUpTime + GetTickCount64）、作业目录逐文件 created/modified 纳秒时间戳（全部早于本次启动）。
- apply：abandon_new（省略 pending 字段）→ `succeeded`/`reconciliation_committed`/模型 `abandoned`/`recovery_pending` 清空。
- **仅关闭实际覆盖的外部跨启动 abandon_new 子项**（含双源启动核验与逐文件时间戳）；其余恢复动作矩阵、其他历史记录形态按卡保留。该时间+文件核验规则不得外推到身份完整但存活/不可查询的进程（见 [BUG-081](BUG-081.md)）。归档见 [feedback-0.5.0-0.5.1-2026-10-23](../validation/feedback-0.5.0-0.5.1-2026-10-23/manifest.json)。
