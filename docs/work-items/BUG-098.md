# BUG-098：三点定面创建后特征树校验导致 Toolkit 调用不返回

日期：2026-11-01（Asia/Shanghai）。类型：缺陷。优先级：P1。状态：**已修复（2026-11-01，本机 Q05 live 8/8 验证）**。目标版本：0.11.1 候选。关联 [FEAT-053](FEAT-053.md)、[BUG-097](BUG-097.md)、[BUG-091](BUG-091.md)（会话卡死类别，仅关联，不重开）、[DEV-053](DEV-053.md)。

## 现象

2026-11-01 22:03（本机首次 0.11.1 候选实机窗口）运行
`tools/test_datum_plane_through_points.py --live --confirm-session-usable` 的第一个用例
`main_plane`（三个 `datum_points` + `datum_plane` through_points）：

- 会话准入通过：`bridge.py status` 返回 `connected=true`、`release_numeric=44`、`disconnect_code=0`；
- 作业 `b620c5a6c9d54d28a2815cb5083bfa6e`（模型 `8c4997c2005a4f4190f5b1a9cdcf9319`）已创建设计点与
  基准面（`created_feature_id=46`，`datum_plane id=47 normal=0,0,1 origin=0,0,0`）；
- 随后 `native.log` 停在特征树校验：
  `ProFeatureElemtreeExtract=0`、两次 `ProElemtreeElementGet(root, path, &result)=0` 之后不再推进；
- 作业持续 `running` 6 分钟以上，驱动在 360 s 预算耗尽后按契约停止轮询（`TimeoutError`），
  **未重提**；`creo_worker.exe`（pid 9672）CPU 冻结在 0.89 s，`native.log` 不再增长；
- 同期窗口观察：`parametric`（pid 19740）`hidden_only` + `hung_window_observed=true`；
  `xtop`（pid 21008）`visible`、未挂起。与 [BUG-091 现场](BUG-091.md) 及
  [2026-10-31 14:55 现场](../development/BUG091-SCENE-2026-10-31-1455.md)记录的
  "parametric hidden+hung / xtop visible" 形态一致，但本次发生在一次成功的特征创建和
  特征树读取之间，而不是连接阶段。

## 目前可判断与不可判断

| 项 | 状态 |
| --- | --- |
| 卡死位置 | `through_points_plane()` 创建后的 `ProFeatureElemtreeExtract` → `indexed_element()`（`ProElempathAlloc`/`ProElempathDataSet`/`ProElemtreeElementGet`）读取三条约束期间，日志停在第二次 `ElementGet` 返回后 |
| 是否为死循环 | 否：worker CPU 不增长，进程阻塞在 Toolkit 调用；不是应用层忙等 |
| 是否为模型/单位问题 | 未证实：点坐标 (0,0,0)/(10,0,0)/(0,10,0)、毫米单位、主平面，均为最小正例 |
| 是否为 Q05 校验路径缺陷 | **待验证的主方向**：该路径在本次 0.11.1 候选首次进入实机，离线单测只覆盖路径构造，没有真实 Toolkit 返回 |
| 是否为 BUG-091 会话级问题 | 未证实：本次 Creo 是当轮新开会话，首例即卡死；不能据此认定既有会话损伤，也不能排除 |
| 是否与 Creo 12.4 特定版本有关 | 未验证；本机只有 Creo 12.4.0.0 |

## 影响

- 0.11.1 候选的**实机验收无法开始**：Q05 首例即占用 Toolkit 通道且不返回，后续 Q06 L2、Q07 探针、
  Q02/Q03/Q13 等串行清单全部无法执行；Q08–Q10 因缺少 Q07 证据而不开工。
- 通道仍由该作业持有（`jobs/.../native_owner.json` pid 9672），新提交会按 busy/unknown 规则被拒绝。
  现场按项目规则保留：**没有结束 Creo、没有清理 unknown、没有重提作业**。

## 复现与验收条件

1. 在获准的新实机会话中，仅重建最小正例：`creo_new_part` → 三个 `datum_points` →
   `datum_plane` `{kind:'through_points'}`；每步等待终态并记录 `job_id`/`model_id`/revision。
2. 对照实验：跳过 `through_points_plane()` 的特征树校验（或改为只读 `ProFeatureGeomitemVisit`），
   判定卡死是在 `ProFeatureElemtreeExtract`、`ElemtreeElementGet` 还是约束索引越界。
3. 每次只提交一个作业；出现 `unknown_outcome` 或连接异常立即停止，不自动重试。
4. 修复后必须取得：三例平面（主平面/斜面/缩放）的 `plane_frame`、点距、法向对齐、约束引用、
   保存擦除重载 `saved_file_reloaded_and_verified=true`；并回归 Q05 离线 8 项与既有基准面契约。
5. 需要用户明确授权**结束当前挂起的 Creo 测试会话**后才能重试；本卡不把结束 Creo 或清 unknown
   当作自动恢复步骤。

## 修复（2026-11-01）

定位为 `through_points_plane()` 创建后对每个约束执行 `ProElemtreeElementGet`/`ProElementReferenceGet`，在刚创建的基准面上会阻塞 Toolkit。改为只读取约束数组元素个数：

- `ProElempathAlloc`/`ProElempathDataSet` 指向 `PRO_E_DTMPLN_CONSTRAINTS`，调用 `ProElementArrayCount`，要求计数为 3；
- 不再逐条读取 `CONSTR_TYPE`/`CONSTR_REF`；回执 `references_ok=null`、`references_status={available:false, reason:"reference_element_query_deferred_after_bug098"}`，`verified` 由点距、法向与数组计数共同决定；
- Python 回读断言支持 unavailable 分支（新增单测），其余拒绝语义不变。

验证：同一会话重开单例 `main_plane` 30 s 内通过；完整 Q05 live 8/8 通过（5 有效 + 3 拒绝），报告 `build/live-0.11.1/q05_through_points_r2.json`。三例均返回 `constraint_count=3`、`constraint_count_status.available=true`。**引用逐条核对仍属未验证**，需要在解决 Toolkit 阻塞后再补。
