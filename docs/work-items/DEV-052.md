## 问题或目标

0.9.0 已正式发布后，用户又提交了七份 0.8.x 期间的外部反馈（本机 `Downloads/0.8.x`）。这批反馈在本轮开始前既没有归档，也没有对应的固定 ID；同时 `docs/DEVELOPMENT.md` 与 `docs/work-items/DEV-051.md` 的当前入口仍停留在 0.8.5 / 「十个离线提交未合 main」阶段，与 0.9.0 已发布的最终账并存，形成互相矛盾的当前状态。

本卡的目标是：把七份原件逐字节归档并逐件核 SHA256；核号登记下一批固定 ID；按 0.9.0 最终账校正当前入口；给后续窗口一份固定 ID ↔ N 编号 ↔ 证据路径的映射，使接手者不必重新推导本轮讨论。

范围包含：原件归档目录 `docs/validation/feedback-0.8.x-2026-10-30/`、本卡与三张新工作卡、`docs/BACKLOG.md` 登记、`docs/DEVELOPMENT.md` 当前入口、`docs/work-items/DEV-051.md` 首页与当前矩阵、`docs/development/RELEASING.md` 当前版本。

不包含：任何实现、单元测试、原生构建、Creo 实机、MCP 客户端创建、版本号变更、`main` 合并、push 或 Release 发布。既有 ID 的技术状态不因本卡改变。
