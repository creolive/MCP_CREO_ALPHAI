# BUG-064：自定义基准面草图两处硬失败（surface 引用与纯轴向 u_axis）

日期：2026-10-18。类型：缺陷。优先级：P1。状态：待复现。目标版本：未排期。

来源：外部 0.3.5 能力边界反馈 P3（Creo 10.0.0.0 / release 42），见[原件](../validation/FEEDBACK-0.3.5-CAPABILITY-2026-10-18.md)。关联 [FEAT-008](FEAT-008.md)（字典平面引用格式说明）。

## 报告现象（外部实机）

同一倾斜基准面（id 163，法向 (0.587785,0.809017,0)）上的两组失败：

1. **`kind:'surface'` 引用必失败，与文档不符**：文档写 `plane` 可为 `{reference:{kind:'surface',id:N},origin,u_axis}`；实测 `surface` + 30 段弧闭环或仅 4 条直线矩形 + autodim 均 `AutodimensionSketch failed with code -1`（排除轮廓复杂度）；**未文档化的 `datum_plane` 才成功**。
2. **`u_axis` 为纯轴向时报 Zero direction vector**：Right 平面上 `u_axis:[0,0,-1]` 与 `[0,0,1]` 均 `Zero direction vector`（execute_sketch 失败）；对照含 X/Y 分量的倾斜 u_axis 成功。疑似内部 v 向计算只取 X/Y 分量。后果：摆杆狗骨截面需要 (u=−Z, v=+Y) 手性帧，**无其他途径建立**，零件主体阻断。

## 待核对

- surface 引用分支是被校验拒绝还是进入原生后失败；文档与实现对齐（支持 surface、或改文档为 datum_plane 并说明）。
- u_axis→v 向公式的纯轴向退化；修复应归一化 u 并对 |n×u|<eps 给出"u_axis 与平面法向平行"的明确报错，而非 Zero direction vector。
- 反馈另建议增加不依赖几何引用的 `plane={origin,normal,u_axis}` 写法（规格直接给平面方程的场景）——属能力扩展，核实后归 FEAT 候选另行评估。
