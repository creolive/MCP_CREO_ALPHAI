## 已闭环（不再重复做）

- `tools/package.py` 的 `--seed-archive` 为必填，先 `release_integrity.validate_release_inputs()` 再写出源码包/stage；失配 exit 非零。
- `seeds.install_seed_library(archive_file=...)` 先 `validate_seed_archive()`（摘要、版本前缀、成员路径、原生 PRT 字节），再写入目标。
- `docs/development/RELEASING.md` 第 5 步已写入“把实测 SHA256 显式回填到 `docs/seed_package.json` 的 `seed_archive_sha256`，重建一次确认哈希不变”。
- `tests/unit/test_release_integrity.py` 已有真实归档安装、篡改一字节拒绝、错摘要拒绝三例。

## 残留缺口

1. `SeedArchiveFixture.setUp()` 自己调用 `write_record(self.digest, VERSION)` 写记录，因此**仓库里真实的 `docs/seed_package.json` 是否等于“用当前源码当场重建的种子包哈希”，没有任何测试或 `dev_check` 断言**。发布者忘回填时，只有真正跑 `tools/package.py` 才失败。
2. `tools/package_seeds.py` 生成归档后仍只 `print` 一句提示，不校验、不退出非零、不回写。

## 范围

包含：

- 新增仓库级用例：以 `ROOT` 为源构建种子归档到临时目录，并与仓库 `docs/seed_package.json` 的 `seed_archive_sha256` / `compatible_server_version` 比对；不一致必须失败并给出“回填该哈希”的可执行提示。
- `tools/package_seeds.py` 增“构建后断言仓库记录一致”的默认行为（可用显式 `--allow-record-mismatch` 关闭，仅用于准备回填前的草稿构包），失配 exit 非零。
- 不改变 `docs/seed_package.json` 的字段语义，不自动改源码文件（回填仍由发布者显式执行）。

不包含：

- 不自动写入 `version.py` 或种子清单；不做联网发布。

## 2026-11-02 交付（随 0.11.2 发布）

- `src/creo_mechdog/release_integrity.py` 新增 `assert_repo_record_matches(root, seed_archive, *, record_path=None)`：只比对 `seed_archive_sha256` 与 `compatible_server_version`，失配消息直接给出“回填 `docs/seed_package.json`”的下一步；成员级校验仍由 `validate_seed_archive` 负责，不重复。
- `tools/package_seeds.py`：构包后默认调用该断言；失配时**保留刚构建的归档**（供发布者读摘要回填）并 `return 2`；`--allow-record-mismatch` 仅用于准备回填并打印警告；通过时才写 `.zip.sha256` 边车。`main(argv)` 可注入参数，便于测试。
- `docs/development/RELEASING.md` 第 5 步写入新闸门与“`--allow-record-mismatch` 不得用于发布”。
- 验证：`tests/unit/test_seed_record_gate.py` 7 项通过（真实重建与仓库记录一致 `f1794794…`、陈旧摘要、版本不符、缺归档、CLI 失配非零且保留归档、CLI 匹配为 0、显式跳过）。连同 `tests/unit/test_release_integrity.py` 共 32 项通过。

## 未验证 / 风险

- 该闸门只覆盖“仓库记录与源码一致”，不覆盖远端 Release 附件与 body 记载（仍按 RELEASING 第 7 步人工核对）。
- 重建归档需写入临时目录，注意清理与路径越界；不写入仓库目录。
- CLI 新增的 `return 2` 语义与旧脚本“只打印提示即 0”不同：任何仍假设旧行为的本地脚本需同步。
