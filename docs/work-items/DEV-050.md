## 问题或目标

统一开发检查入口 `tools/dev_check.py` 的单元阶段硬编码 300 秒预算，与实际约 347 秒的完整套件矛盾：真实运行会被判 `timed_out`，只能用拆开的命令（`tools/test_unit.py`）代替统一入口，长期会把拆开通过冒充统一入口通过。目标是给单元阶段一个**有界、可配置**的超时预算，并如实报告真实结果。

## 范围

- CLI 契约：新增 `--unit-timeout-seconds`，正整数，默认 **900** 秒；0、负数、非整数在参数阶段拒绝。`--skip-unit` 仍不运行单元，且不移除超时上限语义。
- 报告契约：development_check 报告记录 `unit_test_timeout_seconds`；继续保留 passed / failed / timed_out 三态区分与非零退出码；`timed_out` 不得被报告为 success。
- 新增回归：`tests/unit/test_dev_check_timeout.py`，覆盖默认预算、显式预算、非法参数、skip-unit、子进程非零、TimeoutExpired 与正常完成（用替身重现，不真等 347 秒）。
- 不包含：只改单元阶段；不改风格工具预算、不重建 [style-baseline](../development/style-baseline.json)、不绕过 Windows 检查、不改业务代码；最终统一入口全量运行留给 T08。
