# DEV-058：WorkBuddy 黑盒验收执行与回填

类型：工程整理（验收）

优先级：P3

状态：待规划

目标版本：未排期

来源与关联：[WorkBuddy 0.11.1 提示词](../validation/WORKBUDDY-0.11.1.md)、[根级规范 WorkBuddy 约定](../../AGENTS.md)、[开发入口 WorkBuddy 约定](../DEVELOPMENT.md#workbuddy-测试约定)、[DEV-053](DEV-053.md)（提示词随 0.11.1 交付）、[BUG-109](BUG-109.md)、[BUG-110](BUG-110.md)、[BUG-111](BUG-111.md)、[BUG-108](BUG-108.md)、[FEAT-052](FEAT-052.md)、[DEV-063](DEV-063.md)。

分类依据：执行时点与目标版本需用户确认，提示词需先改版，故为"待规划"。

## 问题或目标

按项目约定，WorkBuddy 验收 = **只用已连接的 MCP 工具对最终用户可见行为做黑盒验收**，不读源码、不跑本地脚本、不查 Git 与配置。现有提示词写于 0.11.1，此后的契约变化没有反映进去，且从未执行过。目标：产出对应版本的提示词、执行一次、把结论单独成档并回填。

## 已有成果（2026-11-03 核对）

- 提示词：[WORKBUDDY-0.11.1.md](../validation/WORKBUDDY-0.11.1.md)，七场景 + 报告要求（环境身份、失败清理与同名重建、已保存模型回滚、三点定面斜面草图、显式容差、busy 并发、阶段与分页、预览与上色回归）。
- **执行状态：未执行**。仓库内没有 0.11.1 或之后任何版本的 WorkBuddy 结果档；台账与各版发布记录一致记为"WorkBuddy 未执行/未验证"。历史报告（`WORKBUDDY-0.4.7-*`、`WORKBUDDY-0.5.0-open-file-2026-10-20.md` 等）只可作格式参考，与 0.11.x 无关。
- **可直接复用（0.11.2—0.11.6 未改这些契约）**：场景 0（环境与 `tool_count=95`）、场景 1（`failed_model_cleanup` 五字段 + 同名重建）、场景 2（已保存模型回滚 `rollback_status`）、场景 3（三点定面 + 三个负例，仅需补记草图新增字段，见下）、场景 5（真实并发 busy，含背靠背）、场景 7.1/7.3（预览与工具数）。
- **必须调整**：
  - 场景 4 容差：coordinates 的 1e-5 闸现在对"可证刚体平移且 ≤1e-2 mm"放行并标 `accepted_rigid=true`（0.11.6/BUG-108），"超出即失败"的预期需改写，并新增 `shape_deviation_mm`/`residual_mm`/`rigid`/`translation_mm` 观察。
  - 场景 6 阶段序列：0.11.6 起 `verify_model` 拆为 `verify_model_*` 子阶段并新增只读 `native_progress`（BUG-109），旧阶段名清单不完整；须把"子阶段推进/停滞归因"写成可判断项。
  - 场景 7.2 上色：0.11.3 起支持 `refresh_baseline`（缺 `appearance` 基线时实读填基线）与 `random:true`（FEAT-056），预期与拒绝文案需同步。
  - 需新增两节：`creo_reconcile_model` 的 `ack_failure`（对 `ready` 模型应被拒；成功路径无法在不冒组件风险的装配上安全构造，只能记"未验证"）与 `geometry_transform` 旋转范围（225° 提交前拒绝并给 -135；5 个 `keep_original` 副本中第 5 个在 0.11.6 已知失败于 `operation_index=4`，属未定因，提示词须要求"如实记录、不得据此判通过"）。

## 剩余范围

1. 出 0.11.6（或用户指定版本）版提示词：新文件，`WORKBUDDY-0.11.1.md` 原文不改。
2. 用户确认会话可用后执行一次，按场景记录工具与完整输入、`job_id`/`model_id`、终态、几何与参数、保存重载、revision、回滚、原始错误。
3. 结论单独成档并回填本卡与相关工作卡（BUG-108/109/110/111、FEAT-052、DEV-063 等），与开发者实机证据分开记录。

## 不包含

- 不做源码检查、不跑 `tools/test_*.py`/单元测试/`dev_check.py`、不做并发以外的压力或故障注入。
- 不启动、重启或结束 Creo，不清 unknown 保护，不重投已受理作业。
- 不把 WorkBuddy 结论写成开发者实机证据，也不反向用开发者证据替代。
- 无法由 MCP 观察的内部机制（文件占用、重试预算、临时文件清理、响应字节数）不纳入结论，记"无法确认"。

## 依赖与缺件

- 可用会话：`creo_session_status` 的 `connected=true`、`toolkit_code=0`，且操作者确认 GUI 可操作、无阻塞对话框。
- 目标版本的部署身份（版本号本身不足以证明修复已部署），由测试发起者提供。
- 用户对执行时点、目标版本与是否使用 0.11.6 编号的确认。
- 本卡不具备"自行开始验收"的授权：本次只做提示词差异核对。

## 执行步骤

1. 按上述差异改提示词，逐场景写明输入、可判断预期与报告字段。
2. 用户确认后执行；每场景独立隔离模型名，不触碰历史失败模型。
3. 并发结论文本只写在真实制造时间重叠时；否则记"未验证"。
4. 结果成档（建议 `docs/validation/WORKBUDDY-<版本>.md`），回填本卡、相关卡与台账，未覆盖项单列。

## 验收标准

| 环境 / 用例 | 命令或操作 | 可判断的预期结果 |
| --- | --- | --- |
| 文档 | 新版提示词评审 | 只含 MCP 场景、输入、预期与报告要求；无源码/Git/本地命令要求 |
| 执行 | 用户确认后逐场景 | 每场景给出通过/未通过/无法确认及依据字段与实测值 |
| 台账 | 回填 | 结论与开发者证据分开记录；未验证项显式列出；不据历史版本结论判通过 |
