# BUG-107：`HEADERS` 清单缺存在性过滤，Creo 10 首次构建硬崩溃

日期：2026-11-02。类型：缺陷。优先级：P1。状态：本批实现（离线验证；Creo 10 实机未验证）。目标版本：0.11.4。关联 [BUG-090](BUG-090.md)（同族：函数有 `MECHDOG_HAS_*` 门控、头文件清单没有）、[FEAT-055](FEAT-055.md)（G5 三算子保持待规划，探测头 DEV-055 仅台账登记）、[DEV-064](DEV-064.md)。

## 来源

- 原件：[0.11.1 反馈 F02 §1](../validation/feedback-0.11.1-2026-11-02/originals/2026-11-02CREO10.0.0.0-0.11.1-门控未延伸到头文件清单Probblh硬崩溃与盲孔口径标记第三次未加.md)；归档与逐章映射见 [MAPPING](../validation/feedback-0.11.1-2026-11-02/MAPPING.md)。
- 环境：外部 Creo Parametric 10.0.0.0 / Toolkit SDK 10.0.0.0 / VS2022 BuildTools 14.44.35207 / Python 3.13 / MCP 0.11.1。

## 现象（报告方实测，本仓库无 Creo 10 SDK 无法复现）

0.11.1 首次 `bridge.py build` 失败：

```
FileNotFoundError: 'D:\...\protoolkit\includes\Probbl.h'
→ RuntimeError: SDK constant generation failed
```

报告方本机存在性：`Probbl.h` 缺失；`ProTrim.h`、`ProStdSection.h`、`ProMerge.h`、`ProAsmcomp.h` 存在。失败链路本身可读（指向 `build/generate_constants.log`，日志含完整 traceback）。

## 当前实现（本批只读核对 0.11.3）

- `tools/generate_constants.py:7-41` 的 `HEADERS` 共 34 项，`"Probbl.h"` 在第 37 行，注释为 "Q07 G5 probe symbols…"。清单是**无条件**的：`generate()` 在 `:58-59` 直接 `(inc_dir / header).read_text(...)`，缺失即抛 `FileNotFoundError`。
- `:78` 的 include 段同样按 `HEADERS` 全量输出 `#include <...>`，与枚举扫描集合同源但都不做存在性判断。
- 本仓库 native 源码核对：无任何 `Probbl.h` 独有符号引用（P08 走 `ProSmtedgeContourGet`，属既有头），与报告方结论一致——该头目前只为 Q07 G5 落地预做准备。
- 既有门控先例：`PROBES`（交集为空不产生宏）、`FUNCTION_PROBES` + `MECHDOG_HAS_*`（`:43-50`），契约见 `tests/unit/test_g5_native_contract.py` 的 `GATED_SDK_CALLS`。
- 既有测试：`tests/unit/test_generate_constants.py` 覆盖 `PROBES`/`FUNCTION_PROBES`，无"清单缺头"用例。

## 范围

包含：

1. `generate()` 读取前对 `HEADERS` 做存在性过滤：缺失头**跳过读取**，只把存在的头写进 include 段；`HEADERS` 与 include 段来自同一份"可用头"集合，保证枚举集合与 include 集合永远一致。
2. 缺失清单可观测：写进 `build/generate_constants.log`（沿用既有日志通道），并在函数返回结构中可断言（当前只返回枚举计数，保持兼容）。
3. `GATED_HEADERS` 契约测试：`HEADERS` 里的头要么存在于参考 SDK、要么有显式跳过用例；`constants.inc` 不含缺失头的 include；全头存在时输出字节与旧行为一致。
4. 文档：`docs/COMPATIBILITY.md` 记"Creo 10/9 缺头不进编译单元"，`docs/DEVELOPMENT.md` 构建段落说明缺头跳过语义。

不包含：

- 不采用 `#if __has_include(...)`：`native/constants.inc` 在库外生成，编译期与生成期双闸门会出现"头存在但枚举未读"或"枚举已读但 include 被跳过"的偏差。
- 不改 `FUNCTION_PROBES`/`PROBES` 语义，不改枚举正则与宏排序。
- 不实现 G5 三算子（FEAT-055 保持待规划）。

## 证据

实现（2026-11-02，分支 `codex/DEV-064-r12-feedback0111`）：

- `tools/generate_constants.py` 新增 `available_headers(inc_dir) -> (present, missing)`；`generate()` 只用 `present` 驱动枚举扫描与 include 段，缺失头逐条打印 `MISSING_SDK_HEADER=<name>`（经 `bridge.py` 的 stdout 捕获落进 `build/generate_constants.log`），不写任何文件、不改枚举。
- 契约：`tests/unit/test_gated_headers.py`（4 项）——清单唯一且为裸文件名；**逐个抽掉清单中的任一头**仍生成成功且不产生该 include（31 个子用例，即"要么存在、要么有跳过用例"的可执行形式）；有本机 SDK 时 `present ∪ missing = HEADERS` 且实际 `constants.inc` 的 include 集合等于 `present`。
- 用例：`tests/unit/test_generate_constants.py` 新增 `MissingHeaderGateTests`（3 项）——缺头跳过且不出现在 include 段、`available_headers` 划分正确、全头存在时 include 块与旧行为逐行一致。
- 运行：`python -m unittest tests.unit.test_generate_constants tests.unit.test_gated_headers` → 13 项通过（本机 Creo 12.4 SDK `present=31 missing=0`）；`python bridge.py build` exit 0，`build/generate_constants.log` 无 `MISSING_SDK_HEADER` 行，5001 → 6563 常量（未变化），执行器 13 250 048 B / `a61fad90…`（0.11.3 基线一致，说明门控未改变全头场景输出）。
- **未验证**：Creo 10 / Creo 9 实机（本机无该 SDK）；报告方"跳过 `Probbl.h` 后构建成功"未在本机复现，缺头路径仅由离线夹具与契约覆盖。
