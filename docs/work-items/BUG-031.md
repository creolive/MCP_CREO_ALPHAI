## 现象与待验证根因

`creo_mirror.plane={"kind":"datum_plane","axis":"x","offset":45}` 在 job `33722efd` 失败：`Plane reference must identify exactly one surface; inspect the model and use a surface ID`，failed_stage=`execute_mirror`。offset=0 的 job `367d9f2f`、省略 offset 的 job `feaa568f` 成功；实体面 ID 对照也成功。

报告认为非零 offset 不受支持，但没有确认 x=45 的已有平面/实体面是否存在且唯一。`datum_plane` 引用的 offset 可能用于选择已有面，不能等同 `creo_datum_plane` 创建新平面的 offset；不同模型的成功/失败对照也需统一。先核对实际输入、能力示例、面匹配规则和基准特征引用支持，再判断实现错误或契约/诊断缺陷，不直接采用“复用 draft 解析器”的建议。

## 范围与验收

Windows x64 / Creo 12.4.0.0 / 匹配 SDK；仅镜像平面解析及其说明，不扩展所有工具自动创建基准面。

| 场景 | 可判断的完成条件 |
| --- | --- |
| 已有 x=45 的唯一平面 | 先创建并查询实际平面，再分别按支持的基准特征标签/ID与轴+offset 引用镜像；契约支持的形式成功，几何关于 x=45 对称，体积/bbox、原生特征和保存重载正确，revision +1 |
| 零/省略 offset、已有实体面 | 既有正例不回归，面法向和位置含义明确；各引用形式给可执行示例 |
| 无匹配或多匹配 | 按契约明确拒绝并说明“匹配已有面”与创建/显式引用的下一步；不误导为所有非零偏移均不可用；无残留特征，保存检查点/revision 保持 |

若确需凭参数创建临时平面，须先定义清理、标签与回滚契约；不把该扩展当作已承诺能力。开发者执行统一检查、受影响 SDK 构建和原生回归；WorkBuddy 通过 MCP 查询平面并验收几何及回滚。本次仅登记。

## 2026-10-16：0.3.2 字典平面补充证据

[0.3.2 报告 A](../validation/FEEDBACK-0.3.2.md) P3 记录草图字典平面 `{kind:datum_plane, axis:x, offset:20}` 仍报 `Plane reference must identify exactly one surface`，补 `reference` 容器后同样失败（job `334a1a1366374dccb15bd598f2b737ac` / `d14ce9cf5a4b419aa23d631749a010f7`）；正面变化是缺 `reference` 时先给明确 JSON 错误。报告未提供实际平面/面 ID 清单与环境身份，仍按本卡先核对引用形式与匹配规则，不据此断定所有非零偏移均不可用。

## 2026-10-16：履带多共面基准面线索

[履带报告](../validation/TRACK-FEEDBACK-2026-10-16.md)第十四节据称 datum_plane/offset=0 多匹配时取最小ID，而 plane 多匹配报非唯一；这是Creo10/0.3.2的源码/实测混合来源，本次未复现。将零偏移多共面、已命名基准特征/实体面的对照加入本卡：先确认默认基准选择是否为既有有意契约，再定义可见选中对象、候选列表与显式ID/标签路径；不能直接移除分支破坏旧调用，也不保证新增候选引用形式当前已支持。FEAT-008同步“匹配已有面”和字符串offset建构造面的不同语义。
