# BUG-110：装配作业失败后四个恢复动作全不可用，只能手改登记文件

日期：2026-11-03。类型：缺陷（恢复可用性）。优先级：P1。状态：本批实现（新增元数据动作 `ack_failure`）。目标版本：未定（R13 版本待裁定）。关联 [BUG-105](BUG-105.md)（零变更失败 `ack_no_mutation`）、[BUG-096](BUG-096.md)、[FEAT-048](FEAT-048.md)（装配重建）、[FEAT-052](FEAT-052.md)（装配上色）、[DEV-065](DEV-065.md)。

## 来源

- 原件：[0.11.5 反馈 F02 核心问题 3](../validation/feedback-0.11.5-2026-11-03/originals/2026-11-02CREO10.0.0.0-0.11.5-刚性平移仍被拒且G5四版未动.md)；归档与逐章映射见 [MAPPING](../validation/feedback-0.11.5-2026-11-03/MAPPING.md)。

## 现象（报告方实测）

装配命中任何作业失败（**含 connect 阶段零变更的预检拒绝**）后，四个恢复动作全部返回：

```
"Assembly/drawing reconciliation is not supported"
```

唯一出路是手改 `models/<id>/model.json` 的 `status`。装配是上色（FEAT-052）与装配重建（FEAT-049）的唯一载体，所以这条死路直接影响两个已交付能力。

## 当前实现（本批只读核对，基线 `main@b3f6d43`）

- `src/creo_mechdog/reconciliation.py:526`：
  ```python
  supported = model.get("model_type", "part") in ("part", "sheetmetal")
  ```
- `:545-561` `states[action]["available"] = bool(stopped and supported and ok and status != "abandoned")`，`reason` 对装配固定为 `"Assembly/drawing reconciliation is not supported; preserve component ownership"`。
- `:562-589` BUG-105 的 `ack_no_mutation` 已允许装配（"This is a metadata transaction only, so assembly/drawing models are eligible too"），但要求 `status=="failed"`、无 pending/recovery、`rollback_status!="failed"`、`baseline.verified is True`——只覆盖"可证零变更"。
- `:24-28` `ACTIONS` 元组目前为 `restore_baseline`/`accept_saved`/`accept_live`/`abandon_new`/`ack_no_mutation`。
- R12 MAPPING §四 曾记录"装配四恢复动作扩展"本批不做，本轮只新增独立元数据动作，不扩展四个触碰组件所有权的动作。

## 范围

包含：

1. **恢复动作分层**：四个既有动作继续要求 `part`/`sheetmetal`（组件所有权与磁盘文件不动，理由不变）；新增元数据动作 `ack_failure` 不区分模型类型。
2. **`ack_failure` 契约**：需要 `confirm_failure_ack=true`、`evidence_token`、`expected_revision`、`idempotency_key`；前置为模型处于终态失败、无 `pending_job`/`recovery_pending`、`rollback_status != "failed"`、无失败后成功保存的相反证据（文件 identity/revision 未被推进）。
3. **只做登记表事务**：动作只把 `status` 置回 `ready` 并写 `reconciliation{action, original_job_id, prior_status, prior_rollback_status, acknowledged_at}` 审计块；revision、`part_file`、组件绑定、磁盘文件一概不动。
4. **零变更回归**：装配 connect 阶段零变更失败必须保持 `ready`（沿用 BUG-105 原生 `!mutated → model_unchanged` 口径），不得落 `failed`。
5. **描述与能力文案**：`server.py` 的 `creo_reconcile_model` `action` 枚举与描述、`capabilities.py` 恢复动作说明补 `ack_failure`；工具数不变（95）。

不包含：

- 装配自动改组件、自动重解约束、`adopt_session_copy`、自动擦除会话对象。
- 放宽四个既有动作的 `supported` 判定。
- 清理 unknown 保护、重提已受理作业。
- FEAT-049/FEAT-052 的装配重建与新上色范围。
