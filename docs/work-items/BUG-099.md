## 现象

Q13 预览/分页实机（`tools/test_t07_preview.py --live --confirm-session-usable`）在 `disk_cut_pattern` 用例稳定失败：

- 计划：对已有 `cut` 执行 `axis_pattern`（count=4，increment=90°，轴 `zaxis`）。
- `CreateNativeAxisPattern=0`、`ProFeaturePatternGet=0`、`ProPatternHeaderGet=0`，作业通过 `verify_model`，随后停在 `save_and_reload`。
- `ProMdlnameBackup(board, destination)` 返回 **-1**；`ProMdlSave(board)` 也返回 **-1**。
- 同时段其它 43+ 个非 pattern 作业均在同一输出目录保存成功；三次 pattern 作业全部失败，属确定性、pattern 相关。
- 失败后作业回滚，`saved_file_reloaded_and_verified=false`，Q13 其余用例未执行。

## 已排除

| 尝试 | 结果 |
| --- | --- |
| 干净 Creo 会话重跑 | 同一用例同一阶段失败 |
| `ProSolidRegenerate(PRO_REGEN_FORCE_REGEN)` 后 Backup | 再生=0，Backup 仍 -1 |
| Backup 失败后回退 `ProMdlSave` | 也 -1 |
| save 前调用 `ProMdlDisplay(board)` | 干净会话重跑时 `empty_part_solid` 在 save 阶段更早失败；该调用本身会破坏保存路径，已回退，未采用 |
| 磁盘/权限 | 输出目录存在、可写，磁盘剩余约 1.3 TB；非 pattern 作业同一目录保存成功 |
| 基线对照 | 主库 10-31 同一夹具曾成功（job `0cb4d2dc36524fb2a35b69c3bb46b4f4`）；但 2026-11-02 用主库 `50636bf` 源码与 worker 在同一环境重跑，`disk_cut_pattern` 同样在 `ProMdlnameBackup` -1 失败（job `be5684c594e14fa68b73eeda30878a55`）。**不是 0.11.1 回归**，属既有缺陷/环境差异 |

## 待查方向

1. pattern 创建后模型是否处于“pattern 编辑未结束”状态（`ProPatternCreate` 后是否需要额外的完成/关闭调用；`ProPatternDelete` 语义是删除 pattern，不可盲调）。
2. 该 `cut` 是否适合作为 pattern leader（count=4/90° 在圆盘上可能产生失效成员），以及 `ProFeatureStatusGet`/成员状态为何未在保存前健康检查中暴露。
3. `ProMdlnameBackup` 与 `ProMdlSave` 同时 -1 时，Creo trail/消息窗口是否有未读错误；需要在 `ProErrorlist` 或 UI 消息层补捕获。

## 影响

Q13 预览/分页与 pattern 相关的实机验收不能通过；本机 0.11.1 不宣称 Q13 通过。修复前不要用“串行调用成功”替代本用例。

### trail 原始证据（轮1失败会话）

- `build/creo_session/trail.txt.5`（会话 10:20:48 起）含 r3 失败：`10:22:41 阵列创建成功。` → 两次「未被更改」→ 没有 `已保存`、没有 `Start …prt.3`，作业随即 failed。解码件 `trail5_u8.txt`。

- 保存被拒时 Creo 不写 trail 消息；`dbg_err_crash(ORDER_DEBUG)` 在**成功**作业保存后也出现（`trail10_u8.txt`），不能当作 pattern 相关证据。

### 轮1失败与本树源码不一致（定因）

- r5 作业 `3cee405d…` 的终态消息为 `Toolkit call ProMdlSave(board) …`，而本仓库任何提交都没有 `ProMdlSave`（`git log -S'ProMdlSave' -- native/generic.cpp` 为空；当前 `save_and_reload` 只调用 `ProMdlnameBackup`）。该次 worker 由未提交代码编译。
- 同窗口 r6/r7 在 `empty_part_solid` 更早失败（save 前 `ProMdlDisplay` 实验），与卡内“该实验破坏保存路径、已回退”的记录一致，进一步证明当时二进制含实验改动。
- 轮1记录 r2/r3 `dirty=false` 只说明**报告时刻**工作树干净；驱动与任务都不记录 worker 二进制摘要，无法回溯其编译来源，故不把这两次当作本树源码缺陷证据。
- 因此本轮不改产品代码：当前源码无法构造该失败，且 Q13 驱动本身完整通过，不属于“改用例或串行调用掩盖”。
