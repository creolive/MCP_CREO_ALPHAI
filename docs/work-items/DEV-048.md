## 问题或目标

0.6.0 的四份反馈指向两类问题：

1. **文档与发布流程事实滞后**：工作条目的“状态/目标版本”连续两版未随发布回填；`support_status` 曾漏掉新工具、`release_status` 与 `is_prerelease` 曾自相矛盾；反馈原件未按节奏归档。其中 `support_status`、`release_status`、README 单位口径、`session_health`、显式回收均已在 0.7.0 交付，剩余是回填与检查项，不需要重新开发。
2. **两类仍有代码缺口的行为**：原生 sidecar 写入/发布失败只在日志留 `INSPECTION_SPLIT_FAILED`，公开结果仍返回 `inspection_ref`；Python 同名校验只比大小，不核对完整 SHA256；窗口收养拒绝清理 staging 后，预检 job 的 `inspection_ref` 成为悬空引用。此外 Right 面 ±Z 的定向实机证据仍不足，倾斜面/多轮廓/纯 Z `u_axis` 等历史现象需要按当前源码分别核对或保留未测。

目标：先建立可被其他任务读取的文档基线（T00），再按 T01—T05 修复 sidecar 完整性与引用生命周期、回填台账与发布检查、补齐 Right 面定向证据，最后由 T05 统一集成并按 PATCH 交付。

## 本批共享接口约定（T00 固定，T01/T02 共用）

本节落实用户已确认的[完善计划](../development/0.6.0-FEEDBACK-PLAN-2026-10-27.md)与[派发表](../development/0.6.0-FEEDBACK-TASKS-2026-10-27.md)第二节，描述**本批目标接口**；除注明“既有”者外，不表示 0.7.0 已公开或已通过验收。T01/T02 不得各自建立另一套诊断格式；需要改变共享契约时先回报集成负责人并同步本节与相关任务。

### 1. 公开诊断结构

```json
{
  "inspection_warnings": [
    {
      "stage": "live",
      "reason_code": "native_sidecar_write_failed",
      "fallback_status": "verified",
      "message": "Native sidecar write failed; Python fallback was verified"
    }
  ]
}
```

- `stage` 取值 `live` 或 `verified`；`fallback_status` 取值 `verified`、`failed` 或 `not_attempted`。
- `fallback_status=verified` 必须有最终完整引用的大小、完整 SHA256 和可读性核验，不能仅因文件存在而填写。
- 本批原因码固定为 `native_sidecar_write_failed`、`native_sidecar_publish_failed`、`inspection_ref_invalid`、`inspection_ref_removed_after_refusal`；原始异常保留在作业日志中，不得用字符串模糊匹配猜测原生失败阶段。
- 每个公开结果或批量 item 最多 4 条警告，按 `(stage, reason_code)` 去重；每条 `message` 最多 256 个 UTF-8 字节且不截断编码字符；完整原始错误留在作业日志。公开结果不得出现尚待回退的临时状态。

### 2. 兼容与语义边界

- 字段可缺省；旧原生结果或旧登记没有该字段仍然兼容。旧内联资料正常拆分不是故障，不凭空产生警告。
- 警告是存储事实，不改变作业成功/失败、revision 推进、保存重载结论或 unknown/回滚保护。
- 公开收养/恢复结果、批量每个 item 以及 `creo_get_job` 的 compact/full 保留同义诊断；结果嵌套或分页不得静默丢失。批量父作业不无限复制子项错误全文。

### 3. 共用函数（T01 实现，T02 复用）

`inspection_refs.make_ref`、`split`、`load_ref` 的既有调用签名不变。T01 在同包模块新增：

- `split_result(result: dict, directory: Path) -> dict`
- `add_warning(holder: dict, *, stage: str, reason_code: str, fallback_status: str, message: str) -> None`
- `warnings_of(holder: dict) -> list[dict]`

既有 `adoption._split_result` 委派共用处理，恢复路径也复用同一实现。T02 使用上述约定完成引用生命周期，不新建相同职责的工具或模块。
