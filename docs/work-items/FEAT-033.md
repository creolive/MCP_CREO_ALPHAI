# FEAT-033：按作业执行预算与阶段耗时的公开契约

日期：2026-10-16。类型：功能。优先级：P1。状态：待规划（T09D 基准已实测并补满；公开预算/阶段契约未实现）。目标版本：未排期。

来源：[履带反馈](../validation/TRACK-FEEDBACK-2026-10-16.md)第十九、二十节；关联 BUG-001、BUG-053、FEAT-007、FEAT-021、FEAT-023。

## 目标与范围

让调用方在提交前可理解所用执行预算，并评估按作业覆盖全局配置的受限入口，分别记录构建/准备、原生执行、保存重载和登记的时间。报告中 `timeout_seconds`、300～7200 的范围、900/1800/3600 的默认值及自适应公式仅为建议，不是本任务已确定参数。

先核对当前实际默认值、配置读取时机、worker timeout、看门狗、启动预算与客户端轮询/读超时，区分“服务仍在执行但客户端超时”和“执行器已停止”。客户端读超时不得触发重交。首批明确覆盖的入口以选型登记为准，不只修改 execute_plan 而遗漏等价独立写工具。

不通过 `assertions.verify=false` 或跳过保存重载来省预算，不假设能在硬 kill 前保证写检查点或自动回滚，不把增大预算当作 BUG-053 的提速成果；通用取消仍归 FEAT-021。

## 验收标准

| 场景 | 可判断的预期结果 |
| --- | --- |
| 默认/配置/作业参数 | 优先级、单位、起止点、上限及非法值校验明确，接收结果和任务查询回显实际使用预算与来源；旧调用保持文档化兼容 |
| 内外预算一致 | 原生执行 timeout 和看门狗按实际契约协调，外层不先杀仍在合法预算内的任务；准备和重载阶段边界能解释清楚 |
| 客户端超时后轮询 | 已接收任务只按 job_id 查询，无重复写入；最终成功仍保存重载/交付通过、revision 仅一次 |
| 到期和未知结果 | 给出可确认阶段、已确认操作与不确定范围；超时后保护与恢复衔接 BUG-001/FEAT-018，不伪造成功或自动清锁 |
| 长/短任务对照 | 较长预算只是上界，短任务完成即返回；固定长任务在显式预算内可完成，保存重载与几何检查不降级 |
| 全局并发边界 | 单通道忙时仍立即拒绝，不因长预算变成排队、自动重试或 FIFO 保证 |

开发环境 Windows x64 / Creo 12.4 / 匹配 SDK。预算边界用可控时钟/子进程回归验证，真实长任务另做原生验收；WorkBuddy 只验证公开预算、真实阶段/耗时、轮询与终态，不读取 config.json 或内部计时日志，不靠等待接近某秒数证明看门狗实现。

## 实现与证据

本次仅建卡，没有改默认预算、配置或 MCP 参数。选型须冻结数值、兼容性和到期动作后才能进入开发；外部 644/619 s 成功据报在 1500 s 全局配置下，不算现默认值通过。
