## 现象

- schema 层显式校验正确拒绝（pydantic `value_error`："Arc dir must be the strict integer +1 (counterclockwise) or -1 (clockwise) … input_value=0"）；
- **未产生作业**（`job_id`/`terminal_status`/`rollback` 全 null），模型 revision 3→3 不变、基线体积 1428.0972451017303 保持；
- 缺的是**拒绝之后的同源实测体积**：驱动在拒绝后用 `creo_refresh_model` 取体积，本次该结果块未带 `volume_mm3`（`measured_volume_mm3=null`），判 `volume_missing`；

**不是"作业失败"，也不是"非法编辑被接受"**；但按严格判定该反例未通过，不得改判为通过或放宽判定。

## 实现与证据

### 2026-10-31 离线定因与驱动修复（Post-0.10.0 批次 P03）

**定因结论：驱动读错层，不是生产漏字段。** 待查项 1 的答案为第一种（历史同类：重载标志误读顶层）。

原始证据：N07 现场拒绝后唯一的 refresh 终态 `jobs/cddccfd2a3b6457c9bf9d7cb2eb0ee03/job.json`（2026-10-31T04:02:05Z，readonly、空操作清单）。其 `result` 块经 BUG-077 的 `split_job_result` 拆分后不再携带内联 `inspection`，只带 `inspection_ref`（sidecar `inspection-verified-1a6e4242…json`，17541 字节）与 `inspection_summary`，其中 `inspection_summary.volume_mm3 = 1428.0972451017303` 与基线完全一致——同源体积由生产正确携带。而驱动 `tools/test_arc_direction_live.py` 的 `measured_volume_mm3()` 只读 `result.inspection` 内层或 result 顶层 `volume_mm3`，读不到拆分后的 `inspection_summary` 层，返回 `None`，被判 `volume_missing`。生产代码（`generic_bridge.py`/`model_registry.py`/`operation_results.py`）无需改动。

顺带证实并修复同一读取边界的两个判定缺陷：载荷选定层缺 `volume_mm3` 时旧实现会从其他层抄值（如顶层旧体积）；`bool` 是 `int` 子类，`volume_mm3=true/false` 会被读成 1.0/0.0 mm³。

变更（仅驱动公共读取边界，未改生产行为）：

- `tools/test_arc_direction_live.py`：`measured_volume_mm3()` 改为选定层语义——`inspection`（inspect 回复/legacy 内联）优先、其次 `inspection_summary`（BUG-077 拆分后的 job result 块）、最后顶层；选定层缺字段即缺证据，不从其他层抄值；新增 `numeric_volume_mm3()` 排除 `bool`/非数值/非有限值。`judge_illegal_edit()` 新增 keyword 参数 `model_id`/`refresh_terminal`：refresh 终态的 `model_id` 与被测模型不一致判 `wrong_model_refreshed`，行内记录 `expected_model_id`/`refreshed_model_id`。`live()` stage 4 传入两参数。
- `tests/unit/test_arc_direction_live.py`：新增 `RefreshVolumeEvidenceTests`（11 例）：以 N07 真实拆分终态形状复现 `volume_missing` 的失败回归；直接/嵌套真实载荷；缺字段不从其他层或基线抄值；bool/null/字符串不当数值；错误 model_id；旧 revision；N07 形状端到端通过判例。oracle、native 回显与 `saved_file_reloaded_and_verified is True` 成功判据未动。
- 验证：`.\.venv\Scripts\python.exe -m unittest tests.unit.test_arc_direction_live` 46/46 通过（本机 Windows，未连接 Creo）。提交：见分支 `codex/dev053-post0100`（BUG-093 标题提交）。
