# BUG-081：迁移 owner 拒绝诊断与停止证据核对（alive=None 可见性不足，是否误判待复现）

日期：2026-10-25 登记（外部报告 2026-10-23）。类型：缺陷（诊断与判定核对）。优先级：P1。状态：验收中（诊断已实现并随集成尖 `e2bba08` 收口；停止判定未改，实机拒绝时序待复现）。目标版本：0.5.3（目标，未发布）。

来源：[0.5.0/0.5.1 Creo 9 反馈计划](../development/0.5.0-0.5.1-FEEDBACK-PLAN-2026-10-23.md)阶段一/阶段三；外部第八轮报告 §五（[归档原件](../validation/feedback-0.5.0-0.5.1-2026-10-23/manifest.json)）。关联 BUG-074（历史记录启动时间核验先例）、BUG-077（迁移与恢复链路）、BUG-078（会话核对前置）。

## 问题或目标

已证实现象（外部 Windows 10 / Creo 9.0.0.0 / 服务 0.5.0，2026-10-23 09:02–09:40）：

- `creo_migrate_registry(mode=apply)` 连续两次被拒：`Registry migration cannot rewrite an active or unproven job`，holder 指向作业 `ba0901e5…`（model `701981d4…`/wb_reg_pat2，operation=registry_owner）。该作业为终态 `succeeded`（10-16 06:37 完成）、模型 `ready`、`pending_job`/`recovery_pending` 均为 null。
- 报告者在**本地进程用同一函数、同一参数**直调 `_check_owners` 通过，并完整 apply 成功（`migrated: 14, job_files_split: 219, refused: 0`）；随后 MCP 路径同 `idempotency_key` 重放返回 `replayed: true`。
- 报告的时间差解释：被引用 owner pid 15332（10-22 18:23 的残留 Creo worker）在 MCP 两次拒绝时**仍存活**（10-23 09:05 随残留进程清理死亡），本地直调在其后。**迁移被拒的调用在进程清理前、本地直调成功在清理后，这个对照不能证明客户端路径差异或守卫误判；作业终态也不证明 owner 已停止。**

待验证根因与定性：

- 当前代码 `reconciliation._stopped()` 对 `process_identity` 查询失败（`alive=None`）判“未证明停止”；`OpenProcess` 错误 87（ERROR_INVALID_PARAMETER，进程不存在）已映射 `alive=False`，错误 5（拒绝访问）及其他查询失败为 `alive=None`。**是否存在判定缺陷须复现后决定，不以 alive=None 直接定性误判。**
- 可确认的缺口是证据可见性：迁移拒绝不携带 observed/Windows 错误/原因，inspect 也不预标注将被 owner 守卫阻塞的条目，调用方无法自救。

## 范围

包含：

- 核对 `recovery.process_identity` → `reconciliation._stopped/_owners` → `registry_ops._check_owners` 链路，不重复实现已有的错误码映射。
- 迁移 inspect 预检标注：阻塞 job/model、runner/worker、recorded/observed、Windows 错误及原因；apply 拒绝附有界证据和下一步。字段名与大小约束在实施前于本卡确定，不能只返回笼统 busy。
- inspect 只报告观察；apply 在通道锁内重验身份、作业状态和保护，inspect 曾通过不构成写入授权；活动/已预留作业不得迁移，终态不替代停止证明。

不包含：

- 不改保护边界：对无法查询的进程保持“未证明停止”。
- **不采用“错误 5 + created 早于启动即放行”方案。** BUG-074 只对身份不完整的历史记录使用独立核验的启动时间及完整文件证据；完整但存活/不可查询身份明确不被时间覆盖。残留 worker 启动在本次 Windows 启动之后时，旧作业结束时间不能证明它已停止；PID 复用须有可验证的不同创建身份。
- 不引入队列、自动重试或新的并发原语（BUG-009 边界不变）。

## 诊断字段契约（2026-10-25 实施前固定）

以下字段名与上界为本卡固定，inspect 预检与 apply 拒绝共用同一有界结构；超出上界的输入在投影时截断或丢弃，禁止只返回笼统 busy。

阻塞条目 `owner_block`（仅当该条目会被 owner 守卫阻塞时出现；inspect 挂在对应 entry 下，apply 挂在 `ToolkitBusy.payload["owner_block"]`）：

| 字段 | 类型与上界 |
| --- | --- |
| `job_id` / `model_id` | 服务内 job/model 标识（hex32） |
| `reason_code` | 枚举，仅 `active_job` / `runner_unproven` / `worker_unproven` / `protected_owner_unproven` |
| `job_status` | 字符串，≤24 字符 |
| `runner` / `worker` | `owner_view` 或 null |
| `next_steps` | 固定指引文案，≤600 字符 |

`owner_view`：`stopped`（bool）、`reason`（≤120 字符）、`recorded`（有界投影：`pid` int、`created` int、`session_fingerprint` ≤64 字符，仅接受合法类型，畸形值丢弃）、`observed`（`pid` int、 `alive` bool/null、`created` int/null、`windows_error` int/null）。

inspect 响应另增顶层 `blocked_entries`（int，将被阻塞的条目数）；未阻塞条目不携带 `owner_block`，响应仍受既有 32 KiB 预算约束。

## 验收标准

| 环境 / 用例 | 命令或操作 | 可判断的预期结果 |
| --- | --- | --- |
| owner 不存在（错误 87） | 单测构造 | 映射 alive=False、stopped=True，该 owner 不再阻塞迁移 |
| 同一活进程 | 单测 | alive=True 且 created 一致 → 未停止，拒绝并附 runner/worker 证据 |
| 已确认 PID 复用 | 单测（不同 created） | 判未停止/身份不符，拒绝并说明 |
| 拒绝访问（错误 5）与其他查询失败 | 单测（mock OpenProcess/GetProcessTimes） | alive=None → 未证明停止，继续拒绝；拒绝负载含 observed、Windows 错误、原因与下一步 |
| 缺失/畸形身份、GetProcessTimes 失败 | 单测 | 保持未证明，不崩溃、不误放行 |
| 历史启动证据（BUG-074 同源规则） | 单测 | 仅身份不完整的历史记录适用时间+文件核验，不外推到完整身份 |
| inspect/apply 间状态变化 | 单测 | apply 在锁内重验；inspect 结果过期不导致误写 |
| 幂等重放与 pending/recovery 保护 | 回归 | 同 key 重放语义不变；既有保护不放松 |
| 开发检查 | `tools/dev_check.py` | 无新增语言问题，单测通过 |

实机迁移链路验收归 BUG-077 既有范围，本卡不重复安排实机迁移全矩阵；仅 Python 诊断字段改动不触发原生重编验收。
