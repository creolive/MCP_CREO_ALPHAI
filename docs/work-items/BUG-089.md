## 现象与根因

已确认 0.8.1 的 `version.py` 为 `0.8.1`，两份种子清单仍声明 `0.8.0`。直接运行文档中的 `tools/package_seeds.py --output` 因版本断言 exit 1。0.8.1 种子附件通过进程内修改版本构建，内部仍声明 0.8.0；`tools/test_installation_loft.py` 的安装版本核对在真实 0.8.1 安装上会失败。根因是发版时遗漏更新清单版本，并缺少对仓库实物的回归测试。

0.9.0 复发同一类缺陷：随 0.9.0 发布的种子包被它自己的 `creo_install_seed_library` 拒绝（种子包 SHA256 与 `seeds.py` 的 `expected_digest` 常量不一致），根因是"回填摘要"只是 `tools/package_seeds.py` 打印的一句提示，没有任何闸门，也没有回归测试覆盖 archive 安装路径。

## 范围与验收

0.8.2 只同步版本及两份清单，保留种子列表、每个种子哈希和公开工具 94 个；补充离线回归测试。直接调用未修改的种子打包命令两次，哈希必须一致；回填 `seeds.py` 摘要并再构建核对。两次源码打包应一致，包含两份清单和反馈归档，禁入路径为零。`tools/dev_check.py` 必须成功、单元失败和错误均为零。禁止 Creo 和 WorkBuddy；无原生改动，不重编。证据见 [0.8.2 发布记录](../validation/RELEASE-0.8.2.md)。

## 防复发范围（DEV-053 P04，2026-10-31）

历史修复（0.8.2 同步版本与两份清单）保持原样，不改写。P04 只补"同一缺陷不再靠人记住"的机制，不改种子内容、种子身份或公开工具数：

- **受信摘要入口**：`docs/seed_package.json` 显式记录本版本的 `compatible_server_version` 与 `seed_archive_sha256`。`src/creo_mechdog/release_integrity.py` 的 `trusted_seed_package()` 是唯一读取处；不再从待验证 ZIP 自身读取"期望摘要"，篡改或重打的包无法自带自己的期望值。
- **安装路径闸门**：根 `seeds.py` 的 `install_seed_library(archive_file=...)` 先经 `validate_seed_archive()` 校验摘要、版本前缀、清单一致性、ZIP 内原生 PRT 字节与成员路径，再写入安装目标；负例在写入目标前拒绝。目录安装路径保持兼容。
- **打包入口闸门**：`tools/package.py` 新增必填 `--seed-archive`，先 `validate_release_inputs()` 校验 `version.py`、两份种子清单、README 标题与当前版本段、种子包摘要与成员集合，再写源码包与 stage。缺参或失配 exit 非零且不创建源码 ZIP/stage，不回退为警告继续。打包不自动改写源码，摘要回填仍由发布者显式完成。
- **单一成员清单**：`seed_library_files()` 同时供种子打包与发布闸门使用，避免两处手抄白名单漂移。
- **离线回归**：`tests/unit/test_release_integrity.py` 用实际构建的 ZIP 覆盖正例安装与篡改字节、错误摘要、错误版本、双清单不一致、README 版本段滞后五类负例；`tests/unit/test_seed_distribution.py` 补目录安装兼容与 ZIP 内原生 PRT 字节/路径保护；`tests/unit/test_seed_manifest_version.py` 补受信记录、README 版本段与 `--seed-archive` 必填的断言。

证据与命令见 [DEV-053](DEV-053.md) 的 P04 段。正式 0.10.0 附件的离线安装核对在本机缺正式附件，记为待补；合成包单元与正式包验收分别记录。
