# BUG-079：就地修改圆弧半径导致特征再生失败（autodim 路径欠约束），回转/拉伸上下文均复现

日期：2026-10-23。类型：缺陷。优先级：P1。状态：已修复，WorkBuddy 复验通过（待发布）。目标版本：下一未发布 PATCH（建议阻塞合入）。

来源：WorkBuddy 黑盒验收（MCP_CREO_MechDog_dev，服务 0.5.0，Creo 12.4.0.0/release 44）场景 3；开发侧已独立复现并收窄范围。

## 报告现象（WorkBuddy 实测，仅 MCP 可观察行为）

回转草图 rev_sk = centerline `axis`(0,0)→(0,20) + 弧 `prof_arc` R5（0°→180°，圆心 (8,5)）+ 直线 `prof_line`(13,5)→(3,5)，revolve 360° 成功（体积 1973.920881015659 = 200π²，半圆环截面）。随后：

| 操作 | 结果 |
| --- | --- |
| 就地改弧 R5→R6（auto 与 autodim 两种模式、两个圆心位置） | 三次均失败："Regeneration produced a failed, suppressed or incomplete feature"，`rollback_succeeded=true`，revision 不变 |
| 缺实体／改名／改类型 | 准确拒绝，现场保持（BUG-062 既有行为正确） |
| 合法编辑：整体上移（弧圆心 (8,6)、R5 不变，直线随动） | 成功，体积不变、bbox 更新、特征 ID 保持 |

即：**圆心移动成功、半径变化一律失败**。

## 开发侧复现与范围收窄（build/editing-closeout/bug058-snap2/）

复现脚本 `wb-r6-repro.py`（回转）与 `wb-r6-extrude.py`（拉伸），报告 `wb-repro-r6.json`、`wb-repro-r6-extrude.json`：

| 变体 | 上下文 | 提交 | 结果 |
| --- | --- | --- | --- |
| A/B/C | 回转 360° | 弧 R6 + 直线端点随动（两种方向） | 全部失败，体积回到 1973.921 |
| D | 回转 360° | 弧 R5.5 + 直线随动 | 失败 |
| E | 拉伸 4（无 centerline/轴） | 弧 R6 + 直线随动 | 失败，体积回到 157.0796（基线 157.0796 = π·25/2·4） |

失败作业原生日志（如 `jobs/c1d9304f…/native.log`）关键序列：三个实体 `ProSectionEntityReplace` 均=0、旧尺寸 `ProSecdimDelete`=0、`SKETCH_SOLVE=-1 mode=autodim`、`SECTION_ERRORS phase=solve count=0`（无任何具体错误项）、`AutodimensionSketch=0`、`RegenerateSolvedSketch=0`、`ProSolidRegenerate` 后 REV_SK 与 REV1 `status=6`（未再生）→ BUILD_FAILED → 回滚。

## 现象边界（已核实）

- 失败仅当**圆弧半径（进而端点坐标）变化**；圆心平移（半径不变）、同几何重复提交（unchanged 快捷路径）、`set_sketch_dimensions` 尺寸路径（圆 Ø16→20）均正常。
- BUG-062 回归夹具（半圆弧圆心在回转轴上、直径线即 centerline，R5→R6）实机通过——该几何恰好不触发本缺陷，不能覆盖离轴弧+闭合直线的常见情形。
- 与近期缓存守卫改动无关：失败路径走完整实体替换（非 unchanged 快捷路径），且 10-22 版本源码同样不含此场景的通过记录。

## 根因（已核实，2026-10-23）

对比失败作业（`jobs/2b0cb2a7…`，改弧半径）与成功作业（`jobs/37e63969…`，圆心平移；`jobs/69bdf485…`，创建）的实机检查结果：

- 创建时 REV_SK 有 3 个截面尺寸（半径、y 位置、x 位置，特征尺寸 d2/d3/d4）。就地编辑删除全部尺寸后 autodim 在**半径变化的截面上只重建 2 个尺寸**（半径 + x 位置，y 位置缺失），而半径不变的编辑重建 3 个。
- 再定义后特征尺寸出现孤儿映射（d12 type=-1 value=0），REV_SK `geometry_items` 为空，`status=6`——草绘特征再生失败，REV1 随之失败并回滚。
- `SKETCH_SOLVE=-1`（无诊断条目）在创建路径、成功编辑路径同样出现，不是判别点；显式 `dimensioning=coordinates` 成功（`jobs/a1752549…`）是因为坐标尺寸把截面完全约束，特征尺寸整体重映射（d12–d19）后再生通过。
- 结论：缺陷在 autodim 路径——就地重建后再自动标注可能欠约束截面，残留孤儿特征尺寸使草绘特征再生失败；与实体替换方式（Replace 或 Delete+Add）无关。

## 修复（native/sketch_edit.cpp，2026-10-23）

1. 未变实体直接跳过（保持实体 ID，不做替换/删除，避免无谓求解扰动）；变更实体 Add 新实体后 `ProSectionEntityDelete` 旧实体并回写新 ID；centerline 例外保持 Add+Replace（保留实体身份以维持回转轴引用）。
2. 自动标注路由：`dimensioning=auto` 的就地编辑在主平面、全部实体类型支持坐标标注（line/centerline/circle/arc）且截面存在坐标系时，改走已验证的坐标尺寸路径（完全约束、特征尺寸整体重映射）；显式 `autodim` 请求、非主平面、含 ellipse/spline 的截面仍走原 autodim 路径。
3. 附带：抽取 `entity_matches` lambda 时触发了 MSVC 传统 lambda 处理器（/std:c++17）的捕获登记缺陷（C2065"未声明标识符"——捕获首次引用位于长分支链深处时被丢弃）；将 `u_alignment` 计算上移到 lambda 体开头规避，代码内有注释说明。
