# BUG-034：清单有效的叶片种子在 Creo 9 原生加载失败

日期：2026-10-16。类型：缺陷。优先级：P1。状态：待复现。目标版本：未排期。

来源：[Creo 9 / 0.3.0 报告](../validation/feedback-2026-10-16/2026-10-15_CREO_0.3.0_叶片种子加载失败与筋特征失败.md) P0-1；[补录与环境边界](../validation/FEEDBACK-2026-10-16.md)。关联 BUG-033（SDK 编译）、FEAT-030（原生预检）、FEAT-008（能力与诊断）。

## 2026-10-18 分类与下一步

按 [DEV-039](DEV-039.md) 从“待核实”调整为“待复现”。有失败报告，需在明确环境和输入下复现、定位；本次没有新增复现结果。 本轮未运行实机；下文保留原日期和证据范围。

## 现象与待验证原因

`creo_new_airfoil_blade` 两站 chord=100/80、offset=0/150、末站 twist=20，smooth/straight 均在 `ProMdlFiletypeLoad` 返回 -16。报告称 two_smooth 文件 116535 字节、清单哈希有效且隔离复制正常；两个失败模型 revision=0。未提供完整 stations、job/model ID 和实际受测源码身份。

报告根据 UGC 文件头 2128 与本会话 2023 推测新文件不能被 Creo 9 加载。本次未复核文件头含义、原生错误原因或本地补丁；不把 -16 单独等同版本不兼容。

## 范围与验收

先核对种子生产版本、目标原生加载能力和实际失败来源；区分文件完整性、原生加载和 blade 参数编辑。明确种子最低版本或按版本提供已验证产物，方案经复现后决定，不直接承诺重制 9 个种子或扩大种子在 Creo 9 的已验证范围。Creo 9 整体有限支持定位见 [DEV-026](DEV-026.md)，不代表本缺陷已修复。

| 用例 | 可判断的结果 |
| --- | --- |
| 清单/哈希有效但加载失败 | 保留 seed ID、加载阶段/原始错误，说明 available 的文件完整性范围；未知原因明确未知，不返回“原生已验证” |
| smooth/straight 合法两站 | 支持环境中原生种子加载、参数更新、几何/扭转/体积正确，保存重载 true、revision 正确；隔离副本不改源种子 |
| 失败新建 | 登记终态与产物可核对，给可行恢复指引，不删除未知作业或冒充成功；衔接 FEAT-018 |

开发验证使用本机 Windows x64 / Creo 12.4 / 匹配 SDK、针对性种子/叶片实机回归及适用开发检查；原始 Creo 9 场景按反馈补录，不设旧版独立复测门槛。本次仅登记，根因、复现、修复与新测试均未完成。

## 2026-10-23 外部 Creo 9 证据补录（第八/九轮，2026-10-25 归档登记）

- 环境：外部 Windows 10 / Creo 9.0.0.0（release 41）/ 服务 0.5.0、0.5.1。
- 种子加载 -16 持续复现：`creo_new_airfoil_blade` 与 `creo_new_loft_part`（种子放样）均 `ProMdlFiletypeLoad failed with code -16 during connect`；直接 `creo_loft` 在该会话未完成回调注册（`BLEND_CALLBACK_SETUP_REQUIRED`，0.3.2 起行为未变）。
- 记录口径：**该受测环境两条放样路径均未成功**，不外推为所有 Creo 9 放样均不可用；-16 本身不足以唯一归因为版本不兼容。
- UGC 2128/2023/1934 与产品版本的对应关系未获可追溯证明，不据此宣称种子由 12.4 构建或确定最低加载版本；线索按 [FEAT-030](FEAT-030.md) 的来源字段与按哈希历史加载记录核对（未知生产版本为 null）。
- 来源披露、能力/兼容说明与 -16 失败诊断改进归 0.5.3 计划（FEAT-030/BUG-034 联合条目）；种子重生成另列环境受阻子项。归档见 [feedback-0.5.0-0.5.1-2026-10-23](../validation/feedback-0.5.0-0.5.1-2026-10-23/manifest.json)。

## 2026-10-25：-16 失败诊断与来源透明化实现（开发分支，未做实机连接）

本轮**没有复现也没有修复** -16 本身：外部 Creo 9 的失败原因仍未定位。实现的是让失败可核对、让未知保持未知（与 [FEAT-030](FEAT-030.md) 同批）。

- 失败诊断（`seed_compatibility.load_failure_diagnosis()` 与 `generic_bridge` 收尾）保留原始 API、错误码、实际阶段、种子标识与 SHA256、可取得的运行版本与原生消息原文，并提示核对兼容性与来源。
- **不硬写"由 Creo 12.4 构建，当前版本无法加载"**：没有绑定该 SHA256 的可追溯来源记录时，原因记为 `undetermined_by_error_alone`；只有当来源记录的 release 高于当前会话 release 时才给出有界的版本提示（`recorded_release_newer_than_session_release`）。
- UGC 2128/2023/1934 仍只是诊断线索，未建立任何产品版本映射；`seed_build_version` 在来源不足时保持 null。
- 加载成功与后续建模成功分别记录，失败终态不因诊断写入失败而改变。

本轮为开发分支改动，**未连接 Creo 会话、未做实机建模与保存重载**；-16 的根因复现与修复仍未完成，原生侧实机回归留给回归收口任务。种子库重生成是另列的环境受阻子项，本机无匹配旧版生成/验收环境，未承诺完成。证据见[本轮验证记录](../validation/FEAT030-BUG034-SEED-TRANSPARENCY-2026-10-25.md)。

## 2026-10-25 阶段三验收证据（收口）

环境：主仓 dev 环境，Windows 11 x64 / Creo 12.4.0.0 / 匹配 SDK / Python 3.12.14；集成尖 `e2bba08`（[阶段三收口](../validation/PHASE3-CLOSEOUT-2026-10-25.md)）。

- 实现摘要：-16 失败诊断与来源透明化随 `e2bba08` 进入集成尖；本轮不新增代码，只核对实机行为与证据边界。
- 本次证据：本机 12.4 上 `two_straight`（job `d161f855…`，体积 5131.268000863329、保存重载 true）与 `two_smooth`（job `fe8bf5ed…`，保存重载 true）**均加载并建模成功**，`seed_load_evidence.status=loaded`；`creo_validate_seed` 仍报 `available` 只代表文件/哈希、`native_status=not_verified_for_current_session`、`seed_build_version=null`。这证明“清单有效但加载失败”的可用性在 12.4 不出现，**不证明 Creo 9 已修复**。
- 未测范围：本机无 Creo 9 SDK 与实机环境，`ProMdlFiletypeLoad=-16` 的根因、复现与修复均未在 Creo 9 复验（本卡保持“待复现”）；UGC 2128/2023/1934 与产品版本映射仍未证实；种子重生成未执行。Creo 12.4 通过不等于 Creo 9 通过。
