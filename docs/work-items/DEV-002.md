### 本批设计与选择

当前根 seeds.py 仍实现种子查找、校验、注册和安装；capabilities.py 仍保存操作清单和能力声明。三个既有辅助模块已采用包内唯一实现、根薄导出的模式，本批沿用。下列选择作为执行设计供审查，不代表本轮已完成实现。

| 方案 | 影响与取舍 | 本批安排 |
| --- | --- | --- |
| 只搬 seeds/capabilities，保留兼容入口 | 范围明确，可独立验收，能接续前两批 | 采用；优先补齐安装/路径/指纹 |
| 同时重写 bridge 的路径和 JSON I/O | 能减少反向依赖，但会触及持久化与任务保护 | 后续单独规划 |
| 一次搬迁服务、启动、桥接及 C++ | 影响面跨协议、进程、SDK 与回滚，无法作为小批迁移验收 | 不纳入第三批 |

包内新增 creo_mechdog.seeds / creo_mechdog.capabilities。根同名文件保留薄导出，seeds 脚本入口转交包内 main(argv)。capabilities 常量和函数对象在新旧导入间共享，不复制第二套定义。

调查确认两项必须随迁移处理的依赖：setup.ps1 直接运行根 seeds.py --install；当前 editable 安装从仓库外找不到根 bridge/seeds/capabilities。种子实现继续调用既有 bridge 的 ROOT/read_json/write_json，本批为 bridge、seeds、capabilities 补显式 py-modules 安装声明，暂不复制 I/O 或移动桥接实现。实际安装身份须在新解压副本的新环境验证。
