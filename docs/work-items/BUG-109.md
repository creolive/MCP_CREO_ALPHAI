# BUG-109：`verify_model` 只有一个阶段名，首建停滞时无法区分"在算"与"挂了"

日期：2026-11-03。类型：缺陷（可观测性）。优先级：P1。状态：离线实现完成（阶段归因与停滞判定；卡死根因未定；本机 Creo 12.4 实机未执行）。目标版本：未定（R13 版本待裁定）。关联 [BUG-085](BUG-085.md)（断连调查）、[BUG-088](BUG-088.md)（预览文件缺失，**非同一缺陷**）、[FEAT-007](FEAT-007.md)（任务进度细分）、[DEV-065](DEV-065.md)。

## 现象（报告方实测时间线）

```
22:36:09  creo_new_part(wb_acc115_onaxis) 提交
22:36:2x  native.log 走到 PHASE=loaded_blend_validation → PHASE=verify_model 后停止输出
22:46:13  服务端预算到点 → unknown_outcome（"Native worker timed out"），全程卡在 verify_model 约 10 分钟
22:46+   creo_session_status：visible_hung_window_observed=true、probe_timeout；
         Creo 进程 alive、Responding=True、CPU 仅 14.4 s（非死循环）
22:53   人工结束病态会话；22:55 新会话（launch_attempt 27）连接成功
22:57:52 同一 new_part 请求重发 → 22:58:2x succeeded（约 30 秒）
```

关键事实：**非确定性复现**（同参数第二遍 30 秒通过）；卡点不在 blend 重建（`loaded_blend_validation` 已过），在其后的 `verify_model`（保存 → 擦除 → 重载 → 巡检）。

## 当前实现（本批只读核对，基线 `main@b3f6d43`）

- `native/generic.cpp:125-128` `generic_stage()`：只写一行 `PHASE=<name>`，无时间戳、无子阶段。
- `native/generic.cpp:6272` 起：一个 `verify_model` 阶段包住——`ProSolidRegenerate`（`:6281`）、`inspection()`（`:6282`）、`verify_assertions`（`:6285`）、`before_save_blend_validation`（`:6288-6289`）、`ProMdlnameBackup` + `latest_model_file()`（`:6293-6294`）、`ProMdlErase`（`:6296`）、`ProMdlFiletypeLoad`（`:6300`）、再次 `ProSolidRegenerate`（`:6301`）、`verify_saved`（`:6307`）、`after_reload_blend_validation`（`:6320-6321`）、`display_preview`（`:6327`）。卡在其中任一步，日志都只停在 `PHASE=verify_model`。
- 服务端：`bridge.py:1251-1255` native helper `timeout=config()["native_timeout_seconds"]`；`:1364-1369` `generic_timeout_seconds` 默认 **600**（与报告方 22:36:13 → 22:46:13 的 600 s 吻合）；`:1304-1310` `TimeoutExpired` → `status="unknown_outcome"` + "Native helper timed out and was stopped; inspect native checkpoint and Creo before retrying."，**不带最后阶段**。
- `get_job` 的 compact 白名单（`bridge.py:1497-1503`）无任何进度/阶段字段。

## 范围

包含：

1. **原生子阶段化**：把 `verify_model` 拆成可命名的子阶段并逐个输出 `STAGE name=<sub> elapsed_ms=<n> since_start_ms=<n>`（含 `verify_model_regenerate` / `verify_model_inspect` / `verify_model_assertions` / `verify_model_before_save` / `verify_model_save` / `verify_model_erase` / `verify_model_reload` / `verify_model_reload_regenerate` / `verify_model_compare` / `verify_model_after_reload`）；失败时 `report["verify_stages"]` 带已完成子阶段与各自耗时。
2. **有界日志归因**：新增 `src/creo_mechdog/native_stage.py`，`stall_report(directory, *, tail_bytes=8192)` 只 seek 日志末尾 8 KiB，解析最后 `PHASE=` / `STAGE name=` 及其 `elapsed_ms`，产出 `{readable, stage, sub_stage, elapsed_ms, log_bytes, idle_seconds, reason}`；不可读/截断/旧日志无 `STAGE` 行时如实降级。
3. **作业回执**：`get_job` 追加 `native_progress`（只读、有界），`status="running"` 与超时终态都带；超时文案点名最后子阶段与停滞秒数。
4. **回归**：既有 `PHASE=` 行保持原样（旧日志解析、外部脚本与 `native_log_tail` 仍可用）。

不包含：

- **不做进程内子阶段强杀**：Toolkit 调用不可中断，提前杀 worker 会把"慢但成功"的保存变成新的 `unknown_outcome`。
- 不改 `generic_timeout_seconds` 默认值、不改 `unknown_outcome` 保护语义、不自动重试。
- 不断言卡死根因（Creo 9 首建慢的诱因本机无环境）；不把本机未复现写成"已修复"。
- 不实现 `get_job wait_seconds`（FEAT-007）。
