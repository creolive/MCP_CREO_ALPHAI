# BUG-078：恢复 accept 路径 ProMdlnameBackup 稳定 -1，accept_saved/accept_live 实机不可用

类型：缺陷

优先级：P1

状态：根因已定位（会话级损坏；代码序列无罪）；accept 两动作健康会话各 3/3 实机闭环；三个旧现场待操作者选择收尾（仅 restore_baseline 可用）

目标版本：待排期（2026-10-22 根因定位后 accept_saved/accept_live 已在健康会话各 3/3 实机闭环，不再阻断 BUG-077；偶发编辑 -1 子项与三个旧现场收尾保留；"修复排期或不修"结论待台账/用户明确；按对照证据暂不安排延迟、重试或替换保存接口）

来源与关联：BUG-077 第 2 组恢复链路实机验收过程中发现；BUG-055 记录的"accept_live 实机正向路径未验证"历史上从未取得实机通过，与本次发现一致。

## 问题或目标

已证实现象（本机 Creo 12.4.0.0 / 0.4.7 dev / 会话指纹 6265530161255170365，2026-10-22）：

1. **恢复 accept 路径 0/4 全败**：accept_saved/accept_live 的 native `recovery_save_and_reload` 阶段 `ProMdlnameBackup(board, destination)` 稳定返回 -1。四个失败样本（含教科书场景：candidate 由 native_result.json 佐证、三动作同时 available、owners stopped）：
   - `de6f0bb5…` accept_live 恢复作业 `3a219968…`
   - `bebe7e2b…` accept_live 恢复作业 `ee170974…`
   - `e5009037…` accept_saved 恢复作业 `2a1a47e3…` 与 `d8dea4ce…`（同模型同场景连续两次）
2. **对照证据**：同一会话内普通编辑路径 `save_and_reload` 的 `ProMdlnameBackup` 9/12 成功（创建首存、改尺寸后保存、孤儿执行器保存、非只读 regenerate 保存均成功）；恢复路径 `restore_baseline`（不做 Backup，直接采用 source_file）两次成功。失败集中于恢复 accept 路径的"erase 会话 live → 紧接 load 磁盘 source → 仅 Regenerate → Backup"序列。
3. **次要现象**：普通编辑路径当天另有 3 次 `ProMdlnameBackup -1`（`9506cdce…`/`dc9537e2…`/`446a3381…`），与成功样本操作同构，呈偶发；同日早晨存在"无人桌面期自动启动的 Creo async 通道未建立"事故（处置见 BUG-077 恢复链路记录），新会话由协调器重启后建立，但**复用了前一会话遗留的孤儿 nmsd（07:14 启动）**，是否与偶发 -1 相关未证实。
4. **影响**：模型保护语义正确（失败恢复作业保留 unknown_outcome/recovery_pending，不丢数据），但 accept_saved/accept_live 无法在实机完成 revision 推进；被阻断模型只能以 restore_baseline（若现场与基线一致或 live 已缺失）收尾，dirty 现场模型（`de6f0bb5…`/`bebe7e2b…`/`57294ff8…`）在修复前保持保护状态挂起。

## 范围

本次包含：问题登记与证据归档；机理分析（erase→load 邻接序列嫌疑、clean 模型 Backup 假说已被非只读 regenerate 成功对照排除）；2026-10-22 下午批次根因定位（事故会话 trail.txt.45 共 70 条 dbg_err_crash、健康会话 trail.46/49 零 crash）与两种 accept 各 3/3 独立夹具闭环（同键重放、恢复后编辑）。

不包含：native 修复——根因定位后建模/恢复代码序列无罪、本批零行为改动，延迟、重试、替换保存接口等候选均被对照排除；编辑路径偶发 -1 的根因（3 样本已归档并经 trail 归因同一损坏会话，健康会话 10 组对照未复现，保留为子项不宣称已解决）；孤儿 nmsd 生命周期治理；损坏会话再制造与会话级损坏检测代码。

## 实现与证据

### 2026-10-22 登记与证据

发现于[BUG-077 恢复链路验收记录](../validation/BUG077-RECOVERY-2026-10-22.md)第 5 节；全部 job_id/model_id/native 日志在该记录及 jobs 目录留档。四个失败恢复作业的 native 日志尾部一致：`PHASE=recovery_save_and_reload → ProMdlnameBackup(board, destination)=-1`；与成功编辑作业（`PHASE=save_and_reload → ProMdlnameBackup=0 → ProMdlErase=0 → ProMdlFiletypeLoad=0`）逐阶段对比已排除：目标目录、版本号、clean 模型（regenerate 对照成功）、显示窗口状态、磁盘/杀毒环境。

修复方向候选（未实施）：erase 与 load 之间增加延迟/窗口清理；accept_saved 直接采用 candidate 文件为 part_file 而不重写；Backup 失败重试一次。修复时须同步复核编辑路径偶发 -1（3 样本）是否同根因。

### 2026-10-22 对照补录

图纸路径同日 4 次连续 `ProMdlnameBackup` 成功（创建+三次编辑，`run_drawing` 无 erase→load 邻接），进一步支持"恢复路径 erase→load→Backup 序列"嫌疑。test_general 适配 0.4.7 结果摘要化结构后 7/7 通过，与偶发 -1 无关。

### 2026-10-22 下午批次：根因定位与实机闭环

[完整记录](../validation/BUG078-ROOT-CAUSE-2026-10-22.md)。要点：

- **根因**：全部 7 次 -1 集中于上午事故会话（trail `trail.txt.45`，复用孤儿 nmsd 启动）；该会话共 70 条 `dbg_err_crash() - continuing from serious error`（5 组×14，紧跟成功保存之后），保存子系统带伤运行。健康会话（trail.46/49）零 crash。erase→load→Backup 序列嫌疑被排除（accept_saved 即该序列，健康会话一次通过）；失败编辑与成功编辑日志完全同构。**建模/恢复代码零改动**——延迟、重试、换保存接口等候选均被对照排除。
- **实机闭环**：两种 accept 各 3 个独立夹具（delayed 悬挂场景）连续三轮全部 succeeded，revision 仅 +1、saved_file_reloaded_and_verified=true；同键重放返回原作业；恢复后可继续编辑/保存/重载。夹具脚本 `build/bug078/repro.py`（含重放与后编辑断言）、`build/bug078/baseline.py`（10 组创建+编辑对照，30 作业全过）留存可复跑。
- **子项保留**：编辑路径偶发 -1 本轮 10 组对照未复现；3 个历史样本经 trail 归因于同一损坏会话，按任务要求保留为子项不宣称根因在健康环境已解决。
- **旧现场**：三个挂起模型 live 已随损坏会话消失，live inspect 确认 baseline SHA 核验通过、owners stopped、**仅 restore_baseline 可用**（accept_live 因 live not loaded 不可用、accept_saved 因无 candidate 不可用）；收尾动作待操作者明确选择，原始异常历史保留。
- **未验证**：损坏会话再制造未实施；会话级损坏无 Toolkit 可观测前兆，暂不加检测代码；nmsd 生命周期治理维持范围外。
