# MCP_CREO_MechDog 0.14.0 版本说明

2026-11-06，PATCH 性质的回执与预览补证批；条目：[FEAT-039](work-items/FEAT-039.md)（W05 `extrude_depth` 回执、W06 只读预览与失败编辑回滚、偏置 Thin 树复测），随附 [BUG-102](work-items/BUG-102.md)、[BUG-094](work-items/BUG-094.md)、[BUG-095](work-items/BUG-095.md) 的发布后实机补证。公开工具仍为 **100** 个，无新增工具、无参数迁移、无回调注册变化、无新增原生编译要求。

本版不含 `surface_trim` 的 `offset_mm`/`offset_side` 开放：2026-11-06 的 Thin 树复测只证明了偏置会产生"移除厚度带"的几何，方向元素无效，与公开契约的 `keep_side` 语义冲突，两字段继续由 `capabilities.require_available` 在排队前拒绝。

- 拉伸深度回执（W05）：`creo_extrude` 的 `depth`/`depth_type` 改为可省略，省略按既有契约执行 blind / 1 mm，结果新增 `extrude_depth` 块（7 键：`requested_*` / `effective_*` / `source` / `query_code` / `defaulted_fields`），`effective_*` 从创建后的特征树实读 `PRO_E_STD_EXT_DEPTH → PRO_E_EXT_DEPTH_TO → PRO_E_EXT_DEPTH_TO_TYPE/_VALUE`，不靠回显。实机：`creo_extrude` 不传深度 → 体积 99.99999999999997 mm³、`requested` 两键 null、`effective=blind/1.0 mm`、`defaulted_fields=["depth","depth_type"]`；`creo_execute_plan` 只给 `depth=10` → 体积 999.9999999999999 mm³、`effective=blind/10.0 mm`、`defaulted_fields=["depth_type"]`，两例 `saved_file_reloaded_and_verified=true`、`extrude_depth_receipt="passed"`。`through_all` 的 `effective_depth_mm` 恒为 null，树读失败保留 `query_code` 且不伪造数值。入口用 `dump_plan_operations()` 按 `model_fields_set` 保留省略，`validate_operations` 的既有归一化契约不变；14 项单测覆盖省略捕获、plan 往返、`through_all` 不伪造与归一化丢弃未知键。
- 只读预览入口（W06）：不新增工具——`creo_export_model(format="jpeg")` 提交 READ 作业、不保存、revision 不推进，结果 `preview` 块（`status`/`path`）供界面显示，docstring 写明空件 `status="skipped_no_geometry"`、渲染失败 `status="failed"` 带 `failed_step`/`failed_code`。实机三段（run `20261106T004546_2a364d3b`，`preview_acceptance="passed"`）：空件跳过不报错；有几何 `status="written"`、`file_verified=true`、`preview_code=0` 且 9 个渲染步骤码全 0；两次编辑后重新生成预览；显式 jpeg 导出 `revision 3→3` 未推进（`read_only_revision_unchanged=true`）。
- 失败编辑回滚（BUG-096 场景，W06）：实机三场景全通过（run `20261106T004748_84fc913a`）——新建件建特征失败后孤儿模型被擦除（`reason="cleaned"`、`absence_verified=true`、`erase_code=0`）且同名重试成功；同名件已存在时 `reason="preexisting_same_name"`，不谎报已擦除、既有件 revision 不变；已保存件的失败编辑 `rollback_status="succeeded"`、`failed_model_cleanup.reason="not_new_model_job"`、revision 1→1 不变并可继续编辑。
- 偏置 Thin 树复测（门禁保持）：用低层 `creo_create_feature_tree` 按 `ProTrim.h` §(4.1) 构造两个 type 元素均为 `PRO_SURF_TRIM_THIN` 的树复测。40×20 填充 + x=20 竖直 quilt 工具：厚度 5 → 目标面积 **700**、厚度 10 → **600**、x=2 → **760**，工具 quilt 盒按厚度单向移动；即 `offset_mm` 只对 **quilt 工具**生效且语义是**移除厚度带、两侧保留**，`offset_side` 六种写法结果完全相同（方向由工具 quilt 朝向决定），负厚度再生成失败，基准面工具忽略厚度，厚度 0 再生成失败。结论见 [G5 契约 §2.7b](development/G5-NATIVE-CONTRACT.md)。原生侧偏置分支改为文档 Thin 树（Python 门禁下不可达），`capabilities` 的拒绝消息改为引用上述实测依据；公开 schema 不变。
- 发布后实机补证（W02—W04，属本版随附证据）：拔模双向 +352.044362 / −353.263560 mm³ 且 `effective_flip` 两次均 true（原始 Creo 10 `-1` 未复现，[BUG-102](work-items/BUG-102.md)）；基准面方向矩阵六例法向/原点解算与两入口三拒绝（无 job、无特征、revision 不变，[BUG-094](work-items/BUG-094.md)）；草图 origin 偏差矩阵（省略/精确/0.5e-6 通过，2e-6 与 ±1.07e-4 拒绝并带 signed/distance 诊断，[BUG-095](work-items/BUG-095.md)）。
