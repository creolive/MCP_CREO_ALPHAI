# Python 与 C++ 编码规范

规则适用于本项目代码；第三方代码、SDK、生成的常量表及运行产物保留原样。自动格式整理与行为修改分开提交。检查方法和存量问题处理见 [开发入口](../DEVELOPMENT.md)。

## 通用规则

- 长度为毫米，角度为度。特征标签以小写字母开头，仅含小写字母、数字、下划线，最多 28 字符。
- 协议字段、错误码和工具名属于公共接口；修改前明确兼容影响。诊断必须保留操作、阶段和有依据的原因，不凭单一错误码推断许可或版本。
- MCP 服务 stdout 仅承载协议消息；日志写 stderr 或日志文件。开发检查脚本可在 stdout 输出自身报告。
- 不记录许可值、敏感会话标识或本机配置全文。路径、许可、SDK 文件和二进制不进入源码提交。
- 输入校验、状态保护和几何成功判定保持显式。不能吞掉错误后返回成功，不能把未知结果当作可安全重试。
- 外部输入或原生测量涉及长度、坐标、变换、面积或体积时，记录实际单位名、到毫米的换算信息和原始查询码；查询未执行、返回不可靠或单位未知时用 `null` 表示，不能填成功码或默认为毫米。同层对象可共享同一份可信单位证据。混合单位的完整坐标变换须覆盖旋转块和平移。
- 注释说明原因、约束和 Toolkit 特殊要求；对复杂行为记录边界和验收方式。避免在多个位置维护同一业务规则。

## Python

- Python 3.12+、四空格、UTF-8、LF，格式行宽 100。函数/模块 `snake_case`，类 `PascalCase`，常量大写。
- Ruff 统一导入检查、未定义/未使用代码检查与格式化；配置在 `pyproject.toml`。首批规则为 E4/E9/F/I，后续增加规则需独立条目和基线审查。
- 新增公共函数标注参数及返回类型；复杂 JSON 边界优先使用已有 Pydantic 模型、明确结构或验证函数。先在公共边界推进类型，不要求立即全库严格类型检查。
- 避免通配导入、隐式依赖和新建 `sys.path` 补丁；迁移前已有独立脚本可保留入口定位。新模块以包依赖为目标，运行数据根目录不能隐式依赖模块位置。
- 异常在能补充上下文或执行恢复的层捕获；具体错误附带字段或操作信息。子进程设置超时，检查返回码，明确终态与未知结果。
- 保留原子文件替换和版本防护。修改登记、锁、回滚或恢复逻辑必须补回归用例，不能通过删除保护来解决阻塞。

```powershell
# 仅整理选定模块，先审查差异；不要混入建模行为修改
.\.venv\Scripts\python.exe -m ruff check --fix tools\selected_module.py
.\.venv\Scripts\python.exe -m ruff format tools\selected_module.py
```

## C++

- 保持 C++17 和当前 MSVC/Toolkit 构建约定。使用仓库 `.clang-format`：四空格、行宽 100、Microsoft 基础风格、附着花括号，保持 include 顺序，避免影响 SDK 声明依赖。
- 项目函数/变量使用清晰、与所在模块一致的名称；Toolkit API 和类型维持原命名。新增共享类型使用清晰类名，避免一次全库改名。
- 每次 Toolkit 调用检查 `ProError`；允许失败或忽略返回值时注释原因并验证后续状态。诊断带上 API 名称和错误码。
- `ProArray`、`ProSelection`、`ProElement`、`ProSection` 等资源明确所有权、释放 API 和异常路径；提取模块时优先引入能覆盖失败路径的 RAII 包装，遵守 SDK 对回调和句柄寿命的要求。
- C/C++ 回调边界明确错误传播方式，避免新增不受控的异常跨 SDK 边界传播。数值计算核对有限值、单位、容差及退化几何。
- 新增模块以头文件声明和 `.cpp` 独立编译为目标。已有文本包含方式属于迁移债务；先建立执行上下文和接口，再逐个改为独立编译，禁止直接全量拆分。
- 构建依赖清单按**实际引用**确定：被 loader/payload 或构建脚本实际包含的仓库原生文本（含 `native/third_party/` 协作头文件）必须参与对应构建指纹；不能按"第三方库/协作头文件"类别统一排除，也不能把未引用文件加入清单。行尾差异不影响指纹：仓库原生文本在计算构建指纹前统一做 CRLF→LF 归一化（`creo_mechdog.build_fingerprints`），二进制完整性与发布附件仍按原始字节计算（DEV-027）。
- MSVC 当前使用 `/W3`。新警告逐项处理；升级警告级别或加入静态分析先验证 SDK 兼容性，不能直接把第三方警告全部提升为构建失败。

```powershell
# 原生文件先格式整理、审查，再进行语义改动
.\.venv\Scripts\clang-format.exe -i --style=file native\selected_module.cpp
```

格式工具只处理代码外观，单元测试只验证其覆盖的逻辑；二者均不能替代原生几何和保存重载验收。

工具参考：[Ruff](https://docs.astral.sh/ruff/configuration/)、[clang-format](https://clang.llvm.org/docs/ClangFormatStyleOptions.html)。
