# v0.4.3 反馈开发完善计划

状态（2026-10-21 回填）：两批均已实施并随 **0.4.6 PATCH** 交付（用户指定两批统一按 PATCH 发布，含新增公开工具 `creo_erase_session_models`，按版本约定本应为 MINOR，遵用户指定作为本版例外，同 0.4.1/0.4.2 先例）；实施证据见[实施记录](../validation/FEEDBACK-0.4.3-IMPLEMENTATION-2026-10-21.md)与[发布核对](../validation/RELEASE-0.4.6.md)。DEV-027/030 已随 0.4.4、BUG-076 首批诊断已随 0.4.5 交付，未重复实施。以下正文保留规划时点。

## 1. 目标与基线

按已确认的节奏执行：**首批修复阻断问题，第二批补会话管理能力**。

- 首批完成真实零件“打开→收养→编辑→保存重载”，修复锁文件首建竞争，并完成指纹归一化和编译环境兼容。
- 第二批支持显式清理装配及其组件，完善依赖加载、快照变化和回调目录信息。
- 以当前 0.4.3 为基线。DEV-027/030 已有未提交改动，实施前审查并接续，保留其他工作区内容。
- 附件中的修法作为候选依据；外部测试通过、失败和未测范围分别保留，不直接改写为本机结论。

## 2. 第一批：修复与工程完善

### P1：真实零件收养被 16 MiB 预算阻断

新增 **BUG-076**，关联 FEAT-042、FEAT-023、BUG-071。

源码已确认预检包含完整几何资料；但尚缺外部原始结果文件，不能断言具体哪个文件超限。

- 为读取失败补充文件用途、阶段、实际字节数及预算诊断。
- 分离小型控制元数据与完整检查资料。结果、令牌、请求和登记使用摘要及受控文件引用，避免完整几何反复内联。
- 完整资料绑定所属目录、SHA256、会话和令牌；保留原生完整基线，以及源模型、复制后、保存重载后的带容差比较。
- 同时覆盖 `inspect/apply/prepare/confirm`、快照续签及登记读取，避免只修预检、后续再次超限。
- 预检预算拒绝统一返回 `available=false`、`reason_code=adoption_metadata_budget_exceeded`、实际量、预算和处理指引，不发布令牌或半登记。
- 已可能产生副本后的异常继续保留作业及 unknown 保护。兼容旧内联记录，公开调用参数保持不变。

首批解决资料传输和存储膨胀；进一步减少完整几何计算另作性能优化，不依赖尚未证明能覆盖所有编辑的版本戳。

### P1：BUG-057 外部复验失败

继续使用原 ID，将“验收中”调整为“待开发”，分别记录主通道锁和启动协调锁。

- 在包内统一 Windows 锁文件打开机制，两种锁继续使用独立路径。
- 优先 `OPEN_EXISTING`；不存在时 `CREATE_NEW`；创建碰撞或首建阶段拒绝访问时，仅立即回退一次共享打开。
- 保留非阻塞字节锁、常驻锁文件、不共享删除和 busy 立即拒绝；不增加延时循环、排队或 Toolkit 请求重试。
- 只有实际字节锁竞争返回 busy。ACL、共享打开及其他 I/O 错误保留原始错误码。
- 启动协调增加明确的锁访问错误分类，避免误报为配置错误。

附件第三项启动测试实际竞争的是独立 `startup.lock`，不能把三项失败写成同一已证实根因。离线诊断脚本应同时保留 CRT 对照和生产打开路径，分别统计结果。

### P2：DEV-027 指纹归一化

接续此前已确认方案和当前在途实现。

- 保留 `json.hpp` 等真实编译依赖，仅对仓库文本计算构建指纹时执行 `CRLF→LF`。
- SDK、有效配置、DLL 完整性和发布附件 SHA256 继续按原始字节计算。
- 分离逻辑指纹与物理世代目录键。旧缓存等价及 DLL 完整性均验证通过时，复用原目录，首次升级保持注册文件及 `exec_file` 不变。
- 真实依赖变化正常触发重建；损坏缓存或非法世代键不能被当作等价复用。

### DEV-030：显式编译环境兼容

沿用已确认的“**必需三键，其余接受并忽略**”。

- Python、PowerShell、配置回写统一要求大写 `INCLUDE/LIB/PATH`。
- 缺键列出缺项和最小示例；额外键仅提示键名，不回显值、不透传、不影响构建指纹。
- 保留必需值校验、缺省/null 行为及 compiler preflight；说明 SDK 路径须已并入完整的 `INCLUDE/LIB`。
- 本子项完成不代表 DEV-030 整卡完成。

同步将 `open_file/` 补入本机运行目录及升级保留说明，纠正开发入口、安装说明中的过时“当前版本”表述；历史原件保持不变。

## 3. 第二批：会话管理与可观察性

### 新增 FEAT-046：显式擦除会话模型

新增 `creo_erase_session_models`，覆盖用户选定的装配及组件清单：

- `inspect(targets)` 返回目标身份、阻断原因、擦除顺序、剩余对象和 600 秒令牌。
- `apply(evidence_token, idempotency_key)` 仅执行令牌中的清单，返回 `job_id`，通过现有工具轮询。
- 仅允许有盘、`modified=false`、非托管且无未知保护的对象；查询不完整、清单外引用或依赖环均拒绝。
- 按“装配→子装配→零件”顺序逐项执行，不自动扩大清单，不调用全局或递归擦除接口。
- 每项执行前复核身份、修改状态和引用关系。擦除后返还控制给 Creo，再分阶段查询确认消失；不能仅凭 API 返回零报告成功。
- 全作业持有同一通道锁。中途失败停止剩余项，明确报告已完成和未确认清单，不自动重载或重放。
- 不保存模型、不删除磁盘文件。允许处理符合条件的当前显示模型。

## 4. 验收标准

| 范围 | 必须取得的证据 |
|---|---|
| 收养 | 超过 16 MiB 的完整检查夹具贯通各模式；引用篡改、缺失、过期和源模型变化准确拒绝，无半登记 |
| 实机收养 | 复杂零件完成打开、收养、编辑、revision 推进和保存重载；原文件不变，详情分页可取全 |
| 锁竞争 | absent/empty/one_byte 下双线程及双进程各 200 轮，恰好一方获准、一方 busy；持续权限错误不伪装竞争 |
| 外部 BUG-057 | Windows 10 19045/Python 3.13.14 重跑原失败测试及全量单元后，才关闭原环境问题 |
| 指纹与配置 | LF/CRLF 等价、旧缓存迁移不改注册、真实变化触发重建；三键、额外键、非法值及双入口一致性通过 |
| 会话擦除 | 装配及组件清单清理后可再次打开装配；清单外引用、dirty、托管、部分失败及幂等均有证据 |

每批执行针对性回归、`tools/dev_check.py` 和适用 SDK 构建。原生变更取得本次实机证据；WorkBuddy 只做公开 MCP 黑盒验收，不执行源码测试。

外部两个原始零件优先用于复验；缺少样件时明确保留“原场景未复验”，不以简单模型替代。既有会话准入及故障注入限制继续有效。
