### T00 固定、T01/T02 共用的接口约定

下列是本批目标，尚未实现。T00 将它写入 DEV-048 的共享基线，不编写实现；T01/T02 不各自建立另一套诊断格式。

```json
{
  "inspection_warnings": [
    {
      "stage": "live",
      "reason_code": "native_sidecar_write_failed",
      "fallback_status": "verified",
      "message": "Native sidecar write failed; Python fallback was verified"
    }
  ]
}
```

- `stage` 为 `live` 或 `verified`；`fallback_status` 为 `verified`、`failed` 或 `not_attempted`。`verified` 必须有最终完整引用的大小、完整 SHA256 和可读性核验，不能仅因文件存在而填写。
- 本批原因码固定为 `native_sidecar_write_failed`、`native_sidecar_publish_failed`、`inspection_ref_invalid`、`inspection_ref_removed_after_refusal`；原始异常保留于日志，不能用字符串模糊匹配猜测原生失败阶段。
- 每个公开结果或批量 item 最多 4 条，按 `(stage, reason_code)` 去重，每条 `message` 最多 256 个 UTF-8 字节且不截断编码字符；完整原始错误留在作业日志。公开结果不出现尚待回退的临时状态。
- 字段可缺省；旧原生结果或旧登记无此字段仍兼容。旧内联资料正常拆分不是故障，不凭空增加警告。警告是存储事实，不改变作业成功、revision、保存重载或保护结论。
- 公开收养/恢复结果、批量每个 item 与 `creo_get_job` compact/full 保留同义诊断；结果嵌套或分页不得静默丢失。批量父作业不无限复制子项错误全文。
- `inspection_refs.make_ref`、`split`、`load_ref` 保持现有调用签名。T01 在该包内模块增加共用 `split_result(result: dict, directory: Path) -> dict`、`add_warning(holder: dict, *, stage: str, reason_code: str, fallback_status: str, message: str) -> None`、`warnings_of(holder: dict) -> list[dict]`；既有 `adoption._split_result` 委派共用处理，恢复路径也复用。T02 使用这些约定，不另建相同职责的工具或模块。
